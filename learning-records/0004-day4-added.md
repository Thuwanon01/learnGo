# Day 4 เข้าระบบ — จุดที่เปลี่ยนจาก "เขียนโค้ดได้" เป็น "ออกแบบระบบได้"

เพิ่มบทเรียน 09–13 จากสไลด์ Day 4 (66 หน้า) ตามขั้นตอนใน [[NOTES.md]]
หัวข้อ "เวลาเพิ่มวันใหม่"

**ทำไมวันนี้ต่างจาก Day 1–3:** สามวันแรกเป็นไวยากรณ์ — ตัวแปร, control flow,
โครงสร้างข้อมูล ถ้าจำได้ก็เขียนโค้ดที่รันได้ **Day 4 เป็นวันแรกที่สอน
"การตัดสินใจเชิงออกแบบ"** — จะแยก type ไหม, interface ควรใหญ่แค่ไหน,
error ควรพกอะไรไปด้วย, JSON ควรแยก struct ไหม
คำถามพวกนี้ไม่มีคำตอบเดียว แต่มีคำตอบที่ทีมรับได้กับรับไม่ได้

**ผลที่ตามมากับรูปแบบบทเรียน:**
- บทเรียน 09–13 มีหัวข้อ "กับดัก" มากกว่าบทก่อนหน้าอย่างเห็นได้ชัด
  เพราะเรื่องเหล่านี้พังแบบ**เงียบ ๆ** ไม่มี error — ต่างจาก slice/pointer
  ที่พังแล้ว panic ให้เห็นทันที
- predict-the-output ในวันนี้จึงเน้นคำถาม **"มี error ไหม"** มากกว่า
  "ได้ค่าอะไร" เพราะคำตอบที่น่ากลัวคือ "ไม่มี error แต่ข้อมูลหาย"

**จุดที่รันแล้วเจอเพิ่มเติมจากที่สไลด์บอก** (ทั้งหมดยืนยันบน Go 1.26.5):

| เรื่อง | สิ่งที่พบ |
|---|---|
| `encoding/json` จับคู่ key | **case-insensitive** — `{"ID":"P001"}` เข้า field ที่ tag ว่า `json:"id"` ได้ ทำให้ contract ไม่ตรงกันแต่โค้ดยังทำงาน |
| typed nil | คืน `var e *AppError = nil` จากฟังก์ชันที่คืน `error` → `err != nil` เป็น **true** |
| ลำดับ case ใน type switch | type ที่ implement ทั้ง `error` และ `fmt.Stringer` เข้า case แรกที่เขียนไว้ · `fmt.Println` เลือก `Error()` ก่อน `String()` |
| `map[string]any` | ตัวเลขทุกตัวออกมาเป็น `float64` ไม่ใช่ `int` |
| ไม่มี `Unwrap()` | `errors.Is` พัง (`false`) แต่ `errors.As` **ยังรอด** เพราะ error ชั้นนอกสุดคือ type นั้นอยู่แล้ว |

**Implications:**
- ข้อ "case-insensitive" กับ "typed nil" ไม่มีในสไลด์เลย แต่เป็นสองเรื่องที่
  ทำให้ระบบจริงพัง — ใส่เป็นหัวข้อเต็มในบทเรียน 12 และ 13
- ยังเหลือหัวข้อ **Generics** ที่อยู่ใน outline แต่ไม่มีในสไลด์
  (ดู [[0002-course-slides-have-errors]]) — ยังไม่ทำบทเรียนจนกว่าผู้เรียนจะสั่ง
  หรือสไลด์วันถัดไปมาถึง
