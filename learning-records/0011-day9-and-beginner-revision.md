## brief ของผมผิดอีกครั้ง — คราวนี้เกือบทำให้บทกล่าวหาสไลด์ผิด ๆ

ผมเขียน brief สั่ง agent ให้ไปพิสูจน์ว่า `GOOSE_DBSTRING` ในสไลด์หน้า 50 พังสองจุด
คือ `@` ในรหัสผ่านไม่ได้ encode และใช้ `?database=` แทน path

รันเองแล้วพบว่า **ไม่พังสักจุด**:

```
postgres://postgres:x@localhost:5432?database=wongnok           Database="wongnok"
postgres://postgres:x@localhost:5432/other?database=wongnok     Database="wongnok"  ← query ชนะ path
```

`net/url` ของ Go ตัด userinfo ที่ `@` **ตัวสุดท้าย** และ pgx รับ `?database=` เป็น
connection parameter จริง · agent ก็รายงานกลับมาตรงกันว่า brief เดาผิด

**แต่ agent ไปเจอของที่ทั้งผมและสไลด์มองข้าม** — `libpq` (ฝั่ง `psql`) ตัดที่ `@` **ตัวแรก**
พฤติกรรมสองฝั่งไม่ตรงกัน ผู้เรียนที่ก๊อป DSN เดียวกันไปวางใน `psql` จะพังทันที
ข้อสรุปที่ถูกจึงไม่ใช่ "สไลด์ผิด" แต่คือ **"เขียน `%40` เสมอ เพราะ Go กับ psql ตีความไม่เหมือนกัน"**

## สิ่งที่ตั้งใจสร้าง: บทเรียนที่มือใหม่อ่านรู้เรื่อง

ผู้เรียนสั่งกลางทางว่า *"ให้ยกตัวอย่างที่เห็นภาพง่ายๆ ไม่ต้องศัพท์เยอะ เน้นเข้าใจ"*
แล้วเสริมอีกประโยคที่เปลี่ยนทุกอย่าง:

> *"พออธิบายเสร็จ ยกตัวอย่างเสร็จ ค่อยเติมศัพท์ technic เข้ามา
> เพื่อให้ผู้เรียนคุยกับ Dev senior / AI ได้อย่างรู้เรื่อง"*

จึงกลายเป็น **ลำดับ 3 ขั้น** ที่ใช้กับทุกบท และเพิ่มกล่องใหม่ 2 แบบใน `assets/lesson.css`:

1. อธิบายด้วยภาษาคนธรรมดา
2. `.analogy` — เทียบกับของในชีวิตจริง **บังคับให้มีท่อน "ที่ไม่เหมือนกัน"**
3. `.jargon` — ติดป้ายศัพท์ทีหลัง พร้อมประโยคที่เอาไปพูดกับ senior ได้จริง

ตัวอย่างที่ออกมาดี (บทเรียน 06 — slice aliasing):

> **โต๊ะยาว 5 ที่นั่งกับใบจอง** — ใบจองเขียนว่า "โต๊ะ A · เริ่มเก้าอี้ตัวที่ 2 · จองไว้ 2 ที่"
> ถ่ายเอกสารแจกเพื่อน 10 ใบ โต๊ะก็ยังมีตัวเดียว · **slice = ใบจอง · array = ตัวโต๊ะ**
> *ที่ไม่เหมือนกัน:* ที่ร้านจริงพนักงานจะทักถ้าใบจองทับกัน แต่ Go ไม่มีใครทัก

แล้วกล่องถัดไปเรื่อง `len`/`cap` **ต่อยอดอุปมาเดิม** ไม่เปลี่ยนเรื่องใหม่ให้สับสน

## บทเรียนสำคัญ: การทำให้ง่ายขึ้น ทำให้ผิดง่ายกว่าเดิม

นี่คือสิ่งที่ไม่ได้คาดไว้ — **การเขียนคำอธิบายให้ง่าย อันตรายกว่าการเขียนโค้ด**
เพราะโค้ดผิดแล้ว compiler ฟ้อง แต่การเปรียบเทียบที่ผิดไม่มีใครฟ้อง

รอบตรวจจับได้ **288 จุด (ผิดจริง 33)** ตัวอย่าง:

- **บทเรียน 02** กล่องเปรียบเทียบเขียน `int(3.9)` ได้ `3` — Go คอมไพล์ไม่ผ่าน
  (`cannot convert 3.9 (untyped float constant) to type int`)
  และที่หนักคือ **กล่อง `.note` ที่อยู่ห่างลงไป 8 บรรทัดในไฟล์เดียวกัน เขียนไว้เองว่าอันนี้ไม่ผ่าน**
- **บทเรียน 02** อีกจุด — ของเดิมเขียนว่า "ต้องขึ้นต้นด้วย keyword (package, import, func, var, const, type)"
  ซึ่งถูก · agent แก้เป็น "keyword ซึ่งมีแค่ 6 คำนี้" → **Go มี keyword 25 คำ**
  นี่คือกรณีที่ **การแก้ทำให้แย่ลงกว่าเดิม**
- **บทเรียน 03** กล่อง "หลักกิโลเมตร" อ้างว่าบรรทัดว่างใน `const` ได้เพราะ `iota` นับให้ —
  **ผิดกลไก** พิสูจน์ได้ว่า `const ( a = 5; b )` ให้ `b == 5` ทั้งที่ไม่มี `iota` เลย

กฎที่เพิ่มเข้าไปในสัญญาของ agent หลังจากนี้: **ความถูกต้องมาก่อนความง่ายเสมอ ·
ถ้าเปรียบเทียบแล้วเลี่ยงความเข้าใจผิดไม่ได้ ให้ตัดการเปรียบเทียบทิ้ง แล้วเขียนตรง ๆ สั้น ๆ แทน**

## กับดักของเครื่องตัวเอง — เกิดขึ้นจริงตามที่กันไว้

รอบที่แล้วเจอว่า agent เอา output ของ wrapper (`diff` → `[ok] Files are identical`) ไปใส่บทเรียน
รอบนี้ใส่กฎกันไว้ใน brief ตั้งแต่ต้น แล้ว**มันก็เกิดอีกในรูปแบบใหม่**:

```
$ ls -l .../go.sum
444  /Users/.../go.sum  0B          ← รูปแบบของ wrapper ล้วน ๆ
```

`/bin/ls` ตัวจริงขึ้นต้นด้วย permission string เสมอ ผู้เรียนรันตามจะไม่มีทางเห็น `0B`
ตัวตรวจจับได้เพราะกฎอยู่ใน brief · **บทสรุปคือกฎนี้ต้องอยู่ในทุก brief ตลอดไป**
และเวลาจะโชว์ขนาดไฟล์ ให้ใช้ `wc -c` ที่ output เหมือนกันทุกเครื่อง
