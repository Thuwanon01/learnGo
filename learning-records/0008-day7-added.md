## ใช้ workflow กระจายงาน — ผลจริงเป็นยังไง

โครงที่ใช้: **Verify (4 agent รันของจริงคู่ขนาน) → Write (5 agent เขียนบทเรียน) → Cheat sheet**

**ที่ได้ผลดีมาก:** ให้ agent ติดตั้งเครื่องมือจริงแล้ว *สั่งให้ตั้งใจทำให้พัง*
ได้กับดักที่พิสูจน์แล้วรวม 55 ข้อ พร้อม error verbatim — มากกว่าที่คนเดียวจะทำทันในวันเดียว
ของที่ได้มาแบบนี้เอาไปทำ predict-the-output ได้ตรง ๆ

**บั๊กที่ตัวเองทำ:** ประกาศตัวแปร `LESSONS` ไม่ครบในสคริปต์ → เฟส Verify วิ่งจบสวยงาม
แต่เฟส Write พังทั้ง 4 กลุ่มด้วย `LESSONS is not defined`
**สิ่งที่ช่วยไว้คือ resume** — แก้สคริปต์แล้ว resume จาก runId เดิม
ผลตรวจที่แพงที่สุด (ติดตั้ง + docker) ถูกดึงจาก cache ไม่ต้องรันซ้ำ
→ **บทเรียน: ตรวจว่าตัวแปรทุกตัวถูกประกาศก่อนยิง workflow ยาว ๆ**

## เรื่องที่สำคัญที่สุดของวันนี้ — subagent ตัดสิน "สไลด์ผิด" ไม่ได้

agent รายงานกลับมาว่าเจอสไลด์ผิด **21 จุด** · คัดกรองเองแล้วเหลือ **5 จุด**

| ประเภทที่ตัดออก | ตัวอย่าง |
|---|---|
| สไลด์ไม่ได้เขียนผิด แต่ agent ตีความเกิน | "Redis เก็บใน RAM" — สไลด์เขียน *"เป็นหลัก"* ไว้แล้ว |
| ช่องว่างของสไลด์ ไม่ใช่ความผิด | สไลด์ไม่ได้บอกเรื่อง `GOOSE_DRIVER` / `DOCKER_HOST` |
| **agent อ่านสไลด์คลาดเคลื่อนเอง** | อ้างว่าสไลด์ตั้ง `all` ผิดระดับ ทั้งที่สไลด์ถูกอยู่แล้ว |

**สาเหตุ:** agent เห็นแต่ผลรันของตัวเอง มันไม่ได้อ่านสไลด์ทั้งหน้า
มันจึงเก่งเรื่อง *"ของจริงทำงานยังไง"* แต่ตัดสิน *"สไลด์พูดว่าอะไรกันแน่"* ไม่ได้

**กฎใหม่ของ workspace:** ผลตรวจจาก subagent เอาไปใส่ learning record ไม่ได้ทันที
ต้องเอามาเทียบสไลด์เองก่อนเสมอ · ทั้ง 5 จุดที่บันทึกไว้ รันซ้ำด้วยมือเองทุกจุด

## จุดที่ยังตรวจซ้ำไม่ได้ — ต้องกลับมาทำเมื่อเปิด Docker

ให้ผู้ตรวจ "ตั้งข้อสงสัย" กับข้อความที่อ้างผลรัน โดยห้ามแก้เอง ได้มา **27 จุด**
คัดแล้วเป็นดังนี้:

**ตัดสินได้เองทันที (goose/mockery ยังติดตั้งอยู่ ไม่ต้องใช้ Docker) — 6 จุด**

| ข้อสงสัย | ผลตัดสิน |
|---|---|
| `goose create` น่าจะมี `StatementBegin/End` มาให้ | **บทเรียนถูก** — รันเองแล้วได้แค่ `Up`/`Down` · ผู้ตรวจเดาจากความจำ |
| usage ของ goose น่าจะเป็น `[OPTIONS] DRIVER DBSTRING` | **บทเรียนถูก** — ของจริงคือ `goose DRIVER DBSTRING [OPTIONS] COMMAND` |
| `.mockery.yml` "28 บรรทัด" | **ผู้ตรวจถูก** — นับจริงได้ **27** · แก้แล้ว 2 จุด |
| ตารางเทียบบรรทัดเขียนชื่อไฟล์ `mocks.go` | **ผู้ตรวจถูก** — ทั้งบทใช้ `mocks_test.go` · แก้ชื่อให้ตรงแล้ว |

Docker (colima) เปิดแล้วจึงยิง 3 agent รันของจริงเทียบ **ทุกบล็อก output** ในบท 30/31/32

### จุดเดียวที่เป็นข้อผิดพลาดเชิงการสอน — และเป็นของผมเอง ไม่ใช่ของสไลด์

บท 30 หัวข้อ 4 เขียนไว้ว่า:

> มีคนแก้ด้วยการเรียก `flag.Parse()` เองก่อน `m.Run()` — **อย่าทำ**
> เพราะ flag ตระกูล `-test.*` ถูกลงทะเบียนโดย package `testing` ตอน `m.Run()`

**ผิดทั้งกลไกและคำแนะนำ** — รันเองแล้วได้:

```
$ go test -v
ใน TestMain หลัง flag.Parse(): testing.Short() = false
$ go test -short -v
ใน TestMain หลัง flag.Parse(): testing.Short() = true
```

`flag` ตระกูล `-test.*` ถูกลงทะเบียนโดย `testing.Init()` ซึ่ง `MainStart` เรียก
**ก่อน `TestMain` จะเริ่มทำงาน** (`$(go env GOROOT)/src/testing/testing.go` บรรทัด 2321)
สิ่งที่ยังไม่เกิดตอน `TestMain` เริ่มคือ *การ parse* ไม่ใช่ *การลงทะเบียน*

แก้แล้ว: เขียนหัวข้อนั้นใหม่ทั้งย่อหน้า — บอกว่า `flag.Parse()` **ใช้ได้จริง** พร้อมผลรัน
แล้วเปลี่ยนเหตุผลที่ยังแนะนำ `sync.Once` ให้เป็นเหตุผลที่ถูก:
`-short` เป็นสวิตช์ที่หยาบเกินไป — โครง `TestMain` ยัง boot container ทุกครั้งที่รัน package นี้
แม้จะสั่ง `go test -run TestOneUnitTest` ที่ไม่แตะ DB เลย ส่วน lazy boot จะเกิดเมื่อมีเทสขอใช้จริงเท่านั้น

### agent ตัดสินผิดหนึ่งจุด — ยืนยันว่ากฎ "ห้ามเชื่อทันที" ยังจำเป็น

agent บท 32 รายงานว่าบล็อก eviction เป็น MISMATCH เพราะมันรัน 5 ครั้งแล้วได้
`รอบ 1: 0` ทุกครั้ง ไม่ใช่ `รอบ 1: 1` อย่างที่บทเขียน

**ผมรันตามบทเป๊ะ ๆ เอง (maxmemory 3mb · allkeys-lru · 3 รอบ รอบละ 50,000) แล้วได้ตรงกับบททุกบรรทัด:**

```
รอบ 1: EXISTS important:1 = 1   DBSIZE=15596
รอบ 2: EXISTS important:1 = 0   DBSIZE=15390
รอบ 3: EXISTS important:1 = 0   DBSIZE=15390
TTL important:1 = -2
```

LRU ของ Redis เป็นแบบ **approximate** (สุ่ม sample ไม่ได้ไล่จริง) ผลจึงแกว่งตามวิธียัดข้อมูล
agent เปลี่ยนขนาด payload ไปทดลองเอง เลยได้คนละผล → **บทถูก ไม่ต้องแก้**

> กฎเดิมจาก Day 7 ที่ว่า *"ผลตรวจจาก subagent ห้ามเชื่อทันที"* ยังใช้ได้ —
> แต่ต้องขยายความ: มันผิดได้**สองทาง** ทั้งบอกว่าผิดทั้งที่ถูก (เคสนี้)
> และบอกว่าถูกทั้งที่ผิด · ทางแก้เดียวกันคือ**รันเองก่อนตัดสิน**

### สภาพแวดล้อมที่ใช้ตรวจรอบนี้

Docker บนเครื่องนี้คือ **colima ไม่ใช่ Docker Desktop**
(`docker context` active = `colima` · Ubuntu 24.04.4 · Docker Server 29.5.2 · 6 CPU · RAM 8 GB)
testcontainers ทำงานได้ปกติ แต่ agent ต้องตั้ง
`TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock` คู่กับ `DOCKER_HOST`
