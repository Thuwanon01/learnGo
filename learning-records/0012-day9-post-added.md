## สามการแก้ในเนื้อหา

### 1. ลบ `KC_HOSTNAME: localhost` ออกจาก compose (หน้า 40) — อันนี้สำคัญที่สุด

บทเรียน 51 ที่ผมเขียนไว้แล้วบอกว่า compose ตั้งสองบรรทัดที่ตีกัน
(`KC_HOSTNAME` กับ `KC_HOSTNAME_STRICT`) โดยอ้างล็อกของ Keycloak เองที่พิมพ์ว่า
*If hostname is specified, hostname-strict is effectively ignored*
แล้วผมสรุปว่า **"ลบ `KC_HOSTNAME_STRICT` ทิ้งได้ ผลเหมือนเดิมทุกประการ"**

อาจารย์ลบอีกบรรทัดหนึ่ง

ตอนแรกผมคิดว่าเป็นเรื่องรสนิยม จนกระทั่งยกคอนเทนเนอร์ขึ้นมาเทียบสองตัวจริง ๆ
แล้วยิง discovery ด้วย `Host:` header ต่างกัน:

| ยิงด้วย `Host:` | มี `KC_HOSTNAME` | ไม่มี |
|---|---|---|
| `localhost:<port>` | `http://localhost:8093/realms/master` | `http://localhost:8091/realms/master` |
| `127.0.0.1:<port>` | `http://**localhost**:8093/…` | `http://**127.0.0.1**:8091/…` |
| `evil.example.com` | `http://localhost/…` (พอร์ตหายด้วย) | `http://**evil.example.com**/…` |

แล้วจุดที่ทำให้มันไม่ใช่เรื่องรสนิยม — เรียกจากในเน็ตเวิร์ก Docker ด้วยชื่อคอนเทนเนอร์
(ซึ่งคือสิ่งที่ Go API จะทำเมื่อย้ายเข้าไปอยู่ใน compose ด้วยกัน):

```
kcpre  (ปักหมุด)   http://kcpre:8080/…  -> issuer = http://localhost:8080/realms/master
kcpost (ไม่ปักหมุด) http://kcpost:8080/… -> issuer = http://kcpost:8080/realms/master
```

แถวบนคือ "เรียกไปที่หนึ่ง เขาตอบว่าอยู่อีกที่หนึ่ง" ซึ่ง `go-oidc` ปฏิเสธทันที
ผมเขียนโปรแกรมสั้น ๆ ยืนยัน ได้ error จริง:

```
oidc: issuer URL provided to client ("http://127.0.0.1:8093/realms/master")
did not match the issuer URL returned by provider ("http://localhost:8093/realms/master")
```

**นี่คือความผิดพลาดของผมเอง ไม่ใช่ของอาจารย์:** ผมพิสูจน์ได้ถูกต้องว่า
`KC_HOSTNAME_STRICT` ไม่มีผล แล้ว**หยุดตรวจตรงนั้น** —
โดยไม่ได้ถามต่อว่า "แล้วบรรทัดที่ *มี* ผล มันมีผลอะไรบ้าง"
พอเจอสองอย่างที่ตีกัน ผมสรุปว่า "ตัดอันไหนออกก็ได้" ซึ่งเป็นคำตอบที่**สมมาตรเกินจริง**

ของแถมที่เจอตอนตรวจซ้ำ: บรรทัด `KC_HOSTNAME_STRICT: "false"` ที่เหลืออยู่
**เปลี่ยนสถานะจาก "ถูกเมิน" เป็น "ถูกอ่านจริง"** — ลองสามแบบ:
ไม่ใส่ = รันขึ้น · ใส่ `"false"` = รันขึ้น · ใส่ `"true"` = **คอนเทนเนอร์ตาย**
พร้อมข้อความ `hostname is not configured; either configure hostname, or set hostname-strict to false`

### 2. เพิ่ม `image_url TEXT` ในตาราง `users` (หน้า 51)

คอลัมน์เดียว แต่มันไม่ได้โผล่มาลอย ๆ — หน้าโจทย์สอบที่เพิ่มเข้ามาใหม่
สั่งให้ทำ `PUT /api/v1/users/me` ที่แก้ได้แค่ `bio` กับ `imageUrl`
**ถ้าไม่มีคอลัมน์นี้ก็เขียนข้อนั้นไม่ได้**

รัน goose ของจริงกับ Postgres 17 เพื่อเอา `\d users` ที่ถูกต้องมาแทนของเดิมในบทเรียน
(ไม่ได้แก้ตารางในบทเรียนด้วยมือ)

ของแถม: สไลด์ฉบับ Post เขียน SQL ด้วยรูปแบบที่ผ่าน formatter มา
(`CREATE TABLE` ขึ้นบรรทัดใหม่ · `now ()` มีเว้นวรรค) — goose รับได้ปกติ ไม่ต้องแก้

### 3. Mid Exam Brief จาก 1 หน้าเป็น 2 หน้า

หน้าที่เพิ่มมาคือหน้าที่ **ยากกว่า** — `PUT`/`DELETE` recipe และ profile endpoint
ที่ `:id` รับได้แค่ `"me"` · ส่วนหน้าเดิมถูกแก้สองจุด:
`average_rating` → `averageRating` และ `favorite=true` → `favorite=true|false`

การแก้อันหลังดูเล็กมาก (6 ตัวอักษร) แต่มัน **เปลี่ยนโจทย์จากสองสถานะเป็นสามสถานะ**
ผมรัน `httptest` เทียบ `bool` กับ `*bool`:

```
/x                 -> *bool=nil (ไม่ได้ส่งมา)  bool=false
/x?favorite=false  -> *bool=false              bool=false
```

`bool` ธรรมดาแยก "ไม่ได้ส่ง" กับ "ส่ง false" ไม่ออก **และไม่มี error ใด ๆ**
นี่จึงเป็นข้อที่เสียคะแนนได้โดยที่เทสของตัวเองผ่านหมด

## จุดที่สไลด์ยังไม่แก้

`GET /api/v1/recipes?favoite=true` — ตก `r` เหมือนเดิม
ทั้งที่บรรทัดหัวข้อเหนือมันในหน้าเดียวกัน**ถูกแก้ในรอบนี้**
แปลว่าคนแก้อ่านผ่านบรรทัดนั้นไปแล้วแต่ไม่เห็น ซึ่งเป็นธรรมชาติของ typo
ที่อยู่ในบล็อกโค้ด — ตายังอ่านมันเป็น "ของที่ถูกอยู่แล้ว"

## บทเรียนที่เอาไปใช้ต่อ

**เมื่อพิสูจน์ได้ว่า "บรรทัดนี้ไม่มีผล" ยังไม่จบ — ต้องถามต่อว่าบรรทัดที่มีผล มีผลอะไร**
ตอนตรวจ config ที่ตีกัน สมองอยากได้คำตอบว่า "อันไหนไร้ประโยชน์"
แล้วพอได้คำตอบก็หยุด แต่คำถามที่มีค่ากว่าคือ "**ถ้าเอาแต่ละอันออก จะเกิดอะไรขึ้น**"
ซึ่งต้องรันสองรอบ ไม่ใช่รอบเดียว

**ความต่างที่มองไม่เห็นบน `localhost` คือความต่างที่จะไปโผล่ตอนขึ้น compose**
ทั้ง `kcpre` และ `kcpost` เปิดผ่านเบราว์เซอร์แล้วเหมือนกันเป๊ะทุกอย่าง —
ถ้าตรวจแค่ "เปิดได้ไหม" จะไม่มีวันเห็นปัญหานี้
ต้องจงใจ**เรียกด้วยชื่ออื่นที่ไม่ใช่ `localhost`** ถึงจะเจอ
