## วันนี้ต่างจากทุกวันตรงไหน

หกวันแรกสอน *ภาษา* Day 7 สอน *เครื่องมือรอบฐานข้อมูล* — Day 8 เป็นวันแรกที่
**ผู้เรียนต้องเปิด port แล้วให้คนอื่นยิงเข้ามา** ซึ่งเปลี่ยนคำถามที่ต้องตอบไปทั้งหมด
จาก "โค้ดนี้ทำงานถูกไหม" เป็น "สัญญาที่เราให้ไว้กับคนนอกคืออะไร"

ผลคือบทเรียนวันนี้ **แบ่งเป็นสองครึ่งที่คนละธรรมชาติกัน**

- **บท 33–36 ไม่มีโค้ด Go เลยแม้แต่บรรทัดเดียว** — เป็นบทออกแบบล้วน
  (resource, status code, query/body/header, กฎตั้งชื่อ + idempotency)
  เพราะการเลือก `404` หรือ `409` ไม่ใช่เรื่องของภาษา
- **บท 37–42 เป็นโค้ดล้วน** — net/http → Gin → binding/middleware → httptest → Swagger → workshop

ถ้าเอาสองครึ่งนี้ปนกัน ผู้เรียนจะจำ API ของ Gin ได้แต่ยังออกแบบ endpoint ไม่เป็น
ซึ่งเป็นอาการที่เจอบ่อยที่สุดของคนที่เรียน framework ก่อนเรียน HTTP

## จุดที่ผมเขียน brief ผิดเอง แล้ว agent แก้ให้

ผมเขียนใน brief ของบท 38 ว่า *"route `/users/:id` ชนกับ `/users/me` → Gin panic
(net/http ไม่ panic) — นี่คือความต่างที่จับต้องได้ที่สุดระหว่างสองตัว"*

**ผิด** — agent เฟส Verify รันจริงแล้วได้ `OK (no panic)` ทั้งสองลำดับ
แล้วยังไปรันซ้ำบน gin v1.9.1 เพื่อยืนยันว่าไม่ใช่เรื่องเวอร์ชัน ได้ผลเหมือนกันทุกบรรทัด
static ชนะ param ทั้งใน Gin และ net/http

agent ที่เขียนบท 38 อ่าน facts แล้ว **ไม่เชื่อ brief ของผม** — มันเอาความเข้าใจผิดอันนี้
ไปทำเป็น predict-the-output เสียเลย แล้วเขียนว่า *"ที่คน (และบทความจำนวนมาก)
เข้าใจผิดว่า static ชนกับ param แล้ว Gin panic"*

> **บทเรียนที่ต้องจำ**: brief ที่ผมเขียนให้ agent **ก็ต้องผ่านการตรวจเหมือนกัน**
> วิธีที่กันไว้ได้คือลำดับ Verify → Write และเขียนในคำสั่งว่า
> *"ถ้าผลจริงต่างจากที่คำถามคาดไว้ ให้รายงานตามจริง อย่าดัดให้ตรงคำถาม"*
> ประโยคนี้คือสิ่งเดียวที่กันไม่ให้ agent เขียนตามที่ผมสั่งผิด

## ของที่ตรวจเจอเองระหว่างรอ agent

Swagger ทั้งหมดผมรันเอง ไม่ได้ปล่อยให้ agent ตรวจ — และเจอกับดักที่**สไลด์ไม่ได้พูดถึงเลย**
แต่คนที่ทำตามสไลด์ตรง ๆ มีโอกาสเจอสูงมาก:

`gin-swagger v1.6.1` ลาก `swaggo/swag` **v1.8.12** เข้ามาเป็น dependency
แต่ `swag` CLI ที่เพิ่ง `go install ...@latest` เป็น **v1.16.4** →
`docs.go` ที่มันสร้างใช้ field ที่ library เก่ายังไม่มี:

```
docs/docs.go:169:2: unknown field LeftDelim in struct literal of type "github.com/swaggo/swag".Spec
FAIL	wongnok/cmd/api [build failed]
```

แก้ด้วย `go get github.com/swaggo/swag@latest` (v1.8.12 → v1.16.6)
**หลักการ**: `swag` CLI กับ `github.com/swaggo/swag` ใน `go.mod` ต้องเป็นรุ่นใกล้กัน
