# โครงสร้าง workspace: แยกตามวัน + index เป็นประตูเดียว

ผู้เรียนขอให้จัดใหม่เป็นโฟลเดอร์ `day-1/` `day-2/` `day-3/` และทำ `index.html`
เป็นไฟล์ตั้งต้นที่มี Content Table ของทุกเรื่อง พร้อมบอกว่า
**"ฉันจะเอาวันอื่น ๆ มา add เพิ่มให้คุณ ทำสรุปแบบนี้เรื่อย ๆ"**

**ทำไมถึงสำคัญ:** เปลี่ยนจาก "ตอบคำถามครั้งเดียว" เป็น **คอร์สที่โตขึ้นเรื่อย ๆ**
การตัดสินใจเชิงโครงสร้างจึงต้องรองรับการเพิ่มวันใหม่โดยไม่ต้องรื้อของเดิม:

- **เลขบทเรียนต่อเนื่องข้ามวัน** (0001–0008 แล้วต่อ 0009+) ไม่ใช่รีเซ็ตทุกวัน
  → ลำดับการเรียนชัดเจน และแทรกวันใหม่ต่อท้ายได้ทันที
- **cheat sheet หนึ่งอันต่อวัน** ชื่อ `cheatsheet.html` เหมือนกันทุกวัน
  → เดาที่อยู่ได้โดยไม่ต้องเปิดดู
- **assets ใช้ร่วมกันทั้งคอร์ส** (`lesson.css`, `quiz.js`, `progress.js`)
  → หน้าตาเหมือนกันหมด แก้ที่เดียวมีผลทุกหน้า
- **progress tracking ใน localStorage** ที่ `index.html`
  → ผู้เรียนกลับมาแล้วรู้ว่าค้างตรงไหน โดยไม่ต้องมี backend

**Implications:** เวลารับสไลด์วันใหม่ ให้ทำตามขั้นตอนใน [[NOTES.md]] หัวข้อ
"เวลาเพิ่มวันใหม่" และ**รัน link checker ทุกครั้ง** — ตอน restructure รอบนี้
เจอ link พัง 1 จุดจากการเปลี่ยนชื่อไฟล์ ถ้าไม่ได้ตรวจจะหลุดไปถึงมือผู้เรียน
