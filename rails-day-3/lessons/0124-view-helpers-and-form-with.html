1 · helper คืออะไร — เครื่องมือในลิ้นชักของคนจัดจาน

helper คือ method ที่ Rails เตรียมไว้ให้เรียกใน view เพื่อทำงานจัดหน้าตาที่ทุกหน้าต้องทำซ้ำ ๆ — ตัดข้อความยาวให้สั้น · บอกว่า "เขียนเมื่อ 1 เดือนก่อน" · ใส่หน่วยเงินให้ตัวเลข · มันรับค่าเข้าไป แล้วคืนข้อความ (หรือ HTML) ออกมาให้ <%= %> วางบนหน้า

ถ้าไม่มี helper ทุกหน้าต้องเขียนวิธีตัดข้อความ วิธีจัดวันที่ของตัวเอง · ผลคือแต่ละหน้าทำไม่เหมือนกัน และพังคนละแบบ

🍽 เทียบให้เห็นภาพ — ลิ้นชักเครื่องมือจัดจาน

คนจัดจาน (view) มีลิ้นชักเครื่องมือ: ที่ตัดเค้กให้ชิ้นเท่ากัน · ขวดบีบซอสที่บีบเป็นเส้นสวย · ตรายางวันที่ · เขาไม่ต้องกะเอาด้วยมีดเองทุกจาน หยิบเครื่องมือมาใช้ ทุกจานก็ออกมาหน้าตาเดียวกัน · link_to ที่ใช้มาตั้งแต่บท 103 คือเครื่องมือชิ้นแรกในลิ้นชักนี้

ที่ไม่เหมือนกัน: คนจัดจานจริงปรับมือได้ตามหน้างาน · helper ทำตามสูตรเป๊ะ — ที่ตัดเค้กไม่รู้ว่าข้อความเป็นภาษาไทย (เดี๋ยวเห็นในหัวข้อ 2) · และเครื่องมือหลายชิ้นพูดภาษาอังกฤษเป็นค่าตั้งต้น จนกว่าเราจะใส่ภาษาไทยให้มัน

เทียบกับ Next.js: ในฝั่ง FRONT เราเขียนฟังก์ชันเล็ก ๆ เช่น formatDate(post.createdAt) แล้วเรียกใน JSX ด้วย {formatDate(…)} · helper คือฟังก์ชันแบบนั้นที่ Rails เขียนมาให้แล้วเป็นร้อยตัว และเราเพิ่มของเราเองได้ (หัวข้อ 4) · เทียบกับ Go: คล้าย package strings · fmt ที่มีฟังก์ชันจัดข้อความสำเร็จรูป แต่ helper ถูกออกแบบมาเพื่อใช้ในหน้าเว็บโดยเฉพาะ

ลองใน console ยังไง: console (ครัวทดลอง บท 104) ไม่ใช่ view จึงเรียก helper ตรง ๆ ไม่ได้ · ต้องเรียกผ่านตัวแปรชื่อ helper ที่ Rails เตรียมไว้ให้ใน console · ผมลองทั้งสองแบบ: 

wongnok-blog-all-in-one(dev):001> truncate("ต้มยำกุ้ง", length: 5)
(wongnok-blog-all-in-one):1:in '<main>': undefined method 'truncate' for main (NoMethodError)
wongnok-blog-all-in-one(dev):002> helper.truncate("ต้มยำกุ้ง", length: 5)
=> "ต้..."
  • บรรทัด 001 = เรียกเฉย ๆ → NoMethodError "ไม่รู้จัก method truncate" · คำว่า for main = "ในตัว console เอง" · console ไม่ได้ถือลิ้นชักเครื่องมือของ view
  • บรรทัด 002 = เรียกผ่าน helper. → ได้ผล · ใน view ไม่ต้องมี helper. เขียน <%= truncate(…) %> ได้เลย
  • "ต้..." = ยาวรวม 5 ตัว: ต + ้ (ไม้โท นับเป็นหนึ่งตัว) + จุดสามตัว · เรื่องนี้แหละที่หัวข้อถัดไปจะขุด

2 · ตัดข้อความภาษาไทย — [0..19] กับ truncate

หน้ารายการบทความอยากโชว์แค่ต้นเรื่องสั้น ๆ · วิธีที่คนเขียน Ruby นึกออกก่อน (และ AI ชอบเขียน) คือหยิบตัวอักษรช่วงแรกด้วย [0..19] = "ตัวที่ 0 ถึงตัวที่ 19" (รวม 20 ตัว) · ลองกับบทความแรกใน seeds (ต้มยำกุ้งน้ำข้น) ซึ่งเนื้อหาขึ้นต้นว่า "ต้มยำกุ้งแบบน้ำข้นใส่นมข้นจืด รสเปรี้ยวเผ็ดกลมกล่อม …": 

wongnok-blog-all-in-one(dev):001> post = Post.find(1)
wongnok-blog-all-in-one(dev):002> post.description[0..19]

ตัวอักษรตัวที่ 20 ของประโยคนี้ตกอยู่กลางคำว่า "ใส่" · บรรทัด 002 จะได้อะไร — ตัวอักษรเพี้ยนเป็นเครื่องหมายแปลก ๆ? ได้ "ใส่" ครบ? หรืออย่างอื่น?

ผลจริง (ตัดบรรทัด SQL ออก):

wongnok-blog-all-in-one(dev):001> post = Post.find(1)
=>
#<Post:0x0000000125d4ffc8
...
wongnok-blog-all-in-one(dev):002> post.description[0..19]
=> "ต้มยำกุ้งแบบน้ำข้นใส"
  • ตัวอักษรไม่เพี้ยน — Ruby นับเป็น "ตัวอักษร" ไม่ได้นับเป็นไบต์ (ไบต์ = หน่วยย่อยที่คอมพิวเตอร์ใช้เก็บข้อมูล · ตัวไทยหนึ่งตัวกินหลายไบต์ ถ้าตัดกลางไบต์ตัวอักษรจะแตก) จึงไม่มีตัวไหนแตกเป็นเครื่องหมาย ?
  • แต่ความหมายเปลี่ยน — "ใส่" กลายเป็น "ใส" · ในภาษาไทย ไม้เอก สระบน สระล่างนับเป็นตัวอักษรแยกที่ลอยอยู่บนพยัญชนะ · ตัดตรงไหนก็ได้ ไม่สนว่ากลางคำหรือเปล่า ไม้เอกที่อยู่ตัวที่ 21 จึงหลุดไป · ต้มยำ "น้ำข้นใส" จึงโผล่บนหน้าเว็บ
  • ไม่มี ... ต่อท้าย ผู้อ่านไม่รู้ด้วยซ้ำว่าข้อความถูกตัด

ทีนี้ลองเครื่องมือของลิ้นชัก — truncate แปลว่า "ตัดให้สั้น":

wongnok-blog-all-in-one(dev):003> helper.truncate(post.description, length: 40)
=> "ต้มยำกุ้งแบบน้ำข้นใส่นมข้นจืด รสเปรี้..."
wongnok-blog-all-in-one(dev):004> helper.truncate(post.description, length: 40, separator: " ")
=> "ต้มยำกุ้งแบบน้ำข้นใส่นมข้นจืด..."
  • length: 40 = "ผลลัพธ์ยาวไม่เกิน 40 ตัว รวมจุดสามตัวแล้ว" · truncate เติม ... ให้เอง ผู้อ่านรู้ว่ายังมีต่อ
  • บรรทัด 003 ยังตัดกลางคำ ("รสเปรี้...") — truncate ก็นับตัวอักษรเหมือน [0..19] ไม่ได้รู้จักคำไทยเลย
  • separator: " " (บรรทัด 004) = "ถ้าจะตัด ให้ถอยไปตัดที่ช่องว่างตัวสุดท้าย" · คนไทยเว้นวรรคระหว่างวลี จุดตัดจึงอ่านรู้เรื่อง: "…ใส่นมข้นจืด..."
  • ถ้าในช่วงนั้นไม่มีช่องว่างเลย separator ช่วยไม่ได้ — ผมลอง length: 20 และ 30 กับประโยคเดียวกัน ได้ผลเหมือนไม่ใส่ separator (ตัดกลางคำ) เพราะช่องว่างแรกอยู่ตัวที่ 30

✅ สูตรที่ใช้กับภาษาไทย: truncate(ข้อความ, length: 80, separator: " ") · ได้สองอย่างที่ [0..N] ไม่มี — จุดสามตัว และจุดตัดที่ช่องว่าง · แต่อย่าเข้าใจว่า truncate "รู้จักคำไทย" — มันไม่ตัดกลางคำก็ต่อเมื่อใส่ separator และข้อความช่วงนั้นมีช่องว่าง

l() คือตรายางวันที่ในลิ้นชัก · ตอนนี้ร้านมีแผ่นยางภาษาอังกฤษแผ่นเดียว ปั๊มกี่จานก็ได้ "October 08" · วันไหนร้านได้แผ่นยางภาษาไทยมา (สมุดคำแปล th) เปลี่ยนแผ่นเดียว ทุกจานเป็นภาษาไทยทันที · ส่วน strftime คือการเขียนวันที่ด้วยมือลงบนจานทีละใบ — อยากเปลี่ยนต้องเขียนใหม่ทุกใบ

ที่ไม่เหมือนกัน: แผ่นยางจริงซื้อมาใส่แล้วใช้ได้เลย · สมุดคำแปลของ Rails ต้องตั้งค่าให้แอปเลือกภาษาด้วย (default_locale) · และมันเปลี่ยนแค่คำ ไม่ได้เปลี่ยนเขตเวลา — เวลา UTC ก็ยังเป็น UTC

4 · เขียน helper ของร้านเอง — reading_time

ของที่ลิ้นชักไม่มี เราเขียนเพิ่มเองได้ · ไฟล์อยู่ใน app/helpers/ (scaffold สร้าง posts_helper.rb ว่าง ๆ ไว้ให้แล้ว) · method ที่เขียนในไฟล์นี้ Rails ส่งให้ view เรียกใช้ได้เอง ไม่ต้อง import อะไร · เทียบ Next.js: เหมือนไฟล์ lib/format.ts ที่รวมฟังก์ชันจัดข้อความไว้ แต่ไม่ต้องเขียน import ที่หัวไฟล์ component

เปิด app/helpers/posts_helper.rb แล้วเติมให้เป็นแบบนี้ (สูตรจากสไลด์หน้า 15 — "บทความนี้อ่านกี่นาที"):

# app/helpers/posts_helper.rb
module PostsHelper
  def reading_time(text)
    "#{(text.to_s.split.size / 200.0).ceil} นาที"
  end
end
  • module PostsHelper … end = กล่องรวม method (scaffold สร้างไว้แล้ว) · module คือกล่องที่ Rails เอาไปเสียบให้ view ใช้ได้ · เราเติมแค่ def … end ข้างใน
  • text.to_s = เปลี่ยนเป็นข้อความก่อน · ถ้า text เป็น nil จะได้ "" แทนที่จะพัง
  • .split = หั่นข้อความตรงช่องว่าง ได้ array ของ "คำ" · .size = นับว่ามีกี่ชิ้น
  • / 200.0 = สไลด์สมมติว่าคนอ่านได้นาทีละ 200 คำ · ต้องมี .0 ไม่งั้น Ruby หารเลขเต็มทิ้งเศษ (11 / 200 ได้ 0)
  • .ceil = ปัดขึ้น (0.055 → 1) · "#{…} นาที" = เอาตัวเลขไปแทรกในข้อความ (string interpolation บท 91)

ที่ไม่เหมือนกัน: ป้าย "ของแผนกบทความ" เป็นแค่การจัดหมวด ไม่ใช่กุญแจ · Rails เปิดให้ทุกหน้าใช้ helper จากทุกไฟล์ — ผมเช็คแล้ว หน้าของหมวด (categories) ก็เรียก reading_time ได้ (วิธีเช็คอยู่ในเฉลย quiz ข้อ 3) · และเครื่องมือที่เราสั่งทำไม่มีใครตรวจคุณภาพให้ — เครื่องมือ reading_time ของเราวัดภาษาไทยผิด ไม่มี error สักตัวเตือน

6 · ของฟรีสามอย่างที่ form_with ให้

① บัตรคิวกันใบสั่งปลอม — ช่องซ่อน authenticity_token คือ "บัตรคิว" (รหัส CSRF) จากบท 103 · ฟอร์มไหนไม่แนบบัตรนี้ Rails ตอบ 422 ไม่รับ · บท 103 บอกไว้ว่า "ฟอร์มของ Rails แนบให้เอง" — form_with คือตัวที่แนบ · ค่าเปลี่ยนทุกครั้งที่โหลดหน้า

② ชื่อช่อง post[title] ตรงกับที่ controller รอ — ดูบรรทัดท้ายของ app/controllers/posts_controller.rb: 

def post_params
  params.expect(post: [ :title, :description, :category_id ])
end

7 · ช่องหมวด — จากพิมพ์เลขเอง เป็นเลือกจากรายการ

8 · ทำเองเป็นแล้ว — เขียนเป็นข้อกำหนดให้ AI และตรวจงานมัน

สไลด์หน้า 15 เตือนว่า ถ้าเราไม่รู้ว่ามี truncate · AI มักเขียน [0..80] · ถ้าไม่รู้ว่ามี l() มันจะเขียนรูปแบบวันที่ตายตัว · ตอนนี้เราลองเครื่องมือทุกตัวด้วยมือแล้ว ก็เขียนลงในข้อกำหนดของ prompt (ส่วน "ข้อกำหนด" ของ prompt 4 ส่วน บท 89 · ไฟล์ prompts/ ในบท 121): 

ข้อกำหนดของ view:
- ตัดข้อความด้วย truncate(…, length: 80, separator: " ") ห้ามใช้ [0..N]
- วันที่ใช้ l(…) หรือ time_ago_in_words ห้าม strftime
- เงินใช้ number_to_currency(…, unit: "฿")
- ช่องในฟอร์มใช้ form.text_field / form.collection_select ห้ามเขียน <input> เอง
- collection_select ใส่ปีกกา { … } (options) ก่อน class: เสมอ

AI เขียนเสร็จแล้ว ตรวจเร็ว ๆ ด้วย grep (ค้นข้อความในทุกไฟล์ของโฟลเดอร์ · -rn = ค้นทุกไฟล์ข้างใน และบอกเลขบรรทัด) — ไม่มีผลขึ้นเลย = ผ่าน · ผมรันทั้งสามคำสั่งกับโค้ดตั้งต้นแล้ว ไม่มีผลขึ้น:

$ grep -rn '\[0\.\.' app/views     # เจอ = ตัดข้อความเอง → เปลี่ยนเป็น truncate
$ grep -rn 'strftime' app/views   # เจอ = จัดวันที่เอง → เปลี่ยนเป็น l()
$ grep -rn '<input' app/views     # เจอ = เขียนช่องฟอร์มเอง → ดูหัวข้อ 6 ว่าทำไมเสี่ยง

\[0\.\. ในบรรทัดแรกหน้าตาแปลกเพราะ [ กับ . มีความหมายพิเศษใน grep · ขีด \ ข้างหน้า = "อ่านตัวนี้ตรงตัว" · ทั้งก้อนจึงแปลว่า "หาคำว่า [0.."

ตัวเลือกที่ 1 ผิด — Ruby นับเป็นตัวอักษร ไม่มีตัวไหนแตก แต่ไม้เอกหลุดได้ ("ใส่" เป็น "ใส") · ตัวเลือกที่ 2 ผิด — truncate ไม่รู้จักคำไทย ต้องอาศัยช่องว่าง · ตัวเลือกที่ 4 ผิด — ไม้เอกไม้โทนับเป็นหนึ่งตัวทั้งใน [ ] และ truncate ("ต้..." ยาว 5 ตัวพอดี)

จุดที่ต้องจำ: ภาษาไทยใช้ truncate(text, length: N, separator: " ") · และอย่าเชื่อว่า helper ตัวไหน "รู้จักภาษาไทย" จนกว่าจะลองเอง

2. หน้า edit ของบทความเลข 1 ใช้ form_with(model: post) ตัวเดียวกับหน้า new · แท็กฟอร์มที่เบราว์เซอร์ได้รับหน้าตาแบบไหน?

ตัวเลือกที่ 4 ถูก · ตรงกับ HTML จริงจาก curl ในหัวข้อ 5 · form_with ถาม persisted? ได้ true จึงส่งไป /posts/1 และแปะป้าย PATCH

ตัวเลือกที่ 1 ผิด — นั่นคือหน้า new (แฟ้มที่ยังไม่อยู่ในตู้) · ตัวเลือกที่ 2 ผิด — ฟอร์ม HTML ส่งได้แค่ GET กับ POST จึงต้องมีช่องซ่อน _method · ตัวเลือกที่ 3 ผิด — /posts/1/edit คือหน้าที่โชว์ฟอร์ม ไม่ใช่ที่รับใบสั่ง และงานที่เปลี่ยนข้อมูลไม่ใช้ GET

จุดที่ต้องจำ: ฟอร์มเดียวพอ — แฟ้มใหม่ไป POST /posts · แฟ้มเก่าไป PATCH /posts/:id · ตัดสินจาก persisted?

3. เขียน reading_time ไว้ใน app/helpers/posts_helper.rb · ถ้าเรียกใน app/views/categories/show.html.erb จะเกิดอะไร?

ตัวเลือกที่ 2 ถูก · ผมเช็คใน console ด้วย CategoriesController.helpers.respond_to?(:reading_time) (= ถามว่า "ลิ้นชักของหน้าหมวดมี reading_time ไหม") ได้ true · ชื่อไฟล์แค่ช่วยจัดหมวด

ตัวเลือกที่ 1 ผิด — ฟังดูมีเหตุผลแต่ไม่ใช่ค่าตั้งต้นของ Rails · ตัวเลือกที่ 3 ผิด — ไม่ต้อง include เอง Rails ทำให้แล้ว · ตัวเลือกที่ 4 ผิด — view ไม่มีการ import แบบ JavaScript · helper ทุกตัวพร้อมใช้ใน view เลย

จุดที่ต้องจำ: helper ทุกตัวใช้ได้ทุกหน้า → ตั้งชื่อให้ชัด อย่าตั้งชื่อกว้าง ๆ ที่อาจชนกับ helper ไฟล์อื่น

4. เพื่อนยังใช้ form_with แต่เขียนช่องเองทุกช่องด้วยชื่อเปล่า ๆ เช่น <input type="text" name="title"> แทน form.text_field :title · กดส่งแล้วได้อะไร?

ตัวเลือกที่ 1 ถูก · ผมส่งใบสั่งที่ไม่มีกลุ่ม post ได้ 400 Bad Request + param is missing or the value is empty or invalid: post

ตัวเลือกที่ 2 ผิด — Rails ไม่เดาใจ params.expect(post: …) ต้องเจอกลุ่ม post · ตัวเลือกที่ 3 ผิด — รหัส CSRF เป็นช่องซ่อนของทั้งฟอร์ม (form_with ใส่ไว้แล้ว) ไม่ได้ผูกกับช่องใดช่องหนึ่ง · ตัวเลือกที่ 4 ผิด — ไม่ถึงขั้นบันทึกเลย controller หยุดตั้งแต่ post_params

จุดที่ต้องจำ: ให้ form builder ตั้งชื่อช่อง แล้วชื่อจะตรงกับ params.expect เสมอ · เห็น 400 ParameterMissing ให้ดูชื่อช่องก่อน

ถามกลับได้เลย — ถ้าฟอร์มส่งไม่ผ่านแล้วไม่รู้ทำไม ก็อปบรรทัด Parameters: {…} จาก log ของ server กับบรรทัด params.expect ใน controller มาถาม · สองอย่างนี้บอกเกือบทุกอย่างว่าชื่อช่องตรงกันหรือเปล่า
