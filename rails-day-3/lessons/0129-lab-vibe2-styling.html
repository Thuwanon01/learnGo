ขั้น 1 — เปิดธีมใน CSS: บอก daisyUI ว่าร้านเรามีธีมอะไรบ้าง

ธีม (theme) คือชุดสีทั้งชุดของเว็บ: สีพื้น สีตัวอักษร สีปุ่มหลัก สีเตือน · daisyUI มีธีมสำเร็จรูปให้หลายสิบชุด แต่จะใส่ลงไฟล์ CSS เฉพาะธีมที่เรา "เปิด" · เปิดแล้วจะเลือกใช้ธีมไหน ก็แค่ติดป้าย data-theme="ชื่อธีม" ที่แท็ก <html>

เปิดไฟล์ app/assets/tailwind/application.css · ตอนนี้บรรทัดที่ 3 เป็นแบบนี้:

@plugin "./daisyui.mjs";

เปลี่ยนบรรทัดนั้นเป็นบล็อก 3 บรรทัด · ไฟล์ application.css ทั้งไฟล์หลังแก้:

@import "tailwindcss";
@source not "./daisyui{,*}.mjs";
@plugin "./daisyui.mjs" {
  themes: light --default, dark --prefersdark;
}

@theme {
  --font-sans: "Noto Sans Thai", ui-sans-serif, system-ui, sans-serif;
}
  • @plugin "./daisyui.mjs" { … } = เปิดใช้ daisyUI จากไฟล์ที่อยู่ข้าง ๆ กัน และส่งการตั้งค่าไปในวงเล็บปีกกา (บรรทัดอื่นมีอยู่แล้ว ไม่ต้องแตะ — บท 128)
  • themes: = รายชื่อธีมที่เปิด คั่นด้วยจุลภาค
  • light --default = ธีมสว่าง และเป็นธีมตั้งต้น เมื่อ <html> ยังไม่มีป้าย data-theme
  • dark --prefersdark = ธีมมืด และใช้อัตโนมัติถ้าเครื่องของผู้ใช้ตั้งโหมดมืดไว้ (และยังไม่มีป้าย)

⚠️ สไลด์หน้า 30 เขียน @plugin "daisyui" (ไม่มี ./ และ .mjs) · อย่าก็อปแบบนั้น — repo นี้ไม่มี Node ไม่มี package ชื่อ daisyui ให้หา มีแต่ไฟล์ daisyui.mjs วางไว้ในโฟลเดอร์ · ลองแล้วได้ (ผลจริง ย่อ path):

ธีมทำงานยังไง? daisyUI ไม่ได้เขียนสีลงในคลาสตรง ๆ แต่เขียนเป็นตัวแปรของ CSS (ชื่อขึ้นต้นด้วย --) แล้วให้แต่ละธีมตั้งค่าตัวแปรชุดเดียวกันต่างกัน · ตัวอย่างจากไฟล์ CSS ที่ build ได้จริง (ตัดมาบางส่วน): 

/* app/assets/builds/tailwind.css — ไฟล์ที่ Tailwind สร้าง (บรรทัดเดียวยาว ๆ ตัดมาให้ดู) */
[data-theme=dark]{color-scheme:dark;--color-base-100:oklch(25.33% .016 252.42);--color-base-200:oklch(23.26% .014 253.1);…
.bg-base-100{background-color:var(--color-base-100)}
  • [data-theme=dark]{ … } = "ถ้าเจอป้าย data-theme="dark" ให้ตั้งตัวแปรพวกนี้" · --color-base-100 คือตัวแปรชื่อ "สีพื้นระดับ 100" · color-scheme:dark = บอกเบราว์เซอร์ให้วาดของที่มันวาดเอง (แถบเลื่อน · ช่องกรอก) เป็นโทนมืดด้วย
  • .bg-base-100{background-color:var(--color-base-100)} = คลาส bg-base-100 ไม่ได้รู้ว่าเป็นสีอะไร มันแค่บอกว่า "ใช้ค่าในตัวแปรนั้น" · var(…) = อ่านค่าตัวแปร
  • เปลี่ยนป้ายเป็น dark → ตัวแปรเปลี่ยนค่า → ทุกที่ที่ใช้ bg-base-100 เปลี่ยนสีพร้อมกันทันที โดยไม่มีใครต้องแก้ HTML สักบรรทัด

ถ้าเคยทำ บท 81 (design token ของ shadcn) นี่คือกลไกเดียวกันเป๊ะ — ที่นั่นใช้คลาส .dark ประกาศ --primary ซ้ำ · ที่นี่ใช้ป้าย data-theme แทน

เทียบให้เห็นภาพ

ธีมคือการเปลี่ยนธีมทั้งร้านด้วยป้ายเดียวที่หน้าประตู · ร้านเตรียมชุดของไว้แล้วสองชุด: "ชุดกลางวัน" (ผ้าปูขาว ไฟสว่าง) กับ "ชุดกลางคืน" (ผ้าปูเข้ม ไฟสลัว) · ป้ายหน้าประตู (<html data-theme>) เขียนว่า "กลางคืน" เมื่อไหร่ พนักงานทุกคนหยิบของชุดกลางคืนพร้อมกัน · คนจัดจานไม่ต้องรู้ว่าชุดไหนสีอะไร แค่หยิบ "ผ้าปูโต๊ะประจำร้าน" (bg-base-100) ตามป้าย · ส่วน themes: ใน CSS คือรายการชุดที่ร้านซื้อมาเก็บไว้ — ชุดที่ไม่ได้ซื้อ ต่อให้แขวนป้ายชื่อมันก็ไม่มีของให้หยิบ

ที่ไม่เหมือนกัน: ร้านจริงถ้าแขวนป้ายชื่อชุดที่ไม่มี พนักงานจะงงแล้วมาถาม · CSS ไม่ถามอะไรเลย มันใช้ชุดตั้งต้น (light) เงียบ ๆ ไม่มี error ที่ไหน (ภารกิจท้ายบทจะได้เห็นกับตา) · และป้ายนี้อยู่ในเบราว์เซอร์ของลูกค้าแต่ละคน ไม่ใช่ป้ายเดียวของทั้งร้าน — คนหนึ่งเลือกมืด อีกคนยังเห็นสว่างได้

ศัพท์ที่ใช้คุยต่อได้
theme · data-theme
ชุดสีทั้งชุดของเว็บ · data-theme คือ attribute บนแท็ก (ส่วนใหญ่ <html>) ที่บอก daisyUI ว่าใช้ชุดไหน · บอก AI ได้ว่า "switch daisyUI themes by setting data-theme on the html element, not by adding a dark class"
CSS variable (custom property)
ตัวแปรของ CSS ชื่อขึ้นต้นด้วย -- อ่านค่าด้วย var(--ชื่อ) · ธีมทุกแบบคือ "ตั้งตัวแปรชุดเดียวกันด้วยค่าต่างกัน" · ถาม senior ได้ว่า "สีนี้มาจาก CSS variable ของธีม หรือเขียนค่าตายตัวไว้"
--default · --prefersdark
ป้ายกำกับในรายการ themes: ของ daisyUI 5 · --default = ธีมเมื่อไม่มีป้าย · --prefersdark = ธีมเมื่อเครื่องตั้งโหมดมืด · บอก AI ได้ว่า "we use daisyUI 5 with Tailwind v4: configure themes inside @plugin in CSS, there is no tailwind.config.js"

บันทึกไฟล์ · bin/dev จะสร้าง CSS ใหม่ให้เอง (ดูในหน้าต่างที่ 1) · ถ้าอยากสั่งเองก็ได้:

$ bin/rails tailwindcss:build
≈ tailwindcss v4.3.3

ไม่ต่างเลยสักไบต์ · ผมก็อปไฟล์ CSS ตอนก่อนแก้เก็บไว้ชื่อ before.css แล้วเทียบด้วย cmp (คำสั่งเทียบไฟล์สองไฟล์ · ไม่พิมพ์อะไรเลย = เหมือนกันทุกไบต์):

$ cmp app/assets/builds/tailwind.css before.css
$ grep -o '\[data-theme=[a-z]*\]' app/assets/builds/tailwind.css | sort | uniq -c

เพราะค่าตั้งต้นของ daisyUI 5 ก็คือ light --default, dark --prefersdark อยู่แล้ว · บรรทัดที่เราเขียนจึงไม่ได้เปลี่ยนผล แต่เปลี่ยนความชัด: คนอ่านไฟล์ (และ AI) รู้ทันทีว่าร้านนี้เปิดธีมอะไร และมีที่ให้เติมธีมที่สาม (ภารกิจท้ายบท) · คำสั่ง grep … | sort | uniq -c = หาข้อความ [data-theme=…] ทุกจุดแล้วนับว่าแต่ละชื่อเจอกี่ครั้ง — ใช้ตรวจว่าธีมไหนอยู่ในไฟล์บ้าง

ขั้น 2 — navbar: แถบเมนูบนสุดที่อยู่ทุกหน้า

แถบเมนูต้องโผล่ทุกหน้า → ที่ของมันคือ layout (จานรองที่ห่อทุกหน้า) · แต่เราจะไม่เขียนลงใน layout ตรง ๆ ให้แยกเป็น partial ชื่อ shared/_navbar.html.erb ตามข้อกำหนดของสไลด์ — layout จะได้สั้นอ่านง่าย และหาเจอว่าเมนูอยู่ไฟล์ไหน

สร้างไฟล์ใหม่ app/views/shared/_navbar.html.erb (โฟลเดอร์ shared/ มีแล้วจากบท 126):

<%# locals: () -%>
<header class="navbar bg-base-100 shadow-sm">
  <div class="flex-1">
    <%= link_to "Wongnok Blog", posts_path, class: "btn btn-ghost text-lg sm:text-xl" %>
  </div>

  <nav class="flex-none flex items-center gap-1">
    <%= link_to "บทความ", posts_path, class: "btn btn-ghost btn-sm" %>
    <%= link_to "หมวด", categories_path, class: "btn btn-ghost btn-sm" %>
    <button type="button" class="btn btn-ghost btn-sm" aria-label="สลับธีมสว่าง/มืด"
            data-controller="theme" data-action="theme#toggle">🌓</button>
  </nav>

เทียบให้เห็นภาพ

Stimulus controller คืออุปกรณ์บนโต๊ะที่ทำงานเองโดยไม่ต้องเรียกครัว — เหมือนสวิตช์หรี่ไฟข้างโต๊ะ ลูกค้ากดเองได้เลย ครัวไม่ต้องรู้ · data-controller="theme" คือป้ายเล็ก ๆ ที่ติดบนโต๊ะว่า "ตรงนี้มีอุปกรณ์ชื่อ theme" · ทุกครั้งที่พนักงานจัดโต๊ะ (หน้าเว็บโหลด) พนักงานเห็นป้ายแล้วติดตั้งอุปกรณ์ให้ (Stimulus เรียก connect()) · data-action="theme#toggle" คือป้ายที่ปุ่มบอกว่า "กดฉันแล้วให้อุปกรณ์ theme ทำงาน toggle"

ที่ไม่เหมือนกัน: สวิตช์ในร้านจริงหรี่ไฟได้แค่โต๊ะตัวเอง · ปุ่มของเราเปลี่ยนป้ายที่ <html> ซึ่งครอบทั้งหน้า — กดจุดเดียวสีเปลี่ยนทั้งเว็บ · และอุปกรณ์นี้ไม่ได้ถูกติดตั้งครั้งเดียวแล้วอยู่ตลอด: navbar อยู่ใน <body> ซึ่งถูกวางใหม่ทุกครั้งที่เปลี่ยนหน้า (กลไกละเอียดในบท 130) → connect() จึงรันทุกหน้า (ผมวัดแล้ว และนี่คือสิ่งที่เราต้องการพอดี)

สร้างไฟล์ใหม่ app/javascript/controllers/theme_controller.js · ชื่อไฟล์สำคัญ: theme_controller.js ↔ data-controller="theme" ต้องตรงกัน (เหมือนชื่อไฟล์ partial กับ render): 

import { Controller } from "@hotwired/stimulus"

// ปุ่มสลับธีมสว่าง/มืด (อยู่ใน shared/_navbar.html.erb)
export default class extends Controller {
  // โหลดหน้า: ถ้าเคยเลือกธีมไว้ ใส่กลับให้
  connect() {
    const saved = localStorage.getItem("theme")
    if (saved) document.documentElement.dataset.theme = saved
  }

  // กดปุ่ม: สลับ light ↔ dark แล้วจำไว้
  toggle() {
    const html = document.documentElement
    const systemDark = window.matchMedia("(prefers-color-scheme: dark)").matches
    const current = html.dataset.theme || (systemDark ? "dark" : "light")
    const next = current === "dark" ? "light" : "dark"

    html.dataset.theme = next
    localStorage.setItem("theme", next)
  }
}

อ่านทีละบรรทัด:

  • import { Controller } from "@hotwired/stimulus" = ดึงแม่แบบ Controller มาจาก library Stimulus · library นี้อยู่ในแอปแล้วผ่าน importmap (สมุดรายชื่อ "ชื่อเล่น → ไฟล์อยู่ไหน" — บท 127) ไม่ต้อง npm install
  • export default class extends Controller { = สร้าง class ใหม่ที่สืบทอดจาก Controller (เหมือน class PostsController < ApplicationController ใน Ruby) · export default = ไฟล์นี้ส่ง class นี้ออกไปเป็นของหลัก (เหมือน export default function Page() ใน Next.js) · ไม่ต้องตั้งชื่อ class เพราะ Stimulus ใช้ชื่อไฟล์แทน
  • connect() { … } = method ที่ Stimulus เรียกเอง เมื่อเจอ element ที่มี data-controller="theme" บนหน้า · คล้าย useEffect(() => { … }, []) ที่รันหลังขึ้นจอ
  • const saved = localStorage.getItem("theme") = อ่านค่าที่เคยจดไว้ชื่อ "theme" · ถ้าไม่เคยจด ได้ null · const = ตัวแปรที่ตั้งครั้งเดียวไม่เปลี่ยน
  • if (saved) document.documentElement.dataset.theme = saved = ถ้ามีค่า ติดป้ายให้ · document = หน้าเว็บที่เปิดอยู่ทั้งหน้า (ของที่ JavaScript ใช้หยิบแท็กต่าง ๆ) · document.documentElement = แท็ก <html> ตัวนอกสุด · .dataset.theme = attribute data-theme (เบราว์เซอร์แปลง data-xxx เป็น .dataset.xxx ให้)
  • toggle() { … } = method ที่ป้าย data-action="theme#toggle" เรียก · ชื่อ toggle เราตั้งเอง จะเรียกอะไรก็ได้ขอให้ตรงกันสองฝั่ง
  • window.matchMedia("(prefers-color-scheme: dark)").matches = ถามเบราว์เซอร์ว่า "เครื่องนี้ตั้งโหมดมืดอยู่ไหม" ได้ true / false · window = ตัวหน้าต่างเบราว์เซอร์ (ของที่รู้เรื่องเครื่องและจอ)
  • html.dataset.theme || (systemDark ? "dark" : "light") = ถ้ามีป้ายอยู่แล้วใช้ป้าย ถ้ายังไม่มี (|| = "ถ้าซ้ายว่าง ใช้ขวา") ให้เดาจากเครื่อง · เงื่อนไข ? ก : ข = ถ้าจริงได้ ก ไม่จริงได้ ข (ตัวเดียวกับที่ใช้ใน JSX)
  • current === "dark" ? "light" : "dark" = ตอนนี้มืดอยู่ → ไปสว่าง · นอกนั้น → ไปมืด · === = เท่ากันเป๊ะ
  • html.dataset.theme = next = เปลี่ยนป้าย → สีทั้งเว็บเปลี่ยนทันที (ขั้น 1) · localStorage.setItem("theme", next) = จดลงสมุดว่าเลือกอะไร

localStorage คือสมุดโน้ตเล่มเล็กที่ลูกค้าพกติดกระเป๋ามาเอง เขียนไว้ว่า "ร้านนี้ ชอบนั่งโซนไฟสลัว" · ทุกครั้งที่มาร้านนี้ พนักงานเปิดสมุดของลูกค้าดูแล้วจัดโต๊ะให้ตามนั้น (connect() อ่าน getItem) · ร้านไม่ต้องจดอะไรเลย

ข้อ 3 · รัน assets:precompile แล้วสียังอยู่ครบ

สไลด์บอกว่า "ข้อนี้คือข้อที่คนลืมตรวจ" · assets:precompile คือการซ้อมเตรียมไฟล์แบบขึ้นเครื่องจริงบนเครื่องเรา (บท 127) · ถ้าคลาสไหนหลุดจาก CSS ตอนซ้อม ก็จะหลุดบนเครื่องจริงด้วย · ผลจริง: 

$ bin/rails assets:precompile
≈ tailwindcss v4.3.3

/*! 🌼 daisyUI 5.7.50 */
Done in 92ms
Warning: You are precompiling assets in development. Rails will not serve any changed assets until you delete public/assets/.manifest.json

  • ทุกชื่อเจออย่างน้อย 1 ครั้ง = มีกฎ CSS ของคลาสนั้นจริง (ตัวเลขไม่ต้องสนใจ — บางคลาสถูกพูดถึงหลายจุดในไฟล์) · ธีม light และ dark อยู่ครบ

  • บนเครื่องผมทั้งคำสั่งใช้ราว 1 วินาที (สไลด์บอก 20 วินาที — แอปที่ใหญ่กว่านี้ หรือเครื่องที่รันตรวจอัตโนมัติก่อน deploy ที่เรียกว่า CI จะนานขึ้น)
