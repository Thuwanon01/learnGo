Tailwind v4 และ daisyUI — และกับดักชื่อคลาสที่ต่อ string

~22 นาที · ควรผ่าน บทเรียน 127 (asset pipeline) มาก่อน · ใช้ของจาก บท 72 (Tailwind) และ บท 81 (design token) ด้วย

บท 127 ตามดูว่าไฟล์ tailwind.css เดินทางไปถึงเบราว์เซอร์ยังไง · บทนี้ย้อนไปดูว่าไฟล์นั้นถูกสร้างขึ้นมายังไง และเราสั่งอะไรมันได้บ้าง
อ่านจบแล้วคุณจะ: อ่านไฟล์ตั้งค่า Tailwind ของแอปออกทุกบรรทัด · เพิ่มสีของร้านเองได้ · ใช้ปุ่มสำเร็จรูปของ daisyUI และเปลี่ยนธีมทั้งเว็บด้วย attribute ตัวเดียว · เห็นกับตาว่าทำไมชื่อคลาสที่ต่อ string ทำให้สีหาย และพิสูจน์ได้ด้วย grep · และไม่ลืมรัน bin/dev อีกเลย

🔁 ทวนก่อนเริ่ม — คำจากบทก่อน ๆ ที่บทนี้ใช้

  • Tailwind · utility class (บท 72) — คลาสสั้น ๆ อย่าง p-4 text-3xl ที่แต่ละตัวคือ CSS หนึ่งบรรทัด · Tailwind อ่านไฟล์ของเราแล้วสร้างไฟล์ CSS เฉพาะคลาสที่เจอ
  • @theme แทน tailwind.config.js (บท 72 หัวข้อ 4) — Tailwind v4 ตั้งค่าในไฟล์ CSS · ไฟล์ config แบบ JavaScript เป็นของ v3
  • semantic token (บท 81) — ตั้งชื่อสีตามหน้าที่ (primary) แทนชื่อสีตรง ๆ (blue-600) · เปลี่ยนค่าที่เดียว ทั้งแอปเปลี่ยนตาม
  • app/assets/builds/tailwind.css · assets:precompile · assets:clobber (บท 127) — ไฟล์ CSS ที่ Tailwind สร้างให้ · คำสั่งเตรียมไฟล์แบบขึ้นเครื่องจริง · คำสั่งล้างของที่เตรียมไว้
  • prompts/00-context.md (บท 121) — แฟ้มคู่มือพนักงานใหม่ที่แนบให้ AI ทุกครั้ง

Tailwind ในแอป Rails อยู่ตรงไหน — เปิดไฟล์ตั้งค่าของจริง

ทวนจากบท 72 ครึ่งย่อหน้า: เราเขียนคลาสอย่าง font-bold ใน view · Tailwind อ่านไฟล์ทุกไฟล์ในโปรเจกต์เป็นตัวหนังสือ แล้วเขียน CSS เฉพาะคลาสที่เจอลงไฟล์เดียว · ไฟล์ CSS จึงเล็ก เพราะไม่มีคลาสที่ไม่มีใครใช้

ใน Next.js เราได้ Tailwind ผ่าน PostCSS และ npm · ใน Rails ใช้ gem tailwindcss-rails ซึ่งพกโปรแกรม Tailwind มาเป็นไฟล์เดียว ไม่ต้องมี Node ไม่ต้องมี npm · ทางเดินของมันมีแค่นี้:

app/views/**/*.erb ─┐ app/helpers/*.rb ─┼─► Tailwind อ่านเป็นตัวหนังสือ ─► app/assets/builds/tailwind.css ─► Propshaft (บท 127) ─► เบราว์เซอร์ ไฟล์อื่นในโปรเจกต์ ─┘ ▲ │ ทำตามใบสั่งใน app/assets/tailwind/application.css

อ่านแผนภาพ: app/views/**/*.erb = "ไฟล์ .erb ทุกไฟล์ ในทุกโฟลเดอร์ย่อยของ app/views" (** = ลงไปกี่ชั้นก็ได้) · ลูกศรขวาคือทางที่ CSS เดินต่อ · ลูกศรขึ้นจากด้านล่างคือไฟล์ตั้งค่าที่บอกว่าให้ Tailwind ทำอะไร

ไฟล์ตั้งค่า (ใบสั่งงาน) ของ Tailwind คือ app/assets/tailwind/application.css · เปิดดูของจริงในแอป (สถานะหลังบท 126):

/* app/assets/tailwind/application.css */
@import "tailwindcss";
@source not "./daisyui{,*}.mjs";
@plugin "./daisyui.mjs";

@theme {
  --font-sans: "Noto Sans Thai", ui-sans-serif, system-ui, sans-serif;
}

อ่านทีละบรรทัด:

  • @import "tailwindcss"; = "เอา Tailwind ทั้งชุดมาใช้" · บรรทัดเดียวกับใน globals.css ของ Next.js (บท 72) เป๊ะ
  • @source not "./daisyui{,*}.mjs"; = "อย่าอ่านไฟล์ daisyui.mjs กับ daisyui-ตัวอะไรก็ได้.mjs" ({,*} แปลว่า "ไม่มีอะไรต่อ หรือมีอะไรต่อก็ได้") · สองไฟล์นี้เป็นโค้ดของ daisyUI ที่มีชื่อคลาสทุกตัวของมันอยู่ข้างใน · ผมลองลบบรรทัดนี้แล้ว build ไฟล์ CSS โตจาก 34,146 เป็น 380,038 byte (มี .modal ที่เราไม่เคยใช้โผล่มาด้วย)
  • @plugin "./daisyui.mjs"; = "เสียบส่วนเสริม daisyUI จากไฟล์ข้าง ๆ นี้" · เดี๋ยวดูละเอียดในหัวข้อ daisyUI
  • @theme { … } = ที่ตั้งค่าของร้านเรา · ข้างในเป็นตัวแปร CSS (ชื่อขึ้นต้นด้วย -- ใช้เก็บค่าไว้ใช้ซ้ำ · เคยเห็นในบท 81) · ตอนนี้มีค่าเดียวคือ --font-sans (ฟอนต์หลัก) — ลองใช้ฟอนต์ "Noto Sans Thai" ก่อน · เครื่องไหนไม่มีฟอนต์นี้ก็ข้ามไปใช้ตัวถัดไปในรายการ

🛒 เทียบให้เห็นภาพ — ฝ่ายจัดซื้อที่อ่านเมนูบนกระดาษ

Tailwind คือฝ่ายจัดซื้อของร้าน · ก่อนเปิดร้าน เขาเดินอ่านรายการเมนูทุกแผ่นที่เขียนไว้บนกระดาษ (ไฟล์ view) แล้วซื้อวัตถุดิบเฉพาะที่เห็นชื่อ (เขียน CSS เฉพาะคลาสที่เจอ) · ของที่ไม่มีเมนูไหนเขียนถึง ไม่ซื้อ ตู้เย็นจึงไม่รก
application.css คือใบสั่งงานที่แปะไว้บนโต๊ะฝ่ายจัดซื้อ: "ใช้วัตถุดิบมาตรฐานชุดนี้ (@import) · ห้ามอ่านคู่มือของซัพพลายเออร์ (@source not) · รับชุดจานชามจากเจ้านี้ (@plugin) · สีประจำร้านคือ… (@theme)"

ที่ไม่เหมือนกัน: ฝ่ายจัดซื้อจริงอ่านแล้วเข้าใจความหมาย เห็นคำว่า "ต้มยำ" ก็รู้ว่าต้องซื้อข่าตะไคร้ · Tailwind ไม่เข้าใจอะไรเลย มันแค่หาคำที่หน้าตาตรงกับชื่อคลาสที่มันรู้จัก · และมันอ่านทุกไฟล์ในโปรเจกต์ ไม่ใช่แค่ view — ไฟล์จดโน้ตหรือไฟล์ HTML เก่าที่วางทิ้งไว้ในโปรเจกต์ ถ้ามีชื่อคลาสอยู่ข้างใน มันก็ซื้อของให้ด้วย

v3 กับ v4 — ไม่มี tailwind.config.js แล้ว และทำไมต้องบอก AI

บท 72 เทียบไว้แล้วว่า Tailwind v3 ตั้งค่าในไฟล์ JavaScript ชื่อ tailwind.config.js · v4 ย้ายทุกอย่างมาอยู่ในไฟล์ CSS · ในแอป Rails ของเราหน้าตาเป็นแบบนี้ (สมมติอยากได้สีประจำร้านชื่อ brand):

v3 — ของเก่าที่อินเทอร์เน็ตเต็มไปหมด

// tailwind.config.js
module.exports = {
  content: ["./app/views/**/*.erb"],
  theme: { extend: { colors: {
    brand: "#ff3d7f"
  } } },
}

v4 — ของจริงในแอปเรา

/* app/assets/tailwind/application.css */
@theme {
  --font-sans: "Noto Sans Thai", …;
  --color-brand: #ff3d7f;
}
/* แล้วใช้ class="text-brand" ได้เลย */

ฝั่งซ้ายเป็น JavaScript: module.exports = { … } = "ส่งก้อนตั้งค่านี้ออกไปให้โปรแกรมอื่นใช้" · content = รายชื่อไฟล์ที่ให้อ่าน · extend.colors = "เพิ่มสีนี้ต่อจากสีมาตรฐาน" · ไม่ต้องจำ แค่จำหน้าตาไว้ — เห็นแบบนี้ในคำตอบของ AI หรือในเว็บ = ของ v3

ฝั่ง v4 ไม่ต้องบอก content (ไฟล์ไหนให้อ่าน) เพราะมันอ่านทุกไฟล์เอง · ชื่อตัวแปรมีแบบแผน: --color- นำหน้า = สี · ได้คลาส text-brand bg-brand border-brand มาทันที
ลองจริง: เพิ่มบรรทัด --color-brand: #ff3d7f; ใน @theme ตามฝั่งขวา แล้ว build 

$ bin/rails tailwindcss:build
$ grep -c -- '--color-brand' app/assets/builds/tailwind.css

ยังไม่มี view ไหนใช้คลาส text-brand เลย · grep -c นับว่ามีกี่บรรทัดที่เจอคำนี้ — ไฟล์ CSS ที่ได้ถูกบีบเหลือบรรทัดเดียว ผลจึงมีแค่ 1 = เจอ · 0 = ไม่เจอ (ใช้แบบนี้ทั้งบท) · -- ก่อนคำค้น = บอก grep ว่า "คำที่ตามมาไม่ใช่ตัวเลือกของ grep" เพราะมันขึ้นต้นด้วยขีดสองตัว

ไม่อยู่ · Tailwind v4 ใส่ตัวแปรของ @theme ลงไฟล์เฉพาะตัวที่มีคนใช้ — กฎเดียวกับคลาส · ฝ่ายจัดซื้อไม่ซื้อสีที่ไม่มีเมนูไหนสั่ง

ทีนี้ใส่ text-brand ให้หัวข้อหน้า app/views/posts/index.html.erb (ทวนบท 125–126: บรรทัดขึ้นต้น - = ของเดิมที่ลบ · + = ของใหม่ที่ใส่แทน · ตอนพิมพ์จริงไม่ต้องพิมพ์ - +):

-    <h1 class="font-bold text-3xl sm:text-4xl">บทความทั้งหมด</h1>
+    <h1 class="font-bold text-3xl sm:text-4xl text-brand">บทความทั้งหมด</h1>
$ bin/rails tailwindcss:build
$ grep -o -- '--color-brand:[^;}]*' app/assets/builds/tailwind.css
--color-brand:#ff3d7f
$ grep -o '\.text-brand{[^}]*}' app/assets/builds/tailwind.css
.text-brand{color:var(--color-brand)}

เพราะไฟล์ถูกบีบเป็นบรรทัดยาวบรรทัดเดียว (minify) จึงใช้ grep -o = "พิมพ์เฉพาะส่วนที่ตรง" · [^;}]* = "ตัวอะไรก็ได้ที่ไม่ใช่ ; หรือ }" (อ่านไปจนจบค่า) · ได้ทั้งตัวแปร และคลาส .text-brand ที่ชี้ไปหาตัวแปรนั้น · เปิดหน้า /posts หัวข้อเป็นสีชมพู
(ตั้งแต่ตรงนี้ ผมตัดข้อความ 3 บรรทัดของ build — รุ่น Tailwind · ดอกไม้ daisyUI · Done in … — ออก เหลือแค่ผลของ grep)

แล้วถ้าทำตามเว็บเก่า ๆ สร้าง tailwind.config.js ล่ะ? ผมสร้างไฟล์นี้ที่โฟลเดอร์บนสุดของโปรเจกต์ ตั้งสีชื่อ mint แล้วใส่ text-mint ใน <h1> เดิม:

  content: ["./app/views/**/*.html.erb"],

AI ฝึกจากเนื้อหาในอินเทอร์เน็ต · v3 อยู่มาหลายปี ตัวอย่างเยอะกว่า v4 มาก · ถ้าไม่บอก มันมีโอกาสสูงที่จะตอบแบบ v3 ("สร้าง tailwind.config.js แล้วใส่ content") · เราทำตาม → ไม่มี error → นั่งงงว่าทำไมสีไม่มา · บรรทัดเดียวใน 00-context.md ตัดปัญหานี้ทิ้งทั้งก้อน

📒 เทียบให้เห็นภาพ — สมุดสั่งงานเล่มเก่าที่ไม่มีใครเปิด

ร้านเราเคยมีสมุดสั่งงานฝ่ายจัดซื้อแยกเป็นเล่ม (v3 · tailwind.config.js) · พอเปลี่ยนระบบ ร้านย้ายคำสั่งทั้งหมดไปเขียนในใบสั่งงานที่แปะบนโต๊ะ (v4 · @theme ใน CSS) แล้วเลิกเปิดสมุดเล่มเก่า · พนักงานใหม่ (AI) ที่เคยทำร้านอื่นมา จะหยิบสมุดเล่มเก่ามาเขียนคำสั่งเพิ่ม — เขียนสวยแค่ไหนก็ไม่มีใครอ่าน

น้ำเงินหายเพราะคำว่า text-blue-700 เคยอยู่ในไฟล์นี้ที่เดียวในทั้งโปรเจกต์ · พอเราลบมันไปแทนด้วยการต่อ string ฝ่ายจัดซื้อก็ไม่เห็นคำนี้อีก เลยไม่ซื้อ

เหตุผลเดียวกับเรื่องฝ่ายจัดซื้อตั้งแต่ต้นบท: Tailwind อ่านไฟล์เป็นตัวหนังสือ ไม่ได้รันโค้ดของเรา · สิ่งที่มันเห็นในไฟล์คือ text-<%= color %>-700 ซึ่งไม่ใช่ชื่อคลาสอะไรเลย · คำว่า text-pink-700 เพิ่งเกิดตอน Rails เติมแม่แบบ ซึ่งตอนนั้นไฟล์ CSS ถูกสร้างเสร็จไปนานแล้ว

🗣 เทียบให้เห็นภาพ — เมนูที่สั่งด้วยปากตอนเสิร์ฟ

ฝ่ายจัดซื้อซื้อของก่อนร้านเปิด จากเมนูที่เขียนบนกระดาษ · บนกระดาษเขียนว่า "แกงสี ___ (แล้วแต่ลูกค้า)" — ไม่มีชื่อแกงไหนเต็ม ๆ ฝ่ายจัดซื้อเลยไม่ซื้ออะไรเลย · ตอนเสิร์ฟ คนจัดจานเติมช่องว่างว่า "แกงเขียวหวาน" — แต่ในตู้ไม่มีพริกแกงเขียว จานออกไปเปล่า ๆ
ท่าที่ถูก = เขียนบนกระดาษให้ครบว่า "แกงเขียวหวาน หรือ แกงเผ็ด" แล้วตอนเสิร์ฟค่อยเลือกหนึ่งอย่าง · ฝ่ายจัดซื้อเห็นทั้งสองชื่อ ซื้อมาครบ

ที่ไม่เหมือนกัน: ร้านจริงขาดของ พนักงานยังวิ่งไปซื้อเพิ่มกลางกะได้ · Tailwind ไม่ได้อยู่ในร้านตอนเสิร์ฟ มันไม่มีทางรู้ว่าตอนเติมแม่แบบเกิดชื่ออะไรขึ้น · และร้านจริงจานเปล่าลูกค้าบ่นทันที · ของเราไม่มี error สักบรรทัด แค่สีหายเงียบ ๆ

ท่าที่ถูก — เขียนชื่อคลาสเต็มทุกตัว แล้วค่อยเลือก:

<span class="font-medium <%= color_class %>"><%= post.category.name %></span>

โค้ดที่ผิดจึงรอดเพราะโชค · วันหนึ่งมีคนเปลี่ยนเป็น "orange" หรือแก้หน้าตากล่องแจ้งเตือนของ scaffold จนคำนั้นหายไป สีก็หายโดยไม่มีใครแตะบรรทัดนั้นเลย

หลักการที่กว้างกว่า Tailwind: เครื่องมือที่ "อ่านโค้ดโดยไม่รันมัน" (static analysis) มองไม่เห็นของที่โปรแกรมประกอบขึ้นตอนรันเสมอ · ต่อไปเจอเครื่องมือไหนที่ "อ่านไฟล์แล้วเลือกเก็บของ" ให้ถามตัวเองว่ามันเห็นชื่อเต็มไหม

หาจุดต่อ string ในโปรเจกต์ทีเดียวทั้งหมดได้ด้วยคำสั่งนี้ (ลองกับโค้ดที่ผิดข้างบน):

$ git grep -n -E '[a-z]-(<%=|#\{)' app/views
app/views/posts/_post.html.erb:5:    <span class="font-medium text-<%= color %>-700"><%= post.category.name %></span>

แปลว่า "หาบรรทัดใน app/views ที่มีตัวอักษร ตามด้วย - แล้วตามด้วย <%= หรือ #{ ทันที" — คือรูปแบบ text-<%= … %> และ "bg-#{…}" (การเสียบค่าใน string ของ Ruby · บท 91) · -E = ให้ | ในวงเล็บแปลว่า "หรือ" · \{ = ปีกกาจริง ๆ · โค้ดที่สะอาดจะไม่พิมพ์อะไรออกมาเลย

ชื่อคลาสที่ประกอบจากตัวแปรตอนรัน (text-<%= color %>-700 · "bg-#{status}-100") · Tailwind มองไม่เห็น · แก้ด้วยการเขียนชื่อเต็มทุกตัวแล้วเลือก · พิมพ์บอก AI ได้ว่า "never build Tailwind class names with interpolation — write every full class name literally and pick one"
static analysis
การวิเคราะห์โค้ดด้วยการอ่านไฟล์ ไม่ได้รัน · เร็วและปลอดภัย แต่เห็นแค่ตัวหนังสือที่เขียนไว้ · Tailwind และเครื่องมือตรวจโค้ดอีกหลายตัวทำงานแบบนี้ · ถาม senior ได้ว่า "เครื่องมือตัวนี้ทำงานแบบ static ใช่ไหม ต้องระวังของที่สร้างตอนรันตรงไหนบ้าง"

bin/dev — เปิดร้านพร้อมฝ่ายจัดซื้อประจำกะ

ทุกครั้งที่เราเพิ่มคลาสใหม่ ไฟล์ CSS ต้องถูกสร้างใหม่ · ถ้าต้องสั่ง tailwindcss:build เองทุกครั้งคงเหนื่อย · bin/rails tailwindcss:watch คือตัวที่เฝ้าไฟล์ แก้เมื่อไหร่ build ให้เองทันที · และ bin/dev คือคำสั่งที่เปิด server กับตัวเฝ้าไฟล์พร้อมกันในคำสั่งเดียว ตามรายการในไฟล์ Procfile.dev:

production = เครื่อง server จริงที่ผู้ใช้เข้า · ตอนเอาแอปขึ้นไป (deploy) ไฟล์ CSS จะถูกสร้างใหม่ตั้งแต่ศูนย์ด้วย assets:precompile (บท 127) · กับดักต่อ string ข้างบนสีหายตั้งแต่บนเครื่องเรา (ทดลองผ่าน bin/dev) — แต่มีอยู่ทางหนึ่งที่บนเครื่องยังเห็นสี · ผมลองลำดับนี้โดยเปิด bin/dev ค้างไว้ตลอด:

AI ส่งงานมาแล้ว ตรวจรับด้วย 4 ข้อนี้ (ทุกข้อเป็นคำสั่งที่คุณรันเป็นแล้วในบทนี้):

  1. ls tailwind.config.js package.json → ต้องขึ้น No such file or directory ทั้งคู่
  2. git grep -n -E '[a-z]-(<%=|#\{)' app/views → ต้องไม่มีผลลัพธ์
  3. bin/rails tailwindcss:build แล้ว grep -c คลาสใหม่ที่ AI ใส่มาสัก 2–3 ตัว → ต้องได้ 1 ขึ้นไป
  4. เปลี่ยน data-theme เป็น dark ใน Console → ตัวหนังสือยังอ่านออกทุกจุด (ถ้าจม = AI ใช้สีตายตัวแทนสีตามหน้าที่)

🎯 ภารกิจ (~10 นาที) — หากับดัก แก้ แล้วพิสูจน์ด้วย grep

สมมติ AI เขียนป้าย "ใหม่ / เก่า" ให้บทความ (ใหม่ = เขียนภายใน 7 วัน) · ก็อปไปวางใน app/views/posts/_post.html.erb ใต้บรรทัด </p> ตัวแรก (บรรทัดที่ปิดชื่อหมวดกับเวลา):

<% tone = post.created_at > 7.days.ago ? "amber" : "slate" %>
<span class="<%= "mt-2 inline-block rounded px-2 text-xs bg-#{tone}-100" %>">
  <%= post.created_at > 7.days.ago ? "ใหม่" : "เก่า" %>
</span>

7.days.ago = "เวลาเมื่อ 7 วันก่อน" (ของแถมจาก Rails) · post.created_at > 7.days.ago = "เขียนหลังจาก 7 วันก่อน" = ใหม่ · #{tone} = เสียบค่าตัวแปรกลาง string ของ Ruby
บรรทัด 2 มีเครื่องหมายคำพูดซ้อนกัน (class="<%= "…" %>") ไม่พัง เพราะ Rails ทำส่วน <%= %> เสร็จก่อนส่ง · เบราว์เซอร์ได้แค่ class="mt-2 … bg-amber-100"

  1. สั่ง bin/rails tailwindcss:build แล้วนับ: grep -c 'bg-amber-100' app/assets/builds/tailwind.css และ grep -c 'bg-slate-100' app/assets/builds/tailwind.css
  2. สั่ง git grep -n -E '[a-z]-(<%=|#\{)' app/views · ควรเจอบรรทัดที่เพิ่งวาง
  3. แก้ให้ถูก (ใบ้: ตั้งตัวแปร tone_class ที่เก็บชื่อคลาสเต็ม แล้วย้ายคลาสที่ตายตัวออกมานอก <%= %>) · build ใหม่ แล้วนับด้วย grep -c อีกรอบ
  4. เปิด bin/dev แล้วดู /posts
