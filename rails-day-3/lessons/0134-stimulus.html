ปัญหาเดิม: JavaScript ที่ไปตามหาของ "ตอนหน้าโหลด"

งานของบทนี้: ใต้ช่องพิมพ์คอมเมนต์ ให้มีตัวเลขบอกว่าพิมพ์ไปกี่ตัวแล้ว · งานนี้ไม่ต้องถาม server เบราว์เซอร์นับเองได้ จึงต้องใช้ JavaScript

ศัพท์ JavaScript 3 คำที่จะเจอทั้งบท:

  • element = แท็กหนึ่งตัวที่อยู่บนหน้าแล้ว เช่น ช่องพิมพ์ <textarea> หนึ่งช่อง · หน้าเว็บทั้งหน้าคือต้นไม้ของ element พวกนี้ (ชื่อทางการ DOM — อยู่ในกล่องศัพท์ข้างล่าง)
  • event = สัญญาณที่เบราว์เซอร์ส่งเมื่อมีอะไรเกิดขึ้น เช่น คลิก · พิมพ์ · หน้าโหลดเสร็จ
  • listener = ฟังก์ชันที่เราฝากไว้กับ element ว่า "ถ้าสัญญาณนี้ดัง ให้ทำสิ่งนี้" · คล้าย onClick={…} ใน React (บท 73)

ถ้าเขียนแบบที่ตัวอย่างบนอินเทอร์เน็ตส่วนใหญ่สอน จะได้หน้าตาแบบนี้ · ไม่ต้องพิมพ์ตาม เราทดลองให้ดูแล้ว (ใส่ไว้ท้าย app/javascript/application.js และเพิ่ม <p id="old-counter"></p> ใต้ช่องพิมพ์ชั่วคราว): 

// ตัวนับแบบเดิม (ทดลอง)
document.addEventListener("DOMContentLoaded", () => {
  const input = document.querySelector("#comment_body")
  const output = document.querySelector("#old-counter")
  input.addEventListener("input", () => {
    output.textContent = input.value.length
  })
})
  • document.addEventListener("DOMContentLoaded", () => { … }) — ฝาก listener ไว้กับทั้งหน้า: "พอหน้าโหลดเสร็จ ให้ทำสิ่งในวงเล็บปีกกา" · () => { … } คือฟังก์ชันแบบย่อ (เหมือนที่เขียนใน React บท 73)
  • document.querySelector("#comment_body") — "ไล่หาทั้งหน้า เอา element แรกที่ id เป็น comment_body" (# = หาจาก id · id นี้ form.textarea :body ตั้งให้เอง) · หาไม่เจอได้ null (ค่าว่าง เหมือน nil ของ Ruby)
  • input.addEventListener("input", …) — ฝาก listener ไว้กับช่องพิมพ์: "ทุกครั้งที่ช่องนี้ถูกพิมพ์ ให้ทำ…" · value.length = ข้อความยาวกี่ตัว · textContent = ข้อความใน element

ข้อความ error จริงในแถวสุดท้าย:

แถวที่ 2 และ 3 น่ากลัวที่สุด — ไม่มี error สักบรรทัด ผู้ใช้แค่เห็นว่าตัวนับไม่ขยับ · ต้นเหตุคือโค้ดนี้ผูกกับเวลา ("ตอนหน้าโหลด") ไม่ได้ผูกกับของ ("ตอนมีช่องพิมพ์อยู่บนหน้า")

ปัญหาที่สอง: JS ต้องรู้ชื่อ id/คลาสใน HTML เอง · ใครเปลี่ยนชื่อใน HTML โดยไม่ได้เปิดไฟล์ JS ก็พังโดยไม่รู้ตัว

Stimulus — ให้ HTML แปะป้ายบอกเองว่าต้องการ JS ตัวไหน

Stimulus คือ library JavaScript ตัวเล็ก ๆ ที่มากับ Rails 8 (ชิ้นที่สองของ Hotwire · ชิ้นแรกคือ Turbo ที่มี Drive · Frame · Stream) · แทนที่ JS จะไปไล่หา element เอง เราแปะป้ายบน HTML ว่า "ตรงนี้ใช้ JS ตัวไหน · ปุ่มนี้กดแล้วเรียกอะไร · element ไหนคือของที่ JS ต้องใช้"

ป้ายพวกนี้คือ attribute ที่ขึ้นต้นด้วย data- · HTML ยอมให้เราตั้งชื่อ data-อะไรก็ได้ เอง เบราว์เซอร์ไม่เอาไปแสดงผล แต่ JS อ่านได้ · (เคยเห็นแล้วตอน data-theme ของ daisyUI บท 128)

ตัวอย่างจากสไลด์หน้า 48 — เมนูที่กดแล้วเปิด/ปิด (อ่านอย่างเดียว ยังไม่ต้องพิมพ์):

<div data-controller="dropdown">
  <button data-action="click->dropdown#toggle">เมนู</button>
  <ul data-dropdown-target="menu" class="hidden">
    …
  </ul>
</div>
  • data-controller="dropdown" — "กล่องนี้ (และทุกอย่างข้างใน) ใช้ JS ชื่อ dropdown" · JS ตัวนี้เรียกว่า controller (คนละอย่างกับ controller ของ Rails ฝั่ง server — ชื่อซ้ำกันเฉย ๆ)
  • data-action="click->dropdown#toggle" — อ่านว่า "เมื่อ click → ให้ controller dropdown ทำ method toggle" · รูปแบบคือ event->ชื่อcontroller#ชื่อmethod
  • data-dropdown-target="menu" — "element นี้คือของชื่อ menu ที่ controller dropdown จะใช้" · ใน JS เรียกมันว่า this.menuTarget ได้เลย ไม่ต้อง querySelector (this = controller ตัวนี้เอง เหมือน self ของ Ruby)
  • class="hidden" — คลาส Tailwind (บท 72) ที่ซ่อน element · toggle ของ dropdown แค่ใส่/ถอดคลาสนี้ เมนูก็เปิด/ปิด

เปิดไฟล์ HTML ไฟล์เดียวก็รู้แล้วว่าปุ่มนี้ทำอะไร ไม่ต้องไปเปิดไฟล์ JS ไล่ดู · ถ้าเทียบกับ React (บท 73): data-action คล้าย onClick={toggle} ใน JSX — ต่างกันที่ React เป็นคนสร้าง HTML ส่วน Stimulus มาเกาะ HTML ที่ server (ERB) ส่งมาให้แล้ว

⏱ เทียบให้เห็นภาพ — อุปกรณ์บนโต๊ะ และป้ายบอกว่าเป็นอุปกรณ์อะไร

ร้านของเรา: ครัวจัดจานเสร็จแล้วเสิร์ฟ (server ส่ง HTML) · Turbo คือพนักงานที่เปลี่ยนจานบนโต๊ะให้โดยไม่ต้องรื้อโต๊ะ · แต่บางอย่างลูกค้าไม่ต้องเรียกครัว เช่น นาฬิกาจับเวลาบนโต๊ะ — กดแล้วนับเอง
Stimulus คืออุปกรณ์บนโต๊ะพวกนี้ · data-controller คือป้ายบนโต๊ะ "โต๊ะนี้มีนาฬิกาจับเวลา" · พนักงานเห็นป้ายเมื่อไหร่ก็ติดตั้งอุปกรณ์ให้
วิธีเดิมคือพนักงานที่เดินแจกนาฬิกาตอนร้านเปิดรอบเดียว — โต๊ะที่จัดใหม่หลังจากนั้นไม่ได้ของ (แถว 2–3 ในตาราง)

ที่ไม่เหมือนกัน: พนักงานจริงลืมติดตั้งก็ยังมีคนทัก · แต่ถ้าป้ายเขียนชื่อผิดแม้ตัวเดียว (เช่น dropdwon) Stimulus จะเมินเฉย ๆ ไม่บอกใคร เพราะมันคิดว่าเป็นป้ายของอุปกรณ์ที่ร้านไม่มี (เดี๋ยวเห็นของจริง)

ขั้น 1 — สร้างไฟล์ controller

ภาษาคนก่อน — controller ตัวนี้ทำ 3 อย่าง: ① ฟอร์มโผล่ → ฝาก listener ไว้กับช่องพิมพ์ แล้วนับครั้งแรก · ② ทุกครั้งที่พิมพ์ → เขียนตัวเลขใหม่ลงช่องโชว์ · ③ ฟอร์มหายไป → ถอด listener ออก

สร้างไฟล์ใหม่ app/javascript/controllers/character_counter_controller.js (ชื่อนี้ → ใน HTML เรียก character-counter):

import { Controller } from "@hotwired/stimulus"

// ตัวนับอักษรของช่องพิมพ์คอมเมนต์ (อยู่ใน comments/_form.html.erb) แสดงเป็น "12 / 1000"
export default class extends Controller {
  static targets = ["input", "output"]

  // ฟอร์มโผล่ (โหลดหน้า หรือ Turbo Stream ใส่ฟอร์มใหม่): เริ่มฟังการพิมพ์
  connect() {
    this.onInput = this.update.bind(this)
    this.inputTarget.addEventListener("input", this.onInput)
    this.update()
  }

  // ฟอร์มหายไป: ถอด listener ที่ connect ผูกไว้
  disconnect() {
    this.inputTarget.removeEventListener("input", this.onInput)
  }

  update() {
    this.outputTarget.textContent = `${this.inputTarget.value.length} / ${this.inputTarget.maxLength}`
  }
}

ทีละบรรทัด:

  • import { Controller } from "@hotwired/stimulus" — ดึงแม่แบบ Controller มาจาก Stimulus (ชื่อ @hotwired/stimulus อยู่ในสมุด importmap แล้ว บท 127)
  • export default class extends Controller — "ไฟล์นี้ส่งออก class หนึ่งตัว ที่สืบทอดจาก Controller" · เหมือน Ruby class X < Controller แต่ไม่ตั้งชื่อ เพราะชื่อมาจากชื่อไฟล์
  • static targets = ["input", "output"] — ประกาศว่า controller นี้ใช้ target สองตัว · Stimulus อ่านรายชื่อจากบรรทัดนี้แล้วสร้าง this.inputTarget และ this.outputTarget ให้ · (static = ค่าที่ติดกับ class ทั้งก้อน ไม่ใช่ของแต่ละตัว — ตอนนี้จำแค่ว่า "รายการประกาศ" ของ Stimulus ขึ้นต้นด้วย static)
  • connect() { … } · disconnect() { … } · update() { … } — method ของ class · JS เขียนแค่ชื่อตามด้วย () { } ไม่มีคำว่า def แบบ Ruby
  • this.onInput = … — เก็บของไว้ในตัว controller ให้ method อื่นหยิบใช้ได้ · เหมือน @on_input = … ของ Ruby
  • this.update.bind(this) — หยิบ method update ออกมาเป็นฟังก์ชันที่ฝากให้เบราว์เซอร์ได้ พร้อมมัดไว้ว่า this คือ controller ตัวนี้ · ถ้าไม่ bind พอเบราว์เซอร์เรียก this จะกลายเป็นช่องพิมพ์แทน แล้ว this.outputTarget หาไม่เจอ · เก็บไว้ใน this.onInput เพื่อเอาตัวเดียวกันไปถอดใน disconnect
  • addEventListener("input", this.onInput) — event input ดังทุกครั้งที่ข้อความในช่องเปลี่ยน (พิมพ์ ลบ วาง) · removeEventListener คือคำสั่งถอดออก
  • this.update() ใน connect — นับทันทีหนึ่งรอบตอนฟอร์มโผล่ (ฟอร์มที่กลับมาพร้อมข้อความเดิมจะได้ตัวเลขถูกตั้งแต่แรก)
  • `${…} / ${…}` — ข้อความที่แทรกค่าได้ เหมือน "#{…}" ของ Ruby · value.length = จำนวนตัวอักษร · maxLength = ค่า maxlength ของช่อง (1000 · ใส่ในขั้น 2)

วิธีที่สั้นกว่าและ "ปกติ" กว่าคือใส่ data-action="input->character-counter#update" บนช่องพิมพ์ แล้ว Stimulus ผูก/ถอดให้เอง ไม่ต้องมี disconnect · เราเขียนแบบผูกเองเพราะเกณฑ์ตรวจรับของ Lab (บท 135) ข้อ "Stimulus controller มี disconnect" — ได้ฝึกคู่ connect/disconnect ของจริง

  • maxlength: 1000 — attribute มาตรฐานของ HTML: เบราว์เซอร์ไม่ยอมให้พิมพ์เกิน 1000 ตัวเอง (ตรงกับ validation ของ Comment ที่จำกัด 1000) · JS อ่านเลขนี้ไปโชว์ ไม่ต้องจำเลขซ้ำ

connect / disconnect — ผูกกับ "ตอนที่ element มีอยู่" ไม่ใช่ "ตอนหน้าโหลด"

นี่คือหัวใจของ Stimulus (สไลด์หน้า 49) · controller มี method พิเศษสองตัว: connect() ทำงานทุกครั้งที่ element ที่มี data-controller โผล่บนหน้า · disconnect() ทำงานทุกครั้งที่มันหายไป

Stimulus รู้ได้ยังไง? เบราว์เซอร์มีเครื่องมือชื่อ MutationObserver = "ยามที่คอยดูว่ามี element ถูกเพิ่มหรือลบจากหน้าไหม แล้วรายงาน" · Stimulus จ้างยามคนนี้เฝ้าทั้งหน้าตลอดเวลา · ไม่ว่าใครเปลี่ยนหน้า — Turbo Drive · Turbo Stream · broadcast — ยามเห็นหมด

มาดูด้วยตา: ใส่บรรทัด console.log("ตัวนับ: connect") เป็นบรรทัดแรกใน connect() และ console.log("ตัวนับ: disconnect") ใน disconnect() ของตัวนับที่เพิ่งทำ · console.log("…") = พิมพ์ข้อความลงแท็บ Console ของ DevTools (กด F12 หรือ ⌥⌘J บน Mac) · ลองทำตามได้เลย เสร็จแล้ว git restore .

ที่ไม่เหมือนกัน: พนักงานจริงเก็บนาฬิกาออกเองแน่นอน · แต่ Stimulus เก็บให้เฉพาะของที่มันติดตั้งเอง (เช่น data-action) · ของที่เราติดตั้งเองใน connect เราต้องเขียนเก็บเองใน disconnect — หัวข้อถัดไป

เทียบกับ React (บท 74): connect() ≈ โค้ดใน useEffect ตอน component โผล่ · disconnect() ≈ ฟังก์ชันที่ return ออกจาก useEffect · ปัญหาเดียวกัน คำตอบคนละหน้าตา

ของที่สร้างใน connect ต้องเก็บกวาดใน disconnect

ถ้า connect สร้างของที่อยู่นอก element ของเรา ของพวกนั้นไม่หายไปพร้อม element มันอยู่ต่อจนกว่าจะปิดแท็บ · ตัวอย่างเช่น

  • setInterval(ฟังก์ชัน, 1000) — ตั้งนาฬิกาให้ทำซ้ำทุก 1000 มิลลิวินาที (1 วินาที) ไปเรื่อย ๆ · ปิดด้วย clearInterval
  • listener บน window หรือ document — ฝากไว้กับทั้งหน้า ไม่ใช่กับ element ของเรา
  • library ภายนอกที่เปิดไว้ · สาย WebSocket ที่ต่อเอง (สายที่ต่อค้างไว้ บท 133)

เทียบ: React เก็บกวาดใน return () => clearInterval(id) ของ useEffect · Go ใช้ defer (บท 08) ปิดของตอนออกจากฟังก์ชัน — ความคิดเดียวกัน "เปิดอะไร ต้องปิดสิ่งนั้น"

// app/javascript/controllers/theme_controller.js
  connect() {
    const saved = localStorage.getItem("theme")
    if (saved) document.documentElement.dataset.theme = saved
  }

  toggle() {
    const html = document.documentElement
    const systemDark = window.matchMedia("(prefers-color-scheme: dark)").matches
    const current = html.dataset.theme || (systemDark ? "dark" : "light")
    const next = current === "dark" ? "light" : "dark"

    html.dataset.theme = next
    localStorage.setItem("theme", next)
  }

ตัวเลือกที่ 3 ถูก — ทั้งสองข้อใช้ Turbo Stream แต่ใครเป็นคนเริ่มต่างกัน · (ก) เรากดส่งฟอร์มเอง server ตอบกลับคำขอของเรา ด้วยคำสั่งหลายข้อ (append · update ตัวนับ · replace ฟอร์ม — บท 132) · (ข) เราไม่ได้กดอะไร server ประกาศเองผ่านสาย WebSocket ไปทุกแท็บที่เปิดฟังอยู่ (บท 133)

ตัวเลือกที่ 1 ผิดเพราะ Frame เปลี่ยนได้แค่กรอบเดียว แต่โจทย์ต้องเปลี่ยน 3 จุด · ตัวเลือกที่ 2 ผิดเพราะคอมเมนต์ต้องบันทึกลง DB = ต้องถาม server ไม่ใช่งาน Stimulus · ตัวเลือกที่ 4 สลับกัน และ Turbo Drive ทำงานตอนเรากดลิงก์เท่านั้น ไม่ได้โหลดเอง

จุดที่ต้องจำ: Stream ตอบฟอร์ม = เราเริ่ม · Stream broadcast = คนอื่นเริ่ม server ประกาศมา

งานไหนเหมาะกับ Stimulus ที่สุด?

ใส่ console.log ใน connect และ disconnect ของตัวนับ แล้วส่งคอมเมนต์สำเร็จ (URL ไม่เปลี่ยน) · Console จะแสดงอะไร?

ตัวเลือกที่ 1 ถูก — เราดูใน Chrome แล้ว: ตัวนับ: disconnect ตามด้วย ตัวนับ: connect · Turbo Stream replace ลบฟอร์มเก่าออกแล้วใส่ใบใหม่ · Stimulus ผูกกับ element ไม่ได้ผูกกับ URL

ตัวเลือกที่ 2 คือความคิดแบบ "ตอนหน้าโหลด" ที่ทำให้ตัวนับแบบเดิมพัง · ตัวเลือกที่ 3 ผิดเพราะฟอร์มเก่าถูกลบออกจากหน้าจริง ๆ → controller ตัวเก่า disconnect แม้ URL จะเดิม · ตัวเลือกที่ 4 ผิดเพราะฟอร์มใบใหม่มี data-controller → connect ยิงทันที ตัวนับขึ้น 0 / 1000
