4 · ขั้น 1 — ก็อปโปรเจกต์ด้วย git clone แล้วสลับไป day3-start

โค้ดของอาจารย์เก็บอยู่บน GitHub เป็น repository (เรียกสั้น ๆ ว่า repo = โฟลเดอร์โปรเจกต์ที่มี git คอยจดประวัติ) · git clone คือก็อป repo ทั้งก้อนลงเครื่องเรา พร้อมประวัติการแก้ทุกครั้ง ไม่ใช่แค่ไฟล์ล่าสุด

ในประวัตินั้นมีหลายสาย แต่ละสายเรียกว่า branch — อาจารย์ทำสาย day3-start (จุดเริ่มเช้าวันนี้) · day3-a-done (ทำบล็อก A เสร็จ) ฯลฯ · git checkout ชื่อสาย คือสลับไฟล์ทั้งโฟลเดอร์ให้เป็นหน้าตาของสายนั้น

📒 เทียบให้เห็นภาพ — รับร้านต้นแบบพร้อมสมุดบันทึกการปรับปรุงร้าน

git clone คือแฟรนไชส์ยกร้านต้นแบบมาทั้งร้าน พร้อมสมุดบันทึกการปรับปรุงร้านทุกหน้าตั้งแต่วันเปิด · branch คือสมุดแยกเล่ม: เล่ม "เช้าวันนี้" · เล่ม "หลังจัดหน้าร้านเสร็จ" · checkout คือจัดร้านให้ตรงกับเล่มที่เลือก — โต๊ะ เก้าอี้ ป้ายเมนู ย้ายตามเล่มนั้นทันที

ที่ไม่เหมือนกัน: git จัดได้แค่ไฟล์ในโฟลเดอร์ · ของในตู้เก็บแฟ้ม (ข้อมูลใน PostgreSQL) ไม่ได้อยู่ใน git · สลับ branch แล้วข้อมูลในฐานข้อมูลยังอยู่ครบเหมือนเดิม (หลังใส่บทความ 30 ชิ้นในหัวข้อ 7 ผมลองสลับสายแล้ว ยังนับได้ 30) · และร้านจริงย้ายโต๊ะต้องใช้แรง แต่ git สลับทั้งโฟลเดอร์ได้ในเสี้ยววินาที

ไปที่โฟลเดอร์ที่เก็บโปรเจกต์ (โฟลเดอร์เดียวกับที่มี wongnok_blog ของ Day 1–2 · อย่า clone ซ้อนเข้าไปข้างในโปรเจกต์เดิม) แล้วพิมพ์ทีละบรรทัด:

ต่อไปคือตู้เก็บแฟ้ม · repo นี้มีไฟล์ compose.yaml ที่เขียนไว้ว่าต้องเปิดโปรแกรมอะไรบ้าง · docker compose up -d อ่านไฟล์นั้นแล้วเปิดให้ทั้งชุด ในกล่องแยก (container) ที่ไม่ปนกับโปรแกรมในเครื่อง · คุณเคยใช้ไฟล์แบบนี้เปิด PostgreSQL มาแล้วในฝั่ง Go (บท 27) 

# compose.yaml (ตัดมาเฉพาะส่วนที่ต้องรู้)
services:
  postgres:
    image: postgres:18
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql
  minio:
    …
    ports: ["9000:9000", "9001:9001"]
  • postgres: = ตู้เก็บแฟ้ม PostgreSQL รุ่น 18 · ผู้ใช้ postgres รหัส postgres
  • ports: "5432:5432" = เปิดประตูหมายเลข 5432 ของเครื่องเรา ให้ทะลุเข้าไปที่ตู้ในกล่อง (5432 คือหมายเลขประตูมาตรฐานของ PostgreSQL)
  • volumes: pgdata:… = เก็บข้อมูลไว้นอกกล่อง · ปิดกล่องแล้วเปิดใหม่ บทความไม่หาย
  • minio: = โกดังเก็บไฟล์ (ใช้เก็บรูป/ไฟล์แนบ) · วันนี้ยังไม่ใช้ — รอ Part 2

เปิด Docker Desktop ให้ทำงานก่อน แล้วพิมพ์ docker compose up -d ในโฟลเดอร์โปรเจกต์ · -d = เปิดทิ้งไว้เบื้องหลัง คืนเทอร์มินัลให้พิมพ์ต่อได้ · ครั้งแรกจะดาวน์โหลดตัวโปรแกรมนานหน่อย · (เครื่องตรวจของผมไม่ได้รันคำสั่งนี้ เพราะใช้ PostgreSQL ที่เปิดไว้แล้ว — จึงไม่มีผลลัพธ์ให้ดู)

🚪 เทียบให้เห็นภาพ — ตู้เก็บแฟ้มสำเร็จรูป กับเลขที่ประตู

compose.yaml คือใบสั่งอุปกรณ์ของร้านต้นแบบ: "ตู้เก็บแฟ้มรุ่น 18 หนึ่งตู้ กุญแจชื่อ postgres · โกดังเก็บของหนึ่งหลัง" · docker compose up -d คือยกของตามใบสั่งมาวางแล้วเสียบปลั๊ก · แต่ละอย่างต้องตั้งตรงประตูหมายเลขของมัน (ตู้แฟ้มอยู่ประตู 5432)

ที่ไม่เหมือนกัน: ร้านจริงวางตู้สองใบหน้าประตูเดียวกันได้ · ในเครื่องคอมพิวเตอร์หนึ่งหมายเลขประตูมีเจ้าของได้แค่โปรแกรมเดียว · ถ้ามี PostgreSQL ตัวเก่าตั้งอยู่ที่ 5432 แล้ว ตู้ใหม่จะเข้าที่ไม่ได้ (ดูกล่องเตือนข้างล่าง) · และกล่องของ docker ไม่ใช่ตู้ที่จับต้องได้ — มันคือโปรแกรมที่ถูกกั้นให้มองไม่เห็นของอื่นในเครื่อง

⚠️ สองจุดที่พิมพ์ตามแล้วพังบ่อยที่สุด

(1) ประตู 5432 มีเจ้าของอยู่แล้ว — docker compose up -d ฟ้อง error ที่พูดถึง 5432 = มี PostgreSQL ตัวเก่าเปิดอยู่ เช่น container devpool-postgres ของฝั่ง Go บท 27 (ตั้ง restart: always ไว้ = เปิดเครื่องแล้วมันขึ้นเอง) หรือตัวที่ใช้กับแอป Day 2

  • docker ps = ดูรายการกล่องที่เปิดอยู่ · มองคอลัมน์ PORTS ว่าตัวไหนมี 5432
  • docker stop ชื่อกล่อง = ปิดกล่องนั้น · ข้อมูลไม่หาย อยากใช้อีกก็ docker start ชื่อกล่อง
  • ถ้าลง PostgreSQL ผ่าน Homebrew: brew services list ดูชื่อ แล้ว brew services stop ชื่อที่เห็น

(2) ค่า DATABASE_URL ค้างจาก Day 1–2 — ถ้าเคย export DATABASE_URL=… ไว้ (บท 98) Rails จะเชื่อค่านั้นก่อนไฟล์ตั้งค่า แล้วไปใช้ฐานข้อมูลของแอปเก่า · เช็คด้วย echo $DATABASE_URL ต้องได้บรรทัดว่าง · ถ้าไม่ว่างให้ unset DATABASE_URL (ลบตัวแปรนี้ในเทอร์มินัลนี้)

ทำไมไม่ต้องตั้งรหัสฐานข้อมูลเอง? เพราะ config/database.yml ของ repo ตั้งค่าเริ่มต้นไว้ตรงกับ compose.yaml แล้ว · ไฟล์นี้ใช้ ERB (<%= %> ที่เรียนบท 103 — ใช้ได้ในไฟล์ตั้งค่าด้วย):

  host: <%= ENV.fetch("DATABASE_HOST", "localhost") %>
  port: <%= ENV.fetch("DATABASE_PORT", 5432) %>
  username: <%= ENV.fetch("DATABASE_USER", "postgres") %>
  password: <%= ENV.fetch("DATABASE_PASSWORD", "postgres") %>

ENV.fetch("DATABASE_HOST", "localhost") = "อ่านตัวแปรสภาพแวดล้อม (ค่าที่ตั้งไว้ในเทอร์มินัล) ชื่อ DATABASE_HOST · ถ้าไม่มี ใช้ค่าหลังลูกน้ำ" · ของคุณไม่ได้ตั้งอะไร จึงได้ localhost · 5432 · postgres · postgres = ตรงกับตู้ใน compose.yaml พอดี · ของคุณไม่ต้องตั้งตัวแปรพวกนี้ (เครื่องตรวจของผมตั้งไว้ให้ชี้ไปตู้อื่น เพราะไม่ได้ใช้ docker)
