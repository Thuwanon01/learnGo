Turbo Frames — แก้หัวข้อบทความในหน้าเดิม ไม่ต้องเปลี่ยนหน้า

~20 นาทีอ่าน + ลงมือทำตามอีก ~20 นาที · ควรผ่าน บท 130 (Hotwire · Turbo Drive) · บท 123 (partial) · บท 124 (form_with) มาก่อน

ตอนนี้ถ้าอยากแก้หัวข้อบทความคำเดียว ต้องกด "แก้ไข" แล้วย้ายไปอีกหน้าที่มีฟอร์มสามช่อง · บทนี้จะทำให้กดปุ่มข้างหัวข้อ แล้วหัวข้อกลายเป็นช่องพิมพ์ตรงนั้นเลย บันทึกแล้วกลับเป็นหัวข้อใหม่ — หน้าไม่เปลี่ยน URL ไม่เปลี่ยน และไม่ต้องเขียน JavaScript สักบรรทัด
อ่านจบแล้วคุณจะทำ "กรอบที่เปลี่ยนตัวเองได้" (Turbo Frame) เป็น · อ่านอาการเวลามันพังออก · และจำกฎข้อเดียวของมันได้: id ของกรอบต้องตรงกันสองฝั่ง

🔁 ทวนก่อนเริ่ม — คำจากบทก่อน ๆ ที่บทนี้ใช้

  • Turbo Drive (บท 130) — คลิกลิงก์แล้ว Turbo ไปขอหน้าใหม่มาเปลี่ยนเฉพาะจานบนโต๊ะเดิม ไม่รื้อโต๊ะ (<head> อยู่ที่เดิม) · บทนี้ย่อลงอีกขั้น: เปลี่ยนแค่ถ้วยใบเดียว
  • partial · locals (บท 123) — _post.html.erb คือแม่พิมพ์ของบทความหนึ่งชิ้น · ข้างในใช้ post (ของที่ยื่นใส่มือ) ไม่ใช่ @post · หน้า show เรียกด้วย render @post, full: true
  • form_with model: (บท 124) — บทความที่มีอยู่แล้ว → ฟอร์มส่งแบบ PATCH ไป /posts/30 และตั้งชื่อช่องเป็น post[title] ให้เอง
  • validation · 422 (บท 110) — หัวข้อว่าง = บันทึกไม่ได้ · scaffold ตอบกลับด้วย render :edit, status: :unprocessable_content (เลข 422) พร้อมข้อความ error
  • before_action (บท 118) — "ก่อนเข้า action พวกนี้ ให้ทำ method นี้ก่อน" · scaffold มี before_action :set_post อยู่แล้ว

ผลรันทุกก้อนรันจริงแล้วก็อปมา · ตัวอย่างใช้บทความเลขที่ 30 ("นมเย็น" — ใบแรกบนหน้ารวม) · เลข id · เวลา ms · วันเวลาใน log · รหัสกัน CSRF ยาว ๆ ของคุณจะต่าง · path ยาว ๆ ของ gem ย่อเป็น …

ตอนนี้: แก้หัวข้อคำเดียว ต้องย้ายไปอีกหน้า

เปิด http://localhost:3000/posts/30 · ใต้บทความมีปุ่ม "แก้ไข" · กดแล้วเบราว์เซอร์ไป /posts/30/edit ซึ่งเป็นอีกหน้าหนึ่ง มีฟอร์มสามช่อง (หัวข้อ · เนื้อหา · หมวด) · แก้เสร็จกดบันทึก ถูกส่งกลับมาหน้าเดิม

ใช้ได้ แต่ถ้าแค่อยากแก้คำผิดในหัวข้อ มันอ้อมเกินไป · ที่เราอยากได้คือแก้ตรงที่มันอยู่ — กดปุ่มข้างหัวข้อ → หัวข้อกลายเป็นช่องพิมพ์ → กดบันทึก → กลับเป็นหัวข้อใหม่ · ส่วนอื่นของหน้าอยู่เฉย ๆ

ของที่ทำแบบนี้ได้ชื่อ Turbo Frame — ชิ้นที่สองของ Hotwire (ชิ้นแรกคือ Turbo Drive บท 130) · เราเอากล่องพิเศษชื่อ <turbo-frame> ไปครอบส่วนที่อยากให้เปลี่ยนได้ · ลิงก์หรือฟอร์มที่อยู่ข้างในกล่อง เมื่อกดแล้ว Turbo จะเปลี่ยนแค่ข้างในกล่องนั้น ไม่แตะส่วนอื่นของหน้าเลย

🥣 เทียบให้เห็นภาพ — เปลี่ยนแค่ถ้วยใบเดียวบนโต๊ะ

Turbo Drive (บท 130) เหมือนพนักงานเปลี่ยนจานทั้งชุดบนโต๊ะเดิม · Turbo Frame ละเอียดกว่านั้น: ลูกค้าขอเปลี่ยนน้ำจิ้มถ้วยเดียว · พนักงานเดินไปครัว รับถาดที่ครัวจัดมา แล้วหยิบเฉพาะถ้วยที่ป้ายเลขตรงกับถ้วยบนโต๊ะมาวางแทน · ข้าว กับข้าว แก้วน้ำ อยู่ที่เดิมหมด

ที่ไม่เหมือนกัน: ร้านจริงคงไม่มีใครจัดอาหารทั้งถาดเพื่อเปลี่ยนน้ำจิ้มถ้วยเดียว · แต่ Turbo ขอหน้าเว็บมาทั้งหน้าจริง ๆ แล้วทิ้งส่วนที่เหลือ — เดี๋ยวจะเห็นว่า Rails ช่วยให้ "ถาด" นั้นบางลงได้

เทียบกับ React (บท 73): ถ้าทำใน React คุณจะเขียน const [editing, setEditing] = useState(false) สลับการ์ดเป็นช่องพิมพ์ · ยิง fetch (คำสั่งของ JavaScript ที่ส่งคำขอไปหา server) ส่ง JSON ไป · แล้วเก็บหัวข้อใหม่ไว้ใน state ของเบราว์เซอร์อีกชุด · Turbo Frame ไม่มี state ชุดที่สองแบบนั้น — server ส่ง HTML ของกล่องมาให้ทั้งก้อน เบราว์เซอร์แค่เอามาวาง

🗣 ศัพท์ที่เพิ่งเรียนไป
Turbo Frame · <turbo-frame>
กล่อง HTML ที่ Turbo ดูแล · ลิงก์และฟอร์มข้างในกล่องจะโหลดผลมาใส่แค่ในกล่องนั้น · พิมพ์บอก AI ได้ว่า “wrap the post title in a turbo frame so the edit link loads inside it”
inline edit
แก้ของ "ในที่ของมัน" แทนที่จะพาไปหน้าแก้ไขแยก · เป็นงานที่ Turbo Frame เหมาะที่สุด · ถาม senior ได้ว่า “ตรงนี้ทำ inline edit ด้วย Turbo Frame ได้ไหม หรือต้องเปลี่ยนหลายจุดจนต้องใช้ Stream”

Turbo Frame ทำงานยังไง — 5 ขั้น

ก่อนพิมพ์โค้ด ดูภาพรวมก่อน (สไลด์หน้า 42 วาดไว้แบบเดียวกัน) · สมมติหน้า show มีกล่อง id title_post_30 ครอบหัวข้อกับปุ่ม "แก้ไขหัวข้อ":

หน้าที่ผู้ใช้เปิดอยู่ (/posts/30) navbar ┌─ turbo-frame id="title_post_30" ───────── │ นมเย็น [แก้ไขหัวข้อ] └────────────────────────────────────────── เนื้อหา · ปุ่ม "แก้ไข" "ลบบทความ" ข้างล่าง ① กด "แก้ไขหัวข้อ" — ลิงก์นี้อยู่ในกล่อง ② Turbo ไปขอ GET /posts/30/edit ③ คำตอบกลับมา → Turbo หากล่องที่ id = "title_post_30" ในคำตอบ ④ เอาเฉพาะข้างในกล่องนั้นมาวางแทนของเดิม → [ช่องพิมพ์] [บันทึก] [ยกเลิก] ⑤ navbar · เนื้อหา · ปุ่มข้างล่าง ไม่ขยับ · URL ยังเป็น /posts/30

ขั้น ③ คือหัวใจ (id = ชื่อประจำตัวของแท็ก HTML หนึ่งตัว ห้ามซ้ำในหน้าเดียวกัน) · Turbo ไม่ได้เดาว่าจะเอาส่วนไหนของคำตอบ · มันหากล่องที่ id เหมือนกับกล่องที่ลิงก์อยู่ · เจอ = เอาข้างในมาวาง · ไม่เจอ = พัง · นี่คือกฎข้อเดียวของ Frames: id ต้องตรงกันสองฝั่ง (เดี๋ยวเราจะทำให้พังจริงให้ดู)

งานของเราจึงมี 2 ฝั่ง:

  • ฝั่งหน้า show — ครอบหัวข้อ + ปุ่ม "แก้ไขหัวข้อ" ด้วยกล่อง
  • ฝั่งคำตอบ — ตอนกดปุ่มนั้น server ต้องตอบกลับมาด้วยกล่อง id เดียวกัน ที่ข้างในเป็นฟอร์มช่องเดียว

ขั้นที่ 1 — ครอบหัวข้อด้วยกล่อง (_post.html.erb)

เปิด bin/dev ทิ้งไว้ก่อน (บท 128 — มันคอยสร้าง CSS ใหม่ทุกครั้งที่เราใช้คลาสใหม่ · บทนี้มีคลาสที่แอปยังไม่เคยใช้ เช่น input-lg)

เปิด app/views/posts/_post.html.erb · ในก้อน <% if full %> (ส่วนที่ใช้ในหน้า show) มีหัวข้ออยู่บรรทัดเดียว:

    <% if full %>
      <h1 class="card-title text-3xl"><%= post.title %></h1>

เปลี่ยนบรรทัด <h1> นั้นเป็นแบบนี้ (บรรทัด if full กับบรรทัด <p> ข้างล่างไม่ต้องแตะ):

    <% if full %>
      <%# แก้หัวข้อในหน้าเดิม: id ต้องตรงกับ posts/edit.html+turbo_frame.erb %>
      <%= turbo_frame_tag dom_id(post, :title) do %>
        <div class="flex items-start justify-between gap-2">
          <h1 class="card-title text-3xl"><%= post.title %></h1>
          <%= link_to "แก้ไขหัวข้อ", edit_post_path(post), class: "btn btn-ghost btn-sm shrink-0" %>
        </div>
      <% end %>
      <p class="leading-relaxed whitespace-pre-line"><%= post.description %></p>
  • <%# … %> — โน้ตในไฟล์ (ไม่ขึ้นบนหน้าเว็บ · บท 122) · จดไว้เตือนตัวเองว่ากล่องนี้มีคู่อยู่อีกไฟล์
  • turbo_frame_tag … do … end — helper ของ Turbo ที่สร้างแท็ก <turbo-frame id="…"> ครอบทุกอย่างระหว่าง do กับ end · ใช้ <%= (มีเครื่องหมายเท่ากับ) เพราะต้องการให้กล่องขึ้นบนจาน
  • dom_id(post, :title) — helper สร้าง id จากบทความ · ได้ title_post_30 (ดูของจริงข้างล่าง)
  • flex items-start justify-between gap-2 — วางของในแถวเดียวกัน (flex) · ชิดบน (items-start) · หัวข้อชิดซ้าย ปุ่มชิดขวา (justify-between) · เว้นช่องเล็กน้อย (gap-2)
  • link_to "แก้ไขหัวข้อ", edit_post_path(post) — ลิงก์ไป /posts/30/edit · URL เดียวกับปุ่ม "แก้ไข" ข้างล่างเป๊ะ ต่างกันแค่ตัวนี้อยู่ในกล่อง
  • btn btn-ghost btn-sm — ปุ่มของ daisyUI แบบโปร่ง ขนาดเล็ก (บท 128) · shrink-0 — ห้ามบีบปุ่มให้แคบลงเวลาหัวข้อยาว

🗣 ศัพท์ที่เพิ่งเรียนไป
turbo_frame_tag
helper ของ turbo-rails ที่เขียน <turbo-frame id="…">…</turbo-frame> ให้ · พิมพ์บอก AI ได้ว่า “use turbo_frame_tag with dom_id on both sides, don't hardcode the frame id”
dom_id
helper สร้าง id ของ HTML จาก record เช่น post_30 · เติมคำได้ (title_post_30) · ใช้ตั้งป้ายเลขถ้วยให้ตรงกันทุกไฟล์ · ถาม senior ได้ว่า “ในหน้านี้มี dom_id(post) ซ้ำกันสองที่ไหม ควรเติม prefix อะไร”

ลองกดตอนนี้เลย — กล่องยังมีแค่ฝั่งเดียว

ยังไม่ต้องทำอีกฝั่ง · รีเฟรชหน้า /posts/30 จะเห็นปุ่ม "แก้ไขหัวข้อ" ทางขวาของหัวข้อ

ตอนนี้หน้า /posts/30/edit ยังเป็นหน้าเต็มแบบเดิม ไม่มีกล่อง title_post_30 อยู่ในนั้นเลย · ถ้ากด "แก้ไขหัวข้อ" ตอนนี้ คิดว่าจะเกิดอะไร: (ก) ไปหน้าแก้ไขเต็มตามปกติ · (ข) ไม่เกิดอะไรเลย · (ค) อย่างอื่น?

<turbo-frame id="title_post_30" src="http://localhost:3000/posts/30/edit" complete=""><strong class="turbo-frame-error">Content missing</strong></turbo-frame>

src กับ complete คือของที่ Turbo เติมเองหลังกด (ไปโหลดจากไหนมา · โหลดเสร็จแล้ว) · ข้างในเหลือแค่ป้ายเตือน Content missing

และในแท็บ Console ของ DevTools (บท 130 · Mac: ⌘+⌥+J) มี error สีแดง · บรรทัดแรกที่ผมดักได้จาก Chrome:

The response (200) did not contain the expected <turbo-frame id="title_post_30"> and will be ignored. To perform a full page visit instead, set turbo-visit-control to reload.

แปล: "คำตอบ (200 = สำเร็จ) ไม่มีกล่อง title_post_30 ที่รออยู่ จึงไม่เอาอะไรมาวาง" · server ตอบปกติดี แต่ Turbo หาถ้วยที่ป้ายเลขตรงกันไม่เจอ — มันเลยไม่ยอมเปลี่ยนทั้งหน้า และเขียนป้ายเตือนไว้ในกล่องแทน

ท่อนท้าย "To perform a full page visit… turbo-visit-control" = คำแนะนำวิธีบังคับให้โหลดทั้งหน้าแทน — บทนี้ไม่ใช้ ข้ามได้ · ข้างหน้าข้อความอาจมีชื่อ error แปลก ๆ (ผมเห็นเป็น Nt: เพราะไฟล์ Turbo ถูกบีบให้เล็ก) ไม่ต้องสนใจเช่นกัน

นี่คือกฎข้อเดียวของ Frames ที่เห็นด้วยตาแล้ว · รีเฟรชหน้าเพื่อให้หัวข้อกลับมา · ทีนี้ไปทำอีกฝั่งให้ตรงกัน

ขั้นที่ 2 — ทำไมไม่ครอบหน้า edit เดิมเฉย ๆ

ทางที่ตรงที่สุด (และเป็นทางที่สไลด์หน้า 41 สอน) คือเปิด edit.html.erb แล้วครอบฟอร์มด้วยกล่อง id เดียวกัน · สไลด์บอกว่า "controller ไม่ต้องแก้อะไรเลย" — ซึ่งจริงถ้าหน้า edit มีไว้ใช้ในกล่องอย่างเดียว · แต่แอปเรายังต้องใช้หน้า edit เต็ม (ปุ่ม "แก้ไข" ข้างล่าง) · ผมลองทำตามสไลด์ตรง ๆ แล้ว ได้ปัญหาสองอย่าง:

  • ในกล่องได้ฟอร์ม 3 ช่อง (หัวข้อ · เนื้อหา · หมวด) แทนที่หัวข้อ — ไม่ใช่ "แก้หัวข้อ" แล้ว
  • หน้า edit เต็มพัง: เปิด /posts/30/edit ตรง ๆ แล้วกดบันทึก → URL ค้างที่ /posts/30/edit · ฟอร์มหายไป เหลือหัวข้อ "แก้ไขบทความ" กับชื่อบทความ + ปุ่ม "แก้ไขหัวข้อ" (ของในกล่องจากหน้า show) · ไม่มีข้อความ "บันทึกการแก้ไขแล้ว"

ข้อสองเกิดเพราะฟอร์มที่อยู่ในกล่อง จะส่งแบบ "เปลี่ยนแค่กล่อง" เสมอ ไม่ว่าหน้านั้นจะเปิดมายังไง — บันทึกเสร็จ Turbo หยิบแค่กล่องจากหน้า show มาวางแทนฟอร์ม ส่วนอื่นของหน้า edit ค้างอยู่อย่างนั้น · ทางแก้: แยกเป็นสองไฟล์ — หน้า edit เต็มเหมือนเดิมทุกอย่าง · และไฟล์ฟอร์มเล็กที่ใช้เฉพาะตอนคำขอมาจากกล่อง

แล้ว server จะรู้ได้ยังไงว่าคำขอมาจากกล่อง? Turbo บอกให้เอง · ตอนกดลิงก์ในกล่อง มันแนบป้าย (header — ข้อมูลเสริมที่วิ่งไปกับคำขอ ผู้ใช้มองไม่เห็น) ชื่อ Turbo-Frame ไปด้วย · ผมดักคำขอจริงจาก Chrome ตอนกด "แก้ไขหัวข้อ" ได้แบบนี้ (ในเครื่องคุณดูได้ที่ DevTools แท็บ Network → คลิกคำขอ edit → Request Headers): 

GET http://localhost:3000/posts/30/edit
  accept: text/html, application/xhtml+xml
  turbo-frame: title_post_30
  x-turbo-request-id: c2cdefa6-4159-4881-8e47-6bb1787cfdaa   ← เปลี่ยนทุกครั้ง
  • GET …/posts/30/edit — URL เดียวกับที่ลิงก์ชี้ไป (GET = ขอดูหน้า)
  • accept: text/html, … — "ขอคำตอบเป็น HTML นะ" (ไม่ใช่ JSON)
  • turbo-frame: title_post_30 — ป้ายที่เราสนใจ = "คำขอนี้มาจากกล่อง title_post_30"
  • x-turbo-request-id — เลขประจำคำขอที่ Turbo ติดเอง · ไม่ต้องสนใจ

ปุ่ม "แก้ไข" ข้างล่าง (อยู่นอกกล่อง) ไม่มีป้าย turbo-frame · URL เดียวกัน แต่ป้ายต่างกัน — server จึงตอบต่างกันได้

🏷 เทียบให้เห็นภาพ — ใบสั่งที่ติดป้าย "สำหรับถ้วยหัวข้อ"

พนักงานเสิร์ฟ (Turbo) เดินมาสั่งที่ครัวพร้อมแนบป้ายว่า "สำหรับถ้วย title_post_30" · ครัวเห็นป้ายก็ใช้สูตรจานเล็ก (ฟอร์มช่องเดียว) · ลูกค้าที่เดินมาสั่งเองที่เคาน์เตอร์ (เปิด URL ตรง ๆ ไม่มีป้าย) ได้จานเต็มเหมือนเดิม · ชื่อเมนูเหมือนกัน (/posts/30/edit) แต่ได้คนละจาน

ที่ไม่เหมือนกัน: ในครัวจริง พ่อครัวเห็นป้ายก็รู้เอง · แต่ใน Rails ป้ายแค่วิ่งมาถึง ไม่มีใครเปลี่ยนสูตรให้ · เราต้องเขียนกฎเองใน controller ว่า "เห็นป้ายนี้ → ใช้ไฟล์ไหน" (3 บรรทัดข้างล่าง)

ขั้นที่ 3 — บอก controller ว่า "เห็นป้ายแล้วใช้สูตรจานเล็ก"

เปิด app/controllers/posts_controller.rb · เพิ่มบรรทัดที่ 3 ใต้ before_action :set_post ที่มีอยู่แล้ว:

class PostsController < ApplicationController
  before_action :set_post, only: %i[ show edit update destroy ]
  before_action :set_turbo_frame_variant, only: %i[ edit update ]

แล้วเลื่อนลงไปส่วน private · วาง method ใหม่ใต้ set_post (เหนือ post_params):

  private
    # Use callbacks to share common setup or constraints between actions.
    def set_post
      @post = Post.find(params.expect(:id))
    end

    # คำขอที่มาจาก turbo-frame (กด "แก้ไขหัวข้อ" ในหน้า show) → ใช้ edit.html+turbo_frame.erb
    # เปิด /posts/1/edit ตรง ๆ ไม่มี header Turbo-Frame → ได้ edit.html.erb หน้าเต็มเหมือนเดิม
    def set_turbo_frame_variant
      request.variant = :turbo_frame if turbo_frame_request?
    end
  • before_action :set_turbo_frame_variant, only: %i[ edit update ] — ก่อนเข้า edit (เปิดฟอร์ม) และ update (กดบันทึก) ให้ทำ method นี้ก่อน · %i[ edit update ] = รายการ symbol [:edit, :update] แบบย่อ
  • turbo_frame_request? — helper ของ turbo-rails · ตอบ true ถ้าคำขอมีป้าย Turbo-Frame (เครื่องหมาย ? ท้ายชื่อ = method ที่ตอบใช่/ไม่ใช่ · บท 91)
  • request.variant = :turbo_frame — request = ข้อมูลของคำขอที่เพิ่งเข้ามา (Rails เตรียมให้ใช้ใน controller) · บรรทัดนี้บอก Rails ว่า "คำขอนี้เป็นรุ่นพิเศษชื่อ turbo_frame" · ตอนหา view, Rails จะหาไฟล์ที่มี +turbo_frame ในชื่อก่อน · ไม่เจอ = ใช้ไฟล์ปกติ โดยไม่ error (จำไว้ ใช้ในภารกิจ)
  • … if … ท้ายบรรทัด — ทำข้างหน้าเฉพาะเมื่อเงื่อนไขจริง (Ruby บท 94) · ไม่มีป้าย = ไม่ตั้งอะไร = ใช้ไฟล์ปกติ
  • ใส่ทั้ง edit และ update เพราะตอนบันทึกไม่ผ่าน (หัวข้อว่าง) update จะ render :edit — ต้องได้ฟอร์มเล็กในกล่องเหมือนเดิม ไม่ใช่หน้าเต็ม

สังเกตว่า action edit กับ update ของ scaffold ไม่ต้องแก้สักตัวอักษร · ป้ายกับ before_action ทำงานแทนหมด

ขั้นที่ 4 — ไฟล์ฟอร์มเล็กในกล่อง (edit.html+turbo_frame.erb)

สร้างไฟล์ใหม่ app/views/posts/edit.html+turbo_frame.erb — ระวังชื่อ: +turbo_frame อยู่ระหว่าง .html กับ .erb และต้องสะกดตรงกับ :turbo_frame ใน controller · edit.html.erb ตัวเดิมไม่ต้องแตะ

  • บรรทัด 3 — form_with model: @post → ฟอร์ม PATCH ไป /posts/30 (บท 124) · |form| = ชื่อเรียกฟอร์มนี้ข้างใน block (ชื่อเดียวกับที่ scaffold ใช้) · flex flex-col gap-2 = เรียงของจากบนลงล่าง เว้นช่องเล็กน้อย
  • บรรทัด 4 — form.text_field :title = ช่องพิมพ์หัวข้อ · autofocus: true = ให้เคอร์เซอร์ไปรออยู่ในช่องเอง · aria: { label: "หัวข้อ" } = ป้ายชื่อช่องสำหรับโปรแกรมอ่านหน้าจอของคนตาบอด (เราไม่ใส่ form.label เพราะอยากให้ช่องดูเป็นหัวข้อ)
  • บรรทัด 5 — class: [ "…", { "input-error": เงื่อนไข } ] = คลาสในวงเล็บเหลี่ยม: ตัวแรกใส่เสมอ · ตัวใน { } ใส่เฉพาะเมื่อเงื่อนไขจริง — แบบเดียวกับใน _form.html.erb ของ Lab บท 129 · "input-error": ต้องมีเครื่องหมายคำพูดเพราะชื่อมีขีด - · เงื่อนไข @post.errors[:title].any? = "ช่องหัวข้อมี error อย่างน้อยหนึ่งอันไหม" → มี = ขอบแดง
  • คลาส daisyUI (บท 128): input = ช่องพิมพ์ · input-lg = ขนาดใหญ่ · w-full (Tailwind) = กว้างเต็มแถว
  • บรรทัด 7–9 — full_messages_for(:title) = รายการข้อความ error เฉพาะช่องหัวข้อ (เช่น Title can't be blank) · วนโชว์ทีละบรรทัดด้วยตัวหนังสือสีแดง (text-error)
  • บรรทัด 12 — form.submit "บันทึก" = ปุ่มส่งฟอร์ม · btn-primary = สีหลักของธีม
  • บรรทัด 13 — link_to "ยกเลิก", @post → ลิงก์ไป /posts/30 (หน้า show) · ลิงก์นี้ก็อยู่ในกล่อง Turbo จึงไปหยิบหน้า show มา แล้วเอาแค่กล่อง title_post_30 = หัวข้อกับปุ่ม กลับมาวาง · ไม่ต้องเขียน action ใหม่

ถ้าเจออาการนี้ แปลว่า…

  • Content missing ทั้งที่ id ตรงกันทั้งสองไฟล์ — ชื่อไฟล์ variant ผิด (เช่น edit.html+turboframe.erb) หรือลืม before_action :set_turbo_frame_variant · Rails ไม่ error แต่ไปใช้ edit.html.erb ซึ่งไม่มีกล่อง (ผมลองชื่อไฟล์ผิดแล้ว ได้ Content missing ข้อความเดียวกันเป๊ะ) · ดู log: ถ้าเห็น Rendering posts/edit.html.erb แทน edit.html+turbo_frame.erb = ใช่เลย
  • กดแล้วทั้งหน้าเปลี่ยนไป /posts/30/edit — คุณกดปุ่ม "แก้ไข" ข้างล่าง (อยู่นอกกล่อง) ไม่ใช่ "แก้ไขหัวข้อ"
  • curl ได้หน้ายาว ๆ ไม่มีคำว่า turbo-frame เลย — ลืม -H "Turbo-Frame: title_post_30" · ไม่มีป้าย = ได้หน้าเต็ม (ตรงตามที่ควรเป็น)
  • git diff ยังมีบรรทัดขึ้น — แก้กลับไม่ครบ หรือเว้นวรรคต่างจากเดิม · สั่ง git restore app/views/posts/edit.html+turbo_frame.erb ได้เลย

กด "แก้ไขหัวข้อ" แล้วในกล่องขึ้นคำว่า Content missing · log ของ server ขึ้น Completed 200 OK · สาเหตุที่น่าจะเป็นที่สุดคืออะไร?

ตัวเลือกที่ 3 ถูก — server ตอบสำเร็จ (200) แต่ในคำตอบไม่มี <turbo-frame> id ที่หน้ารออยู่ · Turbo จึงไม่วางอะไรและเขียน Content missing ไว้ในกล่อง

ตัวเลือกที่ 1 ผิด เพราะ log บอก 200 OK ชัด ๆ · ถ้า server พังจะเป็น 500 · ตัวเลือกที่ 2 ผิด เพราะถ้า Turbo ยังไม่ทำงาน ลิงก์จะพาไปหน้า edit เต็ม (progressive enhancement) ไม่ใช่ขึ้น Content missing · ตัวเลือกที่ 4 ผิด เพราะบทความที่ไม่มีจริงจะได้ 404 ไม่ใช่ 200

จุดที่ต้องจำ: Content missing + 200 OK = id สองฝั่งไม่ตรง · เทียบ id ใน Console กับ id ที่ curl … | grep turbo-frame เห็น

ปุ่ม "แก้ไขหัวข้อ" (ในกล่อง) กับปุ่ม "แก้ไข" ข้างล่าง (นอกกล่อง) ลิงก์ไป /posts/30/edit เหมือนกัน · ทำไมได้ผลต่างกัน?

ตัวเลือกที่ 1 ถูก — Turbo แนบ header Turbo-Frame: title_post_30 เฉพาะคำขอที่เกิดในกล่อง · turbo_frame_request? เป็นจริง → variant → edit.html+turbo_frame.erb

ตัวเลือกที่ 2 ผิด เพราะทั้งคู่เข้า action edit เดิม (log เขียน PostsController#edit ทั้งสองครั้ง) · Turbo ไม่สร้าง action ให้ · ตัวเลือกที่ 3 ผิด เพราะลิงก์นอกกล่องก็ยังใช้ Turbo Drive ตามปกติ แค่เปลี่ยนทั้งหน้า · ตัวเลือกที่ 4 ผิด เพราะ log แสดงว่ามีคำขอไปถึง server จริงทั้งสองแบบ และได้คนละไฟล์

จุดที่ต้องจำ: URL เดียวกัน แต่ "อยู่ในกล่องหรือไม่" ทำให้ป้ายต่างกัน → server ตอบต่างกันได้

แก้หัวข้อในกล่องสำเร็จ หัวข้อใหม่โผล่แล้ว · แต่ breadcrumb ข้างบนยังเป็นชื่อเก่า และไม่มีข้อความ "บันทึกการแก้ไขแล้ว" · ข้อไหนอธิบายถูก?

ตัวเลือกที่ 4 ถูก — Turbo เอาแค่ข้างในกล่อง title_post_30 มาวาง · ส่วนอื่นของคำตอบทิ้งหมด รวมทั้ง breadcrumb กับข้อความ notice

ตัวเลือกที่ 1 ผิด เพราะ log มี Post Update … UPDATE "posts" แล้ว · รีเฟรชก็เห็นชื่อใหม่ทุกที่ · ตัวเลือกที่ 2 ผิด เพราะ breadcrumb ใช้ @post.title คอลัมน์เดียวกัน · แค่ไม่ได้ถูกวาดใหม่ · ตัวเลือกที่ 3 ผิด เพราะไม่เกี่ยวกับ cache — breadcrumb ไม่เคยถูกขอใหม่เลยตั้งแต่แรก

จุดที่ต้องจำ: Frame = เปลี่ยนกล่องเดียว · อยากให้หลายจุดเปลี่ยนพร้อมกัน → Turbo Streams (บท 132)

ในฟอร์มเล็กในกล่อง อยากมีลิงก์ "เปิดฟอร์มเต็ม" ที่พาไปหน้า /posts/30/edit แบบทั้งหน้า · ต้องทำอย่างไร?

ตัวเลือกที่ 2 ถูก — data-turbo-frame="_top" บอก Turbo ว่าลิงก์นี้เปลี่ยนทั้งหน้า · ผลจริง: URL ไป /posts/30/edit ได้ฟอร์มสามช่อง

ตัวเลือกที่ 1 ผิด เพราะ loading: "lazy" เป็นเรื่องของกล่องที่โหลดเนื้อหาเองทีหลัง ไม่เกี่ยวกับลิงก์ · ตัวเลือกที่ 3 ผิด เพราะลิงก์จะยังอยู่ในกล่อง (กล่องใหม่) ก็ยังไม่เปลี่ยนทั้งหน้า และคำตอบต้องมีกล่อง id นั้นด้วย · ตัวเลือกที่ 4 ผิด เพราะทำให้ปุ่ม "แก้ไขหัวข้อ" พังทั้งหมด — ได้ Content missing (ไม่มีไฟล์ไหนตอบกล่องกลับมา)

จุดที่ต้องจำ: ลิงก์ในกล่อง = เปลี่ยนในกล่องเสมอ · อยากหนีออกทั้งหน้า → _top
