layout, partial และ locals — แม่พิมพ์ที่ใช้ซ้ำได้

~20 นาที · ควรผ่าน บทเรียน 122 (ERB) และ บท 120 (เปิดโปรเจกต์) มาก่อน · ใช้ของจาก บท 103 (layout) และ บท 118 (partial ที่ scaffold สร้าง) ด้วย

หน้าเว็บทุกหน้าของเรามีส่วนที่ซ้ำกัน — หัวเว็บเหมือนกันทุกหน้า · กล่องบทความหน้าตาเดียวกันทั้งในหน้ารายการและหน้าบทความ
บทนี้คุณจะอ่าน layout ของจริงในโปรเจกต์ออกทุกบรรทัด · ตั้งชื่อแท็บเบราว์เซอร์ให้แต่ละบทความได้ · เข้าใจว่า render @posts บรรทัดเดียวทำอะไรให้บ้าง · และรู้ว่าทำไมชิ้นส่วนที่ใช้ซ้ำ (partial) ควรรับของผ่านมือ ไม่ใช่ไปหยิบ @ตัวแปร เอง

🔁 ทวนก่อนเริ่ม — คำพวกนี้จะโผล่ในบทนี้ทั้งหมด

  • layout · <%= yield %> (บท 103) — จานรองลายเดียวกันที่ครอบทุกหน้า · yield คือช่องกลางจานที่ view ของแต่ละหน้าถูกวางลงไป
  • <%= %> กับ <% %> · <%# %> (บท 122) — เติมแล้ววางบนจาน · ทำในครัวเงียบ ๆ ไม่ขึ้นจาน · คอมเมนต์
  • @post (บท 102) — ของที่หัวหน้าเชฟ (controller) วางไว้บนถาดหน้าครัวให้คนจัดจาน (view) หยิบ · ถ้าไม่มีใครวาง = nil
  • partial · render "form", post: @post (บท 118) — ไฟล์ view ชื่อขึ้นต้นด้วย _ ที่ใช้ซ้ำได้ · หน้า new กับ edit เรียกฟอร์มชิ้นเดียวกัน
  • props (บท 71) — ของที่ยื่นเข้าไปให้ component ตอนเรียก เช่น <Button disabled> · และ keyword argument (บท 93) — ส่งของโดยบอกชื่อช่อง make_post(title: "…")

1 · layout ของจริงในโปรเจกต์ — จานรองที่ยังไม่มีโลโก้ร้าน

ทวนสั้น ๆ: layout คือไฟล์ที่ครอบทุกหน้าให้อัตโนมัติ · ของที่ทุกหน้าต้องมี (หัวเว็บ · CSS · JavaScript) เขียนไว้ที่เดียว · ส่วนเนื้อหาของแต่ละหน้าถูกวางลงตรง <%= yield %>

สังเกตว่ายังไม่มีแถบเมนูด้านบน (navbar) และส่วนท้าย (footer) — layout นี้มาจาก rails new ตรง ๆ · เราจะเติม navbar ใน Lab บท 129

ป้ายบอกว่า HTML ก้อนไหนมาจากไฟล์ไหน

โปรเจกต์นี้เปิดตัวช่วยไว้ตัวหนึ่ง (บรรทัด config.action_view.annotate_rendered_view_with_filenames = true ใน config/environments/development.rb) · มันแปะคอมเมนต์ HTML (<!-- … --> ข้อความที่เบราว์เซอร์ไม่แสดง) บอกต้นและท้ายของแต่ละไฟล์ · ลองดึงหน้าบทความแรกแล้วกรองเอาเฉพาะป้ายพวกนี้: 

$ curl -s localhost:3000/posts/1 | grep -E "BEGIN|END"
<!-- BEGIN app/views/layouts/application.html.erb
      <!-- BEGIN app/views/posts/show.html.erb
  <!-- BEGIN app/views/posts/_post.html.erb
<!-- END app/views/posts/_post.html.erb -->
<!-- END app/views/posts/show.html.erb -->
<!-- END app/views/layouts/application.html.erb -->
  • curl -s = ขอหน้าเว็บแบบเงียบ ๆ (ไม่โชว์แถบความคืบหน้า) · | grep -E "BEGIN|END" = เลือกเฉพาะบรรทัดที่มีคำว่า BEGIN หรือ END
  • ป้าย BEGIN ไม่มี --> ปิดท้าย เพราะ Rails ไปปิดไว้บรรทัดถัดไป · grep เลือกมาแค่บรรทัดที่มีคำว่า BEGIN จึงไม่เห็นตัวปิด
  • หนึ่งหน้าเว็บประกอบจากสามไฟล์ซ้อนกัน: layout ครอบ show.html.erb และในนั้นยังมี _post.html.erb อีกชั้น
  • ป้ายนี้โผล่เฉพาะตอนพัฒนาในเครื่อง · ใช้มันได้ทั้งบทเวลาสงสัยว่า "ข้อความตรงนี้มาจากไฟล์ไหน"

มี layout ได้หลายอัน (แค่รู้จักไว้): ถ้าวันหนึ่งหน้าผู้ดูแลระบบต้องหน้าตาต่างจากหน้าผู้อ่าน · เขียน layout "admin" ไว้ใน controller ตัวนั้น แล้ว Rails จะใช้ไฟล์ app/views/layouts/admin.html.erb เป็นจานรองแทน · controller อื่นยังใช้ application เหมือนเดิม · โปรเจกต์เราตอนนี้มีอันเดียว 

# app/controllers/admin_controller.rb (ตัวอย่างจากสไลด์หน้า 12 · โปรเจกต์เรายังไม่มีไฟล์นี้)
class AdminController < ApplicationController
  layout "admin"
end

2 · content_for — ฝากป้ายชื่อเมนูขึ้นไปติดหัวจานรอง

ของในไฟล์ show.html.erb ถูกวางลงตรง yield ซึ่งอยู่ใน <body> · แต่ชื่อแท็บเบราว์เซอร์ (<title>) อยู่ใน <head> ข้างบนโน่น · หน้า show จะส่งชื่อบทความขึ้นไปตรงนั้นได้ยังไง?

คำตอบคือ content_for = ฝากของใส่กล่องที่ติดชื่อไว้ · view เขียน "ฝากใส่กล่องชื่อ :title" · layout เขียน "ตรงนี้เอาของในกล่อง :title มาวาง" · ทำแบบนี้ได้เพราะ Rails จัด view ให้เสร็จก่อน แล้วค่อยเอาไปวางในจานรอง — ตอน layout ทำงาน กล่องมีของรออยู่แล้ว

ลำดับนี้เห็นได้จริงใน log ของ server (หน้าต่างที่รัน bin/dev หรือไฟล์ log/development.log) · ตัวอย่างนี้มาจากตอนเปิดหน้า /posts:

  Rendered posts/index.html.erb within layouts/application (Duration: 9.6ms | GC: 4.2ms)
  Rendered layout layouts/application.html.erb (Duration: 10.6ms | GC: 4.2ms)

บรรทัดแรก = "จัด index เสร็จแล้ว (เพื่อวางใน layout application)" · บรรทัดที่สอง = "จัดจานรองเสร็จ" — view มาก่อนเสมอ · ตัวเลขในวงเล็บคือเวลาที่ใช้ (GC = เวลาที่ Ruby เก็บกวาดหน่วยความจำ) ไม่ต้องสน

ลองจริง: ให้แท็บเบราว์เซอร์ขึ้นชื่อบทความ

scaffold ตั้งชื่อหน้าไว้ให้แล้วในบรรทัดแรกของ app/views/posts/show.html.erb · ดูผลก่อนแก้:

<% content_for :title, "Showing post" %>
$ curl -s localhost:3000/posts/1 | grep '<title>'
    <title>Showing post</title>

ทุกบทความได้ชื่อแท็บว่า "Showing post" เหมือนกันหมด · เปิด 5 แท็บก็แยกไม่ออกว่าแท็บไหนบทความอะไร · แก้บรรทัดนั้น (แทนที่ ไม่ใช่เพิ่มบรรทัดใหม่) ให้เป็น: 

<% content_for :title, @post.title %>
  • <% %> ไม่มี = — เพราะเราไม่ได้อยากให้ชื่อโผล่ตรงนี้ในเนื้อหน้า แค่ฝากไว้ (บท 122: ทำในครัวเงียบ ๆ ไม่ขึ้นจาน)
  • content_for :title, … = "ฝากของชิ้นนี้ใส่กล่องชื่อ :title" (:title คือ symbol · บท 92)
  • @post.title = ชื่อบทความที่ controller วางไว้บนถาด
$ curl -s localhost:3000/posts/1 | grep '<title>'
    <title>ต้มยำกุ้งน้ำข้น</title>

$ curl -s localhost:3000/posts/2 | grep '<title>'
    <title>ก๋วยเตี๋ยวเรืออยุธยา</title>

ฝั่ง layout บรรทัด 4 content_for(:title) || "Wongnok Blog All In One" คือการเปิดกล่องดู · มีของก็ใช้ · กล่องว่างก็ได้ nil แล้ว || หยิบชื่อแอปมาแทน (ผมลองลบบรรทัด content_for ทิ้ง ได้ <title>Wongnok Blog All In One</title> จริง)

⚠️ ถ้าเพิ่มบรรทัดใหม่ใต้บรรทัดเดิมแทนที่จะแก้ — content_for ไม่ได้เขียนทับ แต่ต่อท้ายของที่อยู่ในกล่องอยู่แล้ว · ผมลองมีสองบรรทัด ("Showing post" แล้วตามด้วย @post.title) ได้ <title>Showing postต้มยำกุ้งน้ำข้น</title> · หนึ่งหน้าควรมี content_for :title บรรทัดเดียว

ฝากของที่ยาวกว่าหนึ่งบรรทัด — content_for :head do … end

บรรทัด 12 ของ layout (<%= yield :head %>) คือกล่องอีกใบชื่อ :head · ใช้ฝาก <meta> ที่อยากให้มีเฉพาะบางหน้า · เช่น <meta name="description"> = คำโปรยสั้น ๆ ที่ Google หรือแอปแชตเอาไปโชว์ใต้ลิงก์ · เติมต่อจากบรรทัด title ในไฟล์ show.html.erb: 

<% content_for :title, @post.title %>
<% content_for :head do %>
  <meta name="description" content="<%= @post.description %>">
<% end %>
  • content_for :head do … end = ฝากของทั้งก้อนระหว่าง do กับ end (block · บท 93) · ใช้เมื่อของที่ฝากเป็น HTML หลายบรรทัด
  • <%= @post.description %> ข้างใน = เติมคำบรรยายลงในช่อง content="…" ก่อนฝาก
$ curl -s localhost:3000/posts/1 | grep -B3 'name="description"'
<meta name="csrf-token" content="0C_BIl1dCpfY4FWzXI23fn7TsfMv_5doRL0Hpn9qXuxYmswNS4dyO4l6KLVki1UAdhJBxrJyZqUAYTWzZu-V5g" />


      <meta name="description" content="ต้มยำกุ้งแบบน้ำข้นใส่นมข้นจืด รสเปรี้ยวเผ็ดกลมกล่อม กุ้งแม่น้ำตัวใหญ่ หอมตะไคร้ ข่า ใบมะกรูด กินกับข้าวสวยร้อน ๆ ได้ทั้งถ้วย ร้านนี้เปิดมาสามสิบปีแล้ว คิวยาวทุกวันเสาร์อาทิตย์">
  • grep -B3 = โชว์บรรทัดที่เจอ พร้อม 3 บรรทัดก่อนหน้า (B = before) — จะได้เห็นว่ามันไปอยู่ตรงไหน
  • บรรทัดแรกคือ csrf-token ที่ csrf_meta_tags (บรรทัด 9) พิมพ์ออกมา · บรรทัดว่างสองบรรทัดคือ csp_meta_tag ที่ไม่พิมพ์อะไร กับบรรทัด 11 ที่ว่างอยู่แล้ว · แล้วถึง meta ของเรา = ตำแหน่งของ yield :head (บรรทัด 12) พอดี
  • <meta> ไม่โผล่บนหน้าเว็บ (มันอยู่ใน head) · หน้า /posts ไม่ได้ฝากอะไรไว้ กล่อง :head ของหน้านั้นจึงว่าง
🏷 เทียบให้เห็นภาพ — ป้ายชื่อเมนูที่ส่งขึ้นไปติดหัวจานรอง

คนจัดจานจัดอาหารของเมนูนี้ (view) เสร็จก่อน แล้วเขียนป้ายชื่อเมนูใส่ช่องฝากของที่ติดชื่อ "title" ไว้ · ตอนวางลงจานรอง (layout) จานรองมีช่องเสียบป้ายอยู่ที่หัวจาน มันหยิบป้ายจากช่อง "title" มาเสียบ · ไม่มีป้ายก็ใช้ป้ายชื่อร้านแทน · ช่องตรงกลางจาน (yield เฉย ๆ) ยังเป็นที่วางอาหารหลักเหมือนเดิม

ที่ไม่เหมือนกัน: ป้ายจริงเสียบใหม่ก็ทับป้ายเก่า · content_for ต่อป้ายใหม่ท้ายป้ายเก่า (ได้ "Showing postต้มยำกุ้งน้ำข้น") · และช่องฝากไม่ได้มีแค่ title — ตั้งชื่อช่องอะไรก็ได้ (:head · :sidebar …) ขอแค่ layout มี yield ชื่อเดียวกันรออยู่ ไม่งั้นของที่ฝากไว้ก็ไม่ได้ขึ้นจาน

เทียบกับ Next.js: ใน บท 83 เราเห็น export const metadata ใน app/layout.tsx — ที่ตั้งชื่อหน้าของ Next.js (เป็น object) · content_for :title คืองานเดียวกันฝั่ง Rails แต่ใช้วิธี "ฝากใส่กล่อง": หน้าลูกเป็นคนบอกชื่อ · layout เป็นคนวาง

🗣 ศัพท์ที่เพิ่งเรียนไป
content_for · named yield (yield :head)
content_for :ชื่อ, ของ หรือ content_for :ชื่อ do … end = ฝากของ · yield :ชื่อ หรือ content_for(:ชื่อ) ใน layout = เอาของออกมาวาง · พิมพ์บอก AI ได้ว่า "set the page title with content_for :title in show.html.erb, don't hardcode it in the layout"
layout ของ controller (layout "admin")
เลือกจานรองคนละแบบให้ controller บางตัว · ไฟล์อยู่ที่ app/views/layouts/ชื่อ.html.erb · ถาม senior ได้ว่า "หน้า admin ควรแยก layout หรือแค่ซ่อนเมนูใน layout เดิม"

3 · partial — แม่พิมพ์ที่ scaffold ทำไว้ให้แล้ว

partial คือไฟล์ view ชิ้นเล็กที่ชื่อขึ้นต้นด้วย _ · ไม่เคยถูกเปิดเป็นหน้าเดี่ยว ๆ ต้องมีไฟล์อื่นเรียกใช้เสมอ · มีไว้ให้ของที่หน้าตาเหมือนกันหลายที่ (กล่องบทความหนึ่งชิ้น · ฟอร์ม) เขียนครั้งเดียว · แก้ที่เดียวเปลี่ยนทุกที่

scaffold สร้าง partial ของบทความไว้แล้ว · เปิดไฟล์ app/views/posts/_post.html.erb ของจริง:

<div id="<%= dom_id post %>" class="w-full sm:w-auto my-5 space-y-5">
  <div>
    <strong class="block font-medium mb-1">Title:</strong>
    <%= post.title %>
  </div>
  <div>
    <strong class="block font-medium mb-1">Description:</strong>
    <%= post.description %>
  </div>
  <div>
    <strong class="block font-medium mb-1">Category:</strong>
    <%= post.category_id %>
  </div>
</div>
  • post (ไม่มี @) = บทความหนึ่งชิ้นที่ "ถูกยื่นเข้ามา" ตอนเรียก partial · เรียกว่า local (ตัวแปรเฉพาะในไฟล์นี้) · หัวข้อ 5 จะอธิบายว่าทำไมต้องไม่มี @
  • dom_id post = helper สร้าง id ให้กล่อง เช่น post_1 (ป้ายเลขถ้วย — ได้ใช้จริงในบท 131)
  • post.category_id = โชว์เลขหมวด (เช่น 1) ไม่ใช่ชื่อหมวด — scaffold ไม่รู้ว่าเราอยากเห็นอะไร · ภารกิจท้ายบทจะลองเปลี่ยน
  • class ยาว ๆ เป็น Tailwind (บท 72) — เรื่องหน้าตา ข้ามไปก่อนได้ (บท 128 ว่ากันละเอียด)

แล้วใครเรียกมัน? เปิดสองไฟล์นี้ดู (ตัดมาเฉพาะบรรทัดที่เกี่ยว):

<%# app/views/posts/show.html.erb (บรรทัด 10) %>
<%= render @post %>

<%# app/views/posts/index.html.erb (บรรทัด 15–17 · ในลูปที่วนทีละบทความ) %>
<% @posts.each do |post| %>
  …
    <%= render post %>

ทั้งสองที่ไม่ได้บอกชื่อไฟล์เลย · Rails ดูจากของที่ส่งให้: "นี่คือ object ของ class Post → ไฟล์ต้องชื่อ posts/_post.html.erb → ยื่นของชิ้นนี้เข้าไปในชื่อ post" · นี่คือเหตุผลที่ไฟล์ต้องชื่อ _post เป๊ะ ๆ

🍚 เทียบให้เห็นภาพ — แม่พิมพ์ตักข้าว / ถ้วยน้ำจิ้มมาตรฐาน

ร้านมีแม่พิมพ์ตักข้าวอันเดียว ใช้กับทุกจานที่มีข้าว — ข้าวกะเพรา ข้าวมันไก่ ได้ข้าวทรงเดียวกันหมด · partial _post คือแม่พิมพ์ "กล่องบทความหนึ่งชิ้น" ที่ทั้งหน้ารายการ (30 ครั้ง) และหน้าบทความ (1 ครั้ง) ใช้ร่วมกัน · อยากเปลี่ยนทรง → แก้แม่พิมพ์อันเดียว ทุกจานเปลี่ยนตาม

ที่ไม่เหมือนกัน: แม่พิมพ์จริงไม่สนว่าตักข้าวหอมมะลิหรือข้าวกล้อง · partial ที่เรียกแบบสั้น (render @post) ถูกเลือกจากชนิดของของ — ยื่นบทความ ได้แม่พิมพ์ _post · ยื่นหมวด ได้ _category · ชื่อไฟล์ผิดแม้ตัวเดียว Rails ก็หาไม่เจอ

เทียบกับ React: partial ≈ component (บท 71) · <%= render post %> ≈ <PostCard post={post} /> · ต่างกันที่ React ต้องเขียนชื่อ component เสมอ ส่วน Rails เดาชื่อไฟล์จาก class ของ object ได้

4 · render @posts — บรรทัดเดียวที่ Rails เดาให้ 4 อย่าง

หน้ารายการใน scaffold เขียนลูป each เอง เพราะต้องวางปุ่ม Show/Edit/Destroy ข้างแต่ละบทความ · แต่ถ้าแค่อยากวางกล่องบทความเรียงกัน มีวิธีเขียนแบบยาวกับแบบสั้นที่ได้ผลเหมือนกัน

ทดลอง: ลบทุกอย่างใน app/views/posts/index.html.erb แล้วใส่แบบยาวแทน (ปุ่มต่าง ๆ จะหายไปชั่วคราว จบบทเรา git restore คืน):

แบบยาว — วนเอง ยื่นของเอง

<% @posts.each do |post| %>
  <%= render "post", post: post %>
<% end %>

แบบสั้น — Rails เดาให้หมด

<%= render @posts %>
  • render "post", post: post = "ใช้แม่พิมพ์ชื่อ post (ไฟล์ _post · ไม่ต้องพิมพ์ขีดล่าง) แล้วยื่น post ของรอบนี้เข้าไปในชื่อ post" · post: post คือ keyword argument (บท 93) — ซ้ายคือชื่อช่องในแม่พิมพ์ · ขวาคือของที่ยื่น
  • render @posts = ยื่นบทความทั้งรายการให้ทีเดียว

ภาพในร้าน: แบบยาว = คนจัดจานหยิบแม่พิมพ์ตักข้าวทีละจาน บอกทุกรอบว่า "จานนี้นะ" · แบบสั้น = ยื่นถาดทั้ง 30 จานให้แล้วบอกคำเดียวว่า "ตักให้ทุกจาน" — Rails รู้เองว่าต้องใช้แม่พิมพ์ไหน

ใส่แบบยาวก่อน แล้วสั่งคำสั่งข้างล่าง · จากนั้นเปลี่ยนเป็นแบบสั้น แล้วสั่งซ้ำ · ทุกกล่องมีบรรทัด id="post_…" หนึ่งบรรทัด (มาจาก dom_id ในแม่พิมพ์) · grep -c = นับจำนวนบรรทัดที่เจอ:

ที่ไม่เหมือนกัน: แม่พิมพ์จริงหาของไม่เจอก็รู้ตัวและหยุด · partial ไม่ได้ฟ้องว่า "ไม่มี @post" · มันได้ nil แล้วทำต่อจนไปพังที่ .title · ถ้าบรรทัดนั้นแค่ <%= @post %> เฉย ๆ จะได้ช่องว่างเงียบ ๆ ไม่มี error ให้เห็นเลย
