ทำไมต้องสะอาด: ตอนท้าย Lab เราจะ git commit ทั้งหมดเป็นก้อนเดียว · ถ้ามีของทดลองค้างจากบทก่อนจะปนเข้าไปด้วย · ถ้ายังมีของค้าง ให้ git restore . (คืนไฟล์ที่แก้) แล้ว git status --short อีกรอบ

เปิด http://localhost:3000/posts ดูของเดิมก่อน · แต่ละชิ้นจะมีบรรทัด Category: ตามด้วยเลข เช่น 1 · แล้วดู log ของ request นั้น (ไฟล์ log/development.log หรือหน้าจอแท็บที่ 1) — ผลจริง ตัดมาแค่บรรทัดที่ไปตู้: 

  Post Load (2.4ms)  SELECT "posts".* FROM "posts" /*action='index',application='WongnokBlogAllInOne',controller='posts'*/

อ่านบรรทัดนี้: Post Load = "ไปหยิบบทความจากตู้" · (2.4ms) = ใช้เวลาเท่าไหร่ (ของคุณจะต่าง) · ก้อน /*action='index',…*/ ท้ายบรรทัดคือคอมเมนต์ที่ Rails แปะบอกว่า SQL นี้มาจาก action ไหน — ไม่ต้องสนใจ ต่อจากนี้จะย่อเป็น /*…*/

ไม่มี LIMIT = หยิบทุกแฟ้มในลิ้นชัก มาจัดจานพร้อมกัน · ตอนนี้ 30 ชิ้นยังไม่เป็นไร แต่ถ้าวันหนึ่งมี 30,000 ชิ้น หน้านี้จะช้าจนใช้ไม่ได้ — นี่คือกฎข้อ 6 ใน prompts/00-context.md ("index action ต้องมี limit หรือ pagination") ที่ scaffold ไม่รู้ (บท 121)

ขั้น 1 — ติดตั้ง pagy: ตัวช่วยแบ่งรายการเป็นหน้า ๆ

pagination คือการแบ่งรายการยาว ๆ เป็นหน้า ๆ — หน้า 1 โชว์ชิ้นที่ 1–10 · หน้า 2 โชว์ 11–20 · มีปุ่ม "ถัดไป / ก่อนหน้า" · ใน SQL ทำด้วยสองคำ: LIMIT 10 (เอาแค่ 10 แผ่น) กับ OFFSET 10 (ข้าม 10 แผ่นแรกก่อน)

แล้วทำไมไม่เขียน Post.limit(10).offset(...) เอง? เพราะของที่ต้องคิดเพิ่มเยอะกว่าที่เห็น: ผู้ใช้พิมพ์ ?page=0 · ?page=abc · ?page=99 มาจะเป็นยังไง · ทั้งหมดมีกี่หน้า · หน้าสุดท้ายต้องซ่อนปุ่ม "ถัดไป" · ลิงก์ของแต่ละปุ่มต้องเป็น URL อะไร · สไลด์หน้า 22 จัด "ทำ pagination เองด้วย offset แทนที่จะใช้ gem" ไว้ในรายการที่ AI พลาดประจำ
gem คือแพ็กเกจโค้ดสำเร็จรูปของ Ruby ที่คนอื่นเขียนและทดสอบมาแล้ว (เหมือน module ของ Go ที่ go get มา) · ตัวที่เราใช้ชื่อ pagy

🍽 เทียบให้เห็นภาพ — หยิบแฟ้มจากตู้ทีละปึก

ลิ้นชัก posts มีแฟ้ม 30 แผ่น · ถ้าหยิบมาวางบนจานทีเดียวทั้งหมด จานล้น ลูกค้าอ่านไม่ไหว (และถ้ามี 30,000 แผ่น คนหยิบก็หมดแรง) · pagy คือผู้ช่วยที่หยิบทีละปึก: ก่อนอื่นนับว่ามีกี่แผ่น (จะได้บอกว่า "มีทั้งหมด 3 ปึก") แล้วหยิบมาเฉพาะปึกที่ลูกค้าขอ ปึกละ 10 แผ่น — เหมือนผลค้นหาสินค้าในแอปช้อปปิ้งที่มีเลขหน้า 1 2 3 ด้านล่าง · ลูกค้าขอปึกที่ 99 ก็ไม่โวยวาย แค่ให้จานว่างพร้อมบอกทางกลับ

ที่ไม่เหมือนกัน: คนจริงนับครั้งเดียวแล้วจำได้ · pagy ไม่จำอะไรข้ามคำขอเลย — ทุกครั้งที่ลูกค้าเปิดหน้าใหม่ มันไปนับใหม่ + หยิบใหม่จากตู้ (นั่นคือที่มาของ query COUNT ที่จะเห็นใน log ทุกหน้า)

สั่งติดตั้ง (ผลจริง):

$ bundle add pagy --version "~> 43.5"
Fetching gem metadata from https://rubygems.org/........
Resolving dependencies...
  • bundle add pagy — "เพิ่ม gem ชื่อ pagy ลงโปรเจกต์" · มันเขียนบรรทัดใหม่ลง Gemfile แล้วติดตั้งให้
  • --version "~> 43.5" — ขอรุ่น 43.5 ขึ้นไป แต่ไม่ข้ามไป 44 · ~> อ่านว่า "ประมาณ" (ใน Go คือ go.mod ที่ล็อกรุ่นหลักไว้)
  • เครื่องผมมี pagy อยู่แล้วเลยขึ้นแค่สองบรรทัด · เครื่องที่ยังไม่เคยมีจะเห็นบรรทัดดาวน์โหลดและติดตั้งเพิ่ม — ปกติ

ดูสิ่งที่เปลี่ยน — ท้าย Gemfile มีสองบรรทัดใหม่ (บรรทัดว่าง + บรรทัดนี้):

gem "pagy", "~> 43.5"

และ Gemfile.lock (สมุดจดว่า "ติดตั้งรุ่นไหนไปจริง ๆ") ได้ pagy (43.8.1) กับ yaml (0.4.0) ที่ pagy ต้องใช้ · ถ้าของคุณได้ 43.x ที่ใหม่กว่า ไม่เป็นไร โค้ดในบทนี้ใช้ได้เหมือนกัน

⚠️ ติดตั้ง gem แล้วต้องปิดร้านแล้วเปิดใหม่ — ไปแท็บที่ 1 กด Ctrl+C แล้ว bin/dev อีกรอบ · Rails โหลด gem แค่ตอนเปิดร้าน · ถ้าไม่ restart ขั้นต่อไปจะเจอหน้าแดง NameError (uninitialized constant ApplicationController::Pagy) (ผลจริง)

ขั้น 2 — controller: หยิบทีละ 10 ชิ้น เรียงใหม่ไปเก่า พร้อมหมวด

ก่อนใช้ pagy(...) ใน controller ได้ ต้อง "สอน" controller ให้รู้จักมันก่อน · ทำที่ app/controllers/application_controller.rb (แม่ของทุก controller — ใส่ที่นี่ทีเดียว ทุกแผนกได้ใช้) · ไฟล์ทั้งไฟล์หลังแก้: 

class ApplicationController < ActionController::Base
  include Pagy::Method

  # Only allow modern browsers supporting webp images, web push, badges, import maps, CSS nesting, and CSS :has.
  allow_browser versions: :modern

  # Changes to the importmap will invalidate the etag for HTML responses
  stale_when_importmap_changes
end
  • เพิ่มแค่บรรทัดที่ 2 กับบรรทัดว่างใต้มัน · include Pagy::Method = "เอาความสามารถใน module Pagy::Method มาใส่ class นี้" (module ของ Ruby · บท 95) → ทุก controller เรียก pagy(...) ได้
  • บรรทัด 4–8 เป็นของเดิมที่ rails new ใส่ไว้ ไม่ต้องแตะ · allow_browser = รับเฉพาะเบราว์เซอร์รุ่นใหม่ · stale_when_importmap_changes เกี่ยวกับไฟล์ JavaScript (เรื่อง importmap อยู่บท 127)

⚠️ tutorial บนเน็ตส่วนใหญ่เขียนสำหรับ pagy รุ่นเก่า — ถ้าเจอ include Pagy::Backend อย่าพิมพ์ตาม · รุ่น 43 ไม่มีแล้ว ผลจริงเมื่อลองใส่: หน้าแดง NameError (uninitialized constant Pagy::Backend) · ส่วน items: 10 (ชื่อเก่าของ limit:) แย่กว่า — ไม่ error เลย แค่เงียบ ๆ ได้หน้าละ 20 ชิ้น "หน้า 1 / 2" (ผลจริง)

ต่อไปที่ app/controllers/posts_controller.rb · ใน action index ของเดิมมีบรรทัดเดียวคือ @posts = Post.all · เปลี่ยนเป็นแบบนี้:

  # GET /posts or /posts.json
  def index
    @pagy, @posts = pagy(Post.includes(:category).recent, limit: 10)
  end

อ่านจากในออกนอก:

  • Post.includes(:category) — "ตอนหยิบบทความ หยิบหมวดของมันมาทั้งตะกร้าด้วย" (บท 114) · ต้องมีเพราะขั้น 3 เราจะโชว์ชื่อหมวด
  • .recent — scope ที่มีอยู่แล้วใน model: scope :recent, -> { order(created_at: :desc) } = เรียงจากใหม่ไปเก่า (-> { } = lambda ก้อนโค้ดที่เก็บไว้รันทีหลัง · บท 115)
  • pagy(…, limit: 10) — ส่งใบเบิก (ที่ยังไม่ยื่น) ให้ pagy · pagy อ่าน ?page= จาก URL เอง แล้วคืนของสองชิ้น: ข้อมูลของการแบ่งหน้า (หน้าไหน · ทั้งหมดกี่หน้า) กับบทความ 10 ชิ้นของหน้านั้น
  • @pagy, @posts = … — Ruby รับของสองชิ้นใส่สองตัวแปรในบรรทัดเดียว (เหมือน a, b := f() ของ Go) · ทั้งคู่ขึ้นต้นด้วย @ = วางบนถาดหน้าครัวให้ view หยิบ

  • บรรทัด 2 <article id="<%= dom_id post %>"> — dom_id สร้าง id ให้ทุกชิ้นไม่ซ้ำกัน เช่น post_30 (Day 3 ช่วง Hotwire บท 131 จะใช้ id นี้) · <article> = แท็ก HTML ของ "เนื้อหาหนึ่งชิ้น"

  • บรรทัด 8–10 แบบเต็ม — หัวข้อเป็น <h1> · whitespace-pre-line = คลาส Tailwind ที่ให้การขึ้นบรรทัดใหม่ในข้อความโชว์เป็นบรรทัดใหม่จริง
  • บรรทัด 13 link_to post.title, post — ส่ง object ไปตรง ๆ Rails เดา URL ให้เป็น /posts/30 (บท 103) · ไม่ต้องเขียน "/posts/#{post.id}" เอง
  • บรรทัด 15 truncate(…, length: 80, separator: " ") — ตัดเหลือไม่เกิน 80 ตัวอักษร (รวม ...) และตัดที่ช่องว่างเท่านั้น · ดูเหตุผลด้านล่าง
  • คลาสที่เหลือคือ Tailwind (บท 72) อ่านออกเสียงได้: py-5 เว้นบนล่าง · mt-2 เว้นด้านบน · leading-relaxed ระยะห่างระหว่างบรรทัดมากขึ้น · border-b border-gray-200 เส้นเทาอ่อนด้านล่าง · text-sm text-gray-500 ตัวเล็กสีเทา · text-xl font-semibold ตัวใหญ่หนา · hover:underline ขีดเส้นใต้ตอนเอาเมาส์ชี้

ทำไมต้องมี separator: " " (ทวนบท 124) — ภาษาไทยมีสระกับวรรณยุกต์ที่ "ลอย" อยู่บนล่างตัวอักษร และนับเป็นตัวอักษรแยก · ถ้าตัดตรงกลางคำ อาจได้คำที่วรรณยุกต์หาย · ผลจริงกับ "ข้าวเหนียวมะม่วง" (bin/rails runner · ข้อความยาว 98 ตัวอักษร · … หน้าผลคือเราตัดส่วนต้นออกให้เห็นแค่ท้ายที่ถูกตัด): 

description[0..80]                         → …โรยถั่วทองกรอบ ของหวานที่นัก
truncate(description, length: 80)          → …โรยถั่วทองกรอบ ของหวานที...
truncate(description, length: 80, separator: " ") → …โรยถั่วทองกรอบ...

แบบที่สอง (truncate เฉย ๆ) ได้ ที... — ไม้เอกของ "ที่" หายไป · truncate ดีกว่า [0..80] ตรงที่เติม ... ให้และรับ separator ได้ แต่ตัวมันไม่ได้รู้จักภาษาไทย · พอบอกให้ตัดที่ช่องว่าง (ภาษาไทยเว้นวรรคระหว่างวลีอยู่แล้ว) ก็ได้วลีครบ

🍽 เทียบให้เห็นภาพ — แม่พิมพ์ตักข้าวที่มีสวิตช์ "จานใหญ่"

แม่พิมพ์ _post คือแม่พิมพ์ตักข้าวอันเดียวที่ใช้ได้ทั้งจานเล็กในชุดรวม (หน้า index) และจานใหญ่สั่งเดี่ยว (หน้า show) · คนจัดจานยื่นของใส่มือแม่พิมพ์ชัด ๆ ว่า "นี่ข้าวของจานนี้ (post:) · ขอแบบจานใหญ่ (full: true)" · แม่พิมพ์ไม่ต้องรู้ว่าตัวเองอยู่ครัวไหน ถูกยกไปใช้ที่ไหนก็ได้

ที่ไม่เหมือนกัน: แม่พิมพ์จริงไม่มีทางเผลอเดินไปหยิบของเอง · แต่ partial เขียน @post ได้ — Rails ไม่ห้าม มันจะไปควานหาบนถาดหน้าครัวแล้ว "ใช้ได้แค่ครัวเดียว" (ดู predict ข้างล่าง) · strict locals ช่วยเรื่องของที่ต้องยื่น แต่ไม่ได้ห้ามการใช้ @ — จึงต้องตรวจด้วย grep ในขั้นตรวจรับ

เทียบกับ React: partial = component · locals = props (บท 71) · full: false = ค่าตั้งต้นของ prop แบบ function Post({ post, full = false }) · render @post, full: true ≈ <Post post={post} full /> · ต่างกันที่ React ไม่มีถาดกลางให้แอบหยิบ — component เห็นแค่ props ที่ส่งมา
