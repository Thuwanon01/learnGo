ติดตั้ง Ruby และเริ่มจากตัวแปร — ทุกอย่างเป็น object, string แทรกค่า

~25 นาที · ควรผ่าน บทเรียน 90 (Ruby กับ Rails คือใคร) มาก่อน · ถ้าจำเรื่อง type ของ Go ไม่ได้ ย้อนดู บทเรียน 02 ได้

บทนี้ครอบคลุมสไลด์หน้า 14–17 · เริ่มจากติดตั้ง Ruby ด้วย mise แล้วไปดูของสามเรื่องที่คุณจะพิมพ์ใน Rails ทุกวัน: ตัวแปร · "ทุกอย่างเป็น object" · และ string ที่แทรกค่าได้
ข่าวดีคือคุณรู้ Go กับ TypeScript อยู่แล้ว สไลด์ชุดนี้เลยวางสามภาษาเทียบกันทุกหน้า บทนี้ก็จะทำแบบเดียวกัน แล้วรันทั้งสามภาษาจริงให้ดูว่าโค้ดหน้าตาคล้ายกันแต่ผลต่างกันตรงไหน
มีกับดักสามข้อที่คนมาจาก Go/TS เจอแน่ ๆ: พิมพ์ชื่อตัวแปรผิดแล้ว Ruby ไม่ฟ้อง · ค่าคงที่ที่จริง ๆ แล้วแก้ได้ · และ 'Hi #{n}' ที่ไม่แทรกค่าให้ เพราะใช้ single quote

1 · ติดตั้ง Ruby ด้วย mise (สไลด์หน้า 14)

ปัญหาที่ต้องแก้ก่อนเขียน Ruby บรรทัดแรก: เครื่องหนึ่งเครื่องมักต้องมี Ruby หลายรุ่น
โปรเจกต์เก่าของบริษัทอาจยังใช้รุ่น 3 · คอร์สนี้ใช้รุ่น 4 · ส่วน macOS เองก็แถม Ruby รุ่นเก่ามากมาให้อีกตัว (เครื่องที่ใช้ตรวจ ถ้าไม่ตั้ง PATH ให้ดี พิมพ์ ruby -v จะได้รุ่น 2.6 ของระบบ)
ถ้าติดตั้งทับกันไปมาเอง จะไม่มีวันรู้ว่าตอนนี้กำลังรันรุ่นไหนอยู่

ของที่แก้ปัญหานี้เรียกว่า version manager — โปรแกรมที่เก็บหลายรุ่นไว้แยกกัน แล้วสลับให้ตามโฟลเดอร์ที่คุณยืนอยู่ · สไลด์เลือก mise ด้วยเหตุผลสามข้อ:

  1. คุม Ruby และ Node ในไฟล์เดียว — ไม่ต้องมี rbenv สำหรับ Ruby แล้ว nvm สำหรับ Node แยกกัน
  2. commit ขึ้น repo ได้ — ทุกคนในทีม clone ไปแล้วได้รุ่นเดียวกัน
  3. "โหลด .env ให้เอง" — ข้อนี้จริงแค่ครึ่งเดียว เดี๋ยวพิสูจน์ให้ดูข้างล่าง

ไฟล์ที่สไลด์หน้า 14 ให้วางไว้ที่ราก repo:

# mise.toml
[tools]
ruby = "4.0.6"
node = "22"        # for daisyUI only

และคำสั่งใน terminal ตามสไลด์:

$ mise use -g ruby@4      # ติดตั้ง Ruby รุ่น 4 ล่าสุด แล้วตั้งเป็นค่าเริ่มต้นของทั้งเครื่อง
$ ruby -v                 # สไลด์เขียนว่า ruby 4.0.6
$ gem install rails       # ติดตั้ง Rails ลงใน Ruby ตัวที่เพิ่งได้มา
$ ruby -v                 # สไลด์เช็คซ้ำอีกรอบ ยังได้ ruby 4.0.6
$ rails -v               # สไลด์เขียนว่า Rails 8.1.3

อ่านทีละส่วนแบบภาษาคน:

ส่วนแปลว่า
mise use "ติดตั้งรุ่นนี้ (ถ้ายังไม่มี) แล้วจดลงไฟล์ config ว่าจะใช้รุ่นนี้"
-g ย่อจาก --global · จดลงไฟล์ config ส่วนตัวของทั้งเครื่อง (~/.config/mise/config.toml) ไม่ใช่ mise.toml ในโปรเจกต์ · ถ้าอยากได้ไฟล์ mise.toml แบบในสไลด์ ให้ cd เข้าโปรเจกต์แล้วรันโดยไม่ใส่ -g
ruby@4 "รุ่น 4 ตัวไหนก็ได้ เอาตัวล่าสุด" · เพราะฉะนั้นเลขที่ได้จะขยับไปตามวันที่คุณติดตั้ง — วันที่ทำสไลด์ได้ 4.0.6 · วันที่ผมตรวจได้ 4.0.9 · ส่วน ruby = "4.0.6" ใน mise.toml คือการตรึงเลขเป๊ะ
gem install rails gem คือตัวติดตั้ง package ของ Ruby (เทียบได้กับ go install หรือ npm install -g) · package ของ Ruby เรียกว่า gem · Rails ก็เป็น gem ตัวหนึ่ง

ห้ามรันคำสั่งพวกนี้ซ้ำถ้าเครื่องคุณติดตั้งไว้แล้ว — ใช้คำสั่ง "อ่านอย่างเดียว" เช็คแทนก็พอ · นี่คือผลรันจริงบนเครื่องที่ใช้ตรวจ: 

$ ruby -v
ruby 4.0.9 (2026-10-23 revision 3e93b23afc) +PRISM [arm64-darwin25]
$ rails -v
Rails 8.1.4
$ mise --version
2026.8.1 macos-arm64 (2026-08-03)
$ mise ls
go    1.26.5  ~/.config/mise/config.toml  1.26
ruby  4.0.9   ~/.config/mise/config.toml  4

ดูบรรทัด ruby ของ mise ls ให้ดี: คอลัมน์ที่สามบอกว่ารุ่นนี้ถูกสั่งมาจากไฟล์ไหน (ไฟล์ global) ส่วนคอลัมน์สุดท้าย 4 คือสิ่งที่ขอไว้ — ขอแค่ "4" ได้มาจริง 4.0.9 ตรงกับที่ตารางข้างบนอธิบาย · และสังเกตว่าเครื่องนี้ใช้ mise คุม Go ด้วย — มันไม่ได้จำกัดอยู่แค่ Ruby กับ Node

⚠️ "mise โหลด .env ให้เอง" — ไม่จริง ถ้าไม่ได้สั่ง

ผมสร้างโฟลเดอร์ทดลองที่มีไฟล์ .env หนึ่งบรรทัด (SECRET_GREETING=hello-from-dotenv) แล้วให้ mise พิมพ์ environment ที่มันจะตั้งให้ออกมาดูด้วย mise env (คำสั่งอ่านอย่างเดียว) — ผลรันจริง: 

# แบบ A — mise.toml มีแค่ [tools] เหมือนในสไลด์
$ mise env | grep SECRET
# (ไม่มีบรรทัดไหนออกมาเลย — .env ไม่ถูกโหลด)

# แบบ B — เพิ่ม [env] _.file เข้าไป
$ cat mise.toml
[tools]
ruby = "4.0.9"

[env]
_.file = ".env"
$ mise env | grep SECRET
export SECRET_GREETING=hello-from-dotenv

สรุป: mise โหลด .env ได้ แต่ต้องเขียนบอกมันใน [env] เอง (เอกสาร mise เรียกบรรทัดนี้ว่า env directive · อีกทางคือเปิด setting ชื่อ env_file ของ mise ซึ่งก็ต้องตั้งเองเหมือนกัน — เครื่องที่ใช้ตรวจไม่ได้ตั้งไว้) · และค่าจะเข้าไปถึงโปรแกรมก็ต่อเมื่อรันผ่าน mise — คือเปิด mise activate ไว้ใน shell (คู่มือติดตั้ง Rails ให้ใส่ลง ~/.zshrc) หรือรันด้วย mise exec -- …

อีกด่านที่จะเจอครั้งแรก: mise.toml ที่ mise ไม่เคยเห็นมาก่อน มันจะไม่ยอมอ่านจนกว่าคุณจะอนุญาต · ผลรันจริงตอนยังไม่อนุญาต (ตัด path เต็มเหลือ …): mise ERROR Config files in …/mise.toml are not trusted. ตามด้วย Trust them with `mise trust`. · การทดลองข้างบนผมอนุญาตชั่วคราวผ่านตัวแปร MISE_TRUSTED_CONFIG_PATHS แทน เพื่อไม่ให้ไปเปลี่ยนการตั้งค่าของเครื่อง · ในโปรเจกต์ของคุณเอง รัน mise trust ในโฟลเดอร์นั้นครั้งเดียวก็พอ

🧰 เทียบให้เห็นภาพ — ป้ายรายการเครื่องมือหน้าห้องแล็บ

นึกถึงห้องแล็บที่หน้าประตูแปะป้ายว่า "ห้องนี้ใช้กล้องจุลทรรศน์รุ่น 4.0.6 และเครื่องชั่งรุ่น 22"
ใครเดินเข้าห้องนี้ก็ได้เครื่องมือรุ่นเดียวกันหมด ไม่มีใครต้องถามกันว่า "ของนายรุ่นอะไร" — mise.toml คือป้ายแผ่นนั้น · ส่วน mise use -g คือป้ายที่แปะไว้ที่โต๊ะทำงานส่วนตัว ใช้เมื่อห้องไหนไม่ได้แปะป้ายไว้

ที่ไม่เหมือนกัน: ป้ายจริงแค่บอก ไม่ได้หยิบของมาวางให้ · mise หยิบให้จริง แต่ต้องมีคนเฝ้าประตูก่อน (ต้อง mise activate ใน shell) และมันหยิบเฉพาะที่เขียนไว้บนป้ายเท่านั้น — ป้ายไม่ได้เขียนว่า "เอาตู้ .env มาด้วย" มันก็ไม่เอามา ต่อให้ตู้นั้นวางอยู่ในห้องก็ตาม

🗣 ศัพท์ที่เพิ่งเรียนไป
version manager
โปรแกรมที่เก็บภาษาหลายรุ่นไว้ในเครื่องเดียวแล้วสลับให้ตามโปรเจกต์ (mise · rbenv · nvm) · ถาม senior ได้ว่า “ทีมนี้ตรึงรุ่น Ruby ไว้ที่ไฟล์ไหน — mise.toml หรือ .ruby-version” จะได้ไม่ไปสร้างไฟล์ซ้อนกันสองที่
global config / project config
config ส่วนตัวทั้งเครื่อง (-g) กับ config ที่อยู่ในโปรเจกต์และ commit ขึ้น repo · ของในโปรเจกต์ชนะของ global เสมอ · พิมพ์บอก AI ได้ว่า “pin Ruby 4.0.6 in a project-level mise.toml, not the global config”
gem
package ของ Ruby หนึ่งตัว · Rails เองก็เป็น gem · ติดตั้งด้วย gem install (ในโปรเจกต์ Rails จริงจะใช้ Gemfile แทน — บทเรียน 98)
dotenv / .env
ไฟล์เก็บค่า environment variable แบบ KEY=value ทีละบรรทัด · ห้าม commit ขึ้น repo เพราะมักมีรหัสผ่าน · ถาม senior ได้ว่า “ใน repo นี้ .env ถูกโหลดด้วยอะไร — mise _.file หรือ gem อื่น”

2 · irb — สนามทดลองที่ Go ไม่มีให้

ตอนเรียน Go ทุกครั้งที่อยากลองอะไรสั้น ๆ คุณต้องสร้างไฟล์ มี package main มี func main() แล้ว go run — Go ไม่มีโหมด "พิมพ์บรรทัดเดียวแล้วเห็นผลเลย" มากับตัว
Ruby มี · ติดตั้ง Ruby แล้วได้คำสั่งชื่อ irb (Interactive Ruby) มาด้วยฟรี พิมพ์ irb ใน terminal แล้วพิมพ์โค้ดได้ทีละบรรทัด กด Enter เห็นผลทันที

ผลรันจริง (ตัดโลโก้กับข้อความต้อนรับตอนเปิดออก ส่วนที่เหลือไม่แก้): 

irb(main):001> n = "Nan"
=> "Nan"
irb(main):002> "Hi #{n}"
=> "Hi Nan"
irb(main):003> 42.even?
=> true
irb(main):004> nil.class
=> NilClass
irb(main):005> exit

=> คือค่าที่บรรทัดนั้นคืนออกมา · irb โชว์ให้เองทุกบรรทัด ไม่ต้องสั่ง print · ในบทเรียนและในสไลด์ คุณจะเห็นคอมเมนต์ # => ... ต่อท้ายโค้ด — นั่นคือการก็อปผลแบบนี้มาเขียนไว้

ประโยชน์ที่สองที่คนมักไม่รู้: ใช้ irb ถามได้ว่า "ของชิ้นนี้ทำอะไรได้บ้าง" เช่น อยากรู้ว่า string มี method เกี่ยวกับตัวพิมพ์เล็ก-ใหญ่อะไรบ้าง — ผลรันจริง: 

irb(main):001> "abc".methods.grep(/case/)
=>
[:casecmp,
 :casecmp?,
 :upcase,
 :upcase!,
 :swapcase,
 :downcase,
 :swapcase!,
 :downcase!]

ไม่ต้องจำ API ทั้งหมด แค่จำว่าถามได้ · (ตัวที่มี ? กับ ! ต่อท้ายคืออะไร รอ บทเรียน 93)
พอถึง Rails คุณจะได้ใช้พี่น้องของมันคือ bin/rails console ซึ่งเป็น irb ที่โหลดแอปทั้งตัวไว้ให้ — รายละเอียดอยู่ใน บทเรียน 104

🧰 เทียบให้เห็นภาพ — เครื่องคิดเลขตั้งโต๊ะ

go run เหมือนเขียนจดหมายส่งไปให้คนคำนวณ — ต้องมีหัวจดหมาย ลงท้าย ใส่ซอง (package, import, main) ถึงจะได้คำตอบกลับมา · irb เหมือนเครื่องคิดเลขบนโต๊ะ — กดตัวเลข กด = เห็นคำตอบเลย

ที่ไม่เหมือนกัน: เครื่องคิดเลขโชว์ตัวเลขดิบ ๆ แต่ irb โชว์ในรูปแบบที่โปรแกรมเมอร์อ่าน คือมีเครื่องหมายคำพูดครอบ string และบางทีมี \ โผล่มา (เช่น "Hi \#{n}" ในหัวข้อ 5) ซึ่งไม่ใช่สิ่งที่ puts จะพิมพ์ออกจอจริง · และพอพิมพ์ exit ทุกอย่างหายหมด — โค้ดที่ใช้ได้ต้องก็อปไปใส่ไฟล์ .rb เอง

🗣 ศัพท์ที่เพิ่งเรียนไป
REPL
ย่อจาก Read–Eval–Print Loop · อ่านบรรทัด → รัน → พิมพ์ผล → วนรอบใหม่ · irb คือ REPL ของ Ruby · node เฉย ๆ คือ REPL ของ JavaScript (ไม่ใช่ TypeScript — พิมพ์ const x: number = 1 ลงไปจะ SyntaxError) · พิมพ์บอก AI ได้ว่า “give me a one-liner I can paste into irb to check this” จะได้ของที่ลองได้ทันทีแทนไฟล์ยาว ๆ
return value / # =>
ค่าที่โค้ดหนึ่งบรรทัดคืนออกมา · ใน Ruby ทุกบรรทัดมีค่าคืนเสมอ irb เลยโชว์หลัง => ได้ทุกบรรทัด · คอมเมนต์ # => true ในเอกสารแปลว่า “บรรทัดนี้คืน true”

3 · ตัวแปร — ไม่มี let / var / const (สไลด์หน้า 15)

สไลด์หน้า 15 วางสามภาษาเทียบกันแบบนี้:

GoTypeScriptRuby
var name string = "Nan" let name: string = "Nan" name = "Nan"
count := 42 const count = 42 count = 42
const Max = 100 const MAX = 100 MAX = 100
ต้องประกาศ type หรือให้ := เดาให้ type annotation ไม่บังคับ แต่แนะนำ ไม่มี keyword ประกาศ · ไม่มี type annotation

ใน Ruby การให้ค่าครั้งแรก = การสร้างตัวแปร ไม่มีขั้น "ประกาศ" แยกออกมา · และตัวแปรไม่ได้ผูกกับ type — วันนี้ count เก็บตัวเลข พรุ่งนี้เก็บ string ก็ได้ ไม่มีใครห้าม
ฟังดูสบาย แต่มีราคาที่ต้องจ่าย ลองดูโค้ดที่พิมพ์ชื่อตัวแปรผิดตัวเดียว (cuont แทน count) ในสามภาษา — ผลรันจริงทั้งหมด:

ภาษาโค้ดผลจริง
Go count := 1
cuont = count + 1		 ./main.go:7:2: undefined: cuont
build ไม่ผ่าน
TypeScript let count = 1;
cuont = count + 1;		 cnt.ts(2,1): error TS2552: Cannot find name 'cuont'. Did you mean 'count'?
Ruby count = 1
cuont = count + 1
p count		 1
ไม่มี error · รันจบปกติ — Ruby คิดว่าคุณตั้งใจสร้างตัวแปรใหม่ชื่อ cuont

Go กับ TS จับได้เพราะ "ประกาศ" กับ "ให้ค่า" เป็นคนละท่ากัน (:= กับ = · let กับไม่มี let) — ให้ค่ากับชื่อที่ไม่เคยประกาศ = ผิดแน่นอน · Ruby ไม่มีเส้นแบ่งนี้ เลยแยกไม่ออกว่าคุณพิมพ์ผิดหรือตั้งใจ
ตัวช่วยเล็ก ๆ คือรันด้วย -w (เปิดคำเตือน) — ผลรันจริง: 

$ ruby -w typo.rb
typo.rb:2: warning: assigned but unused variable - cuont
1

มันเตือนเพราะ cuont ถูกให้ค่าแล้วไม่มีใครใช้ — แต่โปรแกรมยังรันต่อ ไม่ได้หยุดเหมือน Go · ในงานจริง ตัวที่จับเรื่องพวกนี้คือ test (ได้เจอใน Day 4) และเครื่องมือตรวจโค้ดที่ทีมตั้งไว้

ค่าคงที่ — ขึ้นต้นตัวใหญ่ = ค่าคงที่ (แต่แก้ได้)

Ruby ไม่มีคำว่า const · มันดูจากตัวอักษรตัวแรกของชื่อแทน: ขึ้นต้นตัวเล็ก = ตัวแปรธรรมดา · ขึ้นต้นตัวใหญ่ = ค่าคงที่ (constant)
สไลด์บอกว่าค่าคงที่ของ Ruby "แก้ได้ แต่จะเตือน" — ลองทายก่อนว่าโค้ดนี้จะออกมาเป็นยังไง 

# vars.rb
MAX = 100
p MAX

MAX = 200
p MAX

รัน ruby vars.rb แล้วจะ (ก) หยุดด้วย error ตรงบรรทัด MAX = 200 · (ข) เตือนแล้วพิมพ์ 200 · หรือ (ค) เตือนแล้วยังพิมพ์ 100? ถ้าเป็น Go หรือ TS จะเป็นยังไง?

ผลรันจริงของไฟล์ข้างบนทั้งหกบรรทัด (นับบรรทัดคอมเมนต์ # vars.rb เป็นบรรทัด 1) — ได้ (ข):

$ ruby vars.rb
100
vars.rb:5: warning: already initialized constant MAX
vars.rb:2: warning: previous definition of MAX was here
200

Ruby ยอมเปลี่ยนค่าให้ แค่บ่นสองบรรทัด: "ค่าคงที่ MAX ถูกตั้งค่าไปแล้ว (ที่บรรทัด 5)" และ "ตั้งครั้งแรกที่บรรทัด 2" · คำเตือนนี้ออกมาโดยไม่ต้องใส่ -w

เทียบกับอีกสองภาษา (ผลรันจริง): Go ได้ cannot assign to Max (neither addressable nor a map index expression) · TypeScript ได้ error TS2588: Cannot assign to 'MAX' because it is a constant. — ทั้งคู่ build ไม่ผ่านเลย · ค่าคงที่ของ Ruby จึงเป็นแค่ข้อตกลงที่มีสัญญาณเตือน ไม่ใช่กำแพง

⚠️ เตือนแค่ตอน "เปลี่ยนป้าย" ไม่เตือนตอน "ยัดของเพิ่ม"

TAGS = ["ruby"]
TAGS << "rails"      # << คือเติมของต่อท้าย array เดิม
p TAGS

ผลรันจริง: ["ruby", "rails"] — ไม่มีคำเตือนสักบรรทัด เพราะ TAGS ยังชี้ไปที่ array ตัวเดิม แค่ของข้างในเปลี่ยน · "ค่าคงที่" ของ Ruby กันแค่การเอาชื่อไปผูกกับของชิ้นใหม่ ไม่ได้กันการแก้ของชิ้นเดิม

การตั้งชื่อ — snake_case กับ PascalCase

สไลด์บอกกติกาไว้สั้น ๆ: ชื่อตัวแปรและ method ใช้ snake_case (ตัวเล็กหมด คั่นด้วย _ เช่น shop_name) · ชื่อ class ใช้ PascalCase (ขึ้นต้นคำด้วยตัวใหญ่ติดกัน เช่น BlogPost)
ใน Go คุณเคยใช้ตัวใหญ่-ตัวเล็กบอกว่า export หรือไม่ · ใน Ruby มันบอกว่าเป็นค่าคงที่หรือไม่ — และชื่อ class ก็คือค่าคงที่ตัวหนึ่ง ถ้าตั้งชื่อ class ขึ้นต้นตัวเล็ก Ruby ไม่ยอมตั้งแต่แรก (ผลรันจริง ตัดมาเฉพาะบรรทัดหลักของ SyntaxError): 

class blog_post
end

# unexpected constant path after `class`; class/module name must be CONSTANT
# cls.rb:1: syntax errors found (SyntaxError)

สไลด์ยังบอกว่า "Rails บังคับใช้จริง ไม่ใช่แค่แนะนำ" — เพราะ Rails เดาชื่อไฟล์จากชื่อ class ตามสูตรตายตัว: class BlogPost < ApplicationRecord ต้องอยู่ในไฟล์ blog_post.rb เท่านั้น
สูตรนั้นคือ method ของ Active Support (ไลบรารีที่มากับ Rails) ลองเรียกตรง ๆ นอก Rails ได้ — ผลรันจริง: 

$ ruby -ractive_support/all -e 'p "blog_post".camelize; p "BlogPost".underscore; p "BlogPost".tableize'
"BlogPost"
"blog_post"
"blog_posts"

ชื่อไฟล์ ↔ ชื่อ class ↔ ชื่อตาราง แปลงกลับไปกลับมาด้วยสูตรเดียว — ตั้งชื่อผิดสูตรเมื่อไหร่ Rails หาของไม่เจอ · รายละเอียดทั้งหมดรออยู่ใน บทเรียน 99 · บทนี้ขอแค่ให้จำว่าตัวพิมพ์ใหญ่-เล็กใน Ruby มีความหมาย

🧰 เทียบให้เห็นภาพ — สติกเกอร์ชื่อในตู้เย็นออฟฟิศ

ตัวแปร Ruby เหมือนสติกเกอร์เขียนชื่อที่แปะบนกล่องข้าวในตู้เย็น · count = 42 คือเอาสติกเกอร์ count ไปแปะที่กล่องเลข 42 · count = "forty-two" คือแกะสติกเกอร์ไปแปะกล่องอื่น — สติกเกอร์ไม่สนว่ากล่องเป็นแบบไหน
ค่าคงที่ (MAX) คือสติกเกอร์สีแดงที่เขียนว่า "ห้ามย้าย" — ย้ายได้ แต่สัญญาณเตือนจะดัง · และถ้าพิมพ์ชื่อผิด (cuont) ก็คือสติกเกอร์ใบใหม่อีกใบ ไม่มีใครมาทักว่า "ชื่อนี้ไม่เคยมี"

ที่ไม่เหมือนกัน: สติกเกอร์ "ห้ามย้าย" ในชีวิตจริงคนมักเข้าใจว่าห้ามแตะกล่องด้วย · แต่ใน Ruby มันห้ามแค่การย้ายสติกเกอร์ — เปิดกล่องแล้วยัดของเพิ่ม (TAGS << "rails") ทำได้เงียบ ๆ ไม่มีอะไรดังเลย

🗣 ศัพท์ที่เพิ่งเรียนไป
local variable
ตัวแปรชื่อขึ้นต้นตัวเล็ก · เกิดขึ้นตอนให้ค่าครั้งแรก ไม่มีขั้นประกาศ · พิมพ์บอก AI ได้ว่า “check this Ruby file for misspelled local variables — Ruby won't error on them”

ชื่อที่ขึ้นต้นตัวใหญ่ (MAX · BlogPost) · ให้ค่าใหม่ได้แต่มี warning: already initialized constant · ชื่อ class ก็เป็น constant · ถาม senior ได้ว่า “ค่าคงที่ที่เป็น array/hash ในโปรเจกต์นี้ใส่ .freeze กันไว้ไหม” — freeze คือท่าที่ใช้กันการยัดของเพิ่มแบบในกล่องเตือนข้างบน
dynamic typing

snake_case / PascalCase

4 · ใน Ruby ไม่มี primitive แม้แต่ตัวเดียว (สไลด์หน้า 16)

ใน Go int string bool เป็นค่าดิบ ๆ ไม่มี method ในตัว · อยากรู้ความยาว string ต้องเอาไปใส่ฟังก์ชัน len("abc") · อยากได้ตัวใหญ่ต้องไปยืมฟังก์ชันจาก package strings.ToUpper("abc")
TypeScript ครึ่ง ๆ กลาง ๆ — "abc".toUpperCase() เรียกได้เพราะ JavaScript แอบห่อค่าดิบเป็น object ชั่วคราวให้ (เรียกว่า auto-boxing) แต่ของบางอย่างก็ไม่มี
Ruby ไปสุดทาง: ทุกค่าเป็น object ที่มี method ของตัวเอง แม้แต่ตัวเลข แม้แต่ nil แม้แต่ true

GoTypeScriptRuby (ผลรันจริงหลัง #)
strings.ToUpper("abc") "abc".toUpperCase() "abc".upcase # => "ABC"
len("abc") "abc".length "abc".length # => 3
strconv.Itoa(42) (42).toString() 42.to_s # => "42"
42%2 == 0 42 % 2 === 0 42.even? # => true
— — nil.to_a # => []
— — true.class # => TrueClass

สองแถวสุดท้ายคือของที่ไม่มีคู่ในภาษาอื่น: nil (คู่ของ nil ใน Go / null ใน TS) ก็มี method — nil.to_a คืน array ว่าง · true ก็รู้ว่าตัวเองเป็น class อะไร · ผมเช็คเพิ่มด้วยว่าทุกตัวนับเป็น object จริงไหม — ผลรันจริง: 

p 42.class              # => Integer
p nil.class             # => NilClass
p 42.is_a?(Object)      # => true
p nil.is_a?(Object)     # => true
p 3.times.to_a          # => [0, 1, 2]

แถวสุดท้ายคือ .times ที่สไลด์บอกว่า "number ใน TS ไม่มี" — ผมลองใน TS จริง: (42).times ได้ error TS2339: Property 'times' does not exist on type '42'.

แต่ "ทุกอย่างมี method" ไม่ได้แปลว่า ทุกอย่างมีทุก method — method ขึ้นกับว่าเป็น object ชนิดไหน · ผลรันจริงของการถามเลขคู่กับ string: 

nm.rb:1:in '<main>': undefined method 'even?' for an instance of String (NoMethodError)

p "abc".even?
       ^^^^^^

ต่างจาก Go ตรงที่ Ruby ไม่รู้จนกว่าจะรันถึงบรรทัดนั้นจริง · Go จับได้ตอน build (นี่คือเหตุผลที่ irb มีประโยชน์มาก — ลองก่อน ไม่ต้องเดา)

ทำไมเรื่องนี้สำคัญ — สไตล์ chain

พอทุกค่ามี method และทุก method คืนค่าที่เป็น object อีกตัว คุณก็ต่อจุดไปเรื่อย ๆ ได้ อ่านจากซ้ายไปขวา · ลองเทียบงานเดียวกัน "ตัดช่องว่างหัวท้าย → ทำเป็นตัวใหญ่ → นับความยาว" — ทั้งสองแบบรันจริงได้ 12:

Go — อ่านจากในออกนอก

len(strings.ToUpper(strings.TrimSpace("  wongnok blog  ")))

Ruby — อ่านจากซ้ายไปขวา

"  wongnok blog  ".strip.upcase.length

สไลด์ชี้ว่าเรื่องนี้ไปโผล่ใน Rails ตรงนี้: 

@posts = Post.published.recent.limit(10)

อ่านเป็นภาษาคนว่า "เอาโพสต์ → เฉพาะที่เผยแพร่แล้ว → เรียงใหม่สุดก่อน → เอาแค่ 10 อัน" · published กับ recent ไม่ได้มากับ Rails — เป็นชื่อที่คุณต้องเขียนเองใน Day 2 (Active Record) · วันนี้ขอแค่อ่านออกว่ามันคือการต่อ method แบบเดียวกับ .strip.upcase.length

🧰 เทียบให้เห็นภาพ — วัตถุดิบดิบกับเครื่องใช้ไฟฟ้าที่มีปุ่มในตัว

ใน Go ค่าอย่าง "abc" เหมือนวัตถุดิบดิบ — อยากหั่นต้องหยิบมีดจากลิ้นชัก strings · อยากชั่งต้องหยิบเครื่องชั่ง len · ตัววัตถุดิบเองทำอะไรไม่ได้
ใน Ruby ทุกค่าเหมือนเครื่องใช้ไฟฟ้าที่มีปุ่มติดมาเลย — กดปุ่ม .upcase บนตัว string ได้ทันที และผลที่ออกมาก็เป็นเครื่องอีกเครื่องที่มีปุ่มให้กดต่อ (นั่นแหละคือ chain)

ที่ไม่เหมือนกัน: เครื่องใช้ไฟฟ้าจริงคุณมองเห็นปุ่มทั้งหมดตั้งแต่ก่อนกด · ใน Ruby ไม่มีใครห้ามคุณกดปุ่มที่ไม่มีอยู่ — กด "abc".even? ได้ตามใจ แล้วค่อยรู้ตอนรันว่าพัง (NoMethodError) · อยากรู้ว่ามีปุ่มอะไรต้องถามเอง (.methods ใน irb)

🗣 ศัพท์ที่เพิ่งเรียนไป
everything is an object
ประโยคประจำตัวของ Ruby · ตัวเลข nil true class ทุกตัวเป็น object มี method · ถาม AI ได้ว่า “what class is this value and what methods does it have” แล้วเอาไปลองใน irb ด้วย .class กับ .methods
method chaining
การต่อ .method หลายตัวติดกัน แต่ละตัวทำงานกับผลของตัวก่อนหน้า · พิมพ์บอก AI ได้ว่า “rewrite this nested call as a Ruby method chain” · ถ้า chain ยาวจนอ่านไม่ออก ถาม senior ได้ว่า “ทีมนี้ตัดบรรทัด chain ยาว ๆ ยังไง”
NoMethodError
error ที่ได้เมื่อเรียก method ที่ object ชนิดนั้นไม่มี · อ่านท่อน for an instance of String ก่อนเสมอ — มันบอกว่าของที่อยู่ในมือจริง ๆ เป็นชนิดอะไร ซึ่งมักไม่ใช่ชนิดที่คุณคิด

5 · String และการแทรกค่า (สไลด์หน้า 17)

GoTypeScriptRuby
แทรกค่า fmt.Sprintf("Hi %s", n) `Hi ${n}` (ต้องใช้ backtick) "Hi #{n}" (ต้องใช้ double quote)
ต่อ string "a" + "b" "a" + "b" "a" + "b"

สังเกตว่าสองภาษาใช้เครื่องหมายเดียวกันในความหมายตรงข้าม: backtick ใน TS = แทรกค่าได้ · backtick ใน Go = ตรงตัวทุกตัวอักษร · ส่วน Ruby ใช้ double quote = แทรกได้ · single quote = ตรงตัว
สไลด์เรียกข้อนี้ว่า "กับดักที่เจอบ่อยที่สุดข้อหนึ่งของคนเพิ่งเริ่ม" และยกตัวอย่างใน Rails ไว้ด้วย — ลองทายจากโค้ดที่จำลองบรรทัดนั้น (ใช้ Struct แทน model จริง เพราะยังไม่มี database) 

@post = Struct.new(:title).new("ข้าวมันไก่")
puts "สร้าง #{@post.title} แล้ว"
puts 'สร้าง #{@post.title} แล้ว'

สองบรรทัดนี้พิมพ์อะไรออกมา? ต่างกันตรงไหน?

ผลรันจริง:

สร้าง ข้าวมันไก่ แล้ว
สร้าง #{@post.title} แล้ว

บรรทัดที่สองพิมพ์ #{@post.title} ออกไปตรง ๆ ทั้งก้อน · ไม่มี error ไม่มี warning — Ruby ไม่ถือว่าผิด เพราะคุณอาจตั้งใจพิมพ์ข้อความนั้นจริง ๆ ก็ได้ · ในสไลด์บรรทัดนี้คือ redirect_to post_path(@post), notice: "สร้าง #{@post.title} แล้ว" — ถ้าเผลอใช้ single quote ผู้ใช้จะเห็นป้ายแจ้งเตือนที่มี #{@post.title} โผล่บนหน้าเว็บ (redirect_to กับ notice คืออะไร รอ บทเรียน 102)

ถ้าลองบรรทัด single quote ใน irb จะเห็นอีกหน้าตาหนึ่ง (ผลรันจริง): 'Hi #{n}' → => "Hi \#{n}" · \ ที่โผล่มาคือ irb บอกว่า "# ตัวนี้เป็นตัวอักษรธรรมดา ไม่ใช่ช่องแทรกค่า" — ไม่ได้อยู่ใน string จริง · ตอน puts จะไม่เห็น \

กับดักข้อที่สองของหน้านี้: ทั้งสามภาษาเขียน "a" + "b" ได้เหมือนกันเป๊ะ ได้ "ab" เหมือนกัน · แต่ถ้าฝั่งขวาไม่ใช่ string ล่ะ? 

// Go
s := "a" + 1

// TypeScript
const s = "a" + 1;

# Ruby
puts "a" + 1

แต่ละภาษาได้อะไร — build ไม่ผ่าน · ได้ "a1" · หรือพังตอนรัน? ทายให้ครบทั้งสามช่องก่อนกดเฉลย

ผลรันจริงทั้งสามภาษา:

$ go build main.go       # Go

  • Go — ไม่ยอมตั้งแต่ build เป็น error ตระกูล mismatched types ตัวเดียวกับที่คุณเจอใน บทเรียน 02
  • TypeScript — ยอมทุกขั้น แปลงเลข 1 เป็น string ให้เงียบ ๆ ได้ "a1" · ไม่ฟ้องแม้เปิด --strict
  • Ruby — อยู่ตรงกลาง: ไม่มี build ให้จับ (รันได้จนถึงบรรทัดนั้น) แต่ไม่ยอมแปลงให้เอง พังตอนรันด้วย TypeError · อ่านข้อความตรง ๆ ได้ว่า "String#+ ไม่แปลง Integer เป็น String ให้โดยอัตโนมัติ"

นักพัฒนาเรียกแบบ Ruby ว่า dynamic แต่ strong — type ไม่ได้เช็คล่วงหน้า (dynamic) แต่ก็ไม่แปลงให้มั่ว ๆ (strong) · ส่วน TS ตอนรันก็คือ JavaScript ที่ยอมแปลงให้ (weak)

แก้ได้สองท่า — ทั้งคู่รันจริงได้ a1: 

puts "a" + 1.to_s     # แปลงเองให้ชัด
puts "a#{1}"          # แทรกค่า — #{} เรียก to_s ให้เอง

ในงานจริงคน Ruby เลือกท่าที่สองแทบทุกครั้ง เพราะไม่ต้องจำว่าค่าไหนเป็น type อะไร — #{} แปลงเป็น string ให้หมด · ใน #{} ใส่นิพจน์อะไรก็ได้ด้วย เช่น "1 + 1 = #{1 + 1}" ได้ 1 + 1 = 2 (รันจริง)

7 · ทดสอบความจำ

ไฟล์ Ruby มี MAX = 100 แล้วบรรทัดถัดไปเขียน MAX = 200 ตามด้วย p MAX — รัน ruby ธรรมดา (ไม่ใส่ -w) จะเกิดอะไร?

ตัวเลือกที่ 2 ถูก · ผลรันจริงคือ warning: already initialized constant MAX ตามด้วย previous definition of MAX was here แล้วพิมพ์ 200

ตัวเลือกที่ 1 คือพฤติกรรมของ Go กับ TS ไม่ใช่ Ruby · ตัวเลือกที่ 3 ผิดเพราะ Ruby ยอมเปลี่ยนค่าให้จริง แค่บ่น · ตัวเลือกที่ 4 ผิดเพราะคำเตือนเรื่องค่าคงที่ออกมาเองโดยไม่ต้องใส่ -w (ที่ต้องใส่ -w คือคำเตือนตัวแปรไม่ได้ใช้แบบ cuont)

จุดที่ต้องจำ: ค่าคงที่ของ Ruby คือข้อตกลงที่มีสัญญาณเตือน ไม่ใช่กำแพง

ค่าไหนต่อไปนี้ ไม่ใช่ object ใน Ruby (เรียก .class ไม่ได้)?

ตัวเลือกที่ 4 ถูก · ผลรันจริง: 42.class ได้ Integer · nil.class ได้ NilClass · true.class ได้ TrueClass · และ 42.is_a?(Object) กับ nil.is_a?(Object) ได้ true ทั้งคู่

ตัวเลือกที่ 1 เอาความคิดแบบ Go มาใช้ — ใน Ruby ตัวเลขมี method เช่น 42.even? · ตัวเลือกที่ 2 คือความเข้าใจผิดที่พบบ่อยที่สุด — nil มี method จริง (nil.to_a ได้ []) · ตัวเลือกที่ 3 ผิดเพราะ true เป็น object ของ class TrueClass

จุดที่ต้องจำ: ใน Ruby ไม่มี primitive · ทุกค่าต่อ .method ได้ — นี่คือรากของสไตล์ chain

ใน controller ของ Rails มีคนเขียน notice: 'สร้าง #{@post.title} แล้ว' (single quote) — ผู้ใช้จะเห็นอะไรบนหน้าเว็บ?

ตัวเลือกที่ 3 ถูก · single quote ไม่แทรกค่า — ผลรันจริงของ puts 'สร้าง #{@post.title} แล้ว' คือ สร้าง #{@post.title} แล้ว ทั้งก้อน

ตัวเลือกที่ 1 ผิดเพราะ ไม่มี error เลย — Ruby ถือว่าเป็นข้อความธรรมดาที่บังเอิญมี # · ตัวเลือกที่ 2 คือผลของ double quote ไม่ใช่ single quote · ตัวเลือกที่ 4 ผิดเพราะ Ruby ไม่ได้ลบ #{…} ทิ้ง มันเก็บไว้ครบทุกตัวอักษร

จุดที่ต้องจำ: เห็น #{ โผล่บนหน้าเว็บ = ไปดูว่า string นั้นใช้ single quote อยู่หรือเปล่า

โปรเจกต์มี mise.toml ที่มีแค่ [tools] (เหมือนสไลด์หน้า 14) และมีไฟล์ .env วางอยู่ข้าง ๆ — ค่าใน .env จะถูกโหลดไหม?

ตัวเลือกที่ 1 ถูก · ผลรันจริงของ mise env: แบบมีแค่ [tools] ไม่มีค่าจาก .env สักตัว · พอเพิ่ม [env] + _.file = ".env" ถึงได้ export SECRET_GREETING=hello-from-dotenv

ตัวเลือกที่ 2 คือสิ่งที่สไลด์ทำให้เข้าใจ แต่ไม่ตรงกับของจริง · ตัวเลือกที่ 3 ผิดเพราะ mise use -g แค่ติดตั้งและจดรุ่นลงไฟล์ global ไม่เกี่ยวกับ .env · ตัวเลือกที่ 4 ผิดเพราะการทดลองแบบ A ก็มีบรรทัด ruby ใน [tools] อยู่แล้ว แต่ไม่โหลด

จุดที่ต้องจำ: mise โหลดเฉพาะสิ่งที่เขียนไว้ใน config — .env ต้องสั่งเอง เช่นด้วย _.file

8 · ลงมือทำ

🎯 ภารกิจ: บัตรร้านอาหารบรรทัดเดียว

สร้างไฟล์ profile.rb ที่มี:

  1. ตัวแปร shop_name เก็บ "wongnok" และ rating เก็บเลข 4
  2. ค่าคงที่ MAX_RATING เก็บเลข 5
  3. พิมพ์ด้วย puts ให้ได้ ห้าบรรทัดนี้เป๊ะ — ห้ามพิมพ์คำว่า WONGNOK true Integer ลงไปตรง ๆ ต้องได้มาจาก method: 
    ร้าน WONGNOK ได้ 4/5 ดาว
4 เป็นเลขคู่ไหม: true
ชนิดของ rating: Integer
คะแนน: 4
ตัวอย่างโค้ด: #{rating}
  4. บรรทัด คะแนน: 4 ต้องใช้ + ต่อ string (ไม่ใช่ #{}) — จะได้เจอ TypeError ด้วยตัวเองถ้าลืมแปลง
  5. บรรทัดสุดท้ายต้องโชว์ #{rating} ตรงตัว ไม่ใช่เลข 4
  6. พิสูจน์: เซฟผลที่คาดไว้ (ห้าบรรทัดข้างบน) ลง expected.txt แล้วรัน ruby -w profile.rb > got.txt && diff got.txt expected.txt && echo "ผ่าน: output ตรงทุกบรรทัด" · ต้องไม่มี warning และต้องเห็นคำว่า "ผ่าน"
# profile.rb
shop_name  = "wongnok"
rating     = 4
MAX_RATING = 5

puts "ร้าน #{shop_name.upcase} ได้ #{rating}/#{MAX_RATING} ดาว"
puts "#{rating} เป็นเลขคู่ไหม: #{rating.even?}"
puts "ชนิดของ rating: #{rating.class}"
puts "คะแนน: " + rating.to_s
puts 'ตัวอย่างโค้ด: #{rating}'

ผลรันจริง:

$ ruby -w profile.rb > got.txt && diff got.txt expected.txt && echo "ผ่าน: output ตรงทุกบรรทัด"
ผ่าน: output ตรงทุกบรรทัด

สี่จุดที่ภารกิจนี้ตั้งใจให้เจอ:

  • #{} ใส่ method ได้ — #{shop_name.upcase} · #{rating.even?} · #{rating.class} และแปลงเป็น string ให้เองทั้งหมด
  • ถ้าลืม .to_s ในบรรทัด "คะแนน: " + rating จะได้ (ผลรันจริง) in 'String#+': no implicit conversion of Integer into String (TypeError) · และสังเกตว่าสามบรรทัดแรกพิมพ์ออกมาแล้วก่อนจะพัง — Ruby รันไปทีละบรรทัดจนเจอปัญหา ไม่ได้เช็คทั้งไฟล์ก่อนเหมือน Go
  • บรรทัดสุดท้ายต้องเป็น single quote · ถ้าใช้ double quote จะได้ ตัวอย่างโค้ด: 4 แล้ว diff จะฟ้อง
  • ruby -w ไม่มี warning เพราะทุกตัวแปรถูกใช้ และไม่มีใครเปลี่ยนค่า MAX_RATING

ทำไมใช้ diff พิสูจน์แทนการ "ดูด้วยตา"? เพราะตาคนมองข้ามช่องว่างเกินหนึ่งช่อง หรือ #{rating} ที่กลายเป็น 4 ได้ง่ายมาก · diff ไม่พิมพ์อะไรเลยแปลว่าตรงทุกตัวอักษร — ระบบ test ของ Rails ที่จะเจอใน Day 4 ก็ใช้หลักเดียวกัน คือเทียบ "ที่ได้" กับ "ที่คาดไว้"
