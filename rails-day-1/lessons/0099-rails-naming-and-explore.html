1 · กฎข้อเดียว: model เอกพจน์ · ตารางพหูพจน์ · controller พหูพจน์

สไลด์หน้า 46 มีตารางหกแถว ทุกแถวใช้กฎเดียวกัน:

  • model คือของหนึ่งชิ้น เลยเป็นเอกพจน์ เช่น Post = โพสต์หนึ่งโพสต์
  • ตารางเก็บของหลายชิ้น เลยเป็นพหูพจน์ และใช้ตัวเล็กคั่นด้วย _ เช่น posts, blog_posts
  • controller ดูแลของทั้งกลุ่ม เลยเป็นพหูพจน์ แล้วต่อท้ายด้วย Controller เช่น PostsController

ประเด็นสำคัญคือ Rails ไม่ได้มีตารางคู่ชื่อเก็บไว้ที่ไหนสักแห่ง · มันคำนวณชื่อใหม่จากชื่อเดิมทุกครั้งด้วย method ของ String ที่ Active Support เพิ่มให้ (open class ที่เรียนในบทเรียน 97) · ลองทายก่อนว่าสี่ชื่อนี้จะกลายเป็นอะไร: 

# guess.rb — ทายชื่อตารางและ controller จากชื่อ model
%w[Person Mouse Sheep Human].each do |model|
  table      = model.tableize
  controller = table.camelize + "Controller"
  puts "#{model.ljust(7)} #{table.ljust(7)} #{controller}"
end

🗣 ศัพท์ที่เพิ่งเรียนไป
Convention over Configuration
หลักของ Rails ที่ว่า "ตั้งชื่อตามกฎแทนการเขียน config" · ถาม senior ได้ว่า "โปรเจกต์นี้มีจุดไหนที่ฝืน convention บ้าง เช่น model ที่ตั้ง table_name เอง" เพราะจุดที่ฝืนกฎคือจุดที่คนใหม่หลงบ่อยที่สุด
inflection / Inflector
การผันคำ (เอกพจน์ ↔ พหูพจน์) และโมดูล ActiveSupport::Inflector ที่เก็บกฎพวกนี้ · pluralize · singularize · tableize · classify อยู่ในนี้ทั้งหมด · พิมพ์บอก AI ได้ว่า "check what table name Rails infers for model X using tableize" ก่อนให้มันเขียน migration
tableize / classify
คู่ที่ใช้แปลงชื่อ model ↔ ชื่อตาราง · จำง่าย ๆ ว่า table-ize = ทำให้เป็นชื่อตาราง · class-ify = ทำให้เป็นชื่อ class · เวลาเปิด console ในโปรเจกต์ใหม่ สั่ง "ชื่อ".tableize ดูก่อนสร้าง model ทุกครั้ง ใช้เวลาสองวินาที

ระบบยังทำงานได้นะ เพราะทั้ง model และตารางใช้กฎเดียวกัน เลยเดาผิดไปในทางเดียวกัน · แต่คนที่เปิดฐานข้อมูลดูจะเจอตาราง humen แล้วงง และพอวันหนึ่งมีคนแก้กฎทีหลัง Rails จะไปหาตาราง humans ซึ่งไม่มีอยู่จริง

ตัวอย่างใน comment บอกครบแล้วว่ามีกฎสี่แบบ: plural/singular (กฎแบบ regex) · irregular (จับคู่คำเฉพาะคำ เหมาะกับเคสของเรา) · uncountable (คำที่ไม่มีพหูพจน์ อย่าง sheep) · acronym (ตัวย่อที่อยากให้เป็นตัวใหญ่ทั้งคำ)

# config/initializers/inflections.rb (เติมท้ายไฟล์)
ActiveSupport::Inflector.inflections(:en) do |inflect|
  inflect.irregular "human", "humans"
end

ทำไม Rails ถึงรู้ว่าพหูพจน์ของ person คือ people ไม่ใช่ persons?

ตัวเลือกที่ 3 ถูก · person → people เป็นคู่ irregular ที่ Active Support ใส่มาให้แล้ว (comment ในไฟล์ inflections.rb ก็ยกคู่นี้เป็นตัวอย่าง) · ส่วน human → humen คือหลักฐานว่ามันใช้กฎตัดท้ายคำ ไม่ได้รู้ความหมาย

ตัวเลือกที่ 1 ผิด เพราะกฎทั้งหมดเขียนอยู่ในไฟล์ active_support/inflections.rb ของ gem เอง (เปิดดูได้ มีบรรทัด inflect.irregular("person", "people") กับ inflect.irregular("man", "men") อยู่ในนั้น) และพจนานุกรมจริงไม่มีทางตอบ humen · ตัวเลือกที่ 2 ผิด เพราะหัวข้อ 3 จะโชว์ว่าแม้ฐานข้อมูลมีตาราง persons อยู่จริง Person.table_name ก็ยังตอบ "people" แล้วพัง · ตัวเลือกที่ 4 ผิด เพราะ generator ไม่ได้ถามอะไรเลย และไม่ได้เขียนอะไรลง config

จุดที่ต้องจำ: ชื่อตารางถูกคำนวณจากกฎทุกครั้ง ไม่ได้ถูกค้นหา · คำไหนไม่แน่ใจให้เช็คด้วย tableize ก่อนสร้าง model

วันที่บริษัทอยากเพิ่มกฎใหม่ให้ทุกสาขา ก็แก้คู่มือเล่มเดียว ไม่ต้องไล่แก้ทีละสาขา

  4. ค่อยสร้าง model จริง + bin/rails db:migrate แล้วเพิ่มเทสข้อที่สาม: Cafe.table_name ต้องเป็น "cafes"
