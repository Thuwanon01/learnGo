บทนี้คุณจะเขียน หน้าเว็บแรกของ Rails ด้วยมือ — สามไฟล์ตามสไลด์หน้า 60 — แล้วเปิดดูว่ามันทำงานจริงยังไงด้วย curl

1 · สามไฟล์แรก — route ชี้ทาง · controller เตรียมของ · view จัดหน้า

ใน Gin คุณเขียนทุกอย่างไว้ในที่เดียว: บอกว่า URL ไหน → ฟังก์ชันไหน → ฟังก์ชันนั้นตอบอะไรกลับไป
Rails แยกงานเดียวกันนี้ออกเป็นสามไฟล์ สามโฟลเดอร์ และให้แต่ละไฟล์มีหน้าที่เดียว:

  1. route — บอกว่า URL นี้ ให้ไปหา controller ตัวไหน action ไหน
  2. controller — เตรียมข้อมูลที่หน้าเว็บต้องใช้ แล้วฝากไว้ในตัวแปรที่ขึ้นต้นด้วย @
  3. view — เอาข้อมูลที่ถูกฝากไว้มาเทลง HTML

นี่คือโค้ดจากสไลด์หน้า 60 ครบสามไฟล์: 

# config/routes.rb
Rails.application
     .routes.draw do
  get "/hello",
      to: "greetings#index"
  root "greetings#index"
end
# app/controllers/greetings_controller.rb  — ⚠️ บรรทัดแรกแก้จากสไลด์ (ดูกล่องเตือนข้างล่าง)
class GreetingsController < ApplicationController
  def index
    @name = params[:name] ||
            "PEA"
  end
end
<%# app/views/greetings/index.html.erb %>
<h1>
  Hello <%= @name %>
</h1>

⚠️ จุดที่สไลด์หน้า 60 ก็อปไปตรง ๆ แล้วพัง: สไลด์ตัดบรรทัด class GreetingsController กับ < ApplicationController ออกเป็นสองบรรทัด (น่าจะเพื่อให้พอดีกล่อง) · ผมพิมพ์ตามนั้นเป๊ะแล้วตรวจ:

เปิด /hello ในตอนนั้นได้ HTTP/1.1 500 Internal Server Error พร้อมข้อความเดียวกันบนหน้าเว็บ
ทำไมบรรทัดอื่นตัดได้ แต่บรรทัดนี้ตัดไม่ได้? Ruby ถือว่าขึ้นบรรทัดใหม่ = จบคำสั่ง ยกเว้นบรรทัดนั้น “ยังพูดไม่จบ” ให้เห็นชัด ๆ — get "/hello", จบด้วยจุลภาค · params[:name] || จบด้วยเครื่องหมาย || · .routes ขึ้นต้นด้วยจุด → Ruby รู้ว่ายังมีต่อ
แต่ class GreetingsController เป็นประโยคที่สมบูรณ์แล้วในตัว (“สร้าง class ชื่อนี้”) Ruby จึงจบตรงนั้น แล้วบรรทัดถัดไปขึ้นต้นด้วย < ลอย ๆ ซึ่งไม่มีความหมาย
วิธีแก้: เขียน < ApplicationController ไว้บรรทัดเดียวกับ class เสมอ — เหมือนไฟล์ที่ generator สร้างให้ในหัวข้อ 3

แก้บรรทัดนั้นแล้ว เปิด server แล้วยิงสาม URL · ผมตัดมาเฉพาะส่วนใน <main> ของ layout:

สังเกตสามอย่าง:

  • / ได้ผลเดียวกับ /hello เพราะ root "greetings#index" ชี้ไป action เดียวกัน
  • คอมเมนต์ <!-- BEGIN app/views/greetings/index.html.erb --> — Rails แปะให้เองเฉพาะตอน development (ไฟล์ config/environments/development.rb บรรทัด config.action_view.annotate_rendered_view_with_filenames = true) มีไว้ให้คุณรู้ว่า HTML ก้อนนี้มาจากไฟล์ไหน · ใน production ไม่มี
  • ใน controller ไม่มีคำว่า render เลย แต่ HTML ก็ออกมา — เรื่องนี้แหละที่หัวข้อ 2 จะแกะ

Rails รู้ได้ยังไงว่าต้องไปหาไฟล์ไหน? ทั้งหมดมาจากสตริง "greetings#index" ตัวเดียว: 

"greetings#index"
   │          │
   │          └─▶ action  = method ชื่อ index        ─▶ ใน class นั้นต้องมี def index
   │                                                   └▶ แล้วเปิด view: app/views/greetings/index.html.erb
   └─▶ controller = GreetingsController             ─▶ ไฟล์ app/controllers/greetings_controller.rb

นี่คือ naming convention ที่บทเรียน 99 พูดถึง — ตั้งชื่อถูก Rails หาให้เอง ตั้งชื่อผิดไฟล์เดียว ทั้งสายหาไม่เจอ

แต่ละแบบได้ Hello อะไร? (ใบ้: ถ้าเคยผ่านบท 94 มาแล้ว ข้อแรกน่าจะเดาได้)

# ผลรันจริง (ตัดมาเฉพาะใน <h1>)
?name=      →   Hello         ← ว่าง! ไม่ใช่ PEA
?name       →   Hello PEA
?NAME=Nan   →   Hello PEA
  • ?name= → Rails ใส่ "" (สตริงว่าง) ลงใน params[:name] · และใน Ruby "" นับเป็นจริง (มีแค่ nil กับ false ที่เป็นเท็จ — บทเรียน 94) → "" || "PEA" ได้ "" → หน้าเว็บขึ้น Hello เปล่า ๆ
  • ?name ไม่มี = → ได้ nil → ตกไปใช้ "PEA"
  • ?NAME=Nan → ชื่อ key แยกตัวเล็กตัวใหญ่ · NAME ไม่ใช่ name → nil → "PEA"

Gin ก็เจอแบบเดียวกันเป๊ะ — c.DefaultQuery("name", "PEA") กับ ?name= ได้ผลจริงว่า /hello?name= -> 200 Location="" body="Hello " เพราะ DefaultQuery ใช้ค่า default เฉพาะตอนไม่มี key เหมือนกัน · ทางแก้ฝั่ง Rails คือ params[:name].presence || "PEA" — เป็นภารกิจท้ายบท

🍜 เทียบให้เห็นภาพ — ร้านก๋วยเตี๋ยวสามคน

route คือพนักงานหน้าร้านที่ดูออเดอร์แล้วตะโกนบอกว่า “โต๊ะนี้ไปหาครัวเส้น เมนูน้ำใส” (greetings#index)
controller คือพ่อครัว — ลวกเส้น ใส่เครื่อง แล้ววางชามไว้บนถาด (@name = ...)
view คือคนจัดชามขึ้นโต๊ะ — หยิบของจากถาดไปจัดให้สวย (<%= @name %>)
พ่อครัวไม่ต้องตะโกนสั่งว่า “ยกไปเสิร์ฟ!” ทุกครั้ง — ร้านนี้มีกติกาว่าทำเสร็จเมื่อไหร่ ชามเมนูน้ำใสไปโต๊ะน้ำใสเอง นั่นคือเหตุที่ไม่มีบรรทัด render

ที่ไม่เหมือนกัน: ในร้านจริง ถ้าพ่อครัววางของไว้บนโต๊ะข้าง ๆ (ตัวแปรธรรมดาไม่มี @) คนเสิร์ฟยังเดินไปหยิบได้
แต่ใน Rails view มองเห็นแค่ของที่อยู่บน “ถาด @” เท่านั้น — ถ้าเขียน name = params[:name] (ไม่มี @) ตัวแปรนั้นหายไปทันทีที่ def index จบ view เรียก name ไม่ได้เลย (ผมลองแล้ว ได้ 500 กับ undefined local variable or method 'name') และอีกเรื่อง: ถาดนี้ใช้ได้แค่ request เดียว ลูกค้าคนถัดไปได้ถาดใหม่เปล่า ๆ เสมอ

🗣 ศัพท์ที่เพิ่งเรียนไป
action
public method หนึ่งตัวใน controller ที่ route ชี้มาหาได้ (def index) · เทียบได้กับ handler หนึ่งตัวใน Gin · ถาม senior ได้ว่า “action นี้ควรแยกไป controller ใหม่ไหม หรือมันเป็นหนึ่งในเจ็ด action มาตรฐานของ resource”
instance variable (@name)
ตัวแปรที่ขึ้นต้นด้วย @ · ใน controller มันคือทางเดียวที่ส่งข้อมูลไปให้ view · พิมพ์บอก AI ได้ว่า “which instance variables does this view expect the controller to set?” เวลาไล่หาว่า view พังเพราะตัวแปรไหนเป็น nil
implicit render
action จบโดยไม่เรียก render หรือ redirect_to → Rails เปิด view ที่ชื่อ app/views/<controller>/<action>.html.erb ให้เอง · ถาม senior ได้ว่า “action นี้ render view ไหนอยู่ — implicit หรือมี render ซ่อนอยู่ใน callback”
controller#action
รูปแบบสตริงที่ใช้ใน routes เช่น "greetings#index" · เวลาอ่าน log ของ Rails จะเห็นเป็น Processing by GreetingsController#index · คุยกับทีมได้ว่า “request นี้วิ่งเข้า greetings#index” ทุกคนเข้าใจตรงกัน

2 · ลบ view ทิ้ง — แล้ว curl กับเบราว์เซอร์ได้ผลไม่เหมือนกัน

ถ้า implicit render คือ “action จบแล้ว Rails ไปหา view ให้” — ถ้าไม่มี view ล่ะ? ผมย้าย app/views/greetings/index.html.erb ออกไป แล้วลองสองแบบ

“ค่าใน params เป็น string เสมอ” — จริงแค่ครึ่งเดียว

def probe
  lines = []
  lines << "params.class       = #{params.class}"
  lines << "params[:page]      = #{params[:page].inspect}"
  lines << "params[:page] == 2 = #{params[:page] == 2}"
  lines << "params[:page].to_i = #{params[:page].to_i.inspect}"
  lines << "params[\"page\"]     = #{params["page"].inspect}"
  begin
    params[:page] + 1
  rescue => e
    lines << "params[:page] + 1  -> #{e.class}: #{e.message}"
  end
  render plain: lines.join("\n") + "\n"
end

📮 เทียบให้เห็นภาพ — ตู้รับของตู้เดียวของคอนโด

Gin เหมือนบ้านที่มีช่องรับของแยก: จดหมายช่องหนึ่ง พัสดุอีกช่อง ของฝากเพื่อนบ้านอีกช่อง — คุณต้องรู้ว่าของที่รอมาทางไหน แล้วไปเปิดให้ถูกช่อง (c.Query · c.Param · c.ShouldBindJSON)
Rails เหมือนคอนโดที่นิติฯ รับของทุกอย่างมาใส่ตู้เดียวที่มีชื่อห้องคุณ — จะมาทางไปรษณีย์ แมสเซนเจอร์ หรือเพื่อนฝาก คุณแค่เปิดตู้แล้วหยิบตามชื่อ params[:page]

ที่ไม่เหมือนกัน: นิติฯ จริงยังดูให้ว่าของไหนมาจากใคร และกล่องพัสดุก็ยังเป็นกล่อง
แต่ตู้ params ไม่บอกว่าของชิ้นไหนมาทางไหน และไม่การันตีหน้าตาของ — ชิ้นเดียวกันอาจเป็น "2" · 2 หรือ ["2"] แล้วแต่ว่าคนส่งส่งมายังไง ใครยัดอะไรมาก็อยู่ในตู้ได้หมด · และของที่ชื่อชนกัน (path กับ query) ตู้เก็บไว้แค่ชิ้นเดียว

🗣 ศัพท์ที่เพิ่งเรียนไป
params / ActionController::Parameters
กล่องรวมค่าจาก query · path · form · JSON · ใช้เหมือน Hash แต่ไม่ใช่ Hash (class จริงคือ ActionController::Parameters) เรียกด้วย params[:page] หรือ params["page"] ได้เหมือนกัน · พิมพ์บอก AI ได้ว่า “coerce and validate params[:page] as a positive integer, default 1” จะได้โค้ดที่ไม่ล้มตอนเจอ "abc"
CSRF · authenticity_token
Cross-Site Request Forgery — เว็บอื่นแอบยิง request โดยใช้ cookie ของเรา · Rails กันด้วย token ที่ form_with และ csrf_meta_tags ใส่ให้ · ไม่มี token → ActionController::InvalidAuthenticityToken · 422 · ถาม senior ได้ว่า “API ตัวนี้ client เป็นใคร ใช้ cookie หรือ token — ต้องใช้ CSRF protection ไหม”
ParamsWrapper
ฟีเจอร์ที่ห่อ JSON body ซ้ำอีกชั้นด้วยชื่อตาม controller ({"title": "hi"} → มี params[:post][:title] ด้วย) · ถาม AI ได้ว่า “why does Rails duplicate my JSON params under the controller name key?” แล้วมันจะพาไปเจอ wrap_parameters
path segment · query string
ส่วนของ URL ที่อยู่ใน path (/posts/42) กับส่วนหลัง ? (?page=2) · เวลารายงานบั๊ก บอกทีมได้ว่า “id มาทาง path segment แต่ page มาทาง query string” คนฟังจะรู้ทันทีว่าต้องไปดูที่ routes หรือที่ลิงก์

5 · render กับ redirect_to — ยื่นจานให้เลย กับ ยื่นใบบอกทาง

สไลด์หน้า 62 บอกว่านี่คือจุดที่คนสับสนบ่อยที่สุดใน controller · ภาษาคนสั้น ๆ คือ:

  • render — “เอาหน้านี้ไปเลย” · server ส่ง HTML กลับใน request เดิม จบ
  • redirect_to — “ไปขอที่อื่นใหม่นะ” · server ส่งแค่ที่อยู่ใหม่กลับไป (ไม่มีหน้าเว็บ) แล้วเบราว์เซอร์ยิง request ใหม่อีกรอบเอง

นี่คือตารางจากสไลด์ เติมคอลัมน์ขวาว่าผมพิสูจน์ด้วยอะไร:

renderredirect_toยืนยันด้วยอะไรในบทนี้

instance variableยังอยู่ ใช้ต่อได้หายหมด ต้องโหลดใหม่ตอน render ช่อง input ยังมีค่าเดิม (value=" ") · ตอน redirect ต้องส่งชื่อไปทาง URL ใหม่

def create
  @post = Post.new(post_params)
  if @post.save
    redirect_to @post, notice: "สร้างแล้ว"        # สำเร็จ -> redirect

ผมเลยเขียนฉบับไม่ใช้ database ที่โครงเหมือนกันทุกบรรทัด — “บันทึกได้” แทนด้วย “กรอกชื่อมา”:

Gin เป็นยังไง? ผมเขียนตัวเดียวกันแล้วรันจริง — Gin ไม่ error แต่ต่อ body ทั้งสองก้อนเข้าด้วยกัน แล้วส่ง 302 ออกไป · โหมด debug พิมพ์เตือนแค่บรรทัดเดียว:

แปลว่าทั้งสองภาษา “ลืม return” เหมือนกัน — ต่างกันที่ Rails ล้มดัง ๆ ให้เห็นตอนพัฒนา ส่วน Gin ส่งของเพี้ยนออกไปเงียบ ๆ

ไฟล์ Gin ที่ใช้เทียบในบทนี้ (รัน go run . ผ่านจริง):

package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"

	"github.com/gin-gonic/gin"
)

func main() {
	gin.SetMode(gin.ReleaseMode)
	r := gin.New()

	// เทียบกับ GreetingsController#index
	r.GET("/hello", func(c *gin.Context) {
		name := c.DefaultQuery("name", "PEA")
		c.String(http.StatusOK, "Hello %s", name)
	})

	// redirect แล้วลืม return
	r.GET("/guard", func(c *gin.Context) {
		if c.Query("name") == "" {
			c.Redirect(http.StatusFound, "/")
		}
		c.String(http.StatusOK, "Hello %s", c.Query("name"))
	})

	for _, url := range []string{"/hello", "/hello?name=Nan", "/hello?name=", "/guard"} {
		w := httptest.NewRecorder()
		r.ServeHTTP(w, httptest.NewRequest("GET", url, nil))
		fmt.Printf("%-16s -> %d Location=%q body=%q\n", url, w.Code, w.Header().Get("Location"), w.Body.String())
	}
}

🏦 เทียบให้เห็นภาพ — เคาน์เตอร์ธนาคาร

render คือพนักงานที่ทำให้เสร็จที่เคาน์เตอร์เลย — กรอกฟอร์มผิด เขาก็ยื่นฟอร์มใบเดิมที่คุณเขียนไว้คืนพร้อมวงตรงที่ผิด (ข้อมูลเดิมยังอยู่ ไม่ต้องเขียนใหม่ทั้งใบ)
redirect_to คือพนักงานที่ทำรายการเสร็จแล้วยื่นบัตรคิวใบใหม่ให้ “เชิญรับสมุดที่ช่อง 5” — คุณต้องเดินไปช่อง 5 เอง (request ที่สอง) · ถ้าคุณเผลอกดเรียกคิวซ้ำ (refresh) ก็แค่ไปถามช่อง 5 ซ้ำ ไม่ได้โอนเงินซ้ำ

ที่ไม่เหมือนกัน: พนักงานธนาคารจริงจำได้ว่าคุณคือคนเดิมที่เพิ่งทำรายการเสร็จ
แต่ช่อง 5 ของ Rails (request ใหม่) จำอะไรจาก request แรกไม่ได้เลย — @name หายหมด · ของที่จะข้ามไปได้มีแค่สองทาง: ใส่ไว้ใน URL ปลายทาง (?name=Nan) หรือฝากไว้ใน flash (หัวข้อถัดไป) · และพนักงาน Rails ไม่หยุดทำงานทันทีที่ยื่นบัตรคิว ถ้าโค้ดยังมีบรรทัดต่อ เขาทำต่อ (DoubleRenderError)

🗣 ศัพท์ที่เพิ่งเรียนไป
render
ตอบกลับด้วยเนื้อหาใน request นี้เลย (view อื่น · plain: · json:) · render :new แปลว่า “ใช้ไฟล์ new.html.erb” ไม่ได้รัน def new · ถาม senior ได้ว่า “ตรงนี้ควร render พร้อม 422 หรือ redirect — ผู้ใช้ต้องเห็นข้อมูลที่กรอกไว้ไหม”
redirect_to · 302 · Location
ตอบ status 3xx พร้อม header Location บอกที่ใหม่ เบราว์เซอร์ยิง GET ตามไปเอง · พิมพ์บอก AI ได้ว่า “after a successful POST, redirect (Post/Redirect/Get) instead of rendering”
Post/Redirect/Get (PRG)
แพตเทิร์น “POST สำเร็จ → redirect ไปหน้า GET” เพื่อให้ refresh แล้วไม่ส่งฟอร์มซ้ำ · คือแถว “กด refresh แล้ว” ในตารางสไลด์ · คุยกับ senior ได้ว่า “action นี้ทำ PRG แล้วหรือยัง”
DoubleRenderError
error ตอนสั่งตอบกลับเกินหนึ่งครั้งใน action เดียว · สาเหตุอันดับหนึ่งคือ redirect_to แล้วลืม return · ถาม AI ได้ว่า “find code paths in this action that can call render or redirect_to twice”

6 · flash — ข้อความที่อยู่ได้ข้าม redirect ครั้งเดียวแล้วหาย

ปัญหาจากหัวข้อที่แล้ว: บันทึกสำเร็จแล้ว redirect ไปหน้าใหม่ · อยากบอกผู้ใช้ว่า “สร้างแล้ว” แต่ @ตัวแปร ข้าม request ไม่ได้
คำตอบคือ flash — กระดาษโน้ตที่ Rails ฝากไว้ในsession cookie ให้หน้าถัดไปอ่าน แล้วฉีกทิ้งทันทีหลังอ่าน (สไลด์หน้า 63: “อยู่ได้แค่ 1 request แล้วหายเอง”)

สไลด์หน้า 63 ฝั่ง controller มีสองบรรทัด — ตั้ง flash พร้อมกับ redirect ในคำสั่งเดียว: 

# controller (สไลด์หน้า 63)
redirect_to @post, notice: "บันทึกแล้ว"

7 · before_action — โค้ดที่รันก่อน action และ %i[...]

controller ที่มี show · edit · update ทุกตัวต้องเริ่มด้วยบรรทัดเดียวกัน: “หาโพสต์ตาม id”
แทนที่จะเขียนซ้ำสามที่ Rails ให้ประกาศไว้บนสุดครั้งเดียว — before_action (สไลด์หน้า 63): 

class PostsController < ApplicationController
  before_action :set_post,
                only: %i[show edit update]

  def show; end     # @post พร้อมใช้แล้ว

  private

  def set_post
    @post = Post.find(params[:id])
  end
end

อ่านเป็นภาษาคน:

  • before_action :set_post — “ก่อนเข้า action ให้เรียก method set_post ก่อน”
  • only: %i[show edit update] — “แต่เฉพาะสาม action นี้” (index · new · create ไม่มี id ให้หา)
  • def show; end — action ว่างเขียนบรรทัดเดียว (; คั่นแทนขึ้นบรรทัด) · ว่างได้เพราะ @post ถูกตั้งไว้แล้ว และ implicit render ทำที่เหลือ
  • private — method ข้างล่างไม่ใช่ action · route ชี้มาหาไม่ได้

%i[...] คืออะไร? เป็นวิธีเขียน Array ของ Symbol แบบสั้น — รันดู:

$ ruby -e 'p %i[show edit update]; p %w[show edit update]; p %i[show edit update] == [:show, :edit, :update]'
[:show, :edit, :update]
["show", "edit", "update"]
true

%i = Array ของ symbol · %w = Array ของ string · คั่นด้วยช่องว่าง ไม่ต้องใส่ : หรือจุลภาค (Symbol อยู่ใน บทเรียน 92) · สังเกตว่า scaffold ของ Rails เขียน %i[ show edit update destroy ] มีเว้นวรรคในวงเล็บ — ได้ผลเหมือนกัน

Post.find ต้องมี database (Day 2) · ผมเลยใช้ Hash แทน database แต่โครงเหมือนสไลด์ทุกอย่าง และเพิ่มอีกบรรทัด: ถ้าหาไม่เจอให้ redirect ออกไปพร้อม alert: 

# config/routes.rb (เพิ่ม)
get "/recipes",          to: "recipes#index", as: :recipes
get "/recipes/:id",      to: "recipes#show"
get "/recipes/:id/edit", to: "recipes#edit"

# app/controllers/recipes_controller.rb
class RecipesController < ApplicationController
  RECIPES = { "1" => "ข้าวมันไก่", "2" => "ส้มตำ" }   # ใช้แทน database ไปก่อน

  before_action :set_recipe, only: %i[show edit update]

  def index
    render plain: "index: @recipe = #{@recipe.inspect} · alert = #{flash[:alert].inspect}\n"
  end

  def show
    render plain: "show: @recipe = #{@recipe.inspect}\n"
  end

  def edit
    render plain: "edit: @recipe = #{@recipe.inspect}\n"
  end

  def update
    render plain: "update: @recipe = #{@recipe.inspect}\n"
  end

  private

  def set_recipe
    @recipe = RECIPES[params[:id]]
    redirect_to recipes_path, alert: "ไม่พบสูตรนี้" if @recipe.nil?
  end
end

  2. เพิ่มให้ส่งชื่อทาง path ได้ด้วย: /hello/Nan → Hello Nan (ใช้ action index ตัวเดิม ห้ามเขียน action ใหม่)
  3. ถ้าชื่อยาวเกิน 20 ตัวอักษร ให้ redirect ไปหน้าแรกพร้อม alert: "ชื่อยาวเกินไป" โดยใช้ before_action · ข้อความต้องโผล่ครั้งเดียวแล้วหาย

พิสูจน์: ยิง curl ทุกกรณี (ข้อ 3 ใช้ -i ให้เห็น 302 และใช้ cookie jar ให้เห็น flash) · ถ้าอยากลองเทสก่อน Day 4 จะสอนเต็ม ๆ ก็ดูตัวอย่างในเฉลยได้ 

# config/routes.rb

     .routes.draw do
  get "/hello",
      to: "greetings#index"

# app/controllers/greetings_controller.rb
class GreetingsController < ApplicationController
  before_action :reject_long_name, only: %i[index]   # ข้อ 3

  def index
    @name = params[:name].presence || "PEA"          # ข้อ 1
  end

  # ... new / create จากหัวข้อ 5

  private

  def reject_long_name
    if params[:name].to_s.length > 20
      redirect_to root_path, alert: "ชื่อยาวเกินไป"
    end
  end
end

10 · ทดสอบความเข้าใจ

action index ไม่มีบรรทัด render และคุณลบ app/views/greetings/index.html.erb ทิ้ง · ยิง curl -i /hello แบบธรรมดา (ไม่ใส่ header) จะได้ status อะไร?

ตัวเลือกที่ 3 ถูก · log จริงเขียนว่า No template found for GreetingsController#index, rendering head :no_content แล้ว Completed 204 No Content เพราะ curl ส่ง Accept: */* Rails จึงเดาว่าเป็น API ที่ไม่ต้องตอบเนื้อหา
ตัวเลือกที่ 1 กับ 2 ผิด — ไม่มี 500 หรือ 404 ในกรณีนี้ · ถ้าส่ง Accept: text/html แบบเบราว์เซอร์ถึงจะเป็น error และ status จริงคือ 406 (MissingExactTemplate) ไม่ใช่ทั้งสองตัวนั้น · ตัวเลือกที่ 4 ผิด — ไม่มี view ให้ใส่ใน layout · Rails ไม่ render layout เปล่า ๆ ให้
จุดที่ต้องจำ: ทดสอบด้วย curl/Postman แล้วได้ 204 อาจแปลว่า “ลืมสร้าง view” ไม่ใช่ “ผ่าน” · เช็ค log บรรทัด No template found

ส่ง JSON {"page": 2} (แนบ CSRF token ถูกต้อง) ไปที่ action หนึ่ง · params[:page] มีค่าอะไร?

ตัวเลือกที่ 2 ถูก · ผลรันจริง params[:page] = 2 และ params[:page] == 2 = true
ตัวเลือกที่ 1 ผิด — “string เสมอ” จริงเฉพาะ query · path · form (ส่ง ?page=2 ได้ "2" จริง) แต่ไม่จริงกับ JSON · ตัวเลือกที่ 3 ผิด — ParamsWrapper เพิ่มสำเนาไว้ใต้ชื่อ controller แต่ key เดิมที่ชั้นบนสุดยังอยู่ (เห็นใน log: {"title" => "hi", "post" => {"title" => "hi"}}) · ตัวเลือกที่ 4 ผิด — Ruby แปลง JSON 2 เป็น Integer ไม่ใช่ Float
จุดที่ต้องจำ: type ใน params ขึ้นกับว่าค่ามาทางไหน · อย่าเชื่อ type ของอะไรใน params แปลงและตรวจเองทุกครั้ง

ใช้ curl -X POST -d 'post[title]=hi' http://localhost:3000/posts ยิงตรง ๆ ไปที่แอป Rails ที่เพิ่ง rails new (ไม่ได้แก้ config อะไร) · จะได้อะไร?

ตัวเลือกที่ 4 ถูก · log จริง: Can't verify CSRF token authenticity. → Completed 422 Unprocessable Content → action ไม่ถูกรันเลย
ตัวเลือกที่ 1 ผิด — Rails อ่าน params ได้แล้ว (เห็นในบรรทัด Parameters:) แต่ไม่ปล่อยเข้า action · ตัวเลือกที่ 2 ผิด — Rails ไม่ได้แยกว่าเป็นเบราว์เซอร์หรือไม่ ส่ง token ด้วย curl ก็ผ่าน (ได้ 200 ในหัวข้อ 4) · ตัวเลือกที่ 3 ผิด — แอปนี้ยังไม่มีระบบ login เลย (รอ Day 4 Keycloak)
จุดที่ต้องจำ: POST แล้วได้ 422 + InvalidAuthenticityToken = ลืมส่ง token · แก้ด้วยการส่ง token (หรือใช้ form_with) ไม่ใช่ปิดระบบป้องกัน

controller มี before_action :set_post, only: %i[show edit update] แต่เขียนไว้แค่ def index กับ def show · ตอน development เปิด /posts (index) จะเกิดอะไร?

ตัวเลือกที่ 1 ถูก · ผลจริงตอนผมยังไม่เขียน update: /recipes (index) ได้ 404 พร้อม AbstractController::ActionNotFound (The update action could not be found for the :set_recipe callback …) — Rails ตรวจทั้ง controller ไม่ได้ตรวจแค่ action ที่ถูกเรียก
ตัวเลือกที่ 2 ผิด — เป็นสิ่งที่คนส่วนใหญ่เดา แต่ raise_on_missing_callback_actions = true ใน development.rb ทำให้ไม่ปกติ · ตัวเลือกที่ 3 ผิด — ไม่ใช่ NoMethodError และไม่ใช่ 500 · ตัวเลือกที่ 4 ผิด — ไม่ใช่แค่คำเตือน request ล้มจริง
จุดที่ต้องจำ: ใส่ใน only: เฉพาะ action ที่มีอยู่จริง · เจอ 404 ทั้ง controller ให้ดู only: ก่อน
