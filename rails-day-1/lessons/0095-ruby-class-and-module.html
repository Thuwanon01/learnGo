Class และ Module — attr_accessor, @ตัวแปร และ mixin ที่มาของ concerns

~25 นาที · ควรผ่าน บทเรียน 94 (nil) มาก่อน · ถ้าลืม interface ของ Go ทวนได้ที่ บทเรียน 10

คุณเขียน struct ของ Go กับ class ของ TypeScript มาแล้ว บทนี้เลยไม่ต้องเริ่มจากศูนย์ แค่ดูว่า Ruby เขียนเรื่องเดียวกันต่างไปยังไง
สไลด์หน้า 28–29 มีโค้ดแค่สองก้อน แต่ถ้าอ่านไม่ออกจะติดทั้งคอร์ส เพราะ ทุก model ของ Rails เป็น class (class Post < ApplicationRecord) และของที่ Rails เรียกว่า concern ก็คือ module ที่จะเรียนในบทนี้นั่นเอง
มีกับดักหนึ่งที่ต้องระวังเป็นพิเศษ: สะกดชื่อ @ตัวแปร ผิด Ruby ก็ไม่เตือน แม้จะเปิด -w แล้วก็ตาม ส่วน Go กับ TypeScript ฟ้องตั้งแต่ยังไม่ได้รัน · หัวข้อ 3 รันให้ดูทั้งสามภาษา

ทุกกล่องที่เป็นผลรันในบทนี้ก็อปมาจากเครื่องจริง ไม่ได้พิมพ์เอง · โค้ด Ruby ล้วนรันด้วย ruby ไฟล์.rb · ส่วนที่เกี่ยวกับ Rails รันในโปรเจกต์ที่สร้างด้วย rails new wongnok_blog --database=postgresql --css=tailwind ตามสไลด์หน้า 40 · ฝั่ง Go ใช้ go1.26.5 ส่วน TypeScript ตรวจด้วย tsc --noEmit --strict (tsc 7.0.2) · เลข 0x0000… ในผลของ p เป็นที่อยู่ใน memory รันแต่ละรอบจะไม่ตรงกัน เป็นเรื่องปกติ

1 · Class เดียวกัน เขียนสามภาษา

เริ่มจากสไลด์หน้า 28 ซึ่งเขียน Post ตัวเดียวกันด้วยสามภาษา แต่ละตัวมีช่อง title หนึ่งช่อง กับ method greeting ที่คืนคำทักทาย:

Go

type Post struct {
  Title string
}

func (p Post) Greeting() string {
  return "Hello, " + p.Title
}

// ไม่มี inheritance

TypeScript

class Post {
  title: string

  constructor(title: string) {
    this.title = title
  }

  greeting() {
    return `Hello, ${this.title}`
  }
}

Ruby

# post.rb — สามบรรทัดล่างเพิ่มเองเพื่อรันให้เห็นผล
class Post
  attr_accessor :title

  def initialize(title)
    @title = title
  end

  def greeting
    "Hello, #{@title}"
  end
end

post = Post.new("Hi")
puts post.greeting
puts post.title
post.title = "Ruby"
puts post.greeting
$ ruby post.rb
Hello, Hi
Hi
Hello, Ruby

ผมรันฝั่ง Go กับ TypeScript ด้วย (เติม package main กับ main() ให้ Go และบรรทัด console.log(new Post("Hi").greeting()) ให้ TS) ทั้งคู่พิมพ์ Hello, Hi เหมือนกัน · ทีนี้ลองจับคู่ทีละบรรทัดดูว่าอะไรตรงกับอะไร:

เรื่องGoTypeScriptRuby
ประกาศว่ามีช่องอะไร Title string ใน struct title: string ไม่ต้องประกาศ · ตั้ง @title = … เมื่อไหร่ก็มีเมื่อนั้น
ฟังก์ชันที่รันตอนสร้าง ไม่มี · ใช้ Post{Title: "Hi"} หรือเขียน NewPost() เอง constructor(title) def initialize(title) · เรียกผ่าน Post.new("Hi")
อ้างถึงช่องของตัวเอง p.Title (p คือ receiver) this.title @title · เครื่องหมาย @ ทำหน้าที่แทน this.
ให้คนนอกอ่าน/เขียนช่องได้ ตัวใหญ่ = export public เป็นค่าเริ่มต้น ต้องเปิดเองด้วย attr_accessor (หัวข้อ 2)
แทรกค่าลงใน string "Hello, " + p.Title `Hello, ${this.title}` "Hello, #{@title}" · ต้องใช้ฟันหนูคู่ "
คืนค่า return return บรรทัดสุดท้ายของ method คือค่าที่คืน ไม่ต้องเขียน return
สืบทอด class ไม่มี (ใช้ embedding แทน) class Recipe extends Post class Recipe < Post (หัวข้อ 6)

2 · attr_accessor คือ method ที่เขียน method ให้เรา

เรื่องนี้ต่างจาก TypeScript ตรงที่ ใน Ruby คนนอกแตะ @title ตรง ๆ ไม่ได้เลย เพราะ @title เป็นของภายใน object ถ้าอยากให้คนข้างนอกอ่านหรือแก้ได้ ต้องมี method ไว้ให้เรียก

ถ้าเขียน method พวกนี้เองทั้งหมดก็จะออกมาแบบนี้ ซึ่งยาวและน่าเบื่อ: 

class D
  def title            # getter — อ่านค่า
    @title
  end

  def title=(value)    # setter — ชื่อ method มี = ติดท้ายจริง ๆ
    @title = value
  end
end

attr_accessor :title บรรทัดเดียวจะสร้างสอง method นี้ให้ · ถ้าต้องการแค่ครึ่งเดียวก็มีอีกสองตัวให้เลือก ลองให้ Ruby บอกเองว่าแต่ละตัวสร้าง method อะไรไว้บ้าง (instance_methods(false) แปลว่า "ขอเฉพาะ method ที่ class นี้มีเอง ไม่เอาของที่สืบทอดมา"): 

class A; attr_reader   :title; end
class B; attr_writer   :title; end
class C; attr_accessor :title; end
# D คือ class ที่เขียนสอง method เองข้างบน

p A.instance_methods(false)
p B.instance_methods(false)
p C.instance_methods(false)
p D.instance_methods(false)
$ ruby methods.rb
[:title]
[:title=]
[:title, :title=]
[:title, :title=]

C กับ D ได้ method ชุดเดียวกันทุกตัว แปลว่า attr_accessor ไม่ได้มีความสามารถพิเศษอะไร มันแค่เขียน def ให้เราแทน · ทีนี้มาดูว่าถ้าเรียก method ที่ไม่ได้สร้างไว้จะเกิดอะไรขึ้น ลองใช้ attr_reader แล้วสั่งแก้ค่า: 

# reader.rb
class Post
  attr_reader :title

  def initialize(title)
    @title = title
  end
end

post = Post.new("Hi")
puts post.title
post.title = "Ruby"
$ ruby reader.rb
Hi
reader.rb:12:in '<main>': undefined method 'title=' for an instance of Post (NoMethodError)

post.title = "Ruby"
    ^^^^^^^^

ให้สังเกตว่า error บอกว่าไม่มี method ชื่อ 'title=' ไม่ได้บอกว่า "ช่องนี้เป็น read-only" เพราะในมุมของ Ruby post.title = "Ruby" ก็คือการเรียก method ชื่อ title= ส่วนช่องว่างก่อน = เป็นแค่ syntax ที่ทำให้อ่านง่าย · ถ้าสลับไปใช้ attr_writer ก็จะพังกลับด้าน คือตั้งค่าได้แต่อ่านไม่ได้: 

$ ruby writer.rb      # attr_writer :title แล้วเรียก puts post.title
writer.rb:11:in '<main>': undefined method 'title' for an instance of Post (NoMethodError)

puts post.title
         ^^^^^^
🏠 เทียบให้เห็นภาพ

ลองนึกว่า object หนึ่งตัวเป็นบ้านหลังหนึ่ง และ @title เป็นของที่วางอยู่ในบ้าน คนข้างนอกเดินเข้าไปหยิบเองไม่ได้ ต้องมีช่องให้ใช้:

  • attr_reader = หน้าต่างกระจก มองเห็นของข้างในได้ แต่ยื่นมือเข้าไปเปลี่ยนไม่ได้
  • attr_writer = ช่องหย่อนจดหมาย ใส่ของใหม่เข้าไปได้ แต่มองไม่เห็นว่าข้างในมีอะไร
  • attr_accessor = ประตู ทั้งมองเห็นและเปลี่ยนของได้

ที่ไม่เหมือนกัน: บ้านจริงที่ไม่มีหน้าต่างก็ยังมีคนแอบส่องหรืองัดเข้าไปได้ ส่วน Ruby ก็มีช่องทางลับคล้าย ๆ กันอย่าง instance_variable_get ให้คนดื้อใช้ ดังนั้น attr_reader ไม่ใช่ระบบความปลอดภัย มันแค่ประกาศว่า "ตามปกติให้อ่านได้อย่างเดียว" และอีกข้อที่ต่างคือหน้าต่างของบ้านต้องเจาะผนังทีละช่อง แต่ attr_accessor :title, :body เปิดหลายช่องได้ในบรรทัดเดียว

🏷️ ศัพท์ที่เอาไปคุยต่อได้
instance variable (@title)
ตัวแปรของ object แต่ละตัว ขึ้นต้นด้วย @ ใช้แทน this.title ของ TS · ถาม senior ได้ว่า "ค่านี้ควรเก็บเป็น instance variable หรือคำนวณสดใน method ดีครับ"
getter / setter (reader / writer)
method ที่อ่านค่าคือ getter ส่วน method ที่ตั้งค่าคือ setter (ชื่อลงท้ายด้วย =) · attr_reader / attr_writer / attr_accessor สร้างให้อัตโนมัติ · พิมพ์บอก AI ได้ว่า "เปลี่ยน attr_accessor เป็น attr_reader ให้หน่อย ไม่อยากให้ข้างนอกแก้ title ได้"
initialize
method ที่ Post.new(...) เรียกให้อัตโนมัติ ตรงกับ constructor ของ TS · เราไม่ได้เรียก initialize ตรง ๆ แต่เรียกผ่าน new · ถาม senior ได้ว่า "ค่า default ของ field นี้ควรตั้งใน initialize หรือให้คนเรียกส่งมาเองครับ"
class macro
method ที่เรียกในตัว class เพื่อเขียน method อื่นให้ เช่น attr_accessor · Rails ใช้ท่านี้เยอะมาก (has_many, validates ซึ่งจะเจอใน Day 2) · ถาม senior ได้ว่า "บรรทัด has_many นี่เป็น class macro ใช่ไหมครับ มันสร้าง method อะไรให้บ้าง"

3 · @ตัวแปร ไม่ต้องประกาศ — สะกดผิดก็ไม่มีใครเตือน

สไลด์หน้า 28 บอกว่า @title ไม่ต้องประกาศล่วงหน้า อ่านค่าที่ยังไม่เคยตั้งจะได้ nil ไม่ error ข้อนี้ถูก และเอกสารทางการก็เขียนไว้ตรง ๆ · แต่ฟังดูเป็นข้อดีอย่างเดียว ทั้งที่มันมีผลเสียซ่อนอยู่ ลองทายดูก่อน: 

# typo.rb — ตั้งชื่อ @title แต่ใน greeting พิมพ์ผิดเป็น @titel
class Post
  attr_accessor :title

  def initialize(title)
    @title = title
  end

  def greeting
    "Hello, #{@titel}"
  end
end

post = Post.new("Hi")
puts post.greeting
p post.greeting

รันด้วย ruby typo.rb แล้วรันอีกรอบด้วย ruby -w typo.rb (เปิด warning ทุกตัว) · คิดว่าได้ error, warning หรือได้ข้อความอะไรออกมา? 

$ ruby typo.rb
Hello,
"Hello, "
# exit code 0

$ ruby -w typo.rb
Hello,
"Hello, "
# exit code 0 — ไม่มี warning สักบรรทัด

ไม่ error และไม่มี warning ทั้งสองรอบ · @titel เป็นตัวแปรที่ไม่เคยถูกตั้งค่า เลยได้ nil · พอแทรก nil ลงใน string ด้วย #{} จะได้ string ว่าง (ทวนเรื่อง nil ได้ในบทเรียน 94) · บรรทัด puts จึงดูเหมือนพิมพ์ "Hello, " เฉย ๆ ต้องใช้ p ถึงจะเห็นว่ามีช่องว่างตามหลัง

ถ้าทำแบบเดียวกันใน Go หรือ TypeScript จะพังตั้งแต่ยังไม่ได้รัน: 

$ tsc --noEmit --strict typo.ts
typo.ts(9,27): error TS2551: Property 'titel' does not exist on type 'Post'. Did you mean 'title'?

$ go run main.go
# command-line-arguments
./main.go:10:23: p.Titel undefined (type Post has no field or method Titel)

สิ่งที่ได้จากตัวอย่างนี้: nil จาก @ตัวแปร ที่พิมพ์ผิดจะไม่พังตรงที่พิมพ์ผิด แต่จะถูกส่งต่อไปเรื่อย ๆ จนไปพังที่อื่น ซึ่งมักอยู่ไกลจากจุดที่ผิดจริง · ตัวอย่างข้างล่างให้ method หนึ่งอ่าน @author ที่ไม่เคยถูกตั้งค่า แล้วเรียก .upcase ต่อ: 

# ivar.rb
class Post
  attr_accessor :title

  def initialize(title)
    @title = title
  end

  # @author ไม่เคยถูกตั้งค่า
  def author_name
    @author.upcase
  end
end

Post.new("Hi").author_name
$ ruby ivar.rb
ivar.rb:11:in 'Post#author_name': undefined method 'upcase' for nil (NoMethodError)

    @author.upcase
           ^^^^^^^
	from ivar.rb:15:in '<main>'

error ข้างบนบอกว่า "upcase ใช้กับ nil ไม่ได้" แต่ไม่ได้บอกว่าต้นเหตุคือ @author ไม่เคยถูกตั้งค่า ถ้าเจอ undefined method '…' for nil ใน Rails ให้สงสัยไว้ก่อนเลยว่าพิมพ์ชื่อ @ตัวแปร ผิด (จะเจอบ่อยเป็นพิเศษในบทเรียน 102–103 เพราะ controller ตั้ง @post แล้ว view อ่าน @post ถ้าสองฝั่งสะกดไม่ตรงกัน view ก็ได้ nil)

ตัวแปรธรรมดาที่ไม่มี @ ไม่เป็นแบบนี้ · ถ้าพิมพ์ "Hello, #{titel}" โดยไม่มี @ จะพังทันทีด้วย undefined local variable or method 'titel' for main (NameError) · มีแค่ตัวแปรที่ขึ้นต้นด้วย @ เท่านั้นที่ได้ nil แบบเงียบ ๆ

4 · Post.new("Hi") กับ Post.new — จำนวน argument ต้องตรงกัน

ถึง Ruby จะไม่สนใจเรื่อง type แต่สนใจจำนวน argument · initialize(title) ประกาศว่าต้องรับ 1 ตัว ถ้าเรียก Post.new โดยไม่ส่งอะไรไปจะพังทันที: 

$ ruby argerr.rb     # บรรทัด 7: Post.new("Hi") ผ่าน · บรรทัด 8: Post.new พัง
argerr.rb:2:in 'Post#initialize': wrong number of arguments (given 0, expected 1) (ArgumentError)

    caller: argerr.rb:8
    | Post.new
          ^^^^
    callee: argerr.rb:2
    |   def initialize(title)
            ^^^^^^^^^^
	from argerr.rb:8:in '<main>'

วิธีอ่าน error ตัวนี้: given 0, expected 1 แปลว่าส่งมา 0 ตัวแต่ต้องการ 1 ตัว · caller คือบรรทัดที่เรียก ส่วน callee คือ method ที่ถูกเรียก · ให้สังเกตว่า Ruby รายงานว่า error เกิดใน 'Post#initialize' ทั้งที่เราเขียน new ซึ่งยืนยันว่า new ส่งต่อไปให้ initialize · ส่วน TypeScript จับ error เดียวกันนี้ได้ตั้งแต่ยังไม่รัน: error TS2554: Expected 1 arguments, but got 0.

5 · puts กับ p — object พิมพ์ตัวเองออกมาเป็นอะไร

ถ้าเอา object ทั้งตัวไปพิมพ์ จะเห็นว่า Ruby มีวิธีแปลง object เป็นข้อความอยู่สองแบบ:

  • to_s สำหรับให้คนทั่วไปอ่าน · puts และ "#{}" เรียกตัวนี้
  • inspect สำหรับให้โปรแกรมเมอร์ debug · p เรียกตัวนี้
# tos.rb — ต่อจาก class Post ที่มีแค่ attr_accessor :title กับ initialize
post = Post.new("Hi")
puts post
p post
puts "โพสต์: #{post}"

class Post          # เปิด class เดิมเพิ่ม method ได้ (Ruby ยอม)
  def to_s
    "Post(#{@title})"
  end
end

puts post
p post
puts "โพสต์: #{post}"
$ ruby tos.rb
#<Post:0x0000000108a5bbb8>
#<Post:0x0000000108a5bbb8 @title="Hi">
โพสต์: #<Post:0x0000000108a5bbb8>
Post(Hi)
#<Post:0x0000000108a5bbb8 @title="Hi">
โพสต์: Post(Hi)

ก่อนเขียน to_s เอง puts พิมพ์ได้แค่ชื่อ class กับที่อยู่ใน memory ซึ่งไม่ค่อยมีประโยชน์ · ส่วน p แสดง @title="Hi" ให้ด้วย จึงเหมาะกับการ debug มากกว่า · เมื่อเขียน to_s เองแล้ว ทั้ง puts และ "#{}" เปลี่ยนตาม แต่ p ยังแสดงเหมือนเดิม · คล้ายกับ String() ของ Go ที่ fmt.Println เรียกให้อัตโนมัติ

object ของ Rails เขียน inspect ไว้ให้แล้ว ลองดู Post ที่เป็น model จริง: 

$ bin/rails runner 'p Post.new(title: "Hi")'
#<Post id: nil, title: "Hi", created_at: nil, updated_at: nil>

6 · Inheritance ด้วย < และ super

Go ไม่มีการสืบทอด class ส่วน TS ใช้ extends · Ruby ใช้เครื่องหมาย < (อ่านว่า "เป็นลูกของ") และใช้ super เพื่อเรียก method ชื่อเดียวกันของ class แม่: 

# inherit.rb — ใช้ Post จากหัวข้อ 1
class Recipe < Post
  attr_accessor :minutes

  def initialize(title, minutes)
    super(title)               # ให้ Post#initialize ตั้ง @title ให้
    @minutes = minutes
  end

  def greeting
    super + " (#{@minutes} นาที)"  # เอาผลของ Post#greeting มาต่อท้าย
  end
end

7 · Module + include — ยกโค้ดทั้งก้อนไปใส่ class

ลองนึกว่าต้องการ method slug (แปลงชื่อเป็นแบบที่ใส่ใน URL ได้ เช่น hello-ruby-world) ให้ใช้ได้ทั้ง Post และ Recipe และ class อื่นที่ไม่ได้เป็นแม่ลูกกันอีกหลายตัว · ถ้าใช้ inheritance ก็ต้องให้ทุก class มีแม่ตัวเดียวกัน ซึ่งไม่สมเหตุสมผล · Ruby แก้ปัญหานี้ด้วย module คือก้อนของ method ที่สร้าง object เองไม่ได้ แต่เอาไปใส่ class ไหนก็ได้ด้วย include

นี่คือโค้ดจากสไลด์หน้า 29 ตามที่เขียนไว้ทุกตัวอักษร:

module Sluggable
  def slug
    title.downcase.tr(" ", "-")
  end
end

class Post
  include Sluggable
end

Post.new.slug      # ใช้ได้เลย

ถ้าก็อปโค้ดนี้ไปรันตรง ๆ จะพัง ไม่ได้ "ใช้ได้เลย" อย่างที่ comment บอก: 

$ ruby slide29.rb
slide29.rb:3:in 'Sluggable#slug': undefined local variable or method 'title' for an instance of Post (NameError)

    title.downcase.tr(" ", "-")
    ^^^^^
	from slide29.rb:11:in '<main>'

สาเหตุคือ slug เรียก method title แต่ Post ในสไลด์ไม่มี method นี้ · สไลด์ตั้งใจละส่วนนั้นไว้เพื่อให้โค้ดสั้น แต่ ส่วนที่ include สำเร็จจริงคือ slug ถูกเรียกได้ (error เกิดข้างใน 'Sluggable#slug' แปลว่าเข้าไปถึง method แล้ว) · ถ้าเติม attr_accessor :title แต่ยังเรียก Post.new.slug โดยไม่ตั้ง title ก็จะได้ undefined method 'downcase' for nil แทน ซึ่งเป็นกับดักเดียวกับหัวข้อ 3

เติม title ให้ Post แล้วรันใหม่ พร้อมถาม Ruby ว่า Post มีบรรพบุรุษเป็นใครบ้าง: 

# sluggable.rb
module Sluggable
  def slug
    title.downcase.tr(" ", "-")
  end
end

class Post
  include Sluggable
  attr_accessor :title

  def initialize(title)
    @title = title
  end
end

อ่านผลทีละบรรทัด:

  • "hello-ruby-world" — downcase แปลงเป็นตัวเล็ก แล้ว tr(" ", "-") แทนช่องว่างด้วยขีด
  • [Post, Sluggable, Object, Kernel, BasicObject] — นี่คือลำดับที่ Ruby ใช้หา method · เมื่อเรียก post.slug Ruby จะหาใน Post ก่อน ถ้าไม่เจอก็ไปหาใน Sluggable แล้วต่อไปเรื่อย ๆ ทางขวา · ให้สังเกตว่า module ถูกแทรกไว้ระหว่าง class กับแม่ของมัน (Kernel ก็เป็น module ที่ Object include ไว้ และเป็นที่อยู่ของ puts กับ p)
  • is_a?(Sluggable) เป็น true — object ที่ include module ถือว่า "เป็น" module นั้นด้วย
  • Sluggable.new พัง — module สร้าง object เองไม่ได้ ทำได้แค่เอาไปใส่ class อื่น

และจุดที่สำคัญที่สุด: ข้างใน slug คำว่า title หมายถึง title ของ object ที่เรียกมัน (คือ post ตัวนั้น) · module ไม่มีข้อมูลเป็นของตัวเอง แต่จะใช้ข้อมูลของ object ที่ include มันไปใช้

เทียบกับ Go และ TypeScript

สไลด์หน้า 29 เทียบ module กับสองอย่างที่คุณรู้จักแล้ว · interface ของ Go และ TS เป็นแค่รายการสิ่งที่ต้องมี คนที่ implement ต้องเขียน method เองทุกตัว (ทวน interface ของ Go ได้ในบทเรียน 10 และของ TS ในบทเรียน 64) · ส่วน module ของ Ruby มีโค้ดที่ทำงานได้จริงมาด้วย include แล้วใช้ได้ทันที ซึ่งใกล้กับ struct embedding ของ Go มากกว่า (ที่เคยใช้ตอน suite.Suite ในบทเรียน 30) 

// Go: struct embedding — รันจริงได้ hello-go-world
package main

import (
	"fmt"
	"strings"
)

type Sluggable struct {
	Title string
}

func (s Sluggable) Slug() string {
	return strings.ReplaceAll(strings.ToLower(s.Title), " ", "-")
}

type Post struct {
	Sluggable // ฝัง struct — ได้ Slug() มาใช้ฟรี
}

func main() {
	p := Post{Sluggable{Title: "Hello Go World"}}
	fmt.Println(p.Slug())
}

ฝั่ง TypeScript สไลด์เขียนว่า class Post implements Timestamped พร้อม comment "ต้องเขียน method เองทุกตัว" · ลองดูว่าถ้า implements แล้วไม่เขียน method เองจะเป็นยังไง: 

// implements.ts
interface Sluggable {
  slug(): string
}

class Post implements Sluggable {
  title = "Hello TS World"
  // ไม่ได้เขียน slug() เอง
}

🔌 เทียบให้เห็นภาพ

interface เหมือนใบประกาศรับสมัครงาน ที่เขียนว่า "ต้องขับรถเป็น" คนที่มาสมัครต้องไปฝึกขับรถเอง ใบประกาศไม่ได้สอนอะไรให้

module เหมือนปลั๊กอินที่เสียบเข้าเครื่องแล้วใช้ได้ทันที · include Sluggable คือการเสียบปลั๊กอิน "ทำ slug ได้" เข้าไปใน Post · class อื่นก็เสียบปลั๊กอินตัวเดียวกันได้ โดยไม่ต้องเป็นญาติกัน

ที่ไม่เหมือนกัน: ปลั๊กอินจริงมักทำงานได้ด้วยตัวเอง แต่ module ต้องใช้ของจากเครื่องที่มันถูกเสียบ เช่น Sluggable ต้องการให้ Post มี title ถ้าไม่มีก็พัง และ Ruby ไม่ได้ตรวจตอนเสียบ แต่จะพังตอนเรียกใช้ครั้งแรก · อีกข้อคือปลั๊กอินจริงถอดออกได้ แต่ module ที่ include ไปแล้วถอดออกไม่ได้

ถ้ามีสอง module ที่มี method ชื่อเดียวกัน แล้ว include ทั้งคู่ จะเกิดอะไรขึ้น ลองทายดู: 

# predict2.rb
module Sluggable
  def label
    "จาก Sluggable"
  end
end

module Timestamped
  def label
    "จาก Timestamped"
  end
end

class Post
  include Sluggable
  include Timestamped
end

puts Post.new.label
p Post.ancestors

label ได้ค่าจาก module ไหน และ Post.ancestors เรียงลำดับยังไง? (บางคนคิดว่าตัวที่ include ก่อนได้สิทธิ์ก่อน บางคนคิดว่า Ruby จะฟ้องว่าชื่อซ้ำ) 

$ ruby predict2.rb
จาก Timestamped
[Post, Timestamped, Sluggable, Object, Kernel, BasicObject]

module ที่ include ทีหลังจะถูกแทรกไว้ใกล้ class มากกว่า จึงถูกหาเจอก่อน · Ruby ไม่ฟ้องว่าชื่อซ้ำ แต่ใช้ตัวที่เจอก่อนตามลำดับใน ancestors ซึ่งอ่านจากซ้ายไปขวา

ถ้า Post เขียน def label เองด้วย ของ Post จะชนะเสมอ เพราะอยู่ซ้ายสุด (ผมรันแยกแล้ว Post ที่มี def label ของตัวเองพิมพ์ "จาก class" ออกมา) · และถ้าใน method นั้นเรียก super ก็จะไปเรียก method ชื่อเดียวกันใน module ตัวถัดไปทางขวา ซึ่งเป็นวิธีเดียวกับที่ภารกิจท้ายบทใช้

🏷️ ศัพท์ที่เอาไปคุยต่อได้
module
ก้อนของ method (และค่าคงที่) ที่สร้าง object เองไม่ได้ · ใช้ได้สองแบบคือเอาไปใส่ class (mixin) หรือใช้เป็น namespace เช่น ActiveRecord::Base · ถาม senior ได้ว่า "method นี้ควรอยู่ใน module แยกหรือเขียนไว้ใน class ตรง ๆ ดีครับ"
mixin / include
การเอา method ของ module ไปใส่ใน class ให้ instance ของ class นั้นใช้ได้ · พิมพ์บอก AI ได้ว่า "แยก method slug ออกมาเป็น module แล้ว include ใน Post กับ Recipe ให้หน่อย"
ancestors / method lookup
รายการที่ Ruby ไล่หา method จากซ้ายไปขวา · ใช้ debug ได้เมื่อไม่แน่ใจว่า method ที่ถูกเรียกมาจากไหน · ใช้คู่กับ Post.instance_method(:title).owner ที่บอกว่า method นั้นอยู่ใน class/module ไหน · พิมพ์บอก AI ได้ว่า "ช่วยดู Post.ancestors หน่อยว่า method save ที่ถูกเรียกจริงมาจาก module ไหน"
super
เรียก method ชื่อเดียวกันของตัวถัดไปใน ancestors (อาจเป็น class แม่หรือ module ก็ได้) · super เฉย ๆ ส่ง argument ทั้งหมดต่อไปด้วย ส่วน super() ไม่ส่งอะไรเลย · ถาม senior ได้ว่า "ตรงนี้ควรเขียน super(title) ให้ชัด หรือ super เฉย ๆ ก็พอครับ"

8 · Concern — module ของ Rails ที่มีโฟลเดอร์ให้เก็บ

สามเรื่องที่ควรสังเกต:

  1. ไม่ต้อง require ไฟล์ sluggable.rb · Rails โหลดให้เองเพราะ app/models/concerns อยู่ในรายการโฟลเดอร์ที่ Rails โหลดอัตโนมัติ (autoload path) · ไฟล์ชื่อ sluggable.rb ต้องมี Sluggable อยู่ข้างใน (ชื่อไฟล์กับชื่อ module ต้องตรงกัน ซึ่งจะเรียนในบทเรียน 99) · และไม่ต้องเขียนเป็น Concerns::Sluggable เพราะโฟลเดอร์ concerns ถูกนับเป็นจุดเริ่มต้น ไม่ใช่ namespace
  2. Post ของจริงมีบรรพบุรุษ 82 ตัว ไม่ใช่ 5 ตัวเหมือน Post ของเรา · แต่ Sluggable ยังอยู่อันดับ 2 ถัดจาก Post เหมือนเดิม ส่วนที่เหลือคือ module ที่ Rails include มาให้
  3. extend ActiveSupport::Concern เป็นบรรทัดที่ concern ของ Rails นิยมเขียนไว้ · แต่ concern ง่าย ๆ ที่มีแค่ method ธรรมดาอย่างตัวนี้จะไม่มีบรรทัดนี้ก็ได้ (ผมลองลบออกแล้วรัน slug ก็ยังได้ "hello-ruby-world" เหมือนเดิม) · มันจะมีประโยชน์ตอนใช้ included do … end เพื่อใส่ของอย่าง validates หรือ scope ลงใน model ซึ่งจะเจอใน Day 2

Concern
module ของ Rails ที่เก็บไว้ใน app/models/concerns/ หรือ app/controllers/concerns/ และมัก extend ActiveSupport::Concern · ใช้รวม method ที่หลาย model หรือหลาย controller ใช้ร่วมกัน · ถาม senior ได้ว่า "logic นี้มีสาม model ใช้เหมือนกัน แยกเป็น concern ดีไหมครับ"
autoload path
โฟลเดอร์ที่ Rails โหลดไฟล์ให้เองตามชื่อ ไม่ต้อง require · ดูรายการทั้งหมดได้ด้วย bin/rails runner 'pp ActiveSupport::Dependencies.autoload_paths' · ถ้าเจอ uninitialized constant ใน Rails ให้เช็คก่อนว่าชื่อไฟล์กับชื่อ class ตรงกันไหม · ถาม senior ได้ว่า "ไฟล์นี้ควรวางใน app/models/concerns หรือ lib ดีครับ ต้อง require เองไหม"

9 · ทดสอบความเข้าใจ

class นี้มี attr_reader :title อย่างเดียว · ถ้าสั่ง post.title = "ใหม่" จะเกิดอะไรขึ้น?

ตัวเลือกที่ 3 ถูก · ผลรันจริงในหัวข้อ 2 คือ undefined method 'title=' for an instance of Post (NoMethodError) · post.title = "ใหม่" คือการเรียก method ชื่อ title= ซึ่ง attr_reader ไม่ได้สร้างให้

ตัวเลือกที่ 1 ผิดเพราะ reader สร้างแค่ getter · ตัวเลือกที่ 2 ผิดเพราะ Ruby ไม่ทิ้งคำสั่งไปเงียบ ๆ แต่พังทันที · ตัวเลือกที่ 4 ผิดเพราะ Ruby ไม่ได้ไปตรวจว่าช่องนี้แก้ได้ไหม แค่หา method ไม่เจอ (FrozenError มีอยู่จริง แต่ใช้กับ object ที่ถูก freeze) · จุดที่ต้องจำ: = หลังชื่อ method ก็เป็นส่วนหนึ่งของชื่อ method ถ้าเห็น error ที่มี 'xxx=' แปลว่าไม่มี setter

ใน initialize ตั้ง @title = title แต่ใน method อื่นพิมพ์ผิดเป็น @titel.upcase · ผลจริงคืออะไร?

ตัวเลือกที่ 1 ถูก · @titel ที่ไม่เคยถูกตั้งค่าได้ nil แบบเงียบ ๆ แล้วไปพังตอนเรียก .upcase · ผลรันจริงในหัวข้อ 3 คือ undefined method 'upcase' for nil (NoMethodError)

ตัวเลือกที่ 2 เป็นสิ่งที่จะเกิดกับตัวแปรธรรมดาที่ไม่มี @ · ตัวเลือกที่ 3 ผิดเพราะแม้จะรันด้วย ruby -w ก็ไม่มี warning · ตัวเลือกที่ 4 ผิดเพราะ Ruby ไม่เคยแก้ชื่อให้เอง (มีแค่คำแนะนำ "Did you mean" ใน error บางประเภทเท่านั้น) · จุดที่ต้องจำ: เจอ undefined method '…' for nil ให้สงสัยไว้ก่อนว่าชื่อ @ตัวแปร สะกดผิด

class Recipe < Post · ใน Recipe#initialize(title, minutes) เขียน super เฉย ๆ ส่วน Post#initialize รับแค่ title · ผลคืออะไร?

ตัวเลือกที่ 4 ถูก · super ที่ไม่มีวงเล็บจะส่ง argument ทุกตัวที่ method ปัจจุบันได้รับต่อไป · ผลรันจริงในหัวข้อ 6 คือ wrong number of arguments (given 2, expected 1)

ตัวเลือกที่ 1 และ 3 คิดว่า super เฉย ๆ ไม่ส่งอะไรต่อ ซึ่งเป็นการทำงานของ super() ที่มีวงเล็บว่าง (และถ้าใช้ super() จริง ผลที่รันได้คือ given 0, expected 1 ไม่ใช่ทำงานปกติแบบตัวเลือกที่ 1) · ตัวเลือกที่ 2 ผิดเพราะ Ruby ไม่ได้เลือก argument ตามชื่อ · จุดที่ต้องจำ: ใน initialize ของ class ลูก ให้เขียน super(…) และระบุ argument ให้ชัดเจนทุกครั้ง

ข้อไหนอธิบายความต่างระหว่าง module ของ Ruby กับ interface ของ Go/TS ได้ถูกต้องที่สุด?

ตัวเลือกที่ 2 ถูก · สไลด์หน้า 29 สรุปว่า "module พกโค้ดจริงมาด้วย" ซึ่งใกล้กับ struct embedding ของ Go มากกว่า interface

ตัวเลือกที่ 1 สลับกัน · ตัวเลือกที่ 3 ผิดเพราะ Sluggable.new พังด้วย undefined method 'new' for module Sluggable · ตัวเลือกที่ 4 ผิดเพราะ Ruby ไม่ได้ตรวจอะไรตอน include โค้ดในสไลด์ include ผ่านแต่ไปพังตอนเรียก slug · จุดที่ต้องจำ: module ให้โค้ดมาฟรี แต่ไม่ได้รับประกันว่า class มีของที่ module ต้องใช้ครบ จะรู้ก็ตอนรัน

10 · ภารกิจ — เขียน class + module แล้วพิสูจน์ด้วยเทส

🎯 ภารกิจ: Post, Recipe และ Sluggable

เขียนทุกอย่างในไฟล์เดียวชื่อ post_test.rb แล้วรันด้วย ruby post_test.rb (Ruby 4.0.9 มี minitest 6.0.6 ติดมาด้วย ไม่ต้องติดตั้งเพิ่ม และไม่ต้องใช้ Rails)

  1. เขียน module Sluggable ที่มี slug แบบในสไลด์หน้า 29
  2. เขียน class Post ที่ include Sluggable และมี title ที่อ่านได้แต่แก้ไม่ได้จากข้างนอก พร้อมเขียน to_s ให้คืน "Post(ชื่อเรื่อง)"
  3. เขียน class Recipe < Post ที่รับ title กับ minutes และเขียน slug ทับของเดิมโดยเรียก super แล้วต่อท้ายด้วย -15min
  4. เขียนเทสด้วย minitest ให้ครบ 5 ข้อ: slug ของ Post · ตั้งค่า title แล้วต้องได้ NoMethodError · "#{post}" ต้องได้ Post(Hi) · slug ของ Recipe · และ Recipe.ancestors.first(4)
  5. ทดสอบเทสของคุณเอง: เปลี่ยน super(title) ใน Recipe เป็น super เฉย ๆ แล้วดูว่าเทสจับได้จริงไหม
# post_test.rb
require "minitest/autorun"

module Sluggable
  def slug
    title.downcase.tr(" ", "-")
  end
end

class Post
  include Sluggable
  attr_reader :title          # อ่านได้ แก้ไม่ได้

  def initialize(title)
    @title = title
  end

  def to_s
    "Post(#{title})"
  end
end

class Recipe < Post
  attr_reader :minutes

  def initialize(title, minutes)
    super(title)
    @minutes = minutes
  end

  def slug
    super + "-#{minutes}min"     # super ไปเรียก Sluggable#slug
  end
end

class PostTest < Minitest::Test
  def test_slug_from_module
    assert_equal "hello-ruby-world", Post.new("Hello Ruby World").slug
  end

  def test_title_has_no_setter
    assert_raises(NoMethodError) { Post.new("Hi").title = "x" }
  end

  def test_to_s
    assert_equal "Post(Hi)", "#{Post.new("Hi")}"
  end

  def test_recipe_slug_calls_super
    assert_equal "tom-yum-15min", Recipe.new("Tom Yum", 15).slug
  end

  def test_ancestors_order
    assert_equal [Recipe, Post, Sluggable, Object], Recipe.ancestors.first(4)
  end
end
