1 · routes.rb คือสมุดจดว่า "URL นี้ ไปหาใคร"

ทุก request ที่เข้ามาในแอป Rails มีของสองอย่างติดมาเสมอ: verb (GET / POST / PATCH / DELETE) กับ path (/posts/42)
router มีหน้าที่เดียว คือเอาสองอย่างนี้ไปเทียบกับรายการใน config/routes.rb แล้วบอกว่า "ส่งต่อให้ controller ตัวไหน method ไหน" — แค่นั้นจริง ๆ มันไม่ได้แตะฐานข้อมูล ไม่ได้ render อะไร

นี่คือโค้ดในสไลด์หน้า 54 ที่ผมพิมพ์ลง config/routes.rb ตรงตัว:

# config/routes.rb
Rails.application.routes.draw do
  get    "/posts",       to: "posts#index"
  get    "/posts/new",   to: "posts#new"
  post   "/posts",       to: "posts#create"
  get    "/posts/:id",   to: "posts#show"
  patch  "/posts/:id",   to: "posts#update"
  delete "/posts/:id",   to: "posts#destroy"

  root "posts#index"
end

อ่านทีละบรรทัดได้ว่า "ถ้ามา GET /posts ให้ไปที่ posts#index" · สตริง "posts#index" แบ่งด้วย # เป็นสองท่อน — ก่อน # คือชื่อ controller (posts → class PostsController ตามกฎตั้งชื่อใน บทเรียน 99) และหลัง # คือชื่อ method ใน class นั้น ซึ่ง Rails เรียกว่า action
ส่วน root คือหน้าแรกของเว็บ (/) — เขียนสั้นกว่าเพราะ path ตายตัวอยู่แล้ว

เทียบกับของที่คุณเคยเขียนมา:

Go (Gin) — บท 38TypeScript (Next.js App Router) — บท 79Ruby (Rails)
เขียน route ที่ไหน ในโค้ด main.go ทีละบรรทัด ไม่มีไฟล์รวม — โฟลเดอร์คือ route เช่น app/posts/[id]/page.tsx ไฟล์เดียว config/routes.rb
หน้าตา r.GET("/posts/:id", showPost) ชื่อโฟลเดอร์ [id] get "/posts/:id", to: "posts#show"
ชี้ไปหาอะไร ตัวฟังก์ชัน (ส่งค่าฟังก์ชันเข้าไปเลย) ไฟล์ page.tsx ในโฟลเดอร์นั้น สตริง "posts#show" — Rails ไปหา class กับ method จากชื่อเอง
อ่านค่า :id c.Param("id") const { id } = await params params[:id]

แถวที่สามคือจุดที่ต่างกันจริง — Gin ส่งตัวฟังก์ชันเข้าไป พิมพ์ชื่อผิด go build ฟ้องทันที แต่ Rails ส่งแค่สตริง พิมพ์ชื่อ action ผิด Rails ก็ boot ได้ปกติ จะรู้ตัวก็ตอนมี request มาจริง หรือตอนสั่ง bin/rails routes -u เอง (หัวข้อ 5)

ดูตารางที่ Rails สร้างจากไฟล์นี้

คำสั่ง bin/rails routes พิมพ์ทุก route ที่ Rails เข้าใจออกมาเป็นตาราง (-c posts คือกรองเอาเฉพาะที่ไปหา PostsController — หัวข้อ 5 จะอธิบายว่าทำไมต้องกรอง): 

$ bin/rails routes -c posts

    posts GET    /posts(.:format)     posts#index
posts_new GET    /posts/new(.:format) posts#new

ครบทั้ง 7 บรรทัดตามที่เขียน · จำสองจุดนี้ไว้ก่อน แล้วหัวข้อ 3 กับ 5 จะกลับมาเฉลย: คอลัมน์ Prefix ของ /posts/new คือ posts_new และของ GET /posts/:id ว่างเปล่า

path เดียวกัน คนละ verb = คนละ action

เพื่อดูว่า router ส่งไปที่ไหนจริง ผมเขียน PostsController ที่แค่พิมพ์สิ่งที่ได้รับกลับมาเป็นข้อความ (ยังไม่แตะฐานข้อมูล — นั่นคือเรื่องของ Day 2) และตั้งใจไม่เขียน update กับ destroy: 

# app/controllers/posts_controller.rb — ตัวที่ใช้ตรวจทั้งบท
class PostsController < ApplicationController
  def index
    render plain: "#{self.class.name}#index\n"
  end

  def new
    render plain: "posts#new\n"
  end

  def show
    render plain: "posts#show  params[:id] = #{params[:id].inspect}  (#{params[:id].class})  format=#{params[:format].inspect}\n"
  end

  def popular
    render plain: "posts#popular\n"
  end
end

แล้วยิง /posts/42 ด้วย 4 verb:

# ยิงด้วย curl -X <verb> localhost:3000/posts/42 แล้วพิมพ์ status + ข้อความหลักของหน้า
GET    /posts/42 -> 200  posts#show  params[:id] = "42"  (String)  format=nil
PATCH  /posts/42 -> 404  The action 'update' could not be found for PostsController
DELETE /posts/42 -> 404  The action 'destroy' could not be found for PostsController
PUT    /posts/42 -> 404  No route matches [PUT] "/posts/42"

(ข้อความของ 404 ดึงมาจากหน้า error ของ development ซึ่งเป็น HTML ทั้งหน้า)
ได้ 404 สามบรรทัดเหมือนกัน แต่คนละเรื่องกันเลย:

  • PATCH กับ DELETE — router หาเจอ แล้วส่งต่อไปที่ PostsController แต่ใน class ไม่มี method ชื่อนั้น → The action … could not be found
  • PUT — router หาไม่เจอตั้งแต่แรก เพราะไม่มีบรรทัดไหนเขียน put ไว้ → No route matches

สองข้อความนี้บอกว่าต้องไปแก้คนละไฟล์ — แบบแรกแก้ controller · แบบหลังแก้ routes.rb · อ่านให้ออกตั้งแต่วันแรก จะไม่ต้องเดา

ส่วนที่สไลด์บอกว่า root "มีได้ตัวเดียว" — ผมลองเขียนสองบรรทัดดู Rails ไม่ยอม boot เลย:

นึกถึงพนักงานโต๊ะประชาสัมพันธ์ของตึกสำนักงาน ในมือมีแผ่นรายการหนึ่งแผ่น เขียนว่า "ถามหาฝ่ายบัญชี → ชั้น 3 ห้อง 301" · "มาส่งของ → ชั้น 1 ห้องรับพัสดุ"
คนมาถาม พนักงานก็ไล่นิ้วจากบรรทัดแรกลงไป เจอบรรทัดที่ตรงก็ชี้ทางให้ แล้วหยุดอ่านทันที
แผ่นรายการนั้นคือ routes.rb · ห้อง 301 คือ PostsController · คนในห้องที่ทำงานให้คือ action

ที่ไม่เหมือนกัน: พนักงานที่เป็นคนจริงจะใช้วิจารณญาณ — ถ้ามีสองบรรทัดที่ดูเข้าเค้า เขาจะเลือกอันที่ตรงกว่าให้คุณ
router ของ Rails ไม่คิดแบบนั้น มันเลือกบรรทัดแรกที่เข้าเงื่อนไข เสมอ แม้บรรทัดถัดไปจะตรงกว่าก็ตาม — ซึ่งต่างจาก Gin ที่คุณเคยใช้ และเป็นที่มาของกับดักในหัวข้อ 6
อีกข้อคือ พนักงานจะบอกคุณว่า "ห้องนี้ปิดแล้ว" ถ้าไม่มีคนอยู่ · router ไม่รู้ว่าในห้องมีคนหรือเปล่า ชี้ทางไปก่อน แล้วค่อยไปพังที่ controller (แบบ PATCH ข้างบน)

🗣 ศัพท์ที่เพิ่งเรียนไป
route
หนึ่งบรรทัดใน routes.rb = กฎหนึ่งข้อที่จับคู่ verb + path เข้ากับ controller#action · ถาม senior ได้ว่า “endpoint นี้ route ไปที่ controller#action ไหน” — คนทำ Rails พูดกันแบบนี้
action
method สาธารณะใน controller ที่ router เรียกได้ เช่น index show · ฝั่ง Gin คือ handler function · พิมพ์บอก AI ได้ว่า “add a popular action to PostsController and route GET /posts/popular to it”
routing DSL
get post root ที่เห็นในไฟล์เป็น method ของ Ruby ธรรมดา ไม่ใช่ภาษาพิเศษ · DSL ย่อจาก domain-specific language = ชุด method ที่ออกแบบให้อ่านเหมือนภาษาเฉพาะเรื่อง · ถาม AI ได้ว่า “in Rails routes.rb, which object is get called on?”
Routing Error / ActionNotFound
สองข้อความ 404 ที่เห็นข้างบน · No route matches = router หาไม่เจอ (แก้ routes.rb) · The action … could not be found = router เจอ แต่ controller ไม่มี method (แก้ controller) · แปะข้อความเต็มให้ AI ดีกว่าบอกว่า “มัน 404” เพราะสองแบบแก้คนละที่

2 · Dynamic segment — ช่อง :id ที่รับค่าอะไรก็ได้

ตัวที่ขึ้นต้นด้วย : ใน path เช่น :id คือช่องว่างที่รอรับค่า — URL ส่งอะไรมาในตำแหน่งนั้น Rails เก็บใส่ params[:id] ให้ · เหมือน :id ของ Gin ทุกอย่าง
สไลด์หน้า 55 เน้นข้อเดียวที่สำคัญที่สุด: ค่าที่ได้เป็น string เสมอ · ก่อนดูผล ลองทายก่อน 

# routes.rb = โค้ดสไลด์หน้า 54 ชุดเดิม (มี get "/posts/:id", to: "posts#show")
$ curl localhost:3000/posts/42
$ curl localhost:3000/posts/abc
$ curl localhost:3000/posts/42.json
$ curl localhost:3000/posts/1.5

สี่บรรทัดนี้ params[:id] ได้อะไร เป็น class อะไร? โดยเฉพาะสองบรรทัดล่างที่มีจุด 

$ curl localhost:3000/posts/42
posts#show  params[:id] = "42"  (String)  format=nil
$ curl localhost:3000/posts/abc
posts#show  params[:id] = "abc"  (String)  format=nil
$ curl localhost:3000/posts/42.json
posts#show  params[:id] = "42"  (String)  format="json"
$ curl localhost:3000/posts/1.5
posts#show  params[:id] = "1"  (String)  format="5"
  • ทุกตัวเป็น String — "42" ไม่ใช่ 42 · URL เป็นข้อความ router ไม่เดาให้ว่าควรเป็นตัวเลข
  • /posts/abc ก็เข้า show ได้สบาย — :id ไม่ได้แปลว่า "ตัวเลข" มันรับอะไรก็ได้
  • จุด . ถูกตัดไปเป็น format — /posts/1.5 ได้ id "1" กับ format "5" เพราะทุก route มีส่วน (.:format) แอบต่อท้าย (เห็นในตาราง bin/rails routes หัวข้อ 1) · คู่มือ Rails เขียนไว้ตรง ๆ ว่า dynamic segment ไม่รับจุดโดยค่าตั้งต้น

ข้อสุดท้ายนี่แหละที่คนพลาด — ถ้า id ของคุณเป็นอะไรอย่าง v1.2 หรือชื่อไฟล์ a.png จะได้ค่าครึ่งเดียวโดยไม่มี error

"เอาไปคำนวณเองต้อง .to_i" — แต่ .to_i ไม่เคยฟ้อง

สไลด์หน้า 55 บอกว่าตอน find Active Record แปลงให้เอง (Day 2) แต่ถ้าจะเอาไปคำนวณเองต้อง .to_i · จริง และมีกับดักที่สไลด์ไม่ได้พูด: 

p "42".to_i          # => 42
p "42" + "1"        # => "421"   ← ลืมแปลง ได้การต่อสตริง
p "42".to_i + 1      # => 43
p "abc".to_i         # => 0     ← ไม่ error!
p "42abc".to_i       # => 42    ← ตัดส่วนที่ไม่ใช่ตัวเลขทิ้งเงียบ ๆ
Integer("abc")        # ArgumentError: invalid value for Integer(): "abc"

(ทุกค่าหลัง => มาจากการรัน ruby จริง)

Go — strconv.Atoi

n, err := strconv.Atoi("abc")
fmt.Println(n, err)
// 0 strconv.Atoi: parsing "abc": invalid syntax

บังคับให้คุณเห็น err ทุกครั้ง

Ruby — String#to_i

"abc".to_i
# => 0

ไม่มี error ให้เห็นเลย · อยากให้พังต้องใช้ Integer("abc")

⚠️ /posts/abc + params[:id].to_i = โพสต์เลข 0 — ไม่ใช่ error · ถ้า id ต้องเป็นตัวเลขเท่านั้น ให้ router คัดออกตั้งแต่ต้นทางด้วย constraint (ข้างล่าง) แทนที่จะไปหวังพึ่ง .to_i ใน controller

ช่องที่ "มีหรือไม่มีก็ได้" — วงเล็บ ( )

# routes.rb
get "/posts(/:id)", to: "posts#show"

$ bin/rails routes -c posts
Prefix Verb URI Pattern            Controller#Action
       GET  /posts(/:id)(.:format) posts#show

$ curl localhost:3000/posts
posts#show  params[:id] = nil  (NilClass)  format=nil
$ curl localhost:3000/posts/42
posts#show  params[:id] = "42"  (String)  format=nil

ข้อยกเว้นของ "string เสมอ" อยู่ตรงนี้: ถ้าช่องไม่ถูกส่งมา ได้ nil ไม่ใช่สตริงว่าง · (เรื่อง nil ทวนได้ใน บทเรียน 94)
สังเกตด้วยว่า (.:format) ที่ Rails แปะท้ายทุก route ก็คือช่อง optional แบบเดียวกันนี้ — วงเล็บ = มีหรือไม่มีก็ได้

/\d+/ คือ regex แปลว่า "ตัวเลขหนึ่งตัวขึ้นไป" · ตารางโชว์ constraint ต่อท้ายให้เห็นด้วย ({id: /\d+/})
/posts/abc ได้ 404 แบบ No route matches [GET] "/posts/abc" — ไม่เข้า controller เลย · และ 42abc ก็ไม่ผ่าน เพราะ Rails ต้องให้ทั้งช่องตรงกับ regex ไม่ใช่แค่บางส่วน
แต่ดูบรรทัดแรกให้ดี: ผ่าน constraint แล้วก็ยังเป็น "42" (String) อยู่ดี — constraint แค่คัดกรอง ไม่ได้แปลงชนิด

route คือ get "/posts/:id", to: "posts#show", constraints: { id: /\d+/ } แล้วมี request GET /posts/42 เข้ามา — ใน action show ค่า params[:id] คืออะไร?

ตัวเลือกที่ 2 ถูก — curl จริงได้ params[:id] = "42" (String) · ตัวเลือกที่ 1 คือความเข้าใจผิดที่พบบ่อยที่สุด: constraint ทำหน้าที่ด่านตรวจ ผ่านหรือไม่ผ่านเท่านั้น ค่าที่ผ่านไปยังเป็นข้อความจาก URL เหมือนเดิม · ตัวเลือกที่ 3 ผิดเพราะ nil เกิดแค่กับช่อง optional ที่ไม่ได้ส่งมา · ตัวเลือกที่ 4 ผิดเพราะ "42" ตรงกับ /\d+/ ทั้งช่อง ได้ 200

จุดที่ต้องจำ: ค่าใน params ที่มาจาก URL เป็น String เสมอ (หรือ nil ถ้าไม่ได้ส่งมา) · จะเอาไปคำนวณต้องแปลงเอง

3 · ชื่อ route และ helper — อย่า hardcode URL เด็ดขาด

กลับไปดูตารางหัวข้อ 1 — GET /posts/:id มีคอลัมน์ Prefix ว่าง แปลว่า route นี้ไม่มีชื่อ · ไม่มีชื่อ = ไม่มี method ให้เรียกเพื่อสร้าง URL ของมัน ผมลองเรียกดูจริง:

ทำไมห้าม hardcode — และ "ย่อได้" ที่สไลด์พูดถึง

🧰 เทียบให้เห็นภาพ — ชื่อในรายชื่อติดต่อของมือถือ

คุณไม่ได้จำเบอร์แม่ คุณบันทึกไว้ในมือถือว่า "แม่" แล้วกดโทรจากชื่อ
วันที่แม่เปลี่ยนเบอร์ คุณแก้ในรายชื่อที่เดียว — ปุ่มโทรด่วน แชท ประวัติโทร ทุกอย่างที่อ้าง "แม่" ใช้เบอร์ใหม่ทันที
ชื่อ route (post) คือชื่อในรายชื่อ · URL จริง (/posts/42) คือเบอร์ · การเขียน "/posts/#{id}" ตรง ๆ คือการจดเบอร์ไว้ในกระดาษ 40 แผ่น

ที่ไม่เหมือนกัน: รายชื่อในมือถือเก็บเบอร์สำเร็จรูปไว้หนึ่งเบอร์ แต่ helper ประกอบ URL ใหม่ทุกครั้งจาก pattern กับค่าที่คุณส่งเข้าไป (42, format:, page:) — มันจึงสร้าง URL ได้เป็นล้านแบบจากชื่อเดียว
และถ้าวันหนึ่งคุณเปลี่ยนชื่อเอง (แก้ as:) ทุกที่ที่เรียกชื่อเก่าจะพัง — แต่พังแบบดัง ๆ เป็น NoMethodError ตอนเปิดหน้านั้น ไม่ใช่ลิงก์เสียเงียบ ๆ แบบ hardcode

4 · จัดกลุ่ม route — namespace · scope · scope module:

พอแอปโตขึ้นจะมีหน้าหลังบ้าน (admin) และ API ปนกัน · สไลด์หน้า 57 มีสามท่า ซึ่งเปลี่ยนคนละส่วนของ route — ผมเขียนแต่ละท่าลงไฟล์ (ใส่ get "/posts" หนึ่งเส้นข้างใน · ท่าที่สามสไลด์เว้นว่างไว้) แล้วดูตารางจริง:

🧰 เทียบให้เห็นภาพ — ย้ายแผนกทั้งแผนก vs เปลี่ยนแค่ป้าย

นึกถึงแผนกบัญชีของบริษัท มีสามอย่างผูกกันอยู่: ป้ายหน้าห้อง (URL) · คนที่นั่งทำงานในห้อง (controller) · ชื่อในสมุดโทรศัพท์ภายใน (ชื่อ helper)

  • namespace :admin = ย้ายทั้งแผนกขึ้นชั้นผู้บริหาร — ป้ายใหม่ คนชุดใหม่ ชื่อในสมุดก็ขึ้นต้นด้วย "admin"
  • scope "/api" = เปลี่ยนแค่ป้ายหน้าห้อง — คนเดิมนั่งที่เดิม ชื่อในสมุดเหมือนเดิม
  • scope module: :admin = ป้ายเดิม แต่เปลี่ยนคนนั่ง — ลูกค้าเดินมาห้องเดิม แต่คนที่บริการเป็นทีมใหม่

ที่ไม่เหมือนกัน: ในบริษัทจริง ถ้าย้ายแผนกไปแล้วลืมจ้างคน ห้องจะว่างและมีคนบอกคุณ · ใน Rails ถ้าใช้ namespace :admin แต่ยังไม่ได้สร้าง Admin::PostsController Rails boot ผ่านปกติ และ bin/rails routes ก็โชว์ route ให้ดูสวยงาม — จะรู้ตัวก็ตอนมี request จริงแล้วได้ 500 · อีกข้อคือในบริษัท สองแผนกใช้ชื่อเดียวกันในสมุดไม่ได้แล้วมีคนทักแน่ แต่ใน Rails ชื่อที่ตั้งให้อัตโนมัติชนกันแล้วเงียบ (กล่องเตือนข้างบน)

  5. เรียก post_path("abc") ตอนที่ มี constraint อยู่ — ได้อะไร?

ก่อนกดเฉลย ตอบให้ได้: ทำไมข้อ 1 กับ 2 อยู่ลำดับ "ผิด" แต่ /posts/popular ยังไปถูกที่ จนกระทั่งลบ constraint? 

# config/routes.rb
Rails.application.routes.draw do
  get "/posts/:id",      to: "posts#show",    as: :post,
      constraints: { id: /\d+/ }
  get "/posts/popular",  to: "posts#popular", as: :popular_posts

  namespace :admin do
    get "/posts", to: "posts#index"
  end

  root "posts#index"
end

  • ทำไมลำดับผิดแต่ยังถูก — constraint /\d+/ ทำให้บรรทัดแรกไม่ match กับคำว่า popular router เลยอ่านต่อไปบรรทัดสอง · พอลบ constraint บรรทัดแรกรับทุกอย่าง popular เลยตกไปที่ show ทันที → constraint คือตาข่ายนิรภัย แต่อย่าใช้แทนการเรียงลำดับให้ถูก (เผื่อวันหนึ่งมีคนลบออก)
