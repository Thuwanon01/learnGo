🔁 ทวนก่อนเริ่ม — บทนี้ใช้คำพวกนี้ตลอด ถ้าข้อไหนไม่คุ้นให้กลับไปบทนั้นก่อน

  • route = บรรทัดใน config/routes.rb ที่บอกว่า URL ไหนไปหาใคร — พนักงานต้อนรับหน้าร้าน (บท 101)
  • controller · action = class ที่รับงาน กับ method ในนั้น — หัวหน้าเชฟของแผนก กับเมนูแต่ละอย่าง (บท 102)
  • @ตัวแปร = ของที่ controller วางไว้ให้ view หยิบไปใช้ (บท 102)
  • view · <%= %> = ไฟล์ HTML ที่แทรกค่าจาก Ruby ได้ — การจัดจานก่อนเสิร์ฟ (บท 103)
  • params = ของที่ผู้ใช้ส่งมากับ URL เช่น ?name=Nan — รายละเอียดในใบสั่ง (บท 102)

ลูกค้า (browser) เปิด http://localhost:3000/hello │ ใบสั่ง: "ขอหน้า /hello" ▼ ① config/routes.rb ← พนักงานต้อนรับ get "/hello", to: "greetings#index" │ "ส่งไปแผนก greetings · เมนู index" ▼ ② app/controllers/greetings_controller.rb ← หัวหน้าเชฟแผนก greetings def index @name = "PEA" ← วางวัตถุดิบไว้บนถาด │ ▼ ③ app/views/greetings/index.html.erb ← คนจัดจาน <h1>Hello <%= @name %></h1> │ ▼ จานอาหาร (HTML) กลับไปที่ลูกค้า

สังเกตว่าสามไฟล์นี้ไม่ได้เรียกกันด้วยโค้ด — มันเชื่อมกันด้วยชื่อล้วน ๆ
คำว่า greetings ใน route ทำให้ Rails ไปหา class GreetingsController ในไฟล์ greetings_controller.rb · คำว่า index ทำให้ Rails ไปหา view ชื่อ index.html.erb ในโฟลเดอร์ greetings/ (กฎตั้งชื่อชุดนี้อยู่ใน บท 99)
greetings แปลว่า "คำทักทาย" — เป็นชื่อแผนกที่เราตั้งเอง (ใช้รูปพหูพจน์ตามกฎของ Rails) ไม่ใช่คำพิเศษ

ใน Go ที่เคยเรียน คุณส่งตัวฟังก์ชันเข้าไปตรง ๆ: 

// Go + Gin — ส่งตัวฟังก์ชัน helloHandler เข้าไปเลย
r.GET("/hello", helloHandler)

ถ้าพิมพ์ helloHandler ผิด Go ไม่ยอม build ตั้งแต่ก่อนรัน · แต่ใน Rails สิ่งที่ส่งคือข้อความ "greetings#index" — สะกดผิดก็ไม่มีใครฟ้อง จนกว่าจะมีคนเปิดหน้านั้นจริง ๆ · นั่นคือเหตุผลที่ครึ่งหลังของ Lab ให้ฝึกอ่านหน้า error

🍽 เทียบให้เห็นภาพ — ร้านแฟรนไชส์ที่ส่งงานกันด้วยป้ายชื่อ

พนักงานต้อนรับ (route) ไม่ได้เดินพาใบสั่งไปส่งเชฟด้วยมือ เขาแค่เขียนชื่อแผนกกับชื่อเมนูลงใบสั่ง แล้ววางไว้
ร้านแฟรนไชส์มีกฎว่าแผนก "greetings" ต้องนั่งที่โต๊ะป้าย greetings_controller.rb และเมนู "index" ต้องจัดจานตามแบบในแฟ้ม greetings/index.html.erb
ทุกคนทำตามกฎตำแหน่งเดียวกัน ใบสั่งจึงถึงมือคนที่ถูกเสมอ — โดยไม่มีใครต้องบอกทาง

ที่ไม่เหมือนกัน: พนักงานจริงเห็นใบสั่งเขียนว่า "แผนก page" (ขาด s) ก็คงเดาออกว่าหมายถึง "pages" แล้วส่งให้ถูกแผนก
Rails ไม่เดาให้ — ชื่อต้องตรงเป๊ะทุกตัวอักษร ไม่งั้นได้หน้าแดงทันที (เราจะทำพังแบบนี้ให้ดูในหัวข้อ "พังแบบที่ 1")

🗣 ศัพท์ของภาพรวม
convention over configuration
แนวคิดของ Rails ที่ว่า "ตั้งชื่อตามกฎ แล้วไม่ต้องเขียนบอกว่าอะไรอยู่ที่ไหน" · ถาม senior ได้ว่า "ตรงนี้ Rails หาไฟล์เจอได้ยังไง ใช้ convention ข้อไหน" — คำถามนี้ช่วยให้เข้าใจโค้ดที่ดูเหมือน "เกิดขึ้นเอง"
"controller#action"
รูปแบบที่ route ใช้ชี้ไปหางาน · ซ้ายของ # คือชื่อ controller (ตัวเล็ก พหูพจน์ ไม่มีคำว่า Controller) · ขวาคือชื่อ method · พิมพ์บอก AI ได้ว่า "add a route GET /about to pages#about" AI จะเข้าใจทันทีว่าต้องสร้างไฟล์อะไรบ้าง

ขั้น 2 — เปิดร้าน: เตรียม database แล้ว bin/rails server

วันนี้เรายังไม่เก็บบทความลง database เลย แต่ Rails ในโหมดพัฒนาต้องคุยกับ database ตอนมีคนเข้าเว็บครั้งแรก (มันเช็คว่าตู้เก็บแฟ้มพร้อมไหม) · ถ้าไม่มีตู้ หน้าเว็บจะพังตั้งแต่หน้าแรก

ต้องมี PostgreSQL เปิดอยู่ในเครื่องก่อน (ยังไม่มี → เปิด container แบบบท 31 ตามที่บท 98แนะนำ) · แล้วบอกแอปว่าตู้เก็บแฟ้มอยู่ที่ไหน ด้วยวิธีเดียวกับบท 98 จากนั้นสั่งสร้าง database: 

$ export DATABASE_URL=postgres://postgres:sandbox@127.0.0.1:55432/a105
$ bin/rails db:prepare
Created database 'a105'
  • export ชื่อ=ค่า — ให้ terminal แท็บนี้จำค่านี้ไว้ โปรแกรมที่รันจากแท็บนี้จะอ่านได้ (แท็บอื่นไม่รู้)
  • DATABASE_URL คือที่อยู่ของตู้เก็บแฟ้ม — หน้าตาเหมือน DSN (สตริงบอกที่อยู่ database) ที่เคยใช้กับ goose ในบท 31 อ่านทีละท่อน: postgres:// ชนิด database · postgres:sandbox ชื่อผู้ใช้:รหัสผ่าน · 127.0.0.1:55432 เครื่อง:พอร์ต · /a105 ชื่อ database

ขั้น 3 — เมนูแรก /hello (ทำไปพร้อมกัน)

ก่อนเขียนอะไร ลองเปิด http://localhost:3000/hello ดูก่อน — จะได้หน้าแดงหน้าแรกของวัน: 

Routing Error
No route matches [GET] "/hello"

แปลตรง ๆ: "ไม่มี route ไหนรับ GET /hello" — พนักงานต้อนรับไม่มีกฎสำหรับใบสั่งนี้ · ไม่ต้องตกใจ นี่คือสิ่งที่ควรเห็น เพราะเรายังไม่ได้เขียน route · status ที่ได้คือ 404 (หาไม่เจอ)

3.1 · route: บอกพนักงานต้อนรับ

เปิด config/routes.rb แล้วเพิ่มบรรทัดเดียวก่อน end บรรทัดสุดท้าย:

# config/routes.rb
Rails.application.routes.draw do
  # … บรรทัดเดิมที่ Rails เขียนไว้ ปล่อยไว้ตามเดิม …

  get "/hello", to: "greetings#index"
end
  • Rails.application.routes.draw do … end — Rails เขียนไว้ให้แล้ว แปลว่า "เริ่มเขียนกฎของพนักงานต้อนรับ … จบ" · do…end คือ block (ก้อนโค้ดที่ส่งให้ method — บท 93) · ไม่ต้องแก้ แค่เขียนของเราไว้ข้างใน
  • get — รับเฉพาะการ "ขอดูหน้า" (HTTP GET) · มันคือ method ของ Ruby ตัวหนึ่ง ไม่ใช่คำพิเศษ
  • "/hello" — URL ที่จะรับ
  • to: "greetings#index" — "ส่งให้ controller ชื่อ greetings ทำเมนู index" · to: คือ key ของ hash ที่ละปีกกาไว้ (บท 97)

3.2 · controller: หัวหน้าเชฟแผนก greetings

สร้างไฟล์ใหม่ app/controllers/greetings_controller.rb:

# app/controllers/greetings_controller.rb
class GreetingsController < ApplicationController
  def index
    @name = "PEA"
  end
end
  • class GreetingsController — ชื่อต้องตรงกับไฟล์: greetings_controller.rb ↔ GreetingsController
  • < ApplicationController — "สืบทอดความสามารถจาก" controller แม่ที่ Rails เตรียมไว้ (บท 95) · ได้ params · render และอื่น ๆ มาฟรี
  • def index — action ชื่อ index ต้องตรงกับขวาของ # ใน route
  • @name = "PEA" — ตัวแปรที่มี @ นำหน้า view จะหยิบไปใช้ได้ · ตัวแปรธรรมดา (ไม่มี @) view มองไม่เห็น
  • end สองตัว — ตัวแรกปิด def ตัวที่สองปิด class · ลืมตัวใดตัวหนึ่ง = พัง (พังแบบที่ 3)

② controller — ไฟล์ใหม่ app/controllers/pages_controller.rb:

พังแบบที่ 4 · พิมพ์ชื่อตัวแปรผิด

ใน controller เปลี่ยน params เป็น parms — ได้หน้า NameError ที่เราแยกส่วนดูไปแล้วข้างบน (status 500) · ตัวนี้อ่านง่ายที่สุด: กรอบโค้ดชี้บรรทัด 3 ในไฟล์ของเรา และ Did you mean? params เฉลยให้เลย

เทียบกับ Go: ถ้าพิมพ์ชื่อตัวแปรผิดแบบเดียวกัน Go ไม่ยอม build ตั้งแต่แรก · ผมเขียนสองบรรทัดนี้ไว้ใน func main() ของไฟล์ main.go (มี package main กับ import "fmt" ครบ) แล้วสั่ง go build: 

params := map[string]string{"name": "Nan"}
fmt.Println(parms["name"])   // พิมพ์ผิด: parms

$ go build main.go
# command-line-arguments
./main.go:6:2: declared and not used: params
./main.go:7:14: undefined: parms

บรรทัด # command-line-arguments คือ Go บอกว่ากำลัง build ไฟล์ที่เราสั่งตรง ๆ — ไม่ต้องสนใจ · error บรรทัดล่างคือตัวที่ตรงกับของเรา: undefined: parms = "ไม่รู้จักชื่อ parms" · บรรทัดบนเป็นโบนัสของ Go — มันเห็นว่า params ประกาศแล้วไม่ได้ใช้ (เพราะเราพิมพ์ผิดไปใช้ parms) ก็ฟ้องด้วย

Ruby ไม่มีขั้น build แบบนั้น — ไฟล์ที่พิมพ์ผิดยังโหลดได้ปกติ จะพังก็ต่อเมื่อบรรทัดนั้นถูกรันจริง · ทีนี้ลองผิดอีกที่หนึ่ง: แก้ controller กลับให้ถูก แล้วไปพิมพ์ผิดใน view แทน

ไฟล์ app/views/pages/about.html.erb — พิมพ์ @name ผิดเป็น @nmae (controller ถูกต้องแล้ว):

<h1>About wongnok_blog</h1>
<p>Hello <%= @nmae %></p>

เปิด /about?name=Nan — จะได้หน้าแดงแบบไหน?

ไม่มีหน้าแดงเลย — ได้ status 200 กับหน้าที่ชื่อหายไปเงียบ ๆ:

$ curl -s -H 'Accept: text/html' "http://localhost:3000/about?name=Nan"
…
<p>Hello </p>

(-H 'Accept: text/html' = ให้ curl บอกว่า "ขอเป็น HTML" เหมือนเบราว์เซอร์)

ตัวแปรที่มี @ นำหน้า ถ้าไม่เคยถูกตั้งค่า Ruby ไม่ฟ้อง แต่ให้ค่าเป็น nil (ไม่มีค่า) และ <%= nil %> พิมพ์ออกมาเป็นความว่างเปล่า (บท 94) · ต่างจาก parms ในพังแบบที่ 4 ที่ไม่มี @ — ชื่อแบบนั้นถ้าไม่รู้จัก Ruby ฟ้อง NameError ทันที

เทียบกับ Go: template ของ Go ที่อ้างชื่อ field ผิด ({{.Nmae}}) ฟ้อง — ผมลองแล้วได้ can't evaluate field Nmae in type main.Page

บทเรียน: ถ้าหน้าเว็บขึ้นปกติแต่ข้อมูลบางส่วนหายไปเฉย ๆ ให้สงสัยชื่อ @ตัวแปร สะกดไม่ตรงกันระหว่าง controller กับ view ก่อนอย่างอื่น

🍛 เทียบให้เห็นภาพ — ถาดที่ติดป้ายผิด

เชฟ (controller) วางวัตถุดิบบนถาดที่ติดป้าย @name · คนจัดจาน (view) เดินไปหยิบถาดป้าย @nmae — ไม่มีถาดนี้ ก็เลยจัดจานโดยไม่ใส่อะไรตรงนั้นแล้วเสิร์ฟไป ไม่มีใครส่งใบแจ้งปัญหาออกมาเลย

ที่ไม่เหมือนกัน: คนจัดจานจริงหาถาดไม่เจอก็คงตะโกนถามเชฟ แต่ Ruby ถือว่า "ถาด @ ที่ไม่มี" = ถาดเปล่า (nil) ซึ่งถูกกติกา จึงเงียบ
ส่วนชื่อที่ไม่มี @ (เช่น parms) ไม่ใช่ถาด แต่เป็น "คำสั่ง" ที่ Ruby ต้องรู้จัก — ไม่รู้จักจึงหยุดครัวทันที

ข้อ 4 · เพิ่ม /about/:id แล้วสลับลำดับ — :id คือช่องว่างใน URL ที่รับค่าอะไรก็ได้ (บท 101) · ผมเพิ่ม action ชื่อ member (ชื่อนี้ตั้งเอง สไลด์ไม่ได้กำหนด) แล้วลองสองแบบ:

get "/about",     to: "pages#about"
get "/about/:id", to: "pages#member"

# แบบ B — สลับสองบรรทัด
get "/about/:id", to: "pages#member"
get "/about",     to: "pages#about"

# action ที่เพิ่มใน PagesController กับ view ของมัน
def member
  @id = params[:id]
end
# app/views/pages/member.html.erb มีบรรทัดเดียว:  <p>id = <%= @id %></p>

# ผลจริง (ทั้งสองแบบได้เหมือนกัน)
/about    <p>Hello PEA</p>
/about/7  <p>id = 7</p>
  • "/about/:id" — URL ที่ขึ้นต้นด้วย /about/ แล้วตามด้วยอะไรก็ได้ ค่านั้นจะไปอยู่ใน params[:id]
  • def member … @id = params[:id] — หยิบค่าจาก URL วางบนถาดชื่อ @id ให้ view
  • บรรทัด /about/7 <p>id = 7</p> — อ่านว่า "เปิด /about/7 แล้วได้ HTML บรรทัดนี้"

ไม่มีอะไรเปลี่ยน — เพราะ /about/:id ต้องมีอะไรต่อท้าย /about/ เสมอ สองเส้นนี้จึงไม่มีวันแย่ง URL เดียวกัน · ลำดับมีผลจริงเฉพาะเมื่อสองเส้นรับ URL เดียวกันได้ — ดู quiz ข้อ 4

ตัวเลือกที่ 2 ถูก · พิสูจน์ด้วยขั้น 3 ของบทนี้เอง: ไฟล์ app/views/greetings/index.html.erb ทำให้ /hello ขึ้นจริง และ comment BEGIN app/views/greetings/index.html.erb ใน HTML ก็ยืนยัน · ส่วนพังแบบที่ 2 หน้า error บอกตรง ๆ ว่าไฟล์ต้องชื่อ app/views/ชื่อ controller/ชื่อ action.html.erb

ตัวเลือกที่ 1 เอาชื่อ URL มาตั้ง — แต่ Rails ไม่ดู URL เลย ดูแค่ "greetings#index" · ตัวเลือกที่ 3 ใช้ชื่อ controller แต่ลืมว่า action คือชื่อไฟล์ในโฟลเดอร์ของ controller · ตัวเลือกที่ 4 ผิดสองชั้น: ใช้ชื่อ URL และอยู่นอก app/views/

จุดที่ต้องจำ: "แผนก#เมนู" → app/views/แผนก/เมนู.html.erb · เปลี่ยน URL เป็น /hi ไฟล์ view ก็ยังเป็นตัวเดิม

ข้อ 2 · ใน Ruby เขียน if 0 แล้วตามด้วยโค้ด — โค้ดข้างในจะทำงานไหม?

ตัวเลือกที่ 2 ถูก · ผลรันจริงบน Ruby 4.0.9:

if 0
  puts "เข้า if"
else
  puts "ไม่เข้า"
end
# ผลที่ได้: เข้า if

ตัวเลือกที่ 1 คือกับดักของคนที่มาจาก JavaScript/TypeScript ซึ่ง 0 เป็นเท็จ · ตัวเลือกที่ 3 เป็นกฎของ Go ไม่ใช่ Ruby — Go ไม่ยอม build (ผมลองแล้วได้ non-boolean condition in if statement) แต่ Ruby รันได้ · ตัวเลือกที่ 4 ผิด — เอกสารทางการของ Ruby เขียนกฎนี้ไว้ตรง ๆ ว่ามีแค่ nil กับ false ที่เป็นเท็จ

จุดที่ต้องจำ: ใน Ruby 0 · "" · [] เป็นจริงหมด · นี่คือเหตุผลที่ ?name= ในภารกิจได้ Hello ว่าง ๆ

ข้อ 3 · posts คือ array ของบทความ (ในตัวอย่างนี้จำลองด้วย Struct — แม่พิมพ์ข้อมูลแบบย่อที่มีช่อง title — เพราะยังไม่มี database) — posts.map(&:title) ได้ผลเท่ากับข้อไหน?

ตัวเลือกที่ 1 ถูก · ผลรันจริงกับบทความจำลองสองชิ้น:

Post = Struct.new(:title)
posts = [Post.new("Hello Rails"), Post.new("Day 1")]

p posts.map(&:title)
# ["Hello Rails", "Day 1"]
p posts.map { |post| post.title }
# ["Hello Rails", "Day 1"]
p posts.map { |post| :title }
# [:title, :title]
p posts.select { |post| post.title }
# [#<struct Post title="Hello Rails">, #<struct Post title="Day 1">]
p posts.each { |post| post.title }
# [#<struct Post title="Hello Rails">, #<struct Post title="Day 1">]

(p หน้าบรรทัดคือคำสั่งพิมพ์ค่าออกจอ บท 93 · บรรทัด # ใต้แต่ละบรรทัดคือผลที่ได้จริง · #<struct Post …> คือหน้าตาของบทความจำลองทั้งชิ้น)

ตัวเลือกที่ 2 คืนป้ายชื่อ :title เฉย ๆ ทุกรอบ ไม่ได้ไปเอาชื่อบทความ · ตัวเลือกที่ 3 ใช้ select ซึ่ง "คัดของ" ไม่ใช่ "แปลงของ" — ได้บทความทั้งชิ้นกลับมา ไม่ใช่รายชื่อ · ตัวเลือกที่ 4 ใช้ each ซึ่ง "เดินดูทีละชิ้น" แล้วคืน array เดิมกลับมา — ค่าที่ block คืนถูกทิ้งไป (บท 92–93)

จุดที่ต้องจำ: &:ชื่อ = "เรียก method ชื่อนี้กับสมาชิกทุกตัว" — ทางลัดของ block ที่ทำแค่เรียก method ตัวเดียว

ข้อ 4 · routes.rb เขียนสองบรรทัดเรียงแบบนี้: บนคือ get "/posts/:id", to: "posts#show" ล่างคือ get "/posts/popular", to: "posts#popular" — เปิด /posts/popular แล้วไปที่ action ไหน?

ตัวเลือกที่ 2 ถูก · ผลรันจริง (ผมสร้าง PostsController ชั่วคราวที่ตอบเป็นข้อความสั้น ๆ) · bin/rails runner '…' = สั่งรันโค้ด Ruby หนึ่งบรรทัดในแอปโดยไม่ต้องเปิด server · recognize_path = ถามพนักงานต้อนรับตรง ๆ ว่า "URL นี้จะส่งไปแผนกไหน เมนูอะไร":

$ bin/rails runner 'p Rails.application.routes.recognize_path("/posts/popular")'
{controller: "posts", action: "show", id: "popular"}

# เปิด /posts/popular จริง
show id=popular

พนักงานต้อนรับอ่านกฎจากบนลงล่าง เจอข้อแรกที่เข้าได้ก็ส่งเลย · :id รับอะไรก็ได้ รวมถึงคำว่า popular · ตัวเลือกที่ 1 คือสิ่งที่อยากให้เป็น แต่ Rails ไม่เลือกเส้นที่ตรงที่สุด เลือกเส้นแรก · ตัวเลือกที่ 3 ผิด — server เปิดได้ปกติ ไม่มีคำเตือน · ตัวเลือกที่ 4 ผิด — ใบสั่งหนึ่งใบไปได้ action เดียว

จุดที่ต้องจำ: เส้นที่เจาะจง (/posts/popular) ไว้บน เส้นที่มี :id ไว้ล่าง · ต่างจากของแถมข้อ 4 ที่สองเส้นไม่แย่ง URL กัน ลำดับจึงไม่มีผล
