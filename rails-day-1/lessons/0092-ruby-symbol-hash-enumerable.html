1 · Symbol — "ชื่อ" ไม่ใช่ "ข้อความ"

สมมติระบบบล็อกมีสถานะโพสต์สองแบบ คือ active กับ draft — ในภาษาที่คุณรู้จักแล้ว จะเขียนแบบนี้ (สไลด์หน้า 18):

GoTypeScriptRuby
const StatusActive = "active"
ตั้งชื่อค่าคงที่ไว้ใช้ซ้ำ (เหมือน enum ใน บทเรียน 03)		 type Status = "active" | "draft"
บอก compiler ว่ายอมแค่สองคำนี้ (ดู บทเรียน 64)		 :active
เขียนได้เลย ไม่ต้องประกาศที่ไหนก่อน

ทั้งสามแบบพยายามทำสิ่งเดียวกัน คือ "ฉันอยากได้ชื่อหนึ่งชื่อ ไว้เรียกของสิ่งหนึ่ง" ไม่ได้อยากได้ข้อความเอาไปโชว์ใคร · Go กับ TypeScript ต้องยืม string มาทำหน้าที่นี้ แต่ Ruby มีชนิดข้อมูลแยกไว้ให้เลย ชื่อว่า Symbol — เขียนด้วยโคลอนนำหน้า

  • :a สองตัว → object ก้อนเดียวกัน (true)
  • "a" สองตัว → คนละก้อน (false) — เขียน "a" หนึ่งครั้ง Ruby สร้าง String ใหม่หนึ่งก้อน
  • แต่ "a" == "a" ยังเป็น true — เพราะ == ของ String เทียบเนื้อความ ไม่ได้เทียบว่าเป็นก้อนเดียวกันไหม

สรุป: String สองก้อน "เหมือนกัน" ได้ แต่ Symbol ชื่อเดียวกัน "เป็นตัวเดียวกัน" เสมอ

ข้อยกเว้นหนึ่งข้อที่ควรรู้ไว้: ถ้าบรรทัดแรกของไฟล์มี # frozen_string_literal: true (พบบ่อยใน gem และโปรเจกต์ที่ตั้ง linter ไว้) บรรทัด "a".object_id == "a".object_id จะกลายเป็น true — ผมรันแล้วได้ true จริง เพราะ Ruby เอา String ที่เขียนเหมือนกันในไฟล์นั้นมาใช้ก้อนเดียวกัน · ไฟล์ใน app/ และ config/ ที่ rails new สร้างให้ (Rails 8.1.4) ไม่มีบรรทัดนี้ ผม grep ดูแล้ว · เพราะฉะนั้นประโยคในสไลด์ที่ว่า "String ตัวเดียวกันสร้างใหม่ทุกครั้งที่เขียน" ถูกในกรณีปกติ แต่ไม่ใช่ทุกกรณี

แล้วมันโผล่ใน Rails ตรงไหน

สไลด์ยกบรรทัดนี้มา — คุณจะเขียนมันใน model ตอน Day 2: 

validates :title, presence: true   # :title และ :presence เป็น Symbol

หน้าตาเหมือน "คำสั่งพิเศษ" แต่จริง ๆ แล้วเป็นการเรียก method ธรรมดาที่ละวงเล็บไว้ (Ruby ยอมให้ละวงเล็บได้) · ลองเขียน method ชื่อเดียวกันขึ้นมาเองแล้วดูว่ามันได้รับอะไร: 

# validates.rb — จำลอง validates ของ Rails ให้เห็นว่ามันคือ "การเรียก method" ธรรมดา
def validates(*attributes, **options)
  p attributes
  p options
end

:title คือชื่อ field ที่จะตรวจ · presence: true คือ Hash ที่ key เป็น Symbol :presence (เรื่อง Hash อยู่หัวข้อถัดไป) · ไม่มีอะไรในบรรทัดนี้เป็น "ข้อความที่จะโชว์ผู้ใช้" เลยสักตัว — ทุกตัวเป็นชื่อ · นี่คือเหตุผลที่ Rails ใช้ Symbol แทบทุกบรรทัด

🏷 เทียบให้เห็นภาพ — ป้ายชื่อห้องประชุม กับกระดาษโน้ต

String เหมือนกระดาษโน้ต — เขียนคำว่า "active" สองรอบ ได้กระดาษสองแผ่น ข้อความบนกระดาษเหมือนกันก็จริง แต่มันคือกระดาษคนละแผ่น ขีดแก้แผ่นหนึ่ง อีกแผ่นไม่เปลี่ยน
Symbol เหมือนป้ายชื่อห้องประชุม — ทั้งตึกมีห้อง "Active" อยู่ห้องเดียว ใครพูดว่า "ไปเจอกันที่ห้อง Active" ก็ไปถึงห้องเดียวกันหมด ไม่มีใครสร้างห้องใหม่ทุกครั้งที่เอ่ยชื่อ

ที่ไม่เหมือนกัน: ป้ายห้องจริงถอดออก เปลี่ยนชื่อ หรือรื้อทิ้งได้ — แต่ Symbol แก้ไม่ได้ อยากได้ชื่ออื่นก็ต้องเขียน Symbol ตัวใหม่ · และป้ายห้องไม่มีทาง "แปลงร่าง" เป็นกระดาษ แต่ Symbol กับ String แปลงไปมาได้ตลอดด้วย .to_s และ .to_sym (ตามที่รันให้ดูข้างบน) · อีกข้อที่ต่าง: กระดาษสองแผ่นที่เขียนเหมือนกัน Ruby ก็ยังถือว่า "เท่ากัน" (== ได้ true) — ความต่างอยู่ที่ "เป็นก้อนเดียวกันไหม" ไม่ใช่ "เท่ากันไหม"

🗣 ศัพท์ที่เพิ่งเรียนไป
Symbol
ชนิดข้อมูลที่เป็น "ชื่อ" เขียนด้วยโคลอนนำหน้า เช่น :active · ชื่อเดียวกัน = object เดียวกันเสมอ · ถาม AI ได้ว่า “when should I use a Symbol instead of a String in Ruby” คำตอบที่ดีควรพูดถึง key ของ Hash และชื่อ option
object_id / identity
เลขประจำตัวของ object แต่ละก้อน · ใช้แยก "ก้อนเดียวกัน" (identity) ออกจาก "หน้าตาเหมือนกัน" (equality) · บอก senior ได้ว่า “ผมเข้าใจว่า == เทียบค่า ส่วน equal? เทียบ identity ถูกไหมครับ” ("a".equal?("a") ได้ false · :a.equal?(:a) ได้ true — ผมรันแล้ว)

key ที่เก็บไว้คือ Symbol :a แต่คุณถามหา String "a" · สำหรับ Hash ธรรมดา สองตัวนี้คนละ key กันเลย · และ Ruby ไม่ฟ้องอะไรทั้งสิ้น แค่คืน nil ให้ แล้วโปรแกรมก็เดินต่อไปพร้อม nil ตัวนั้น จนไประเบิดที่บรรทัดอื่นที่ห่างออกไปไกล

คน Go จะงงตรงนี้ เพราะ Go มี ok บอกว่า "ไม่เจอ" · คน TypeScript ก็งง เพราะ tsc ฟ้องให้ก่อนรัน (ผมลอง m.b กับ const m = { a: 1 } ได้ error TS2339: Property 'b' does not exist on type '{ a: number; }'.) · Ruby ไม่มีทั้งสองอย่าง

แล้วถ้าอยากให้มันฟ้องเวลาไม่เจอ key ล่ะ? นั่นคือหน้าที่ของ fetch — สไลด์บอกว่า "fetch ใช้แทน m[:b] เมื่ออยากได้ค่า default หรืออยากให้ error ถ้าไม่มี key" · ค่า default เห็นไปแล้ว (m.fetch(:b, 0) ได้ 0) ส่วนแบบไม่ใส่ default: 

# fetch.rb
m = { a: 1 }
m.fetch(:b)

📝 เรื่องหน้าตาของผลลัพธ์: Ruby 4.0 พิมพ์ Hash เป็น {a: 1} และ {"a" => 1} · ถ้าไปเจอบทความเก่าหรือคำตอบของ AI ที่เขียน {:a=>1} ไม่ต้องตกใจ — นั่นคือหน้าตาของ Ruby รุ่นเก่า (ผมรันบรรทัดเดียวกันด้วย Ruby 2.6 ที่ติดมากับ macOS ได้ {:a=>1} จริง) · ข้างในคือของชิ้นเดียวกัน

แล้ว params[:post][:title] ใน Rails ล่ะ?

สไลด์บอกว่าเรื่องนี้ไปโผล่ที่ params[:post][:title] — คือการอ่านค่าที่ผู้ใช้กรอกฟอร์มส่งมา · ผมลองสร้าง controller ทดลองในแอป wongnok_blog แล้วยิงฟอร์มเข้าไปจริง (controller เต็ม ๆ เรียนใน บทเรียน 102 — ตรงนี้ดูแค่ว่า params หน้าตายังไง · ถ้าจะลองตาม ต้องเพิ่มบรรทัด resources :posts, only: :create ใน config/routes.rb ด้วย ไม่งั้นได้ 404 — เรื่อง routes อยู่ใน บทเรียน 101): 

# app/controllers/posts_controller.rb — โค้ดทดลอง
class PostsController < ApplicationController
  skip_forgery_protection   # ปิดการตรวจ CSRF เพื่อให้ curl ยิงได้ · ใช้ทดลองเท่านั้น

  def create
    render plain: "symbol: #{params[:post][:title]} | string: #{params["post"]["title"]}\n"
  end
end
# พอร์ต 3000 คือค่าเริ่มต้นของ bin/rails server (ตอนตรวจผมรันบนพอร์ตอื่น ผลเหมือนกัน)
$ curl -s -X POST http://localhost:3000/posts --data-urlencode 'post[title]=ต้มยำกุ้ง' --data-urlencode 'post[body]=อร่อย'
symbol: ต้มยำกุ้ง | string: ต้มยำกุ้ง

# บรรทัดที่ server log พิมพ์ออกมา
  Parameters: {"post" => {"title" => "ต้มยำกุ้ง", "body" => "อร่อย"}}

สังเกตสองอย่าง: ใน log key เป็น String ("post", "title") เพราะข้อมูลที่มาจาก HTTP เป็นตัวอักษรล้วน ๆ · แต่ใน controller อ่านด้วย Symbol ก็ได้ String ก็ได้ ผลเท่ากัน — เพราะ params ไม่ใช่ Hash ธรรมดา มันเป็น ActionController::Parameters ที่ Rails ตั้งใจทำให้ :post กับ "post" ถือเป็น key เดียวกัน

⚠️ อย่าเอานิสัยนี้ไปใช้กับ Hash ธรรมดา — ความ "ใจดี" นี้มีแค่ใน params · Hash ที่ได้จาก JSON.parse หรือที่คุณสร้างเองด้วย "key" => … ยังเป็น Hash ธรรมดา ผมรัน { "post" => { "title" => "ต้มยำกุ้ง" } }[:post] ได้ nil · และถ้าไปต่อ [:title] หลัง nil จะได้ undefined method '[]' for nil (NoMethodError) — ผลรันจริงเช่นกัน

🗄 เทียบให้เห็นภาพ — ตู้ล็อกเกอร์ กับยามหน้าตู้

Hash คือตู้ล็อกเกอร์ ที่แต่ละช่องมีป้ายชื่อ
m[:b] เหมือนเดินไปเปิดช่อง :b เอง — ถ้าไม่มีช่องนั้น คุณก็ได้มือเปล่ากลับมา (nil) ไม่มีใครบอกว่าเดินผิดช่อง แล้วคุณก็เดินถือมือเปล่าไปทำงานต่อ
m.fetch(:b) เหมือนขอให้ยามหยิบให้ — ไม่มีช่องนั้น ยามบอกทันทีว่า "ไม่มีช่อง :b ครับ" (KeyError) · ส่วน m.fetch(:b, 0) คือบอกยามไว้ก่อนว่า "ถ้าไม่มี เอาอันสำรองนี้ให้ผมแทน"

ที่ไม่เหมือนกัน: ล็อกเกอร์จริงถ้าช่องว่างกับไม่มีช่อง คุณเห็นความต่างด้วยตา — แต่ใน Hash m[:a] ของช่องที่มีอยู่แต่ใส่ nil ไว้ กับช่องที่ไม่มีอยู่เลย ให้ผลหน้าตาเหมือนกันทุกอย่าง (nil ทั้งคู่) ต้องถาม key? ถึงจะรู้ · และป้ายชื่อในตู้นี้อ่านตัวอักษรเป๊ะ ป้าย :a กับป้าย "a" ถือเป็นคนละช่อง — ยกเว้นตู้พิเศษชื่อ params ที่ Rails ทำให้อ่านได้ทั้งสองแบบ

🗣 ศัพท์ที่เพิ่งเรียนไป
Hash
กล่องเก็บคู่ key → value ของ Ruby (เทียบได้กับ map ของ Go หรือ object/Record ของ TS) · { a: 1 } คือทางลัดของ { :a => 1 } · ถาม AI ได้ว่า “what's the difference between Hash#[] and Hash#fetch in Ruby”
KeyError
error ที่ fetch โยนออกมาเมื่อหา key ไม่เจอและไม่ได้ให้ค่า default ไว้ · ใน code review พูดได้ว่า “ตรงนี้ key ต้องมีเสมอ ใช้ fetch ดีกว่า จะได้พังตรงจุดแทนที่จะได้ nil ไปพังที่อื่น” — senior หลายคนเรียกแนวคิดนี้ว่า fail fast
indifferent access
ความสามารถของ params (และ HashWithIndifferentAccess ของ Rails) ที่ทำให้ :post กับ "post" เป็น key เดียวกัน · ถาม senior ได้ว่า “Hash ตัวนี้เป็น indifferent access หรือ Hash ธรรมดาครับ” เวลาเจอ bug ที่ได้ nil โดยไม่รู้สาเหตุ

ไฟล์ Ruby ธรรมดา (ไม่ใช่ใน Rails) มี m = { a: 1 } · บรรทัด p m["a"] จะได้อะไร?

ตัวเลือกที่ 2 ถูก — ผลรันจริงของ hash.rb คือ nil · a: 1 เก็บ key เป็น Symbol :a ส่วน "a" เป็น String คนละตัวกัน

ตัวเลือกที่ 1 ผิด: การแปลงให้เองมีเฉพาะใน params ของ Rails (indifferent access) ไม่ใช่ Hash ธรรมดา · ตัวเลือกที่ 3 ผิด: KeyError มาจาก fetch เท่านั้น — [] ไม่เคยโยน error เรื่อง key หาย · ตัวเลือกที่ 4 ผิด: m.a คือวิธีของ TypeScript · ใน Ruby ถ้าเขียน m.a จะเป็นการเรียก method ชื่อ a ซึ่ง Hash ไม่มี

จุดที่ต้องจำ: [] หาไม่เจอ = nil เงียบ ๆ · fetch หาไม่เจอ = KeyError ดัง ๆ

3 · Enumerable — แทนที่ for loop ทั้งหมด

สไลด์หน้า 20 ให้โจทย์เดียวกันสามภาษา: "เอาชื่อของโพสต์ที่เผยแพร่แล้วออกมาเป็น list"

GoTypeScriptRuby
 
out := []string{}
for _, p := range posts {
  if p.Published {
    out = append(out,
      p.Title)
  }
}
 
const out = posts
  .filter(p => p.published)
  .map(p => p.title)

// ใกล้เคียง Ruby มาก
 
out = posts
  .select { |p| p.published }
  .map { |p| p.title }

# หรือสั้นกว่านั้น
out = posts.select(&:published)
           .map(&:title)

ถ้าคุณผ่าน บทเรียน 67 มาแล้ว ฝั่ง Ruby แทบไม่มีอะไรใหม่ — select ของ Ruby = filter ของ TypeScript (Ruby มีชื่อ filter ให้ด้วย ผมรันแล้วได้ผลเท่ากัน) · map ชื่อเดียวกันเลย · ของใหม่จริง ๆ มีแค่สองอย่าง:

  • { |p| p.published } คือ block — ก้อนโค้ดที่ส่งให้ method รันทีละสมาชิก · |p| คือชื่อตัวแปรที่รับสมาชิกแต่ละตัว (เทียบได้กับ p => ของ arrow function) · block มีรายละเอียดอีกเยอะ รอใน บทเรียน 93
  • &:published — อธิบายในหัวข้อ 4

สไลด์บอกว่า "ใน Ruby แทบไม่มีใครเขียน for loop เลย — ถ้าเจอ for ในโค้ด Rails ให้สงสัยไว้ก่อนว่ามีวิธีที่สั้นกว่า" · เหตุผลคือ Array, Hash และของที่เป็น "กองข้อมูล" ทุกชนิดใน Ruby มีชุด method สำเร็จรูปติดมาให้ ชื่อรวม ๆ ว่า Enumerable

🍊 เทียบให้เห็นภาพ — โต๊ะคัดส้มในโรงงาน

นึกถึงส้มหนึ่งตะกร้า (nums) วางบนโต๊ะ แล้วมีพนักงานแต่ละคนทำงานคนละแบบ:
select = คนที่หยิบเฉพาะลูกที่ผ่านเกณฑ์ใส่ตะกร้าใหม่ — ต้องดูครบทุกลูก · reject = คนที่หยิบลูกเสียทิ้ง เก็บที่เหลือ · map = คนที่ปอกเปลือกทุกลูก ได้ส้มปอกจำนวนเท่าเดิม · find = คนที่ถูกสั่งว่า "หาลูกใหญ่มาให้ลูกเดียว" — เจอลูกแรกก็เดินกลับเลย · sum = คนที่ชั่งน้ำหนักรวม · any? = "มีลูกเน่าสักลูกไหม" · all? = "สุกทุกลูกไหม"

ที่ไม่เหมือนกัน: ในโรงงานจริง ส้มลูกที่ถูกหยิบไปจะหายจากตะกร้าเดิม — แต่ใน Ruby select/map/reject ไม่แตะตะกร้าเดิมเลย (หลังรันทุกบรรทัด nums ยังเป็น [3, 1, 4, 1, 5]) มันถ่ายสำเนาส้มใส่ตะกร้าใหม่ทุกครั้ง · และพนักงานในโรงงานทำงานพร้อมกันได้ แต่ .select { … }.map { … } ทำทีละขั้น — select ทำจนเสร็จได้ตะกร้าใหม่ แล้ว map ถึงเริ่ม

nums = [3, 1, 4, 1, 5] · ผลของ nums.find { |n| n > 10 } และ nums.select { |n| n > 10 } คือคู่ไหน?

ตัวเลือกที่ 1 ถูก — ผลรันจริงของ find.rb สองบรรทัดสุดท้ายคือ nil และ [] · find คืน "ค่าเดียว" ไม่เจอจึงเป็น nil · select คืน "list" เสมอ ไม่เจอก็เป็น list ว่าง

ตัวเลือกที่ 2 และ 3 ผิดเพราะคิดว่าสองตัวนี้คืนของชนิดเดียวกัน ทั้งที่ชนิดต่างกันตั้งแต่ตอนเจอ (3 กับ [3, 4, 5]) · ตัวเลือกที่ 4 ผิดเพราะ KeyError เป็นเรื่องของ Hash#fetch · find ไม่เคยโยน error ตอนหาไม่เจอ

จุดที่ต้องจำ: หลัง find ต้องคิดเสมอว่า "ถ้าได้ nil จะเกิดอะไร" · หลัง select ไม่ต้องห่วง

4 · &:symbol — ทางลัดที่เจอทุกไฟล์ใน Rails

สไลด์หน้า 21 ฝั่งขวาบอกว่าสองบรรทัดนี้ "เหมือนกัน": 

posts.map { |p| p.title }
posts.map(&:title)     # เหมือนกัน

อ่านเป็นภาษาคนได้ว่า "กับสมาชิกทุกตัว ให้เรียก method ชื่อ title" · :title คือ Symbol (ชื่อของ method — เห็นไหมว่า Symbol คือ "ชื่อ" จริง ๆ) · ส่วน & ข้างหน้าบอก Ruby ว่า "แปลงชื่อนี้เป็น block ให้ที" · ลองดูว่าทำงานจริงไหม — ผมใช้ Struct สร้าง Post จำลองขึ้นมา (ของจริงใน Rails คือ model ซึ่งรอ Day 2): 

# posts.rb — จำลอง Post ด้วย Struct (ของจริงใน Rails คือ model · รอ Day 2)
Post = Struct.new(:title, :published, :category, :views, :created_at) do
  def published?
    published
  end
end

posts = [
  Post.new("ต้มยำกุ้ง", true,  "อาหาร",  120, 3),
  Post.new("ส้มตำ",     false, "อาหาร",   40, 1),
  Post.new("เที่ยวน่าน", true,  "เที่ยว",  300, 2),
]

# สไลด์หน้า 20 — แบบยาว
p posts.select { |p| p.published }.map { |p| p.title }

# สไลด์หน้า 20 — แบบสั้น
p posts.select(&:published).map(&:title)

# สไลด์หน้า 21 — ฝั่ง posts
p posts.select(&:published?).map(&:title)
p posts.group_by { |p| p.category }.transform_values { |ps| ps.map(&:title) }
p posts.sort_by { |p| p.created_at }.map(&:title)
p posts.sum { |p| p.views }

{ |n| n.upcase }✅ (&:upcase)เหมือนกัน · %w[ruby rails].map(&:upcase) รันได้ ["RUBY", "RAILS"]
{ |n| n * 2 }❌* ต้องการ argument (2) แต่ &: ส่งให้ไม่ได้
{ |p| p.title.upcase }❌ (ต้องแยกเป็นสองขั้น)เรียก method สองตัวต่อกัน · เขียน .map(&:title).map(&:upcase) แทนได้
{ |p| p[:title] }❌สมาชิกเป็น Hash · [:title] ไม่ใช่การเรียก method ชื่อ title

แถวสุดท้ายคือกับดักที่เจอบ่อยที่สุด — ข้อมูลที่มาจาก JSON หรือ API มักเป็น Hash ไม่ใช่ object ที่มี method: 

# posts_hash.rb
posts = [
  { title: "ต้มยำกุ้ง", published: true },
  { title: "ส้มตำ",     published: false },
]

p posts.select { |p| p[:published] }.map { |p| p[:title] }
p posts.map(&:title)

ผลรันจริง (exit code 1):

["ต้มยำกุ้ง"]
posts_hash.rb:8:in 'Array#map': undefined method 'title' for an instance of Hash (NoMethodError)

p posts.map(&:title)
       ^^^^
	from posts_hash.rb:8:in '<main>'

ข้อความ error อ่านออกเลยว่าเกิดอะไร: "Hash ไม่มี method ชื่อ title" · &:title แปลว่า "เรียก method title" เสมอ ไม่ได้แปลว่า "หยิบ key :title"

สไลด์หน้า 20 ปิดด้วยบรรทัดที่คุณจะได้เขียนจริงใน controller — @titles = Post.published.map(&:title) · ตอนนี้คุณอ่าน .map(&:title) ออกแล้ว · ส่วน Post.published (ดึงโพสต์ที่เผยแพร่แล้วจากฐานข้อมูล) เป็นเรื่องของ Active Record ใน Day 2

🗣 ศัพท์ที่เพิ่งเรียนไป
Enumerable
ชุด method สำเร็จรูป (map, select, find, group_by, sum …) ที่ติดมากับ Array, Hash และของที่ "วนได้" ทุกชนิด · ถาม AI ได้ว่า “rewrite this loop using Enumerable methods, no each + push” จะได้โค้ดแบบที่คนเขียน Rails คุ้นตา
block
ก้อนโค้ด { |x| … } หรือ do |x| … end ที่ส่งให้ method รัน · เทียบได้กับ arrow function ที่ส่งเข้า .map() ของ TS (แต่ไม่เหมือนทุกอย่าง — รอบทเรียน 93) · ถาม senior ได้ว่า “block นี้ถูกเรียกกี่ครั้ง และค่าที่ block คืนถูกเอาไปใช้ไหม” — คำถามนี้แยก map ออกจาก each ได้ทันที
&:symbol (symbol to proc)
ทางลัดที่แปลง Symbol เป็น block ที่ "เรียก method ชื่อนั้นกับสมาชิกแต่ละตัว" · ข้างหลังคือ Symbol#to_proc (:upcase.to_proc.call("ab") รันแล้วได้ "AB") · ใน review พูดได้ว่า “block นี้เรียก method ตัวเดียว ย่อเป็น &:title ได้ครับ”
predicate method (?)
method ที่ชื่อลงท้ายด้วย ? และตอบ true/false เช่น any?, all?, key?, published? · ตั้งชื่อ method ของตัวเองแบบนี้ด้วย เพราะคนอ่านโค้ด Ruby คาดหวังว่า ? = คำถามใช่/ไม่ใช่

block ไหนย่อเป็น &:ชื่อ ได้โดยผลลัพธ์ไม่เปลี่ยน?

ตัวเลือกที่ 3 ถูก — block เรียก method เดียว (upcase) บนสมาชิกแต่ละตัว ไม่มี argument ตรงตามเงื่อนไขของสไลด์หน้า 21

ตัวเลือกที่ 1 ผิด: เรียกสอง method ต่อกัน · :title.upcase ไม่ได้แปลว่า "title แล้ว upcase" แต่คือการ upcase ตัว Symbol เอง ได้ :TITLE (ผมรันแล้วได้ undefined method 'TITLE' for an instance of … (NoMethodError)) · ตัวเลือกที่ 2 ผิด: * ต้องการ argument · ผมรัน [1, 2].map(&:*) แล้วได้ wrong number of arguments (given 0, expected 1) (ArgumentError) · ตัวเลือกที่ 4 ผิด: &:title เรียก method title ซึ่ง Hash ไม่มี → NoMethodError (ผลรันจริงของ posts_hash.rb)

จุดที่ต้องจำ: &:ชื่อ ใช้ได้เมื่อ block มีแค่ "x.ชื่อ" ตัวเดียว — ไม่มี argument ไม่ต่อ method ไม่ใช่ [ ] ของ Hash

ใน controller ของ Rails ผู้ใช้ส่งฟอร์ม post[title]=ต้มยำกุ้ง มา · ข้อไหนถูกต้อง?

ตัวเลือกที่ 4 ถูก — curl จริงได้ symbol: ต้มยำกุ้ง | string: ต้มยำกุ้ง คืออ่านได้ทั้งคู่ · และ Rails Guides เขียนไว้ตรง ๆ ว่า params เป็น ActionController::Parameters ที่ถือว่า :foo กับ "foo" เป็น key เดียวกัน

ตัวเลือกที่ 1 และ 2 ผิดเพราะคำว่า "เท่านั้น" — ผลรันจริงอ่านได้ทั้งสองแบบ · ตัวเลือกที่ 3 ผิดครึ่งหลัง: Hash ธรรมดาแยก :post กับ "post" เป็นคนละ key (รัน { "post" => … }[:post] ได้ nil)

จุดที่ต้องจำ: ความ "อ่านได้ทั้งสองแบบ" เป็นของ params โดยเฉพาะ · ออกนอก params แล้วต้องใช้ key ให้ตรงชนิด

5 · ภารกิจ — เขียนโดยไม่มี loop แล้วพิสูจน์ด้วยผลรัน

🛠 สรุปข้อมูลโพสต์ด้วย Enumerable ล้วน ๆ

สร้างไฟล์ task.rb แล้ววางข้อมูลนี้ไว้บนสุด:

Post = Struct.new(:title, :published, :category, :views)

posts = [
  Post.new("ต้มยำกุ้ง", true,  "อาหาร",  120),
  Post.new("ส้มตำ",     false, "อาหาร",   40),
  Post.new("เที่ยวน่าน", true,  "เที่ยว",  300),
  Post.new("ข้าวซอย",   true,  "อาหาร",   80),
]

def check(name, got, want)
  puts "#{got == want ? "PASS" : "FAIL"} #{name}: #{got.inspect}"
end

ห้ามใช้ for และห้ามใช้ each + << · เขียนตัวแปรห้าตัวนี้ให้ได้:

  1. titles — ชื่อโพสต์ที่ published แล้ว เรียงตามลำดับเดิม (ใช้ &: ทั้งสองขั้น)
  2. total — ยอดวิวรวมเฉพาะโพสต์ที่เผยแพร่แล้ว
  3. first_hot — ชื่อของโพสต์ตัวแรกที่วิวเกิน 100
  4. by_cat — Hash ที่ key เป็นหมวด และ value เป็น list ของชื่อโพสต์ในหมวดนั้น
  5. views_of — Hash จากชื่อโพสต์ → ยอดวิว (คำใบ้: posts.to_h { |p| [ … , … ] })

แล้ววางบรรทัดพิสูจน์นี้ไว้ท้ายไฟล์ ห้ามแก้ค่าที่คาดหวัง:

check "1 titles",    titles,    ["ต้มยำกุ้ง", "เที่ยวน่าน", "ข้าวซอย"]
check "2 total",     total,     500
check "3 first_hot", first_hot, "ต้มยำกุ้ง"
check "4 by_cat",    by_cat,    { "อาหาร" => ["ต้มยำกุ้ง", "ส้มตำ", "ข้าวซอย"], "เที่ยว" => ["เที่ยวน่าน"] }
check "5 fetch",     views_of.fetch("ผัดไทย", 0), 0

begin
  views_of.fetch("ผัดไทย")
  puts "FAIL 6 KeyError: ไม่ระเบิด"
rescue KeyError => e
  puts "PASS 6 KeyError: #{e.message}"
end

รัน ruby task.rb จนได้ PASS ครบ 6 บรรทัด · แล้วตั้งใจทำให้พังหนึ่งรอบ: เปลี่ยน views_of.fetch("ผัดไทย") ในบล็อก begin เป็น views_of["ผัดไทย"] ดูว่าบรรทัดที่ 6 เปลี่ยนเป็นอะไร แล้วอธิบายให้ตัวเองฟังว่าทำไม

ก่อนกดเฉลย: ข้อ 3 ถ้าคุณใช้ select แทน find จะต้องเขียนต่อท้ายยังไงถึงจะได้ "ต้มยำกุ้ง" — และทำไม find ถึงดีกว่า?

titles    = posts.select(&:published).map(&:title)
total     = posts.select(&:published).sum(&:views)
first_hot = posts.find { |p| p.views > 100 }.title
by_cat    = posts.group_by(&:category).transform_values { |ps| ps.map(&:title) }
views_of  = posts.to_h { |p| [p.title, p.views] }

ผลรันจริง:

PASS 2 total: 500
PASS 3 first_hot: "ต้มยำกุ้ง"
PASS 4 by_cat: {"อาหาร" => ["ต้มยำกุ้ง", "ส้มตำ", "ข้าวซอย"], "เที่ยว" => ["เที่ยวน่าน"]}
PASS 5 fetch: 0

  • ข้อ 2 — sum รับ &:views ได้ด้วย เพราะ sum ก็รับ block ได้เหมือน map
  • ข้อ 3 — ถ้าใช้ select ต้องเขียน .select { … }.first.title · ได้ผลเท่ากัน แต่ select เดินครบทุกตัวแล้วสร้าง list ใหม่ ก่อนจะทิ้งเกือบทั้งหมดเหลือตัวแรก · find หยุดทันทีที่เจอ (ตามที่ find.rb พิมพ์ให้เห็นในหัวข้อ 3) · และบอกเจตนาตรงกว่า: "ฉันต้องการตัวเดียว"
  • ข้อ 4 — group_by คืน Hash ที่ value เป็น list ของ Post ทั้งก้อน ต้องต่อ transform_values ถึงจะเหลือแค่ชื่อ
  • ตอนตั้งใจทำให้พัง — views_of["ผัดไทย"] ได้ nil ไม่ระเบิด จึงไหลไปพิมพ์ FAIL 6 KeyError: ไม่ระเบิด · นี่คือภาพเดียวกับหัวข้อ 2: [] เงียบ · fetch ดัง

ข้อ 3 ยังมีจุดอ่อนอยู่: ถ้าไม่มีโพสต์ไหนวิวเกิน 100 find จะได้ nil แล้ว .title จะพัง · วิธีรับมือกับ nil แบบ Ruby อยู่ใน บทเรียน 94

6 · สรุปบทนี้เป็นสี่บรรทัด

เรื่องจำแค่นี้พอ
Symbolคือ "ชื่อ" ไม่ใช่ "ข้อความ" · :a ทุกตัวคือ object เดียวกัน · Rails ใช้เป็น key และชื่อ option แทบทุกบรรทัด เช่น validates :title, presence: true
Hash{ a: 1 } key เป็น Symbol · m["a"] ได้ nil เงียบ ๆ · fetch ได้ default หรือ KeyError · มีแค่ params ที่อ่านได้ทั้ง :post และ "post"
Enumerableselect = filter · find คืนตัวแรกหรือ nil และหยุดทันที · ทุกตัวคืนของใหม่ ไม่แก้ของเดิม · อย่าพิมพ์ nums.min / nums.max ตามสไลด์ (ได้ 0)
&:ชื่อ= { |x| x.ชื่อ } · ใช้ได้เมื่อ block เรียก method เดียวไม่มี argument · สมาชิกเป็น Hash ใช้ไม่ได้

✅ ถ้าตอบสี่ข้อนี้ได้ แปลว่าบทนี้ผ่านแล้ว
1. :a.object_id == :a.object_id กับ "a".object_id == "a".object_id ได้อะไร และทำไมไม่เหมือนกัน?
2. อยากให้โปรแกรมพังทันทีถ้า Hash ไม่มี key ที่ต้องการ ต้องใช้ method อะไร?
3. nums.find { … } กับ nums.select { … } ตอนหาไม่เจอ ได้อะไรต่างกัน?
4. rows.map(&:title) พังด้วย undefined method 'title' for an instance of Hash — แก้ยังไง?

ข้อไหนตอบไม่ได้ หรือรันแล้วได้ผลไม่ตรงกับบทนี้ ก็อปโค้ดกับผลรันของคุณมาถาม AI หรือถามเพื่อนในคอร์สได้เลย — ผลที่ต่างจากในบทคือเบาะแสที่ดีที่สุด อย่าเพิ่งสรุปว่าตัวเองผิด
