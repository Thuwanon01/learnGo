rails new และโครงสร้างโปรเจกต์ — เปิดดูทีละโฟลเดอร์, อ่าน Gemfile ให้เป็น

~25 นาที (บทหนัก มีของจริงให้ดูเยอะ) · ควรผ่าน บทเรียน 97 (5 เรื่องก่อนเข้า Rails) มาก่อน · ถ้าจำ go.mod / go.sum ไม่ได้ ย้อนดู บทเรียน 1

ตอนเขียน Go คุณเริ่มจากโฟลเดอร์เปล่า — go mod init แล้วค่อย ๆ เติม main.go · router · config · ต่อ database ทีละชิ้น (บท 27 กับ บท 48 คือภาพนั้น)
Rails กลับด้านกันหมด: คำสั่งเดียวได้โปรเจกต์ที่ "ครบเกินไป" มาก่อน แล้วคุณค่อยเรียนรู้ว่าไฟล์ไหนคืออะไร
บทนี้ผมรัน rails new wongnok_blog --database=postgresql --css=tailwind ใหม่จริง ตามสไลด์หน้า 40 แล้วเปิดดูทีละโฟลเดอร์ นับไฟล์จริง เปิด server จริง และอ่าน Gemfile ตัวจริงที่ได้มา (สไลด์หน้า 39–45)
ระหว่างทางเจอหลายจุดที่ของจริงไม่ตรงกับสไลด์ — ตั้งแต่ "commit แรกให้แล้ว" ที่ไม่มีจริง ไปจนถึง bundle info ที่บอกของคนละอย่างกับที่สไลด์เขียน · ผมจะบอกไว้ตรงจุดนั้นทุกจุด

🍣 เทียบให้เห็นภาพ — ร้านซูชิแบบ omakase

สไลด์ใช้คำว่า Omakase ซึ่งเป็นคำญี่ปุ่นแปลว่า "แล้วแต่เชฟ" — เข้าร้านแล้วไม่ต้องเลือกเมนูเอง เชฟจัดชุดมาให้ 12 คำ เรียงลำดับให้แล้ว คุณแค่นั่งกิน
Go คือร้านอาหารตามสั่ง: อยากได้ router สั่ง Gin · อยากได้ ORM สั่ง GORM · อยากได้ config สั่ง caarlos0/env — อิสระเต็มที่ แต่ต้องรู้ว่าจะสั่งอะไร และต้องจับมาเข้ากันเอง
Rails คือ omakase — คนทำ Rails เลือกให้แล้วว่าแต่ละหน้าที่ใช้ชิ้นไหน และทุกชิ้นถูกทำมาให้เข้ากันพอดี

ที่ไม่เหมือนกัน: ร้าน omakase จริงคุณขอข้ามคำไหนไม่ได้ และสั่งแค่คำเดียวกลับบ้านก็ไม่ได้
แต่ Rails ข้ามชิ้นที่ไม่ใช้ได้ตั้งแต่ตอนสร้าง (rails new … --skip-action-mailer — มีใน rails new --help จริง) และหยิบชิ้นเดียวไปใช้นอก Rails ได้อย่างที่ solo.rb เพิ่งทำให้ดู

🗣 ศัพท์ที่เพิ่งเรียนไป
gem
แพ็กเกจของ Ruby หนึ่งตัว — เทียบได้กับ module หนึ่งตัวใน go.mod หรือ package หนึ่งตัวใน package.json · คลังกลางคือ rubygems.org · ถาม AI ได้ว่า "which gem provides this constant?" เวลาเจอ class แปลก ๆ ในโค้ด Rails แล้วไม่รู้ว่ามาจากไหน
meta-gem
gem ที่ตัวเองไม่มีโค้ด มีไว้ลาก gem อื่นมาเป็นชุด — rails คือตัวอย่างชัดที่สุด · ถาม senior ได้ว่า "โปรเจกต์นี้ใช้ gem "rails" ทั้งชุด หรือเลือกเฉพาะ framework ที่ใช้" (บางทีมเขียน require ทีละชิ้นใน config/application.rb เพื่อตัดของที่ไม่ใช้)
Railties
ส่วนที่ประกอบทุกชิ้นเข้าด้วยกันตอนแอปบูต และเป็นเจ้าของคำสั่ง rails ทุกคำสั่ง (new · server · console · generate) · พิมพ์บอก AI ได้ว่า "this is a railtie / initializer problem, not an Active Record problem" ถ้า error เกิดตอนบูตก่อนแตะ database
omakase
ปรัชญาของ Rails ที่ "เลือกของให้แล้ว" — คำนี้โผล่ในชื่อ gem จริงด้วย (rubocop-rails-omakase ใน Gemfile ที่จะเห็นในหัวข้อ 6) · ถาม senior ได้ว่า "ทีมเราออกจากค่าเริ่มต้นของ Rails ตรงไหนบ้าง แล้วทำไม" — ทุกจุดที่ออกคือที่ที่คนใหม่หลงทาง

สไลด์หน้า 40 บอกว่า rails new ให้ "git repo ที่ commit แรกให้แล้ว" · และเราเพิ่งเห็นบรรทัด git init ในผลข้างบน — git log จะแสดงอะไร? 

$ git log
fatal: your current branch 'main' does not have any commits yet

ยังไม่มี commit เลย · rails new ทำแค่ git init (สร้าง repo เปล่า) — ไม่ได้ git add ไม่ได้ git commit · ไฟล์ทุกตัวยังเป็น untracked: 

$ git status --short

?? .gitattributes
?? .github/
?? .gitignore
?? .kamal/
…(ตัดออก)…
?? test/
?? tmp/
?? vendor/

นี่คือจุดที่สไลด์ผิด · commit แรกต้องทำเอง — และควรทำทันที ก่อนแก้อะไรสักไฟล์ จะได้มี "จุดเริ่มต้นที่สะอาด" ไว้ git diff เทียบได้ตลอด

ทำ commit แรกเองแล้วนับว่าได้ไฟล์จริงกี่ไฟล์: 

$ git add -A
$ git commit -m "rails new"
$ git log --oneline --stat | tail -1

$ git ls-files | wc -l
     109
$ git ls-files | grep -v "\.keep$" | wc -l
      90

ได้ 109 ไฟล์ (ถ้าไม่นับไฟล์ .keep ที่มีไว้กันโฟลเดอร์เปล่าหาย ก็ 90 ไฟล์) · สไลด์บอก "ประมาณ 80 ไฟล์" — ของจริงบน Rails 8.1.4 กับ flag ชุดนี้มากกว่านั้น ส่วนที่เหลือของประโยคในสไลด์ ตรวจแล้วได้แบบนี้:

มีไฟล์หนึ่งที่ห้ามติดเข้า git เด็ดขาด — config/master.key (กุญแจไขไฟล์ความลับ credentials.yml.enc) · ตรวจได้ว่า .gitignore กันไว้ให้จริง และกันด้วยบรรทัดไหน: 

$ git check-ignore -v config/master.key

$ git ls-files | grep -E 'master.key|credentials|Gemfile'

credentials.yml.enc (ความลับที่เข้ารหัสแล้ว) ติดเข้า git · master.key (กุญแจ) ไม่ติด — ตรงกับที่สไลด์หน้า 42 เขียนว่า "encrypted secrets, safe to commit"

หลัง rails new คุณพิมพ์ git add -A — ไฟล์ไหนจะไม่ถูกเพิ่มเข้า git?

ตัวเลือกที่ 3 ถูก · git check-ignore -v ชี้ไปที่บรรทัด 34 ของ .gitignore ตรง ๆ

ตัวเลือกที่ 1 ผิด เพราะไฟล์นี้เข้ารหัสแล้ว ใครได้ไปก็อ่านไม่ออกถ้าไม่มี master.key — จึง commit ได้ (และต้อง commit ไม่งั้นเพื่อนไม่มีความลับชุดเดียวกัน) · ตัวเลือกที่ 2 ผิด เพราะ Gemfile.lock ต้อง commit เสมอสำหรับแอป (หัวข้อ 6.5) · ตัวเลือกที่ 4 ผิด เพราะ .ruby-version บอกว่าทั้งทีมใช้ Ruby รุ่นไหน — มันอยู่ใน git ls-files จริง

จุดที่ต้องจำ: ไฟล์ .enc คือกล่องล็อก commit ได้ · ไฟล์ .key คือกุญแจ ห้าม commit · ถ้าเผลอ commit กุญแจไปแล้ว การลบออกใน commit ถัดไปไม่พอ เพราะมันยังอยู่ในประวัติ git

Unix domain socket (ค่าเริ่มต้นของ database.yml) เหมือนอินเตอร์คอมในบ้าน — กดปุ่มแล้วคุยกับห้องข้าง ๆ ได้ทันที ไม่ต้องรู้เบอร์ ไม่ต้องตั้งค่าอะไร แต่ใช้ได้เฉพาะคนที่อยู่ในบ้านเดียวกัน
TCP (host: … + port: … หรือ DATABASE_URL) เหมือนโทรศัพท์ — ต้องรู้เบอร์ แต่โทรหาใครก็ได้ จะอยู่ในบ้าน ใน container หรืออีกเครื่องก็ได้
Postgres ใน Docker คือคนที่อยู่อีกบ้านหนึ่ง — กดอินเตอร์คอมเรียกยังไงก็ไม่ได้ยิน ต้องโทร

ที่ไม่เหมือนกัน: อินเตอร์คอมจริงพอไม่มีคนรับก็แค่เงียบ แต่ socket ที่ไม่มีอยู่ทำให้ได้ error No such file or directory — เพราะในโลก Unix socket ชนิดนี้เป็นไฟล์จริง ๆ ไฟล์หนึ่งบนดิสก์ (/tmp/.s.PGSQL.5432) ไม่มีไฟล์ = ไม่มีปลายสาย

6.2 ~> — ขยับได้แค่ไหน

~> มีชื่อเล่นว่า pessimistic constraint ("ข้อจำกัดแบบมองโลกในแง่ร้าย") — มองว่า "รุ่นถัดไปอาจทำของพัง" เลยยอมให้ขยับแค่ตัวเลขหลักสุดท้ายที่คุณเขียน
ไม่ต้องเชื่อคำอธิบาย ให้ RubyGems ตอบเอง: 

# tilde.rb
req = Gem::Requirement.new("~> 8.1.3")

%w[8.1.2 8.1.3 8.1.9 8.1.10 8.2.0 9.0.0].each do |v|
  puts "#{v.ljust(6)} => #{req.satisfied_by?(Gem::Version.new(v))}"
end

หกรุ่นนี้ รุ่นไหนได้ true บ้าง? ระวัง 8.1.10 — ถ้าเทียบแบบตัวอักษร "10" น้อยกว่า "9"

ก้อน CHECKSUMS คือ ลายนิ้วมือ sha256 ของแต่ละ gem — หน้าที่เดียวกับ go.sum เป๊ะ (Bundler ตรวจทุก gem ตอนติดตั้ง ถ้าไม่ตรงก็ไม่ยอมลง) · เพราะฉะนั้น Gemfile.lock ของ Ruby = "รุ่นที่ล็อกแล้ว" แบบ package-lock.json บวก checksum แบบ go.sum ในไฟล์เดียว
คู่มือของ Bundler ตอบเรื่อง commit ไว้ตรง ๆ: สำหรับแอป ให้ commit Gemfile.lock เสมอ · ไม่ commit = เครื่องเพื่อนกับ server จะ resolve รุ่นใหม่เองทุกครั้งที่ติดตั้ง แล้วได้คนละรุ่นกับคุณ

🛒 เทียบให้เห็นภาพ — รายการซื้อของ กับ ใบเสร็จ

Gemfile คือรายการซื้อของที่คุณเขียนเอง: "นมสด 1 ลิตร ยี่ห้อไหนก็ได้ ขอแค่ไม่ใช่สูตรใหม่ที่เพิ่งออก" — นั่นคือ ~> 1.2 · เขียนแค่ของที่คุณอยากได้จริง ๆ 24 อย่าง
Gemfile.lock คือใบเสร็จ: บอกยี่ห้อ รุ่น และบาร์โค้ด (checksum) ของทุกชิ้นที่ได้มาจริง — รวมของแถมที่คุณไม่ได้สั่งแต่ติดมาด้วย จนครบ 124 ชิ้น
อยากให้เพื่อนซื้อได้ของชุดเดียวกันเป๊ะ ต้องส่งใบเสร็จให้ ไม่ใช่ส่งรายการซื้อของ — นี่คือเหตุผลที่ต้อง commit lock

ที่ไม่เหมือนกัน: ใบเสร็จจริงเป็นแค่หลักฐานหลังจ่ายเงิน ไม่มีใครเอาไปยื่นให้ร้านจัดของตาม · แต่ Gemfile.lock ถูกอ่านก่อนติดตั้งทุกครั้ง — bundle install จะลงตามรุ่นในใบเสร็จ และถ้าบาร์โค้ดไม่ตรงก็ไม่ยอมลง · มันเลยเป็นทั้งใบเสร็จและใบสั่งซื้อซ้ำในไฟล์เดียว

🎯 ภารกิจ: สร้างโปรเจกต์ของคุณเอง แล้วให้ Minitest ยืนยันสิ่งที่บทนี้พูด

  1. รัน rails new wongnok_blog --database=postgresql --css=tailwind ในโฟลเดอร์ที่คุณเก็บงาน แล้ว cd เข้าไป
  2. รัน git log ยืนยันว่ายังไม่มี commit · รัน git check-ignore -v config/master.key · แล้วทำ commit แรกเอง · นับด้วย git ls-files | wc -l ว่าของคุณได้กี่ไฟล์
  3. ตั้ง DATABASE_URL ให้ชี้ไป Postgres ที่คุณเปิดไว้ (หรือใช้ Postgres ที่ลงในเครื่องตรง ๆ) · รัน bin/rails db:prepare · เปิด bin/rails server แล้ว curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/ ให้ได้ 200
  4. เขียนเทสพิสูจน์ ชื่อ gemfile_test.rb ไว้นอกโฟลเดอร์โปรเจกต์ (เช่นโฟลเดอร์แม่) ด้วย Minitest ที่มากับ Ruby ให้ครบ 5 ข้อ:
    • ~> 8.1.3 รับ 8.1.9 แต่ไม่รับ 8.2.0
    • ~> 1.2 รับ 1.14.0 แต่ไม่รับ 2.2.0
    • gem rails ใน Gemfile.lock ของคุณพึ่ง 10 ชิ้นในสไลด์หน้า 39 ครบ และส่วนที่เกินมาคือ actionmailbox · bundler · railties
    • รุ่น rails ที่ล็อกไว้ อยู่ในช่วงที่ Gemfile ขอ
    • config/master.key ถูก ignore แต่ Gemfile.lock ไม่ถูก ignore
    แล้ว cd เข้าโปรเจกต์ รัน ruby ../gemfile_test.rb ให้ผ่านหมด
  5. ทดสอบเทสของคุณเอง: เปลี่ยน refute ของเคส 8.2.0 เป็น assert แล้วดูว่าเทสแดงจริงไหม

ก่อนกดเฉลย ตอบให้ได้: ถ้าคุณใช้ Rails 8.1.3 แบบในสไลด์ เทสที่ตรวจว่า "รุ่น rails ที่ล็อกไว้อยู่ในช่วงที่ Gemfile ขอ" ยังผ่านไหม? (คิดว่า Gemfile ของคุณจะเขียน constraint ว่าอะไร) 

# gemfile_test.rb — วางไว้นอกโปรเจกต์ รันจากในโปรเจกต์ด้วย ruby ../gemfile_test.rb
require "minitest/autorun"
require "bundler"

class GemfileTest < Minitest::Test
  OMAKASE = %w[
    activerecord actionpack actionview activejob actionmailer
    activestorage actiontext actioncable activesupport activemodel
  ]

  def setup
    @lock = Bundler::LockfileParser.new(File.read("Gemfile.lock"))
    @rails = @lock.specs.find { |s| s.name == "rails" }
  end

  def test_pessimistic_three_digits
    req = Gem::Requirement.new("~> 8.1.3")
    assert req.satisfied_by?(Gem::Version.new("8.1.9"))
    refute req.satisfied_by?(Gem::Version.new("8.2.0"))
  end

  def test_pessimistic_two_digits
    req = Gem::Requirement.new("~> 1.2")
    assert req.satisfied_by?(Gem::Version.new("1.14.0"))
    refute req.satisfied_by?(Gem::Version.new("2.2.0"))
  end

  def test_rails_is_a_box_of_gems
    deps = @rails.dependencies.map(&:name)
    assert_empty OMAKASE - deps
    assert_equal %w[actionmailbox bundler railties], (deps - OMAKASE).sort
  end

  def test_locked_rails_matches_gemfile
    wanted = @lock.dependencies["rails"].requirement
    assert wanted.satisfied_by?(@rails.version)
  end

  def test_master_key_is_ignored
    assert system("git check-ignore -q config/master.key")
    refute system("git check-ignore -q Gemfile.lock")
  end
end

สิ่งที่ต้องสังเกต:

  • Bundler::LockfileParser อ่าน Gemfile.lock ให้เป็น object — ไม่ต้อง parse ข้อความเอง · @lock.dependencies คือส่วน DEPENDENCIES (สิ่งที่ Gemfile ขอ) ส่วน @lock.specs คือรุ่นที่ resolve แล้ว
  • system(…) คืน true เมื่อคำสั่งจบด้วย exit code 0 · git check-ignore -q จบด้วย 0 เมื่อไฟล์ถูก ignore
  • &:name คือท่า &:symbol จากบท 92 · OMAKASE - deps คือลบ array (เหลือตัวที่หายไป) — ว่างแปลว่าครบ
  • วางเทสไว้นอกโปรเจกต์เพราะนี่เป็นการตรวจโปรเจกต์ ไม่ใช่เทสของแอป · เทสของแอปจริงอยู่ใน test/ และรอ Day 4
  • คำถามก่อนเฉลย: ถ้าใช้ Rails 8.1.3 Gemfile จะเขียน "~> 8.1.3" และ lock จะเป็น 8.1.3 — test_locked_rails_matches_gemfile ยังผ่าน เพราะเทสไม่ได้ฝังเลขรุ่นไว้ มันเทียบ "สิ่งที่ขอ" กับ "สิ่งที่ได้" ของโปรเจกต์คุณเอง

ถ้าเผลอรันเทสจากนอกโฟลเดอร์โปรเจกต์ (ruby gemfile_test.rb ในโฟลเดอร์แม่) ทุกข้อจะพังตั้งแต่ setup ด้วย Errno::ENOENT: No such file or directory @ rb_sysopen - Gemfile.lock และสรุปเป็น 5 runs, 0 assertions, 0 failures, 5 errors, 0 skips (ผมลองแล้ว) — cd เข้าโปรเจกต์ก่อนแล้วรันใหม่ · ถ้าพังเฉพาะ test_master_key_is_ignored ให้รัน git check-ignore -v config/master.key ดูว่า .gitignore ของคุณถูกแก้ไปหรือเปล่า
