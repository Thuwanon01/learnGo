rails new — สร้างโปรเจกต์แรก แล้วเดินดูทีละห้อง

~20 นาที (+ ภารกิจ ~10 นาที) · ควรผ่าน บทเรียน 97 (อ่านโค้ด Rails ไม่งง) มาก่อน · ถ้าลืมภาพ "แอป Rails = ร้านอาหาร" ย้อนดู บทเรียน 90

เจ็ดบทที่ผ่านมาคุณเขียน Ruby ล้วน ๆ · บทนี้คือครั้งแรกที่จะได้แอป Rails ตัวจริง
คุณจะพิมพ์คำสั่งเดียว แล้วได้โปรเจกต์ชื่อ wongnok_blog (แอปบล็อกของสไลด์) ที่เปิดดูในเบราว์เซอร์ได้ทันที
อ่านจบแล้วคุณจะ: รู้ว่า rails new ทำอะไรให้บ้าง · เดินในโปรเจกต์แล้วรู้ว่าโฟลเดอร์ไหนคือห้องอะไร · อ่าน Gemfile ออก · และเปิด server จนเห็นหน้าแรกที่ localhost:3000

🔁 ทวนก่อนเริ่ม — คำจากบทก่อนที่บทนี้ใช้

  • terminal (บท 91) — หน้าต่างที่พิมพ์คำสั่งแล้วกด Enter
  • gem (บท 90) — ของสำเร็จรูปที่คนอื่นเขียนไว้ให้ Ruby ใช้ · บทนี้จะเจอละเอียด
  • Convention over Configuration (บท 90) — วางของตามที่ตกลงกันไว้ แล้ว Rails หาเจอเอง
  • symbol · block · hash ท้าย argument (บท 92 · 93 · 97) — :test · do … end · gem "pg", require: false
  • ร้านอาหาร (บท 90) — routes = พนักงานต้อนรับ · controller = หัวหน้าเชฟ · model = ห้องวัตถุดิบ · view = การจัดจาน

🧰 เครื่องที่ใช้ตรวจ: Ruby 4.0.9 · Rails 8.1.4 · PostgreSQL 17 — สไลด์ใช้ Ruby 4.0.6 · Rails 8.1.3 ต่างกันแค่เลขท้าย · จุดที่บทนี้เห็น 8.1.4 ของคุณอาจเห็น 8.1.3
ทุกผลรันในบทนี้ก็อปมาจากเครื่องจริง · path ยาว ๆ ของเครื่องตรวจย่อเป็น … · กล่องไหนตัดบรรทัดออกจะเขียนกำกับไว้

Go เริ่มจากห้องเปล่า — Rails ได้ร้านมาทั้งร้าน

ตอนเริ่มโปรเจกต์ Go คุณพิมพ์ go mod init แล้วได้ไฟล์มาไฟล์เดียว ที่เหลือต้องสร้างเองทั้งหมด: main.go · router ของ Gin · handler · โค้ดต่อ database 

# ผลรันจริง — โฟลเดอร์เปล่า แล้วสั่ง go mod init
$ go mod init blog
go: creating new go.mod: module blog
$ ls -A
go.mod

rails new ทำกลับกัน — คำสั่งเดียวได้ไฟล์มา 109 ไฟล์ และเปิดเป็นเว็บได้ทันทีโดยยังไม่ต้องเขียนโค้ดสักบรรทัด
ข้อดีคือเริ่มได้เร็ว · ข้อเสียคือวันแรกมีไฟล์ที่ไม่รู้จักเต็มไปหมด — บทนี้จะพาดูเฉพาะห้องที่ต้องรู้

🏪 เทียบให้เห็นภาพ — เช่าห้องเปล่าเปิดร้านเอง กับ ซื้อแฟรนไชส์

Go คือเช่าห้องเปล่าแล้วเปิดร้านเอง — go mod init ให้แค่กุญแจห้อง คุณต้องจ้างพนักงานต้อนรับเอง (Gin router) · เขียนใบงานเชฟเอง (handler) · ซื้อตู้เก็บแฟ้มเอง (GORM + database)
Rails คือซื้อแฟรนไชส์ — วันแรกได้ครัวครบชุด เคาน์เตอร์ ตู้แฟ้ม ป้ายร้าน และทุกสาขาวางของตำแหน่งเดียวกัน ใครย้ายมาจากสาขาอื่นก็หาของเจอ

ที่ไม่เหมือนกัน: แฟรนไชส์จริงห้ามรื้อห้องที่บริษัทแม่ให้มา · แต่ห้องไหนใน Rails ที่ไม่ใช้ คุณลบทิ้งได้เลย (หรือสั่งตั้งแต่แรกว่าไม่เอา ด้วย flag ในหัวข้อถัดไป) และไม่มีใครเก็บค่าธรรมเนียม — Rails ฟรีทั้งหมด

ห้องผู้จัดการ — config/

config/ มีของ 20 อย่าง (ไฟล์ + โฟลเดอร์ย่อย) แต่ Day 1 เปิดแค่ config/routes.rb — รายการในมือพนักงานต้อนรับ ที่บอกว่า URL ไหนไปหาแผนกไหน · ดูของจริงที่ได้มา: 

# ผลรันจริง — config/routes.rb (ไฟล์เต็ม)
Rails.application.routes.draw do
  # Define your application routes per the DSL in https://guides.rubyonrails.org/routing.html

  # Reveal health status on /up that returns 200 if the app boots with no exceptions, otherwise 500.
  # Can be used by load balancers and uptime monitors to verify that the app is live.
  get "up" => "rails/health#show", as: :rails_health_check

  # Render dynamic PWA files from app/views/pwa/* (remember to link manifest in application.html.erb)
  # get "manifest" => "rails/pwa#manifest", as: :pwa_manifest
  # get "service-worker" => "rails/pwa#service_worker", as: :pwa_service_worker

  # Defines the root path route ("/")
  # root "posts#index"
end
  • Rails.application.routes.draw do … end = "วาดผัง URL ของแอปนี้" · ของข้างใน do … end คือ block (บท 93)
  • บรรทัดที่ขึ้นต้นด้วย # คือ comment — Ruby ไม่อ่าน (comment ภาษาอังกฤษพวกนี้ Rails เขียนมาให้ อ่านข้ามได้) · ไฟล์นี้จึงมี route (หนึ่งบรรทัดในผัง URL) ที่ใช้งานจริงอยู่บรรทัดเดียว
  • get "up" => … = ถ้ามีคนขอ URL /up ให้ส่งไปแผนกตรวจสุขภาพของ Rails เอง (ใช้เช็คว่าร้านยังเปิดอยู่ไหม) · => อ่านว่า "ส่งไปที่" · "rails/health#show" อ่านว่า "แผนก rails/health เมนู show" (ซ้ายของ # คือแผนก = controller · ขวาคือเมนู = action) · ส่วน as: คือชื่อเล่นของ route (บท 101)
  • # root "posts#index" (แผนก posts เมนู index) ยังเป็น comment = ยังไม่มีหน้าแรกของเราเอง · เดี๋ยวตอนเปิด server จะเห็นผลของบรรทัดนี้

Gemfile — รายการซื้อของของร้าน

gem คือของสำเร็จรูปที่คนอื่นเขียนไว้ เช่นตัวคุยกับ PostgreSQL หรือ web server · Gemfile คือรายการว่าแอปนี้ต้องใช้ gem อะไร รุ่นไหน · Bundler คือโปรแกรมที่อ่านรายการแล้วไปติดตั้งให้ ด้วยคำสั่ง bundle install (rails new สั่งให้แล้วรอบหนึ่ง)

gem ตรงกับอะไรใน Go — module ไม่ใช่ package

ใน Go package คือโฟลเดอร์โค้ดหนึ่งโฟลเดอร์ที่ import ได้ (เช่น net/http) · module คือชุดของ package ที่ปล่อยออกมาพร้อมกัน มีชื่อและเลขรุ่นเดียวกัน = หนึ่งบรรทัดใน go.mod
gem มีชื่อ มีเลขรุ่น และติดตั้งทั้งก้อน → ตรงกับ module · ข้างใน gem หนึ่งตัวมีไฟล์ย่อยหลายไฟล์ เหมือน module หนึ่งตัวมีหลาย package

นี่คือ Gemfile ที่ได้มาจริง ตัดเหลือบรรทัดที่ควรอ่านเป็น (ไฟล์เต็มยาว 68 บรรทัด ส่วนใหญ่เป็น comment):

# ผลรันจริง — Gemfile (ย่อ)
source "https://rubygems.org"

gem "rails", "~> 8.1.4"
gem "pg", "~> 1.1"
gem "puma", ">= 5.0"
gem "tailwindcss-rails"
…(ตัดออก)…
group :development, :test do
…(ตัดออก)…
  gem "brakeman", require: false
…(ตัดออก)…
end

Gemfile เป็นไฟล์ Ruby จริง ๆ · ทุกบรรทัดคือการเรียก method แบบละวงเล็บ (บท 97) — อ่านทีละบรรทัด:

  • source "https://rubygems.org" = ไปซื้อของที่ร้านไหน · rubygems.org คือคลังกลางของ gem (เหมือนแหล่งที่ go get ไปโหลด module มาให้)
  • gem "rails", "~> 8.1.4" = เรียก method gem ส่งของสองอย่าง: ชื่อ gem กับเงื่อนไขรุ่น · เท่ากับ gem("rails", "~> 8.1.4") · ~> อ่านว่าอะไร อยู่หัวข้อถัดไป
  • gem "pg", … = ตัวคุยกับ PostgreSQL — หน้าที่เดียวกับ driver postgres ที่ GORM ใช้ฝั่ง Go
  • gem "puma", ">= 5.0" = web server (ประตูร้านที่รับใบสั่งเข้ามาแล้วส่งต่อเข้าร้าน · ละเอียดในบท 100) · >= = รุ่น 5.0 ขึ้นไปอะไรก็ได้
  • gem "tailwindcss-rails" ไม่มีเงื่อนไขรุ่น = รุ่นไหนก็ได้ ให้ Bundler เลือก
  • group :development, :test do … end = gem ข้างใน block นี้ใช้เฉพาะตอนพัฒนาและตอนเทส ไม่โหลดตอนเปิดร้านจริง (production) · :development คือ symbol (บท 92)
  • require: false = hash ท้าย argument (บท 97) แปลว่า "ติดตั้งไว้ แต่ไม่ต้องโหลดเข้าแอปเอง" · ใช้กับเครื่องมือที่เรียกจาก terminal เช่น brakeman (ตัวสแกนช่องโหว่)

🛒 เทียบให้เห็นภาพ — รายการซื้อของ กับ ใบเสร็จ

Gemfile คือรายการซื้อของที่คุณเขียนเอง: "น้ำปลา 1 ขวด ยี่ห้อเดิม ล็อตไหนก็ได้" · "ข้าวสาร 5 กิโล ยี่ห้ออะไรก็ได้"
Bundler คือคนที่ถือรายการไปซื้อของ · Gemfile.lock คือใบเสร็จที่ได้กลับมา — ระบุยี่ห้อ รุ่น และบาร์โค้ดของทุกชิ้นจริง ๆ รวมของแถมที่ติดมาด้วยโดยคุณไม่ได้สั่ง (24 อย่างในรายการ ได้ของกลับมา 124 ชิ้น)
อยากให้สาขาอื่นได้ของชุดเดียวกันเป๊ะ ต้องส่งใบเสร็จให้ ไม่ใช่ส่งแค่รายการ

ที่ไม่เหมือนกัน: ใบเสร็จจริงเป็นแค่หลักฐานหลังจ่ายเงิน ไม่มีใครเอาไปยื่นให้ร้านจัดของตาม · แต่ bundle install อ่าน Gemfile.lock ก่อนเสมอ แล้วติดตั้งตามรุ่นในนั้นเป๊ะ ๆ — มันจึงเป็นทั้งใบเสร็จและใบสั่งซื้อซ้ำในไฟล์เดียว

ก่อนเพิ่ม gem ใหม่ (เก็บไว้ใช้ทีหลัง) — สไลด์หน้า 45 ให้ถามตัวเองสี่ข้อ: ยังมีคนดูแลอยู่ไหม (commit ล่าสุดเกินปีให้สงสัยไว้ก่อน) · ใช้กับ Rails รุ่นเราได้ไหม · ลาก gem อื่นมาด้วยกี่ตัว · และRails มีให้อยู่แล้วหรือเปล่า — ข้อสุดท้ายสำคัญที่สุด

~> อ่านว่าอะไร

~> แปลว่า "ขยับรุ่นได้ แต่ไม่ไกล" · วิธีอ่าน: ตัวเลขตัวท้ายสุดที่เขียนไว้ ขยับขึ้นได้ ส่วนตัวเลขข้างหน้ามันล็อก

  • ~> 1.2 → ตัวท้ายคือ 2 ขยับขึ้นได้ · 1 ล็อก → ตั้งแต่ 1.2 แต่ต่ำกว่า 2.0
  • ~> 8.1.4 → ตัวท้ายคือ 4 ขยับขึ้นได้ · 8.1 ล็อก → ตั้งแต่ 8.1.4 แต่ต่ำกว่า 8.2

ทำไมต้องล็อก? เพราะเลขหลักหน้าที่เปลี่ยนมักแปลว่า "มีของเปลี่ยนจนโค้ดเก่าอาจพัง" — ~> ยอมรับแค่การแก้บั๊กเล็ก ๆ

🧴 เทียบให้เห็นภาพ — "สูตรเดิม ล็อตใหม่ได้"

~> 1.2 เหมือนเขียนในรายการซื้อของว่า "น้ำปลาสูตร 1 ล็อต 2 ขึ้นไป ล็อตใหม่แค่ไหนก็ได้ แต่ห้ามเอาสูตร 2 มา" · คนซื้อ (Bundler) จะหยิบล็อตใหม่สุดที่ยังเป็นสูตร 1 แล้วจดลงใบเสร็จ (Gemfile.lock)

ที่ไม่เหมือนกัน: คนซื้อของจริงดูฉลากแล้วใช้วิจารณญาณได้ · Bundler ไม่รู้ว่าข้างใน gem เปลี่ยนไปแค่ไหน มันแค่เทียบตัวเลขทีละช่องตามกฎเป๊ะ ๆ — ถ้าคนทำ gem ตั้งเลขรุ่นไม่ตรงกับที่เปลี่ยนจริง ของที่ทำโค้ดพังก็หลุดเข้ามาได้

ไม่ต้องเชื่อคำอธิบาย ให้ RubyGems (ตัวที่ Bundler ใช้ตัดสินจริง) ตอบเอง:

# tilde.rb — ถาม RubyGems ว่า "~> 1.2" ยอมรับรุ่นไหนบ้าง
want = Gem::Requirement.new("~> 1.2")

["1.1.0", "1.2.0", "1.14.0", "1.99.9", "2.0.0"].each do |v|
  puts "#{v} => #{want.satisfied_by?(Gem::Version.new(v))}"
end

อ่านโค้ดก่อน: Gem::Requirement.new("~> 1.2") = สร้างเงื่อนไขรุ่นแบบเดียวกับที่เขียนใน Gemfile (Gem::Requirement = class ชื่อ Requirement ที่อยู่ข้างใน module Gem — :: อ่านว่า "ข้างใน" · Ruby โหลด Gem ไว้ให้เองไม่ต้อง install อะไร) · [ … ] = array ของเลขรุ่น (บท 92) · .each do |v| … end = วนทีละรุ่น (บท 93) · satisfied_by? = "รุ่นนี้ผ่านเงื่อนไขไหม" ตอบ true/false (ชื่อลงท้าย ? บท 93)

ห้ารุ่นนี้ รุ่นไหนได้ true บ้าง? ระวัง 1.14.0 — เลข 14 กับเลข 2 อะไรใหญ่กว่า?

# ผลรันจริง
$ ruby tilde.rb
1.1.0 => false
1.2.0 => true
1.14.0 => true

วิธีแก้ — บอกที่อยู่ database ด้วย DATABASE_URL

ปิด server (Ctrl-C) แล้วตั้งตัวแปร DATABASE_URL — หน้าตาเดียวกับ DSN (สตริงบอกที่อยู่ database) ที่เคยใช้กับ goose ในบท 31 (postgres://postgres:secret@localhost:55433/shopdb…) · แล้วสั่ง bin/rails db:prepare ให้สร้าง database (รายละเอียดคำสั่งนี้รอ Day 2): 

# ผลรันจริง — ค่าใน URL เป็นของเครื่องตรวจ
$ export DATABASE_URL=postgres://postgres:sandbox@127.0.0.1:55432/a98
$ bin/rails db:prepare
Created database 'a98'

แปล URL ทีละท่อน: postgres:// ชนิด database · postgres:sandbox ชื่อผู้ใช้:รหัสผ่าน · 127.0.0.1:55432 เครื่องและพอร์ต · a98 ชื่อ database
ของคุณใช้ค่าตาม Postgres ที่คุณเปิดไว้ เช่น Postgres ใน Docker พอร์ตปกติก็จะเป็น postgres://postgres:รหัสของคุณ@127.0.0.1:5432/wongnok_blog_development · และ export มีผลแค่หน้าต่าง terminal นั้น — ต้องรัน server ในหน้าต่างเดียวกัน
ยังไม่มี Postgres เปิดอยู่เลย? เปิด container แบบเดียวกับบท 31 ได้ แล้วใส่ชื่อผู้ใช้ รหัส และพอร์ตของ container นั้นลงใน URL

ข้อ 7: Rails::WelcomeController — แผนก Welcome ที่มากับ Rails (หัวหน้าเชฟที่ทำได้แค่หน้ายินดีต้อนรับ) · มันรับหน้า / เพราะ config/routes.rb ยังไม่มี root ของเราเอง (บรรทัด # root "posts#index" ยังเป็น comment) · บท 101 จะเขียน route เอง แล้วหน้าต้อนรับจะหายไป

ทดสอบความเข้าใจ

ข้อ 1 · หลัง rails new เสร็จ คุณได้อะไรที่ go mod init ไม่ให้?

ตัวเลือกที่ 2 ถูก · ได้ 109 ไฟล์ เปิด server แล้วได้ 200 แต่หน้าที่เห็นคือหน้าต้อนรับของ Rails เอง (Rails::WelcomeController)

ตัวเลือกที่ 1 ผิด เพราะนั่นคือภาพของ Go · ตัวเลือกที่ 3 ผิด เพราะ app/controllers กับ app/models ยังไม่มีอะไรเกี่ยวกับ Post เลย · ตัวเลือกที่ 4 ผิด เพราะ git log ได้ fatal: … does not have any commits yet — commit แรกต้องทำเอง

จุดที่ต้องจำ: rails new ให้ร้านเปล่าที่ครบชุด ไม่ใช่แอปที่เสร็จแล้ว · และไม่ได้ commit ให้

ข้อ 2 · เพื่อนจะ clone โปรเจกต์ของคุณ แล้วอยากได้ gem รุ่นเดียวกับคุณเป๊ะ ต้องมีไฟล์ไหนอยู่ใน git?

ตัวเลือกที่ 4 ถูก · Gemfile บอกว่าอยากได้อะไร (รายการซื้อของ) · Gemfile.lock บอกว่าได้รุ่นไหนมาจริง (ใบเสร็จ) — Bundler ใช้ทั้งสองไฟล์

ตัวเลือกที่ 1 ผิด เพราะถ้าไม่มี lock Bundler จะเลือกรุ่นใหม่สุดที่ผ่านเงื่อนไข ณ วันที่เพื่อนติดตั้ง ซึ่งอาจไม่ใช่รุ่นของคุณ · ตัวเลือกที่ 2 ผิด เพราะ Bundler ต้องอ่าน Gemfile ด้วยว่าแอปต้องการ gem อะไร (lock เป็นผลลัพธ์ของ Gemfile) · ตัวเลือกที่ 3 ผิด เพราะเพื่อนไม่ได้รัน rails new — เขา clone โปรเจกต์ที่มีอยู่แล้ว

จุดที่ต้องจำ: commit ทั้ง Gemfile และ Gemfile.lock เสมอ · lock คือสิ่งที่ทำให้ทุกเครื่องได้รุ่นเดียวกัน

ข้อ 3 · Gemfile เขียน gem "image_processing", "~> 1.2" · ถ้ามีรุ่น 1.14.0 และ 2.2.0 ออกมาแล้ว Bundler ยอมรับรุ่นไหน?

ตัวเลือกที่ 1 ถูก · ~> 1.2 = ตั้งแต่ 1.2 แต่ต่ำกว่า 2.0 · ตัวเลขท้ายสุดที่เขียน (2) ขยับขึ้นได้ ตัวหน้า (1) ล็อก

ตัวเลือกที่ 2 ผิด เพราะนั่นคือความหมายของการเขียนสามหลัก ~> 1.2.0 · ตัวเลือกที่ 3 ผิด เพราะ ~> มีเพดานเสมอ ถ้าอยากได้ "ใหม่กว่าอย่างเดียว" ต้องเขียน >= แบบ puma · ตัวเลือกที่ 4 ผิด เพราะเลขรุ่นเทียบเป็นตัวเลขทีละช่อง (14 มากกว่า 2) — ผลรัน tilde.rb ได้ 1.14.0 => true

จุดที่ต้องจำ: ~> ล็อกทุกหลักยกเว้นหลักสุดท้ายที่เขียน · สามหลักแน่นกว่าสองหลัก

ข้อ 4 · คุณได้โปรเจกต์ Rails ของคนอื่นมา อยากรู้เร็ว ๆ ว่าแอปนี้มี URL อะไรบ้าง ควรเปิดไฟล์ไหนก่อน?

ตัวเลือกที่ 3 ถูก · URL ทั้งแอปอยู่ใน config/routes.rb ไฟล์เดียว — ห้องผู้จัดการที่แปะผังส่งใบสั่งไว้

ตัวเลือกที่ 1 ผิด เพราะนั่นคือแม่แบบกลางของ controller ไม่ได้บอกว่ามี URL อะไร · ตัวเลือกที่ 2 ผิด เพราะ Gemfile บอกเครื่องมือที่ใช้ ไม่ใช่หน้าที่แอปมี · ตัวเลือกที่ 4 ผิด เพราะ log จดเฉพาะ URL ที่มีคนเคยเข้ามาแล้ว (และขอ URL ที่ไม่มีอยู่จริงก็ถูกจดด้วย)

จุดที่ต้องจำ: อยากรู้ว่าแอปทำอะไรได้ เปิด config/routes.rb ก่อนเสมอ

ติดข้อไหน หรือเครื่องคุณได้ผลไม่ตรงกับบทนี้ แปะ error บรรทัดแรกมาทั้งบรรทัดแล้วถามได้เลย
