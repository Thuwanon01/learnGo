Layout ของแอป — Container, Navbar และ app/layout.tsx

~25 นาที · ควรผ่าน บท 70 (layout.tsx กับ page.tsx) · บท 72 (Tailwind) · บท 82 มาก่อน

ถึงตอนนี้แอป Wongnok มีปุ่มสวย ๆ แล้ว แต่ยังไม่มีโครงของหน้า — ไม่มีแถบเมนูด้านบน ไม่มีท้ายหน้า ทุกหน้าลอยอยู่เปล่า ๆ
สไลด์หน้า 33–40 สร้างโครงนั้น: แบ่งหน้าเป็นส่วน ๆ · เขียน Navbar · แล้วเอาไปวางใน app/layout.tsx ให้โผล่ทุกหน้า
โค้ดในสไลด์สั้นและดูเรียบร้อย แต่มีห้าจุดที่สไลด์ไม่ได้บอก และผมรันให้ดูทุกจุด: Container ไม่มีใครนิยามไว้ · fixed ทำให้หัวข้อแรกหายไปใต้แถบเมนู · link.active ไม่มีที่มา · <Link> ต่างจาก <a> ตรงไหน · และทำไมเมนูหายไปเฉย ๆ บนมือถือ

ส่วนที่ต้อง "ดูด้วยตา" เช่น แถบเมนูบังเนื้อหาไหม · เมนูหายบนจอเล็กไหม · เปลี่ยนหน้าแล้วโหลดใหม่ไหม — ผมเปิดเบราว์เซอร์จริงแล้ววัดตำแหน่งด้วย JavaScript (getBoundingClientRect() · getComputedStyle()) แทนการกะด้วยสายตา

ทุกตัวเลขและทุกข้อความ error ในบทนี้ก็อปมาจากหน้าจอจริง

Layout คืออะไร — แบ่งหน้าเป็นส่วนที่ "อยู่ทุกหน้า" กับส่วนที่ "เปลี่ยนไปตามหน้า"

เปิดเว็บไหนก็ได้ที่คุณใช้ทุกวัน แล้วกดไปสักสามหน้า จะสังเกตว่าแถบบนสุดกับท้ายหน้าไม่เคยเปลี่ยน สิ่งที่เปลี่ยนมีแค่ตรงกลาง
สไลด์หน้า 35 วาดโครงนี้ไว้เป็นกล่องสี่กล่อง:

┌───────────────────────────────────────────────┐ │ Navigation Bar │ ← อยู่ทุกหน้า ├───────────┬───────────────────────────────────┤ │ │ │ │ Sidebar │ Contents │ ← Contents เปลี่ยนตามหน้า │ │ │ ├───────────┴───────────────────────────────────┤ │ Footer │ ← อยู่ทุกหน้า └───────────────────────────────────────────────┘

แล้วหน้า 36–37 เอาแบบร่างของ Wongnok มาวางทับให้ดูว่าแต่ละกล่องกลายเป็นอะไร: แถบบน = โลโก้ W Wongnok + ลิงก์ Home · Recipes + ช่องค้นหา + ปุ่ม Sign in · ตรงกลาง = page content · ท้ายหน้าสีดำ = คอลัมน์ Explore / Account / Legal
สังเกตว่า Wongnok ไม่มี Sidebar — กล่องสี่กล่องในหน้า 35 เป็นแม่แบบ ไม่ใช่ข้อบังคับ แอปส่วนใหญ่ใช้แค่สามส่วน

อีกเรื่องที่เห็นในหน้า 37 แต่สไลด์ไม่ได้พูด: ขอบซ้ายของโลโก้ ขอบซ้ายของเนื้อหา และขอบซ้ายของ footer ตรงกันเป๊ะ ทั้งที่พื้นหลังของแถบบนกับ footer ยาวเต็มจอ — นี่คืองานของ Container ที่เราจะเขียนในหัวข้อถัดไป

📰 เทียบกับของจริง

layout คือแบบฟอร์มหนังสือพิมพ์ — หัวหนังสือ (ชื่อฉบับ วันที่) อยู่บนสุดทุกหน้า เลขหน้ากับชื่อสำนักพิมพ์อยู่ล่างสุดทุกหน้า
กองบรรณาธิการไม่ต้องจัดหัวหนังสือใหม่ทุกหน้า เขาเปลี่ยนแค่ข่าวตรงกลาง · และข่าวทุกหน้าก็เริ่มที่ขอบกระดาษเดียวกัน ไม่มีหน้าไหนเบี้ยวไปทางซ้าย

ที่ไม่เหมือนกัน: หนังสือพิมพ์พิมพ์หัวหนังสือซ้ำลงกระดาษทุกแผ่นจริง ๆ
แต่ใน Next.js แถบบนถูกสร้างครั้งเดียวแล้วอยู่ตรงนั้นตลอด — ตอนเปลี่ยนหน้า มันไม่ถูกทิ้งแล้ววาดใหม่ (เดี๋ยวพิสูจน์ในหัวข้อ app/layout.tsx) · และหนังสือพิมพ์ไม่ต้องรองรับกระดาษที่กว้างตั้งแต่ 375 ถึง 1920 พิกเซล แต่เว็บต้อง

🗣 ศัพท์ของโครงหน้า
layout / app shell
โครงของหน้าที่ใช้ร่วมกันทุกหน้า (แถบบน · ท้ายหน้า · sidebar) · คำว่า app shell ใช้บ่อยในทีม frontend หมายถึง "เปลือก" ที่เหลือเมื่อตัดเนื้อหาของหน้าออก · ถาม senior ได้ว่า "ส่วนนี้ควรอยู่ใน app shell หรืออยู่ในหน้าเฉพาะ"
navbar / header · footer
แถบนำทางด้านบน กับส่วนท้ายหน้า · ใน HTML ใช้แท็ก <header> · <nav> · <footer> ซึ่ง screen reader ใช้กระโดดข้ามไปหาได้ · บอก AI ได้ว่า "use semantic header, nav and footer landmarks"
container
กล่องที่จำกัดความกว้างสูงสุดของเนื้อหาแล้ววางกลางจอ ทำให้ขอบซ้าย-ขวาของทุกส่วนตรงกัน · ประโยคที่ใช้ได้จริง: "ห่อเนื้อหาด้วย Container ตัวเดียวกับ Navbar ให้ขอบตรงกันหน่อย"

Container — component ที่สไลด์ใช้ แต่ไม่ได้เขียนให้ดู

โค้ด Navbar ในสไลด์หน้า 39 บรรทัด 18 เรียก <Container className="...">
ผมไล่ดูสไลด์หน้า 33–40 ครบทุกหน้าแล้ว ไม่มีหน้าไหนนิยาม Container ไว้ และ shadcn ที่ติดตั้งในโปรเจกต์ (button · card · badge · skeleton) ก็ไม่มีตัวนี้ — ถ้าก็อปโค้ดสไลด์ไปวางเฉย ๆ จะ build ไม่ผ่านเพราะหา Container ไม่เจอ

ข่าวดีคือมันเป็น component ที่ง่ายที่สุดในแอปทั้งแอป — <div> หนึ่งตัวที่มีสามหน้าที่: 

// components/layout/Container.tsx  (ผมเขียนเอง — สไลด์ไม่ได้ให้มา)
import { cn } from "@/lib/utils";

export function Container({ className, ...props }: React.ComponentProps<"div">) {
  return (
    <div
      className={cn("mx-auto w-full max-w-7xl px-4 sm:px-6 lg:px-8", className)}
      {...props}
    />
  );
}
classCSS จริงที่ Tailwind สร้าง (ก็อปจากไฟล์ CSS หลัง build)หน้าที่
max-w-7xlmax-width:var(--container-7xl) · และ --container-7xl:80remกว้างได้ไม่เกิน 80rem (1280px) · จอใหญ่กว่านั้นเนื้อหาจะไม่ยืดตาม
mx-automargin-inline:autoช่องว่างซ้าย-ขวาเท่ากัน = อยู่กลางจอ
px-4 sm:px-6 lg:px-8padding-inline:calc(var(--spacing) * 4) · --spacing:.25remเว้นขอบใน 1rem บนมือถือ แล้วค่อยกว้างขึ้นเมื่อจอใหญ่ขึ้น — ตัวหนังสือจะไม่ชิดขอบจอ

ทำไมรับ className แล้วส่งผ่าน cn()? เพราะคนเรียกต้องเติมของเพิ่มได้ — Navbar เติม flex h-16 items-center ... · footer เติม grid py-10
cn() รวม class สองชุดเข้าด้วยกันและตัดตัวที่ชนกันทิ้งให้เหลือตัวหลัง (ในโปรเจกต์นี้ lib/utils.ts มีบรรทัดเดียวคือ export { cn } from "cn" — shadcn ติดตั้งให้) · ผลรันจริงด้วย node ใส่ class ของ Container แล้วตามด้วย "px-8 flex h-16": "mx-auto w-full max-w-7xl sm:px-6 lg:px-8 px-8 flex h-16" — px-4 หายไป เหลือ px-8 ตัวหลัง · ส่วน ...props ทำให้ส่ง id · aria-* อะไรก็ได้ที่ <div> รับ (เรื่อง box model · padding · margin ทบทวนได้ที่ บท 60)

🖼 เทียบกับของจริง

Container คือแผ่นรองรูปในกรอบรูป (passe-partout) — ผนังจะกว้างแค่ไหนก็ตาม รูปถูกวางไว้กลางแผ่นรองเสมอ มีขอบขาวรอบ ๆ ไม่ชิดกรอบ
และถ้าคุณแขวนรูปสามรูปเรียงแนวตั้งด้วยแผ่นรองขนาดเดียวกัน ขอบซ้ายของทั้งสามรูปจะตรงกันเอง โดยไม่ต้องวัดทีละรูป

ที่ไม่เหมือนกัน: แผ่นรองรูปมีขนาดตายตัว แต่ Container หดได้ — จอแคบกว่า 1280px มันก็กว้างเท่าจอ (w-full) เหลือแค่ขอบใน · มันจำกัดแค่ "ใหญ่สุด" ไม่ได้บังคับ "เท่านี้เป๊ะ" · และมันไม่ได้ทาสีพื้นหลังให้ — พื้นหลังเต็มจอต้องใส่ที่กล่องแม่ชั้นนอก (อย่าง <header>) ไม่ใช่ที่ Container

🗣 ศัพท์ของ Container
max-width + margin-inline: auto (centering)
สูตรมาตรฐานของการวางกล่องกลางจอ: จำกัดความกว้างสูงสุด แล้วให้ขอบซ้าย-ขวาเป็น auto · บอก AI ได้ว่า "center the content with a max-w-7xl container and responsive horizontal padding"
className passthrough · ...props (prop spreading)
ออกแบบ component ให้คนเรียกเติม class และ attribute เพิ่มได้ โดยไม่ต้องแก้ตัว component · React.ComponentProps<"div"> คือ type ของทุก prop ที่ <div> รับ · ถาม senior ได้ว่า "component นี้ควรรับ className กับ ...props ต่อไปให้ element ข้างในไหม"
cn() (class merging)
ฟังก์ชันรวม class หลายชุด แล้วตัดตัวที่ชนกันให้เหลือตัวหลัง เช่น px-4 กับ px-8 เหลือ px-8 · เวลาเจอ class ที่ส่งไปแล้ว "ไม่ติด" ให้ถามว่า "ตรงนี้ผ่าน cn() หรือต่อ string ธรรมดา"

ถอดโค้ด Navbar จากสไลด์หน้า 39

นี่คือโค้ดตามสไลด์ทุกตัวอักษรตั้งแต่บรรทัด 12 ถึง 43 ส่วนที่สไลด์ตัดทิ้ง ผมเติมให้ครบพอ build ได้ และติดป้ายไว้ทุกจุดที่ผมเติมเอง: 

// components/layout/Navbar.tsx
// ── บรรทัด 1–11 สไลด์ไม่ได้โชว์ · ผมเติมเท่าที่โค้ดข้างล่างต้องใช้ ──
import Link from "next/link";

import { Container } from "@/components/layout/Container";
import { cn } from "@/lib/utils";

const NAV_LINKS = [
  { href: "/", label: "Home", active: true },          // ← ผมเดาว่า active มาจากตรงนี้
  { href: "/recipes", label: "Recipes", active: false },
];
// ── จากนี้ไปตรงกับสไลด์ ──

function Navbar() {
  return (
    <header
      data-slot="navbar"
      className="fixed inset-x-0 top-0 z-50 border-b border-border-subtle bg-card"
    >
      <Container className="flex h-16 items-center justify-between gap-6">
        <div className="flex items-center gap-6">
          <Link href="/" className="flex shrink-0 items-center gap-2">
            <span className="wongnok-text-base flex size-8.5 items-center justify-center rounded-lg bg-linear-135 from-primary to-primary-hover font-bold text-primary-foreground">
              W
            </span>
            <span className="wongnok-text-h3 font-bold tracking-tight text-foreground">
              Wongnok
            </span>
          </Link>

          <nav
            aria-label="Main"
            className="hidden items-center gap-1 lg:flex"
          >
            {NAV_LINKS.map((link) => (
              <Link
                key={link.href}
                href={link.href}
                aria-current={link.active ? "page" : undefined}
                className={cn(
                  "wongnok-text-sm rounded-md px-3.5 py-2 font-medium transition-colors",
                  link.active
                    ? "text-primary"
                    : "text-secondary-foreground hover:bg-muted",
                )}
              >
                {link.label}
              </Link>
            ))}
          </nav>
        </div>
        {/* สไลด์ตัดจบที่บรรทัด 43 · ช่องค้นหากับปุ่ม Sign in (เห็นในภาพหน้า 36) ไม่ได้โชว์โค้ด */}
      </Container>
    </header>
  );
}

export default Navbar;

ผมเปิดไฟล์ CSS ที่ next build สร้าง แล้วค้นทีละ class ที่ Navbar ใช้ — ผลจริง:

ห้าตัวที่ NOT FOUND เป็นชื่อสีและขนาดตัวอักษรเฉพาะของ Wongnok (design token) ที่ต้องประกาศไว้ใน app/globals.css ก่อน — โปรเจกต์ที่ผมใช้ตรวจยังไม่มี จึงไม่มี CSS ถูกสร้างให้
วิธีประกาศอยู่ใน บท 81 — สีต้องเพิ่มสองชั้น (--primary-hover ใน :root และ --color-primary-hover ใน @theme inline) ส่วน wongnok-text-* ต้องประกาศด้วย @utility
Tailwind ไม่ฟ้องอะไรเลย ทั้งตอน build และตอน lint — class ที่มันไม่รู้จักแค่ถูกข้ามไปเงียบ ๆ (กับดักเดียวกับชื่อ class ที่สร้างจากตัวแปรใน บท 72)
ถ้าเส้นขอบใต้ Navbar ของคุณเป็นสีเทาธรรมดา หรือโลโก้ไม่มีไล่สี ให้เช็คตรงนี้ก่อน

กับดักที่ 1 — fixed top-0 แล้วหัวข้อแรกของหน้าหายไปใต้แถบเมนู

fixed สั่งให้กล่องหลุดออกจากลำดับการวางของหน้า แล้วไปติดอยู่กับหน้าต่างเบราว์เซอร์แทน
ปกติกล่องบนหน้าเว็บวางต่อกันลงมาเหมือนตัวต่อ — กล่องแรกกินที่เท่าไหร่ กล่องถัดไปก็เลื่อนลงเท่านั้น (ดูเรื่อง "กินที่" ใน บท 60)
แต่พอเป็น position: fixed กล่องนั้นไม่กินที่ในลำดับอีกต่อไป — กล่องถัดไปจึงขยับขึ้นมาแทนที่ราวกับว่าไม่มี Navbar อยู่ แล้ว Navbar ก็ลอยทับอยู่ข้างบน (z-50 คือบอกว่า "ลอยอยู่ชั้นบน")

พิสูจน์ด้วยหน้าจริง: หน้า / มีแค่ <h1>HOME PAGE</h1> · <main> ยังไม่ใส่ padding อะไร · เปิดที่จอกว้าง 1280px แล้ววัด: 

// วัดในเบราว์เซอร์ด้วย getBoundingClientRect() · elementFromPoint()
{
  "innerWidth": 1280,
  "header": { "top": 0, "bottom": 65, "height": 65 },
  "h1":     { "top": 0, "bottom": 24, "left": 0 },
  "elementAtH1": "inside HEADER"
}

}

ผลนี้บอกสองอย่างพร้อมกัน: Navbar อยู่ที่เดิม (element ตัวเดิม) แต่ อัปเดตตัวเองได้ (aria-current ย้ายตาม URL) — เพราะ usePathname() คืนค่าใหม่เมื่อ URL เปลี่ยน แล้ว React แก้เฉพาะส่วนที่ต่างไปบน element ตัวเดิม
นี่คือเหตุผลที่ Navbar ควรอยู่ใน layout ไม่ใช่ก็อปไปวางในทุก page.tsx — ตารางใน บท 70 บอกไว้แล้วว่า page "ถูกแทนที่ด้วยหน้าใหม่" ตอนเปลี่ยนหน้า ของที่อยู่ใน page ก็ถูกแทนที่ไปด้วย

🗣 ศัพท์ของการเปลี่ยนหน้าและการวางตำแหน่ง
client-side navigation / soft navigation
เปลี่ยนหน้าโดยไม่ให้เบราว์เซอร์โหลดใหม่ทั้งหน้า — สิ่งที่ <Link> ทำ · ตรงข้ามคือ hard navigation (full page reload) ที่ <a> ธรรมดาทำ · ถาม senior ได้ว่า "ตรงนี้ state หายตอนเปลี่ยนหน้า เป็นเพราะ hard navigation หรือเปล่า"
prefetch
การที่ <Link> ไปขอข้อมูลของหน้าปลายทางไว้ล่วงหน้าก่อนผู้ใช้กด เพื่อให้เปลี่ยนหน้าได้ทันที · ปรับได้ด้วย prop prefetch (มีในหัวข้อ Reference ของเอกสาร Link) · ถาม senior ได้ว่า "เมนูนี้มีลิงก์เยอะ ควรปิด prefetch บางตัวไหม"
fixed vs sticky · breakpoint
fixed หลุดจากลำดับหน้า ต้องเว้นที่ให้เอง · sticky ยังกินที่แต่ติดขอบตอนเลื่อน · breakpoint คือความกว้างจอที่ class อย่าง lg: เริ่มทำงาน (lg = 64rem) · ประโยคที่ใช้ได้จริง: "navbar เป็น fixed แล้วบังหัวข้อ เปลี่ยนเป็น sticky ได้ไหม" · "บน breakpoint ต่ำกว่า lg เมนูหาย ต้องทำ mobile drawer เพิ่ม"

ภารกิจ — ปิดโครงหน้าให้ครบด้วย Footer

🎯 ภารกิจ: Footer ของ Wongnok

สไลด์หน้า 36–37 มี footer สีดำอยู่ในแบบร่าง แต่ไม่มีโค้ด · ลองเขียนเอง:

  1. สร้าง components/layout/Footer.tsx ที่มีชื่อ Wongnok + ข้อความ Share your recipe, inspire a meal. + คอลัมน์ลิงก์อย่างน้อยสองคอลัมน์ (Explore · Account) สร้างจากอาร์เรย์ + .map() แบบเดียวกับ NAV_LINKS
  2. ห่อเนื้อหาข้างในด้วย Container ตัวเดียวกับ Navbar — ขอบซ้ายต้องตรงกับโลโก้
  3. ใส่ <Footer /> ต่อจาก <main> ใน app/layout.tsx
  4. หน้าที่มีเนื้อหาสั้น ๆ footer ต้องไปอยู่ล่างสุดของจอ ไม่ใช่ลอยอยู่กลางจอ
  5. ตอบให้ได้ว่า Footer ต้องมี "use client" ไหม · แล้วรัน npx next build · npx tsc --noEmit · npx eslint . ให้ผ่านทั้งสาม

  • ข้อ 4 แก้ด้วย mt-auto คำเดียว — เพราะ <body> ที่ create-next-app สร้างให้เป็น min-h-full flex flex-col อยู่แล้ว (สูงอย่างน้อยเต็มจอ + เรียงลูกเป็นแนวตั้ง) · margin-top: auto ในกล่อง flex คือ "กินที่ว่างที่เหลือทั้งหมดไว้ด้านบนตัวเอง" footer เลยถูกดันลงล่างสุด

มี mt-auto   →  footer { top: 616, bottom: 800 }   innerHeight: 800

ถ้าของคุณยังลอยอยู่กลางจอ เช็คว่า <body> ยังมี flex flex-col อยู่ไหม — mt-auto ดันได้เฉพาะในกล่อง flex

ลองตอบดู

ใช้โค้ด Navbar แบบ NAV_LINKS ที่เขียน active: true ไว้ที่ Home · ผู้ใช้กดไปหน้า /recipes — ลิงก์ไหนได้ aria-current="page"?

ตัวเลือกที่ 3 ถูก · ผล curl หน้า /recipes จริงได้ <a aria-current="page" ... href="/">Home</a>
ตัวเลือกที่ 1 ผิดเพราะ <Link> ไม่ได้ใส่ aria-current ให้เอง — คุณต้องคำนวณเองด้วย usePathname() (เอกสาร Next.js มีตัวอย่างหัวข้อ Checking active links ไว้แบบนี้พอดี)
ตัวเลือกที่ 2 และ 4 ผิดเพราะ active เป็นแค่ค่าคงที่ในอาร์เรย์ ไม่มีใครล้างหรือสะสมมัน — มันเป็น true ที่ Home ตลอดไป
จุดที่ต้องจำ: สิ่งที่ขึ้นกับ URL ต้องคำนวณจาก URL — เขียนตายตัวไว้จะถูกแค่หน้าเดียว

หน้า Recipes มีช่องค้นหาที่ผู้ใช้พิมพ์ค้างไว้ในตัวแปร state ที่อยู่ใน layout · ถ้าลิงก์ใน Navbar เป็น <a href> ธรรมดาแทน <Link> กดไปหน้าอื่นแล้วจะเกิดอะไร?

ตัวเลือกที่ 1 ถูก · ในการทดลอง ตัวแปร window.__marker หายหลังกด <a> ("GONE (page reloaded)") แต่ยังอยู่หลังกด <Link> ("still-here")
ตัวเลือกที่ 2 ผิดเพราะ next build ผ่าน — ตัวที่ฟ้องคือ eslint (@next/next/no-html-link-for-pages)
ตัวเลือกที่ 3 ผิดเพราะ HTML เหมือนกันจริง แต่พฤติกรรมตอนคลิกต่างกัน · ตัวเลือกที่ 4 ผิดเพราะ <a> ยังพาไปหน้าที่ถูกต้องได้ปกติ แค่ช้ากว่าและล้าง state
จุดที่ต้องจำ: ลิงก์ไปหน้าในแอปเดียวกันใช้ <Link> เสมอ · และรัน eslint ด้วย ไม่ใช่แค่ next build

<nav className="hidden items-center gap-1 lg:flex"> · เปิดบน iPhone ที่จอกว้าง 375px — ผู้ใช้เห็นอะไร?

ตัวเลือกที่ 4 ถูก · ผลวัดจริงที่ 375px: getComputedStyle(nav).display = "none" และ CSS ที่ Tailwind สร้างคือ @media (min-width:64rem){ .lg\:flex{display:flex} }
ตัวเลือกที่ 2 ผิดเพราะลำดับคำใน className ไม่ได้ตัดสินอะไร — ที่ตัดสินคือ CSS ที่ Tailwind สร้าง ซึ่ง .lg\:flex อยู่ใน @media (min-width:64rem) ทำงานเฉพาะจอกว้างเท่านั้น · ตัวเลือกที่ 1 ผิดเพราะ display:none คือไม่แสดงเลย ไม่ได้เปลี่ยนทิศ · ตัวเลือกที่ 3 ผิดเพราะไม่มีอะไรสร้างลิ้นชักให้ — แบบร่างหน้า 36 พูดถึง mobile drawer แต่ต้องเขียนเอง
จุดที่ต้องจำ: Tailwind เป็น mobile-first — class ไม่มีคำนำหน้าคือค่าของจอเล็ก · ซ่อนอะไรบนมือถือ ต้องมีทางอื่นให้ผู้ใช้ไปถึงมันเสมอ

เปลี่ยน Navbar ให้ใช้ usePathname() แล้ว build พังว่า You're importing a module that depends on `usePathname` into a React Server Component module — ควรใส่ "use client" ที่ไหน?

ตัวเลือกที่ 2 ถูก · error ชี้ ./components/layout/Navbar.tsx:2:10 ตรงคำว่า usePathname ใส่ "use client"; บรรทัดแรกของไฟล์นั้นแล้ว build ผ่าน · tsc rc=0 · eslint rc=0
ตัวเลือกที่ 1 ผิดเพราะจะลากทั้งแอปไปฝั่ง client และ build พังอีกแบบ — ผลรันจริง: You are attempting to export "metadata" from a component marked with "use client", which is disallowed. · ตัวเลือกที่ 3 ผิดเพราะ error บอกให้ "mark the file" — "use client" ติดที่ทั้งไฟล์ ต้องอยู่บนสุดก่อน import ทุกตัว ไม่ใช่ติดทีละบรรทัดในฟังก์ชัน · ตัวเลือกที่ 4 ผิดเพราะ Navbar ไม่ได้ถูก import ใน page ใดเลย มันอยู่ใน layout
จุดที่ต้องจำ: อ่าน Import trace จากบนลงล่าง — บรรทัดบนคือไฟล์ที่ต้องแก้ บรรทัดล่างคือคนที่เรียกมันมา

ถามกลับได้เลย

ถ้าเปิดแอปแล้ว Navbar ของคุณหน้าตาไม่เหมือนสไลด์หน้า 40 — สีไม่ออก เส้นขอบหาย โลโก้ไม่ไล่สี — เอา app/globals.css มาคุยกัน ส่วนใหญ่เป็นเพราะ token ของ Wongnok ยังไม่ได้ประกาศ
ถ้าอยากทำ mobile drawer ต่อ หรือสงสัยว่าควรแยก NavLinks ออกเป็น client component ตัวเล็กไหม ก็ถามได้ · หรือถ้าเจอ error ตอน build ก็เอาข้อความทั้งก้อนมา โดยเฉพาะบรรทัด Import trace

อ้างอิง

  • Next.js — Link Component — อ่านหัวข้อ Checking active links ซึ่งเป็นตัวอย่าง usePathname แบบเดียวกับที่บทนี้ใช้แก้ link.active · แล้วอ่าน Scroll offset with sticky headers ต่อ ถ้าคุณใช้ Navbar แบบ fixed แล้วกดลิงก์ไป #id แล้วหัวข้อโดนบัง
  • Next.js — usePathname — อ่านสองย่อหน้าแรกให้จบ — ประโยคแรกบอกตรง ๆ ว่าเป็น Client Component hook และย่อหน้าถัดมาอธิบายว่า component ที่ใช้มันยังถูกเรนเดอร์เป็น HTML ตอนโหลดหน้าแรกอยู่ดี (ตรงกับที่ curl ในบทนี้ยังเห็น aria-current ใน HTML)
  • Tailwind CSS — Responsive design — อ่านหัวข้อ Working mobile-first และตาราง breakpoint ในหัวข้อ Overview (จะเห็น lg = 64rem ตรงกับ CSS ที่บทนี้ก็อปมา)
  • MDN — position — อ่านคำอธิบายค่า fixed กับ sticky ประโยคที่บอกว่า fixed "removed from the normal document flow" คือต้นเหตุของกับดักที่ 1
  • MDN — aria-current — อ่านคำอธิบายค่า page ที่ใช้กับลิงก์ในเมนูนำทาง · หลักคือเมื่อลิงก์ของหน้าปัจจุบันหน้าตาต่างจากลิงก์อื่น (เช่นเป็นสีหลัก) ต้องมี aria-current บอกด้วย คนที่มองไม่เห็นสีจะได้รู้เหมือนกัน
  • Ramotion — Web Design Layout (ลิงก์ในสไลด์หน้า 35) — อ่านหัวข้อ Core Elements of Web Design Layout ซึ่งไล่องค์ประกอบไว้หกอย่าง (Top header · Navigation · Header · Content area · Sidebar · Footer) — กล่องสี่กล่องในสไลด์ยุบมาจากรายการนี้ · แล้วข้ามไป Responsiveness กับ Mobile-Friendliness ซึ่งเป็นเรื่องที่เมนู hidden lg:flex ยังทำไม่ครบ
