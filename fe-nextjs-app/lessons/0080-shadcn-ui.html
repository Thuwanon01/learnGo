1 · shadcn ไม่ใช่ของที่ import — มันคือของที่ก็อป

ลองเทียบสองแบบนี้ดู

แบบ UI library ทั่วไป — คุณสั่ง npm install ชื่อไลบรารี โค้ดของปุ่มไปนอนอยู่ใน node_modules/ แล้วคุณเขียน import { Button } from "ชื่อไลบรารี"
อยากเปลี่ยนสีปุ่ม? ทำได้เท่าที่ไลบรารีเปิดช่องให้ · อยากแก้ข้างในจริง ๆ? ไม่ได้ เพราะมันไม่ใช่โค้ดของคุณ (แก้ใน node_modules/ ได้ แต่ติดตั้งใหม่ครั้งหน้าก็หาย)

แบบ shadcn — คุณสั่ง npx shadcn@latest add button แล้วมันเขียนไฟล์ components/ui/button.tsx ลงในโปรเจกต์ของคุณ เป็น source code ธรรมดา ๆ 57 บรรทัด อ่านได้ทุกบรรทัด
คุณ import มันจาก @/components/ui/button — จากโฟลเดอร์ของตัวเอง ไม่ใช่จาก package 

// โปรเจกต์นี้มี "shadcn" อยู่ใน package.json จริง ๆ (init ใส่ให้)
// งั้นลอง import ปุ่มจากมันตรง ๆ
import { Button } from "shadcn";
export const X = Button;

npx tsc --noEmit ผ่านไหม?

ไม่ผ่าน · ผลรันจริง:

probe-import.ts(1,10): error TS2305: Module '"shadcn"' has no exported member 'Button'.

package shadcn ที่อยู่ใน package.json ไม่มีปุ่มสักตัว — ผมเปิด node_modules/shadcn/package.json ดูแล้ว สิ่งที่มัน export คือ ตัวหลัก . (ฟังก์ชันอ่าน registry เช่น getRegistry) · ./registry · ./schema · ./mcp · ./utils · ./icons · ./preset และ ./tailwind.css ซึ่งเป็นของสำหรับตัว CLI กับไฟล์ CSS ที่ app/globals.css บรรทัด 3 ดึงไปใช้ (@import "shadcn/tailwind.css"; — ตรงกับสไลด์หน้า 13)
ตัวปุ่มจริงมีที่เดียว คือไฟล์ที่ถูกก็อปมาไว้ใน components/ui/

🍳 เทียบกับของจริง

UI library ทั่วไปเหมือนสั่งอาหารกล่องสำเร็จรูป — อุ่นแล้วกินได้ทันที แต่อยากลดเค็มหรือเพิ่มผัก ทำไม่ได้ เพราะกล่องปิดผนึกมาจากโรงงาน
shadcn เหมือนเว็บสูตรอาหาร (อย่าง Wongnok ที่เรากำลังสร้างนี่แหละ) — คุณกด “บันทึกสูตร” แล้วสูตรทั้งหน้าถูกคัดลอกลงสมุดของคุณ จากนั้นจะลดน้ำตาล เปลี่ยนหมูเป็นไก่ ขีดเขียนยังไงก็ได้ เพราะสมุดเป็นของคุณ

ที่ไม่เหมือนกัน: สูตรที่ลอกมายังต้องซื้อวัตถุดิบจากร้าน — button.tsx ที่ถูกก็อปมายัง import @base-ui/react · class-variance-authority · cn ซึ่งเป็น npm package จริง ๆ อยู่ใน node_modules/
และที่ต่างกว่านั้น: สมุดสูตรจริงไม่มีใครมาเปิดเขียนทับ แต่ CLI ของ shadcn เขียนทับสมุดคุณได้ ถ้าคุณสั่งมัน (หัวข้อ 5 จะโชว์ว่าเกิดอะไรขึ้น)

2 · init — เตรียมสมุดก่อนก็อปสูตรแรก

สไลด์หน้า 11 ให้คำสั่งนี้ (ถูกต้อง รันได้): 

$ npx shadcn@latest init -t next

ภาพ terminal ในสไลด์หน้า 11 โชว์ว่ามันถามสองคำถาม: Select a component library (ในภาพเลือก Base UI) แล้วตามด้วย Which preset would you like to use? (Nova · Vega · Maia · Lyra · Mira · Luma · Sera · Rhea · Custom) — preset คือชุดหน้าตาสำเร็จ ส่วนสไลด์หน้า 12 คือหน้า ui.shadcn.com/create ที่ให้ปรับ style / สี / ฟอนต์ / radius เองแล้วกด Get Code

3 · add — พิสูจน์ว่ามันก็อปไฟล์จริง

โปรเจกต์ตั้งต้นมี button · card · badge · skeleton แล้ว ผมเลือก input ซึ่งยังไม่มี · commit ทุกอย่างให้สะอาดก่อน แล้วสั่ง: 

$ npx shadcn@latest add input
✔ Checking registry.
✔ Created 1 file:
  - components/ui/input.tsx

$ git status --short
?? components/ui/input.tsx

$ git diff --stat
(ว่าง — ไม่มีไฟล์เดิมไหนถูกแก้เลย)

อ่านผลสามบรรทัดนี้ให้ออก:

  • ?? แปลว่าไฟล์ใหม่ที่ git ยังไม่รู้จัก — มีไฟล์เดียว
  • package.json ไม่เปลี่ยน — ไม่มี package ชื่อ “input” ถูกติดตั้ง (input ใช้ @base-ui/react ซึ่ง init ติดตั้งไว้ให้แล้วตั้งแต่แรก)
  • components.json ก็ไม่เปลี่ยน — shadcn ไม่ได้จดว่าเราติดตั้งอะไรไปบ้าง ไฟล์ที่อยู่ใน components/ui/ คือบันทึกเดียวที่มี

ไฟล์ที่ได้มาหน้าตาแบบนี้ (class ยาวมาก ผมตัดตรงกลางเป็น …):

// components/ui/input.tsx — 19 บรรทัด ก็อปมาจาก registry ของ shadcn
import * as React from "react"
import { Input as InputPrimitive } from "@base-ui/react/input"
import { cn } from "cn"

function Input({ className, type, ...props }: React.ComponentProps<"input">) {
  return (
    <InputPrimitive
      type={type}
      data-slot="input"
      className={cn(
        "h-8 w-full min-w-0 rounded-lg border border-input bg-transparent px-2.5 py-1 … dark:aria-invalid:ring-destructive/40",
        className
      )}
      {...props}
    />
  )
}

export { Input }

สังเกตว่ามันคือ component ธรรมดาแบบที่เราเขียนเป็นแล้วใน บท 71 — รับ className · กระจาย ...props ที่เหลือ · ครอบตัว InputPrimitive จาก Base UI (ตัวที่จัดการพฤติกรรมกับ accessibility) แล้วแปะ class ของ Tailwind ให้สวย
ไม่มีเวทมนตร์อะไรเลย · คุณเปิดอ่านได้ทุกบรรทัด เพราะมันอยู่ในโปรเจกต์คุณ

🗣 ศัพท์ที่เพิ่งเรียนไป
open code
แนวคิดที่ shadcn ใช้เรียกตัวเอง — ส่งโค้ดของ component ให้คุณเป็นเจ้าของ แทนการส่ง package ปิดผนึก · ภาพหน้าเว็บ ui.shadcn.com ในสไลด์หน้า 10 ก็ปิดท้ายคำโปรยว่า “Open Source. Open Code.” · หน้าแรกของเอกสาร shadcn เขียนไว้ว่ามัน “ไม่ใช่ component library แต่เป็นวิธีสร้าง component library ของคุณเอง” · พิมพ์บอก AI ได้ว่า “this project uses shadcn/ui, components live in components/ui and are owned by us” AI จะได้ไม่แนะนำให้ไป import จาก package
registry
คลังกลางที่ CLI ไปดึงโค้ดมา (บรรทัด ✔ Checking registry. ในผลรัน) · องค์กรใหญ่ทำ registry ของตัวเองได้ เพื่อให้ทุกทีม add component หน้าตาเดียวกัน · ถาม senior ได้ว่า “ทีมเรามี private registry ไหม หรือใช้ของ shadcn ตรง ๆ”
components.json
ไฟล์ตั้งค่าที่ CLI อ่าน — ตัวสำคัญคือ aliases (วางไฟล์ที่ไหน) กับ style · ถ้าย้ายโฟลเดอร์ components/ui ต้องแก้ที่นี่ด้วย ไม่งั้น add ครั้งหน้าจะวางผิดที่
primitive / headless component
component ที่ทำแค่พฤติกรรม ไม่มีหน้าตา — เช่น @base-ui/react/button จัดการคีย์บอร์ด focus และ disabled ให้ถูกต้อง ส่วนสีและขนาดเป็นหน้าที่ของ class ที่ shadcn แปะ · ภาพสไลด์หน้า 11 เลือก Base UI · โปรเจกต์ shadcn จำนวนมากบนเน็ตใช้อีกค่ายคือ Radix (เอกสาร CLI มีคำสั่ง migrate radix ไว้ด้วย) · ถามได้ว่า “โปรเจกต์นี้ใช้ primitive ของ Base UI หรือ Radix” ก่อนก็อปตัวอย่างโค้ดจากเน็ตมาใช้

4 · cn() — ตัวรวม class ที่รู้ว่า class ไหนชนกัน

⚠️ ของจริงต่างจากสไลด์หน้า 15 และจากบทความเก่า ๆ บนเน็ต

สไลด์หน้า 15 โชว์ button.tsx บรรทัด 4 ว่า import { cn } from "@/lib/utils"; และบทความส่วนใหญ่บนเน็ตจะบอกว่า lib/utils.ts ข้างในเป็น clsx + tailwind-merge
แต่ในโปรเจกต์ที่ผมสร้างด้วย shadcn 4.21.0 ของจริงเป็นแบบนี้: 

$ cat lib/utils.ts
export { cn } from "cn"

$ grep cn components/ui/button.tsx | head -1
import { cn } from "cn"

cn กลายเป็น npm package ชื่อ cn (ทีม shadcn ทำเอง · README ของมันบอกว่าเป็นตัวแทนของ clsx + tailwind-merge ใช้ API เดียวกัน) · และ component ที่ add มา import จาก "cn" ตรง ๆ ไม่ผ่าน @/lib/utils
ผลต่อคุณ: เขียน import { cn } from "@/lib/utils" ในโค้ดของตัวเองได้เหมือนเดิม (ผม build ผ่านด้วยวิธีนี้ในหัวข้อ 6) · แต่ถ้าโปรเจกต์ของเพื่อนสร้างด้วย shadcn เวอร์ชันเก่า ไฟล์ lib/utils.ts จะหน้าตาไม่เหมือนของคุณ — ไม่ใช่ใครทำผิด แค่คนละรุ่น

ปัญหาที่ cn() แก้คือแบบนี้: button.tsx มี class ของตัวเองอยู่แล้ว เช่น bg-primary · แล้วคุณส่ง className="bg-orange-500" เข้าไป
ถ้าเอาสองสตริงมาต่อกันเฉย ๆ จะได้ "bg-primary bg-orange-500" — มีพื้นหลังสองสีในแท็กเดียว
คุณคงคิดว่า “ตัวหลังชนะ” เหมือนเขียน prop ซ้ำ… ลองทายดู 

// ต่อสตริงเอง ไม่ใช้ cn — ตั้งใจให้ px-2 (ตัวหลัง) ชนะ
<div className="px-4 px-2">ต่อสตริงเอง</div>

// px-2 = padding ซ้ายขวา 8px · px-4 = 16px

เปิดใน browser แล้ว padding ซ้ายจริง ๆ เป็นเท่าไหร่?

ผลวัดจริงใน browser ด้วย getComputedStyle:

ต่อสตริงเอง => pad-left 16px

16px — px-4 ชนะ ทั้งที่เขียนไว้ก่อน
เพราะลำดับ class ในแท็ก HTML ไม่มีผลเลย · CSS ตัดสินจากว่ากฎไหนอยู่ทีหลังในไฟล์ CSS ผมเปิดไฟล์ CSS ที่ next build สร้างออกมาดู: 

.px-2{padding-inline:calc(var(--spacing) * 2)}   ← เจอก่อนในไฟล์
.px-4{padding-inline:calc(var(--spacing) * 4)}   ← เจอทีหลัง (ห่างกัน 97 ตัวอักษร) จึงชนะ

Tailwind เป็นคนเรียงลำดับในไฟล์ CSS เอง คุณคุมไม่ได้
นี่คือเหตุผลที่ต้องมี cn(): มันลบ class ที่ชนกันทิ้งตั้งแต่ในสตริง ให้เหลือแต่ตัวหลังตัวเดียว — HTML จะไม่มีสองตัวให้ CSS ต้องไปตัดสินอีก

ผลรันจริงของ cn() (node รันไฟล์ที่ import { cn } from "cn"):

$ node cn-probe.mjs
// cn("px-2", "px-4")
"px-4"
// cn("px-2 py-1", "p-4")        p-4 คุมทั้งสี่ด้าน จึงกลืน px/py ที่มาก่อน
"p-4"
// cn("p-4", "px-2")             px-2 มาทีหลัง ทับได้แค่ซ้ายขวา p-4 จึงยังอยู่
"p-4 px-2"
// cn("text-red-500", "text-lg") สีกับขนาด คนละเรื่อง ไม่ชนกัน เก็บทั้งคู่
"text-red-500 text-lg"
// cn("rounded-lg", isActive && "bg-blue-500", { "text-white": isActive, "border": true })  โดย isActive = false
"rounded-lg border"
// "px-2" + " " + "px-4"         ต่อสตริงเอง
"px-2 px-4"

cn() ทำสองงานในตัวเดียว: (1) รวม — รับได้ทั้งสตริง, false (ทิ้งให้), และ object แบบ { "class": เงื่อนไข } · (2) ตัดสินการชน — รู้ว่า text-red-500 กับ text-lg ขึ้นต้นเหมือนกันแต่คนละเรื่อง ส่วน px-2 กับ px-4 คือเรื่องเดียวกัน

📝 เทียบกับของจริง

cn() เหมือนพนักงานรับออร์เดอร์ที่อ่านโน้ตเป็น
ลูกค้าเขียนโน้ตแรกว่า “เผ็ดกลาง” แล้วเขียนเพิ่มทีหลังว่า “ไม่เผ็ด” — พนักงานธรรมดาจะส่งกระดาษทั้งสองแผ่นเข้าครัว แล้วครัวเลือกเอาเองตามอารมณ์ (นี่คือการต่อสตริงเอง แล้ว CSS เลือกตามลำดับไฟล์)
พนักงานที่อ่านเป็นจะขีดฆ่า “เผ็ดกลาง” ทิ้ง เพราะรู้ว่าเป็นเรื่องเดียวกัน แต่ถ้าโน้ตสองคือ “ไม่ใส่ผักชี” เขาจะเก็บไว้ทั้งสองแผ่น เพราะคนละเรื่อง

ที่ไม่เหมือนกัน: พนักงานจริงเข้าใจภาษาคน แต่ cn() รู้จักแค่ชื่อ class ของ Tailwind — มันไม่ได้เปิดอ่านไฟล์ CSS จริง
class ที่คุณตั้งเองมันไม่รู้ว่าชนกับอะไร ผลรันจริง: cn("text-lg", "text-brand") ได้ "text-lg text-brand" · cn("recipe-card", "recipe-card-big") ได้ "recipe-card recipe-card-big" — เก็บไว้ทั้งคู่ แล้วโยนให้ CSS ตัดสินตามลำดับไฟล์เหมือนเดิม

🗣 ศัพท์เรื่อง class
class conflict
สอง utility class ที่ตั้งค่า CSS ตัวเดียวกันในแท็กเดียว เช่น bg-primary กับ bg-orange-500 · ผลลัพธ์ขึ้นกับลำดับในไฟล์ CSS ไม่ใช่ลำดับที่คุณเขียน · บอก AI ได้ว่า “use cn() to merge className so later Tailwind classes override conflicting ones”
clsx / tailwind-merge
สองไลบรารีที่ cn() รุ่นเก่าเอามาต่อกัน — clsx ทำงาน “รวม” · tailwind-merge ทำงาน “ตัดสินการชน” · ถ้าเห็นในโปรเจกต์อื่นให้รู้ว่าคือของเดียวกัน · เอกสาร CLI ของ shadcn มีคำสั่ง migrate cn ไว้ย้ายจากแบบเก่ามาแบบใหม่
cva / variant
class-variance-authority — ตัวที่ button.tsx ใช้ประกาศว่าปุ่มมีกี่แบบ (variant: default · outline · secondary · ghost · destructive · link และ size) แล้วคืนสตริง class ตามที่เลือก · ในภาพสไลด์หน้า 15 คือก้อน const buttonVariants = cva(…) · ถาม senior ได้ว่า “อยากได้ปุ่มแบบใหม่ ควรเพิ่ม variant หรือห่อ component ใหม่” — หัวข้อถัดไปคือคำตอบของคำถามนี้

(ในภาพสไลด์หน้า 15 ก็เห็นโฟลเดอร์ components/Bases วางคู่กับ components/ui — ภาพไม่ได้กางให้เห็นว่าข้างในมีอะไร แต่ตำแหน่งตรงกับแนวคิดนี้) 

// components/ActionButton/ActionButton.tsx
import type { ComponentProps } from "react";
import { Button } from "@/components/ui/button";
import { cn } from "@/lib/utils";

type ActionButtonProps = ComponentProps<typeof Button> & {
  loading?: boolean;
};

const ActionButton = ({
  loading = false,
  disabled,
  className,
  children,
  ...restProps
}: ActionButtonProps) => {
  return (
    <Button
      className={cn("bg-orange-500 text-white hover:bg-orange-600", className)}
      disabled={disabled || loading}
      {...restProps}
    >
      {loading ? "กำลังบันทึก..." : children}
    </Button>
  );
};

export default ActionButton;
// components/ActionButton/index.ts
export { default } from "./ActionButton";
// app/t80/page.tsx
import ActionButton from "@/components/ActionButton";
import { Button } from "@/components/ui/button";

export default function Page() {
  return (
    <main className="flex gap-2 p-8">
      <Button>ปุ่มเดิมของ shadcn</Button>
      <ActionButton>บันทึกสูตร</ActionButton>
      <ActionButton loading>บันทึกสูตร</ActionButton>
      <ActionButton variant="outline" className="bg-white text-orange-600">ยกเลิก</ActionButton>
    </main>
  );
}

สามอย่างที่ทำให้ตัวห่อนี้ “ตามแบบ shadcn”:

  • ComponentProps<typeof Button> — รับ prop ทุกตัวที่ Button รับ (variant · size · onClick …) โดยไม่ต้องพิมพ์ type เอง แล้วต่อ loading ที่เป็นของเราเพิ่ม
  • ...restProps ส่งต่อทุกอย่างที่เหลือ — ท่าเดียวกับ {...restProps} ใน บท 71
  • cn(ของเรา, className) — ใส่ className ของคนเรียกไว้ทีหลัง คนที่ใช้ ActionButton จึงยังทับสีได้ถ้าจำเป็น

🗣 ศัพท์เรื่องการดูแลโค้ดที่ก็อปมา
wrapper component / composition
สร้าง component ใหม่ที่ใช้ component เดิมข้างใน แทนการแก้ของเดิม · React ถนัดท่านี้มาก และหน้าเอกสาร shadcn ก็มีหัวข้อ Composition · พิมพ์บอก AI ได้ว่า “don't modify components/ui, create a wrapper component in components/ instead” — ประโยคนี้กัน AI ไปแก้ไฟล์ของ shadcn ได้ดีมาก
--overwrite / --diff / --dry-run
สาม flag ของ shadcn add ที่ต้องรู้ (ดูครบได้ด้วย npx shadcn@latest add --help) — --overwrite เขียนทับไม่ถาม · --diff โชว์ว่าจะเปลี่ยนอะไร · --dry-run ลองทำโดยไม่เขียนไฟล์ · ถาม senior ได้ว่า “ก่อน overwrite component ใน ui ทีมเราดู diff กันยังไง”
upstream
ต้นฉบับที่เราก็อปโค้ดมา — ในที่นี้คือ registry ของ shadcn · เวลาต้นฉบับอัปเดต โค้ดของเราไม่เปลี่ยนตามเอง (ต่างจาก npm package ที่แค่ขยับเลขเวอร์ชัน) · ราคาที่จ่ายของ open code คือต้องดึงของใหม่มาเองและรับผิดชอบเอง · ประโยคที่ใช้ได้: “component ใน ui ตาม upstream รุ่นไหน มีใครแก้ local ไว้ไหม”

// components/DifficultyBadge/DifficultyBadge.tsx
import type { ComponentProps } from "react";
import { Badge } from "@/components/ui/badge";
import { cn } from "@/lib/utils";

type Difficulty = "easy" | "medium" | "hard";

const LABEL: Record<Difficulty, string> = {
  easy: "ง่าย",
  medium: "ปานกลาง",
  hard: "ยาก",
};

const COLOR: Record<Difficulty, string> = {
  easy: "bg-green-100 text-green-800",
  medium: "bg-yellow-100 text-yellow-800",
  hard: "bg-red-100 text-red-800",
};

type DifficultyBadgeProps = Omit<ComponentProps<typeof Badge>, "children"> & {
  level: Difficulty;
};

const DifficultyBadge = ({ level, className, ...restProps }: DifficultyBadgeProps) => {
  return (
    <Badge className={cn(COLOR[level], className)} {...restProps}>
      {LABEL[level]}
    </Badge>
  );
};

export default DifficultyBadge;
// components/DifficultyBadge/index.ts
export { default } from "./DifficultyBadge";

// app/t80/badge/page.tsx

    <main className="flex gap-2 p-8">
      <DifficultyBadge level="easy" />
      <DifficultyBadge level="hard" className="text-base" />

  );

ถามกลับได้เลย
