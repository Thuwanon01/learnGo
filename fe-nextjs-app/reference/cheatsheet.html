ที่อยู่ใส่อะไรทำไม · ที่ต้องรู้
app/ หน้าจอแต่ละ URL (page.tsx) · กรอบร่วม (layout.tsx) · globals.css โฟลเดอร์ใต้ app/ ที่มี page.tsx = URL ทันที · ไม่มี page.tsx = 404
app/_components · app/_containers ของที่ใช้หน้าเดียว เช่นแบนเนอร์หน้าแรก ขีดล่าง = Next.js ข้ามทั้งโฟลเดอร์ แม้มี page.tsx ข้างใน (/_components ได้ 404 จริง) · แต่ยัง import ได้ — และ import ข้ามหน้าก็ build ผ่าน (กฎ “ใช้หน้าเดียว” เป็นข้อตกลง ไม่ใช่ที่ Next.js บังคับ)
components/ pure · presentational — รับ props แล้ววาดอย่างเดียว ใช้ได้หลายหน้า ไม่มี state ของงาน ไม่รู้ว่าข้อมูลมาจากไหน · ปกติไม่ต้องมี "use client" (ยกเว้นมี event จริง เช่น onClick — บท 84)
containers/ stateful composition — ถือ state + รู้ business rule แล้วประกอบ component หลายตัว มักต้องมี "use client" เมื่อมี hook จริง · ไม่มี hook / event → ไม่จำเป็น (บท 85 build ผ่านทั้งสองแบบ) · Next.js ไม่รู้จักชื่อ components/ containers/ เลย — วินัยของทีมล้วน ๆ
components/ui/ ไฟล์ที่ npx shadcn@latest add เขียนลงมา (button · card · badge · skeleton · input …) เป็น source ของเราแล้ว แต่ add --overwrite เขียนทับได้เงียบ ๆ → อยากได้แบบใหม่ให้ห่อเป็น component ใหม่ใน components/ (หัวข้อ 2)
lib/utils.ts ที่อยู่ของ cn() shadcn 4.21.0 สร้างเป็น export { cn } from "cn" บรรทัดเดียว · สไลด์และบทความเก่าเป็น clsx + tailwind-merge — คนละรุ่น ไม่มีใครผิด · import { cn } from "@/lib/utils" ยังใช้ได้
components.json สร้างโดย init — style · ไฟล์ CSS · aliases aliases.ui = ที่ add จะวางไฟล์ · tailwind.config ว่าง = Tailwind v4 · ไม่ได้จดรายชื่อ component ที่ติดตั้ง — โฟลเดอร์ components/ui/ คือบันทึกเดียวที่มี

3 · cn() — ตัวรวม class ที่รู้ว่า class ไหนชนกัน

ปัญหาที่มันแก้: ต่อสตริง "px-4 px-2" เองแล้วหวังว่าตัวหลังชนะ — วัดจริงได้ padding 16px (px-4 ชนะ) เพราะ CSS ตัดสินจากลำดับ rule ในไฟล์ CSS ที่ Tailwind เรียงเอง (.px-2 มาก่อน .px-4) ไม่ใช่ลำดับใน attribute class

เรียกผลรันจริงอ่านว่า
cn("px-2", "px-4")"px-4"เรื่องเดียวกัน ตัวหลังชนะ
cn("px-2 py-1", "p-4")"p-4"p-4 คุมสี่ด้าน มาทีหลังจึงกลืน px/py
cn("p-4", "px-2")"p-4 px-2"px-2 ทับได้แค่ซ้ายขวา · p-4 ยังต้องอยู่
cn("text-red-500", "text-lg")"text-red-500 text-lg"สีกับขนาด คนละเรื่อง เก็บทั้งคู่
cn("rounded-lg", isActive && "bg-blue-500", { "text-white": isActive, "border": true }) · isActive = false"rounded-lg border"รับ string · false (ทิ้ง) · object { class: เงื่อนไข }
"px-2" + " " + "px-4""px-2 px-4"ต่อสตริงเอง ไม่ตัดอะไร
cn("text-lg", "text-brand")"text-lg text-brand"class ที่ตั้งเอง cn ไม่รู้ว่าชนกับอะไร — เก็บทั้งคู่
cn(Container ของบท 83, "px-8 flex h-16")"mx-auto w-full max-w-7xl sm:px-6 lg:px-8 px-8 flex h-16"px-4 หาย · sm:px-6 อยู่ต่อ (คนละเงื่อนไข)
cn(buttonVariants({ size: "sm" }), "h-12 bg-accent")"… px-3 text-sm text-primary-foreground hover:bg-primary/90 h-12 bg-accent"h-8.5 กับ bg-primary หาย · hover:bg-primary/90 อยู่ (คนละเงื่อนไข)

กติกาที่ใช้ได้ทุก component ที่รับ className: cn(class ของเรา, className) — ใส่ของคนเรียกไว้ท้าย คนใช้จะทับได้ · ต่อสตริงเองหรือส่ง className ให้ cva ตรง ๆ โดยไม่ผ่าน cn → มีทั้ง h-8.5 และ h-12 อยู่ด้วยกัน ผลขึ้นกับลำดับไฟล์ CSS ทายจากโค้ดไม่ได้

ขั้นตอนเพิ่ม token ใหม่ (ทำครบทุกข้อ)

  1. ใส่ค่าจริงใน :root — และใน .dark ถ้ามีธีมมืด
  2. ลงทะเบียน --color-ชื่อ: var(--ชื่อ); ในบล็อก @theme inline เดิม ของ shadcn — อย่าเปิดบล็อก @theme ใหม่
  3. ใช้ใน JSX เช่น bg-accent-subtle · text-accent-strong
  4. npx next build แล้ว grep CSS ที่ build ออกมา ให้เจอทั้ง rule และค่า (หัวข้อ 8) — “เปิดหน้าแล้วสวย” ไม่นับว่าพิสูจน์
