เส้นแบ่งเส้นเดียวที่อธิบายได้ทั้งหมด: block กินทั้งบรรทัดและดันตัวถัดไปลงบรรทัดใหม่ · inline แทรกในบรรทัดและกว้างเท่าเนื้อข้างใน (วัดจริงในหน้ากว้าง 482px: div ได้ 482px ทั้งคู่คนละแถว · span ได้ 95px กับ 94px แถวเดียวกัน)

แท็กพันธุ์ใช้ตอนไหนจุดพลาดที่เจอบ่อยที่สุด
<div>blockมัดของเป็นก้อน เมื่อไม่มีแท็กที่มีความหมายตรงกว่าใส่ซ้อนกันโดยที่ยังตอบไม่ได้ว่าจะแปะ class อะไร
<p>blockย่อหน้าข้อความเอา block ไปใส่ข้างใน แล้วเบราว์เซอร์แอบปิด </p> ให้
<h1>–<h6>blockหัวข้อ · เลือกระดับตามโครงเรื่อง ไม่ใช่ตามขนาดตัวอักษรเลือกตามขนาดแล้วข้ามระดับ (h2 → h4)
<span>inlineจับคำกลางประโยคเพื่อจัดสไตล์สั่ง width/height แล้วงงว่าไม่มีผล (ได้ 118×19 ไม่ใช่ 120×60)
<header>blockส่วนหัวของหน้า (หรือของบทความ)ใช้ <div> แทนทั้งที่ตัวจริงมีอยู่ — หน้าตาไม่ต่างสักพิกเซล (วัดได้ 482px · display: block เหมือนกันหมดทั้งสี่) ประโยชน์อยู่ที่ landmark ของ screen reader · Google · และคนที่มาแก้โค้ดต่อ
<main>blockเนื้อหาหลัก · หน้าละหนึ่งอัน
<footer>blockท้ายหน้า · ลิขสิทธิ์ · ลิงก์ติดต่อ
<img>inlineใส่รูป · เป็น void element ไม่มีแท็กปิดลืม alt หรือใส่ alt เป็นชื่อไฟล์

<input>ช่องกรอกบรรทัดเดียว · void element ไม่มีแท็กปิดtype · id (ให้ label เกาะ) · name (ไม่มี = ไม่ถูกส่ง) · required · placeholder · value

<select>เลือกจากรายการที่กำหนดไว้ พิมพ์เองไม่ได้id · name
<option>หนึ่งตัวเลือกใน <select>value — ใส่ให้ทุกอันเสมอ (ไม่ใส่ = ส่งข้อความข้างในไปแทน วันไหนมีคนแก้คำภาษาไทย ค่าใน database เปลี่ยนตาม) · disabled selected ใช้ทำ "หัวข้อหลอก"

ชั้นคืออะไรพื้นหลังทาถึงไหม
contentตัวข้อความ รูป หรือกล่องลูกที่อยู่ข้างในทา
paddingที่ว่างด้านใน ระหว่างเนื้อหากับขอบกล่องทา
borderเส้นกรอบ — มีความหนาจริง กินที่จริงเป็นเส้นเอง
marginที่ว่างด้านนอก ระหว่างกล่องนี้กับกล่องอื่นไม่ทา — โปร่งใสเสมอ

ช่องขวาสุดคือวิธีดูด้วยตาเปล่า: ทาสีพื้นให้กล่องแล้วดูว่าสีขยายตามไปด้วยไหม — ขยาย = padding · ไม่ขยาย = margin

เขียนค่าได้กี่แบบ — padding กับ margin ใช้กติกาเดียวกันเป๊ะ จำครั้งเดียวได้ทั้งคู่

เขียนแบบตัวอย่างแปลว่า
1 ค่าpadding: 64px;ทั้งสี่ด้าน 64
2 ค่าpadding: 120px 64px;บน/ล่าง 120 · ซ้าย/ขวา 64 — แบบที่เจอบ่อยที่สุดในโค้ดจริง
4 ค่าpadding: 120px 64px 120px 64px;บน · ขวา · ล่าง · ซ้าย (วนตามเข็มนาฬิกา)
แยกด้านpadding-top: 120px;ระบุทีละด้าน มีครบสี่ตัว -top -right -bottom -left

margin มีของแถมที่ padding ไม่มีสองอย่าง: รับค่าติดลบได้ (ดึงกล่องให้ทับกัน) และ รับคำว่า auto — margin: 0 auto; คือวิธีจัดกล่องให้อยู่กลางแนวนอน

border เป็น shorthand รวมสามค่า: ความหนา · รูปแบบ · สี · ไม่ใส่ style เส้นจะไม่ขึ้นเลย เพราะค่าเริ่มต้นของ border-style คือ none — เขียน border: 4px red; อย่างเดียวจึงไม่เห็นอะไรทั้งนั้น

border: 4px solid #495057;      /* shorthand — ใช้แบบนี้เกือบตลอด */
border-width: 4px;              /* เขียนแยกเมื่อต้องแก้เฉพาะบางส่วนทีหลัง */
border-style: solid;             /* เช่น border-color: red; ตอน hover */
border-color: #1971c2;
border-radius: 12px;
⚠ กับดักที่ 1 — width: 100% แล้วล้น

กรอบพ่อ 300px · ลูกสั่ง width: 100%; padding: 20px; border: 4px → วัด getBoundingClientRect() ได้ 348px ไม่ใช่ 300

300 (content) + 20×2 (padding) + 4×2 (border) = 348   /* content-box = ค่าเริ่มต้น */
box-sizing: border-box;                              /* → ได้ 300 พอดี · content หดเหลือ 252 */

border-box ไม่ได้ทำให้ padding หายไป — มันเบียดที่ของ content แทน · ไม่มี error ไม่มี warning · รู้ตัวตอนเห็น scrollbar แนวนอนโผล่มาเท่านั้น · นี่คือเหตุผลที่โปรเจกต์จริงเกือบทุกโปรเจกต์เขียน * { box-sizing: border-box; } ไว้บรรทัดแรกของไฟล์ CSS แล้วไม่ต้องคิดเรื่องนี้อีกเลย

⚠ กับดักที่ 2 — margin collapsing

กล่องบน margin-bottom: 40px · กล่องล่าง margin-top: 24px → ช่องว่างจริง 40px ไม่ใช่ 64

margin แนวตั้งของสองกล่องที่ติดกันไม่บวกกัน — มันยุบรวมเป็นก้อนเดียวแล้วเอา max(40, 24) = 40 · แก้ 24 เป็น 30 ก็ยังได้ 40 (ทุกค่าที่น้อยกว่า 40 ให้ผลเหมือนกันหมด)

เกิดเฉพาะแนวตั้ง ไม่เกิดแนวนอน · และยัง "ทะลุ" ออกจากกล่องพ่อได้ด้วย — พ่อ div เปล่า ๆ ที่ลูกสั่ง margin-top: 30px → ขอบบนของพ่ออยู่ตำแหน่งเดียวกับลูกเป๊ะ และพ่อสูงแค่ 18px · เติม padding-top: 1px ให้พ่อ ระยะกลายเป็น 31px ทันที — 1 pixel เดียวหยุดการยุบได้

ทางออกที่คนสมัยนี้ใช้: ทำพ่อเป็น display: flex แล้วใช้ gap — ข้างในกล่อง flex ไม่มีการยุบรวม (ชุดเดิมเป๊ะ พอสั่ง display: flex; flex-direction: column; ระยะกลายเป็น 64px ทันที)

7 · display — block · inline · inline-block · none

ค่าวางตัวยังไงwidth/height ใช้ได้ไหมใครเป็นแบบนี้อยู่แล้ว
blockขึ้นบรรทัดใหม่เสมอ · กว้างเต็มพ่อได้div · p · h1 · header · main · footer
inlineไหลไปกับข้อความ ไม่ขึ้นบรรทัดใหม่ไม่ได้ — โดนเมินเงียบ ๆspan · a · strong · img
inline-blockไหลไปกับข้อความ แต่ตั้งขนาดได้ได้button · input · select · textarea เป็นมาแต่กำเนิด (อ่านจาก getComputedStyle().display) · ที่ต้องสั่งเองคือ div กับ span
noneหายไปจากหน้าเว็บ ไม่กินที่เลยไม่มีความหมายไม่มี

วัดจริงกับ <span> ที่สั่ง width: 120px; height: 40px เหมือนกันเป๊ะ: inline ได้ 39.89 × 20 (เท่าข้อความ บวก border 1px สองข้าง — ทั้ง width และ height ถูกเมิน) · inline-block ได้ 122 × 42 (120 × 40 ตามสั่ง บวก border 1px สองข้าง) · block เด้งลงบรรทัดใหม่ · none ไม่มีกล่องที่สี่เลย

⚠ display: none ต่างจาก "ซ่อนไว้"

ไม่กินที่แม้แต่ pixel เดียว (กล่องสูง 30px สามใบ ใบกลางสั่ง none → รวมสูง 60px ไม่ใช่ 90px) และโปรแกรมอ่านหน้าจอก็อ่านไม่เจอด้วย · อยากซ่อนแค่ทางสายตาแต่ยังกินที่เดิม → visibility: hidden;

8 · Flexbox — ตัวไหนใส่ที่แม่ ตัวไหนใส่ที่ลูก

9 · justify-content / align-items — row เทียบ column

กับดักที่ทุกคนเหยียบ

อย่าจำว่า "justify = แนวนอน" ให้จำว่า "justify = ตามแถว" แล้วถามต่อทุกครั้งว่า "แถวนี้มันเรียงไปทางไหน"
พิสูจน์แล้วด้วยกล่องสองกล่องที่ CSS เหมือนกันเป๊ะ (justify-content: flex-end; align-items: center;) ต่างกันแค่กล่องขวาเติม flex-direction: column หนึ่งบรรทัด — กล่องซ้ายได้ ชิดขวา + กลางแนวตั้ง ส่วนกล่องขวาได้ ชิดล่าง + กลางแนวนอน

เขียนอะไรrow (ค่าเริ่มต้น) — แกนหลักชี้ขวาcolumn — แกนหลักชี้ลง
justify-content: flex-start (เริ่มต้น)ชิดซ้ายชิดบน
justify-content: flex-endชิดขวาชิดล่าง
justify-content: centerกลางแนวนอนกลางแนวตั้ง
align-items: flex-startชิดบนชิดซ้าย
align-items: flex-endชิดล่างชิดขวา
align-items: centerกลางแนวตั้งกลางแนวนอน
align-items: stretch (เริ่มต้น)ลูกยืดเต็มความสูงของแม่เองลูกยืดเต็มความกว้างของแม่เอง

นี่คือคำตอบของคำถามที่คนถามกันมากที่สุดในโลก CSS — จัดกลางทั้งสองแกน คือ display: flex; justify-content: center; align-items: center; ซึ่งใช้ได้เหมือนกันทั้ง row และ column เพราะ center ของทั้งสองแกนคือจุดเดียวกัน

ค่าที่เหลือของ justify-content — "ที่ว่างที่เหลือไปกองอยู่ตรงไหน"

ค่าที่ว่างไปกองอยู่ตรงไหน
flex-start (ค่าเริ่มต้น)ท้ายแถวทั้งหมด — ของจึงชิดหัวแถว
flex-endหัวแถวทั้งหมด — ของจึงชิดท้ายแถว
centerแบ่งครึ่งไปหัวแถวกับท้ายแถวเท่ากัน
space-betweenแทรกอยู่ระหว่างของเท่านั้น หัวกับท้ายไม่มีเลย
space-aroundทุกกล่องได้ที่ว่างรอบตัวเท่ากัน → ขอบนอกจึงบางกว่าช่องกลางครึ่งหนึ่ง
space-evenlyทุกช่องเท่ากันหมด รวมช่องริมสองข้าง

ค่าที่เหลือของ align-items: stretch (ค่าเริ่มต้น) · flex-start · flex-end · center · baseline (เส้นฐานตัวอักษรตรงกัน ไม่ใช่ขอบกล่องตรงกัน — เห็นชัดตอนตัวหนังสือคนละขนาด)

รายละเอียดที่ทำให้ดูรู้จริง ค่าเริ่มต้นจริง ๆ ของ align-items ตามมาตรฐานคือคำว่า normal ไม่ใช่ stretch — แต่ normal เมื่ออยู่ใน flex container ให้ผลเหมือน stretch · คุยกันเร็ว ๆ พูดว่า "ค่าเริ่มต้นคือ stretch" ได้เลย แต่ถ้าเปิด DevTools แล้วเห็น normal จะได้ไม่ตกใจว่าใครไปแก้

10 · pseudo-class ของ state + ข้อควรระวัง

เขียนเป็นจริงตอนใช้กับต้องระวัง
:hoverตัวชี้ลอยอยู่เหนือ (ไม่เกี่ยวกับการคลิก)element อะไรก็ได้มือถือไม่มี — ห้ามซ่อนของสำคัญไว้หลังมัน
:focusคีย์บอร์ดคุยอยู่กับตัวนี้ (คลิกก็นับ)ตัวที่โฟกัสได้อย่าใส่ outline: none แล้วจบแค่นั้น
:focus-visibleโฟกัสอยู่ และ เบราว์เซอร์เห็นว่าควรโชว์กรอบ (คือตอนใช้คีย์บอร์ด)ตัวที่โฟกัสได้ต้องเขียนหลัง :focus ไม่งั้นโดนทับ
:activeกำลังกดค้างอยู่ (designer เรียก pressed)element อะไรก็ได้ต้องเขียนไว้ล่างสุด ไม่งั้น :hover ทับ
:disabled / :enabledมี / ไม่มี attribute disabledform control เท่านั้น<div> กับ <a> ใช้ไม่ได้ — กฎเงียบไปเฉย ๆ ไม่ error
ลำดับที่จำไว้แล้วไม่พลาด

ปุ่มทั่วไป: ปกติ → :hover → :focus-visible → :active → :disabled

เหตุผลเดียวกันทั้งคู่: pseudo-class พวกนี้ specificity เท่ากันหมด ตัวล่างสุดจึงชนะเสมอ — เรียงจาก "เกิดบ่อย/ถาวร" ไปหา "เกิดชั่วขณะ" แล้วจะไม่มีวันทับกันผิด

❌ ลบทิ้งเฉย ๆ ไม่วาดอะไรกลับมา

button:focus { outline: none; }

ลบกรอบทุกกรณี รวมทั้งตอนกด Tab · คนที่ใช้คีย์บอร์ดจะไม่รู้ว่าตอนนี้อยู่ปุ่มไหน — ไม่ได้มีแค่ผู้พิการ รวมถึงคนที่เมาส์เสียและคนที่ไม่อยากละมือจากคีย์บอร์ดด้วย

✅ ลบของ default แล้ววาดของเราแทน

.btn:focus         { outline: none; }
.btn:focus-visible { outline: 3px solid #1a73e8;
                     outline-offset: 3px; }

คลิกด้วยเมาส์ = ไม่มีกรอบค้าง · กด Tab มา = เห็นวงแหวนชัด · เขียน :focus ก่อน :focus-visible เสมอ

⚠ มือถือไม่มี hover

โทรศัพท์ไม่มีตัวชี้ที่ "ลอยอยู่เหนือ" อะไรได้ · เอาข้อมูลที่จำเป็นไปซ่อนหลัง :hover = คนใช้มือถือไม่มีทางเห็นมันเลย ไม่ใช่ "เห็นยาก"
กฎที่ปลอดภัย: :hover ใช้ตกแต่งได้ ใช้ซ่อนของไม่ได้
อยากเขียนสไตล์ที่เฉพาะเครื่องมีเมาส์จริงถึงใช้ ให้ครอบด้วย @media (hover: hover) { … } — ถามความสามารถของอุปกรณ์ ไม่ใช่ถามความกว้างจอ (แท็บเล็ตจอใหญ่ก็ไม่มี hover · หน้าต่างที่ย่อแคบบน desktop ก็ยังมีเมาส์)

⚠ disabled (attribute) ≠ :disabled (pseudo-class)

attribute disabled ใน HTML ทำสามอย่างให้ทันทีโดยไม่ต้องเขียนอะไรเลย: กดแล้ว event click ไม่ยิงออกมาเลย · กด Tab ข้ามมันไป · และค่าไม่ถูกส่งไปกับฟอร์ม · ส่วน CSS แค่ทำให้จาง ไม่ได้ปิดอะไรเลย — ต้องทำทั้งสองอย่าง

ทดสอบด้วย el.matches(…)ผลจริง
<input> ธรรมดา ตรงกับ :enabled ไหมtrue
<div> ตรงกับ :enabled ไหมfalse
<a href="#"> ตรงกับ :enabled ไหมfalse
<button> ที่อยู่ใน <fieldset disabled> ตรงกับ :disabled ไหมtrue — ปิดยกชุดได้
เรียก .click() ใส่ปุ่มที่ disabled — handler ยิงกี่ครั้ง0 ครั้ง (ปุ่มปกติได้ 1)

อยากได้พฤติกรรมของปุ่ม → ใช้ <button> จริง ๆ แล้วจะได้ :disabled · การข้าม Tab · และการปิด click มาฟรีทั้งชุด

"Dragged" ในสไลด์ รายการ state ในสไลด์ (enabled · hover · focused · pressed · disabled · dragged) คือรายการในภาษาของ design system ซึ่ง Material Design 3 ใช้คำชุดนี้เป๊ะ ไม่ใช่รายการ pseudo-class ของ CSS · ห้าตัวแรกมีให้ใช้ตรงตัว (:enabled · :hover · :focus · :active · :disabled) ส่วน :dragged ไม่มีอยู่จริง — ถามเบราว์เซอร์ตรง ๆ ด้วย CSS.supports('selector(:dragged)') ได้ false · ที่ทำได้ด้วย CSS ล้วนคือ cursor: grab คู่กับ :active { cursor: grabbing } · การลากจริงต้องใช้ JavaScript แปะ class เอง เช่น .is-dragging

เพิ่มตัวเลข margin แล้วระยะห่างไม่ขยับเลยmargin แนวตั้งยุบรวมกัน แล้วใช้ค่าที่มากกว่า — max(40, 24) = 40อย่าเพิ่มตัวเลขมั่ว → เปลี่ยนไปใช้ gap ของ flex/grid จบเรื่องเร็วกว่า (บท 60)
ใส่ margin-top ให้ลูก แล้วทั้งก้อนเลื่อนลงไปทั้งอันmargin ทะลุออกนอกพ่อ เพราะพ่อไม่มี padding/border คั่นpadding-top: 1px ให้พ่อก็หยุดได้ · หรือทำพ่อเป็น flex (บท 60)
ตัวหนังสือบานใหญ่ผิดคาดทั้งที่ CSS เขียน 1.5em เท่ากันทุกชั้นem ทบต้น — 20 → 30 → 45pxใช้ rem เป็นค่าเริ่มต้น เก็บ em ไว้ใช้เฉพาะที่ตั้งใจ (บท 60)
ตั้ง width: 300px ให้การ์ด แล้วเปิดดูได้แคบกว่านั้นอยู่ใน flex container ที่เป็น nowrap แล้วโดน flex-shrink: 1 บีบเลือกตามเจตนา: flex-wrap: wrap ที่แม่ · flex-shrink: 0 ที่ลูก · หรือ min-width (บท 61)
ใส่ flex: 1 แล้วเงียบสนิทกล่องนั้นไม่ใช่ลูกชั้นแรกของ flex container (เป็นหลานอีกชั้น) หรือแม่ยังไม่ display: flexเช็คว่าใครเป็นแม่จริง ๆ · flex item = ลูกชั้นแรกเท่านั้น (บท 61)
ใส่ align-items: center แล้วไม่เห็นความต่างแม่ไม่ได้สูงกว่าเนื้อหา จึงไม่มีที่ว่างในแนวแกนรองให้จัดใส่ height หรือ padding ให้แม่ก่อน (บท 61)
ใส่ justify-content แล้วไม่ขยับไม่มีที่ว่างเหลือให้กระจาย เพราะของเต็มแถวพอดีอยู่แล้วดูว่าลูกกินที่หมดหรือยัง ก่อนไปสงสัยว่าเขียนผิด (บท 61)
flex-grow: -1 เขียนไปแล้วไม่ทำงาน แถวไม่มี error ใน Consoleค่าติดลบใช้ไม่ได้ — เบราว์เซอร์ทิ้งบรรทัดนั้นทั้งบรรทัดแล้วกลับไปใช้ค่าเริ่มต้นที่เดียวที่เห็นคือแผง Styles ใน DevTools ซึ่งขีดฆ่าบรรทัดนั้นไว้ให้ (บท 61)

กดปุ่มค้างด้วยเมาส์แล้วสีของ :active ไม่โผล่ตอนกดค้าง :hover ก็จริงด้วย · specificity เท่ากัน → ตัวที่เขียนทีหลังชนะย้าย :active ลงล่างสุด — แก้ด้วยการย้ายบรรทัด ไม่ใช่เพิ่ม !important (บท 62)
กด Tab แล้วไม่รู้ว่าตอนนี้อยู่ปุ่มไหนของหน้ามีคนเขียน button:focus { outline: none; } ทิ้งไว้โดยไม่วาดอะไรกลับมาย้ายกรอบไป :focus-visible · เบราว์เซอร์ไม่ใส่กลับมาให้เอง (บท 62)
เขียน .my-button:disabled ให้ <div> แล้วไม่มีอะไรเกิดขึ้น:disabled/:enabled ใช้กับ form control เท่านั้น — <div> ได้ falseใช้ <button> จริง ๆ · selector ที่ไม่ตรงกับอะไรถูกข้ามเงียบ ๆ ไม่เคยทำให้ไฟล์พัง (บท 62)
ปุ่มจางลงแล้ว แต่ผู้ใช้ยังกดได้อยู่CSS ทำให้จางอย่างเดียว ไม่ได้ปิดอะไรเลยแปะ attribute disabled ใน HTML ด้วยเสมอ (บท 62)
คนใช้มือถือบอกว่าไม่เห็นราคา/ปุ่มที่คุณเห็นอยู่ชัด ๆของนั้นถูกซ่อนไว้หลัง :hover ซึ่งมือถือไม่มีโชว์ตลอด แล้วใช้ :hover แค่เน้นของที่เห็นอยู่แล้ว (บท 62)
