4 · Server Component vs Client Component

ใน App Router ทุกไฟล์เป็น Server Component โดยปริยาย จนกว่าจะเขียน 'use client' บรรทัดบนสุด · เกินครึ่งของ error ในกลุ่มนี้คือเส้นแบ่งเส้นนี้เส้นเดียว

อยากทำอะไรServer Component (ค่าปริยาย)Client Component ('use client')
useState · useEffect ❌ build พัง — This API is only available in Client Components. ✅ ได้
createContext · useContext ❌ build พัง เหมือนกัน · และพังทั้งแอป ไม่ใช่แค่หน้าเดียว ✅ ได้
useMemo · useCallback · useId ✅ ไม่ error จริง ๆ — สามตัวนี้อยู่ในรายการ export ฝั่ง server ของ react 19.2.8 · แต่ไม่ได้ประโยชน์ เพราะ Server Component วาดครั้งเดียวต่อ request ไม่มีรอบถัดไปให้จำ ✅ ได้ และได้ประโยชน์จริง
onClick และ event ทุกชนิด ❌ ไม่มีการกดปุ่มบนเซิร์ฟเวอร์ ✅ ได้
ถูกรันบนเซิร์ฟเวอร์เพื่อทำ HTML ตั้งต้น ✅ ใช่ (นั่นคืองานของมัน) ✅ ใช่ ก็ยังถูกรันบนเซิร์ฟเวอร์หนึ่งรอบอยู่ดี — ต้นตอของ hydration mismatch
ส่ง JavaScript ไปเบราว์เซอร์ ไม่ส่ง ส่ง — นี่คือความหมายจริงของ 'use client'
ครอบ Client Component เป็น children ✅ ได้ · หน้าที่ไม่มี 'use client' เลยก็ครอบ <ThemeProvider> ได้ และยัง build เป็น ○ (Static) ได้ด้วย —
เป็นหน้า ○ (Static) ✅ ✅ ได้เหมือนกัน — 'use client' ไม่ได้แปลว่า “ห้าม prerender”

ต้องใส่ 'use client' เมื่อไหร่ และตรงไหน

9 · custom hook — กฎ 4 ข้อ

custom hook คือฟังก์ชัน JavaScript ธรรมดาที่ชื่อขึ้นต้นด้วย use และข้างในเรียก hook ของ React · ไม่มี API พิเศษ ไม่ต้อง import อะไรเพิ่ม

กฎ (สไลด์หน้า 62)แปลเป็นภาษาคนใครเป็นคนจับได้
1 · Start with “use” ชื่อฟังก์ชันต้องขึ้นต้นด้วย use eslint ฟ้องตอนตรวจ (react-hooks/rules-of-hooks) · React ตอนรันไม่ดูชื่อเลย โค้ดยังรันได้ปกติ
2 · Call other hooks ข้างในต้องเรียก hook ของ React อย่างน้อยหนึ่งตัว ไม่มีใครฟ้อง — แต่ถ้าไม่ทำ คุณจะโดน eslint ฟ้องผิด ๆ ทีหลัง (called conditionally ทั้งที่โค้ดไม่ผิด) แล้วคุณจะเลิกเชื่อเครื่องมือ
3 · Top-level execution ห้ามเรียกใน if / loop / หลัง return ทั้ง eslint และ React ตอนรัน — React โยน error จนหน้าพัง
4 · Independent state ทุกที่ที่เรียก ได้ state ของตัวเอง ไม่แชร์กัน ไม่มีใครฟ้อง — เพราะมันไม่ใช่ error แต่เป็นวิธีที่มันทำงาน

useDebounce — ตัวที่ได้ใช้บ่อยที่สุด

import { useEffect, useState } from "react";

export function useDebounce<T>(value: T, delay: number): T {
	const [debounced, setDebounced] = useState(value);

	useEffect(() => {
		const id = setTimeout(() => setDebounced(value), delay);
		return () => clearTimeout(id);   // ← ทั้งหมดของ debounce
	}, [value, delay]);

	return debounced;
}

useToggle — โครงที่ใช้ซ้ำได้

import { useCallback, useState } from "react";

export function useToggle(initial = false) {
	const [isOpen, setIsOpen] = useState(initial);
	const open   = useCallback(() => setIsOpen(true), []);
	const close  = useCallback(() => setIsOpen(false), []);
	const toggle = useCallback(() => setIsOpen((v) => !v), []);
	return { isOpen, open, close, toggle };
}

คืน object ดีกว่าคืน array — คืน array แล้วคนเรียกต้องจำลำดับ (สลับ open กับ close ก็ไม่มีใครฟ้อง) · อยากได้แบบสไลด์ให้ใช้ return [isOpen, open, close, toggle] as const;
