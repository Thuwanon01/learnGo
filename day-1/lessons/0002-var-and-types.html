บทเรียน 02 · Day 1 · Variables & Types

var, := และเรื่อง type ที่ Go ไม่ยอมให้ผ่าน

~12 นาที · ต้องมี: บทเรียน 01

Go มีวิธีประกาศตัวแปร 3 แบบ และมีที่ที่ใช้ได้ไม่เหมือนกัน — ที่สำคัญกว่านั้นคือ Go ไม่ยอมแปลง type ให้อัตโนมัติแม้แต่นิดเดียว บวก int กับ float64 ตรง ๆ ก็ไม่ผ่าน บทนี้จะทำให้คุณเลิกงงกับ error ประเภท mismatched types ตลอดไป

1 · สามวิธีประกาศตัวแปร

// 1) var + type — ไม่ใส่ค่า ได้ zero value
var i int                        // i = 0

// 2) var + ค่าเริ่มต้น — ละ type ได้ ให้ compiler เดาเอง
var j int = 2
var c, python, java = true, false, "no!"

// 3) short declaration — สั้นสุด ใช้บ่อยสุด
k := 3
name, age := "Alice", 30
ข้อจำกัดที่ต้องจำ

:= ใช้ได้เฉพาะข้างในฟังก์ชัน — นอกฟังก์ชัน (ระดับ package) ต้องใช้ var เท่านั้น เพราะทุกบรรทัดข้างนอกต้องขึ้นต้นด้วย keyword (package, import, func, var, const, type)

สถานการณ์ใช้อะไร
ในฟังก์ชัน มีค่าเริ่มต้นอยู่แล้ว:= — สำนวนมาตรฐาน
ต้องการ zero valuevar x int
นอกฟังก์ชัน (package level)var เท่านั้น
อยากบังคับ type ให้ชัดvar x float64 = 3

2 · Zero value — Go ไม่มีตัวแปร "ไม่มีค่า"

ประกาศแล้วไม่ใส่ค่า Go จะเติมค่าให้เสมอ — ไม่มีคำว่า undefined

TypeZero value
int, float64 และตัวเลขทุกชนิด0
boolfalse
string"" (สตริงว่าง ไม่ใช่ null)
pointer, slice, map, func, chan, interfacenil
var i int; var f float64; var b bool; var s string
fmt.Printf("%v %v %v %q\n", i, f, b, s)
// 0 0 false ""

ทำไมเรื่องนี้สำคัญ: ในภาษาอื่น "ตัวแปรยังไม่ได้เซ็ต" กับ "ตัวแปรเป็นศูนย์" ต่างกัน แต่ Go ยุบให้เหลืออันเดียว — ตัวแปรพร้อมใช้เสมอ ไม่ต้องเช็ค null ก่อน แลกกับที่คุณต้องระวังว่า "0" อาจแปลว่า "ยังไม่ได้ตั้งค่า" ก็ได้

3 · จุดที่คนใหม่ติดกันทุกคน: Go ไม่แปลง type ให้

var i int = 42
var f float64 = 1.5

result := i + f

โค้ดนี้เป็นยังไง?

compile ไม่ผ่าน:

invalid operation: i + f (mismatched types int and float64)

ในภาษาอย่าง Python หรือ JavaScript อันนี้ผ่านสบาย ๆ แต่ Go บังคับให้ คุณเขียนออกมาเองว่าจะแปลงยังไง ต้องเขียน float64(i) + f

รูปแบบการแปลงคือ T(v) — เอา type มาครอบค่า:

i := 42
f := float64(i)     // int → float64
u := uint(f)        // float64 → uint

// ใช้จริง — math.Sqrt รับ float64 เท่านั้น
var x, y int = 3, 4
var dist float64 = math.Sqrt(float64(x*x + y*y))
ระวังข้อมูลหาย 
f := 3.9
i := int(f)      // 3 — ตัดทิ้ง ไม่ใช่ปัดเศษ!

big := 300
b := uint8(big) // 44 — uint8 เก็บได้แค่ 0–255 ล้นแล้ววนกลับ

การแปลง type ไม่มีการเตือน ถ้าค่าไม่พอดี

แต่ถ้าเป็นค่าคงที่ Go จะจับให้ตั้งแต่ compile 
// ผ่านตัวแปร → รันได้ ตัดค่าเงียบ ๆ
f := 3.9;  int(f)      // 3   ✓ รันได้
big := 300; uint8(big) // 44  ✓ รันได้

// ใส่ค่าคงที่ตรง ๆ → compile ไม่ผ่าน!
int(3.9)                // ✗ cannot convert 3.9 (untyped float constant) to type int
uint8(300)              // ✗ constant 300 overflows uint8

เพราะ ค่าคงที่ (constant) Go รู้ค่าตั้งแต่ตอน compile เลยตรวจได้เลยว่า ข้อมูลจะหาย — แต่ค่าในตัวแปรรู้ตอน runtime เท่านั้น จึงได้แค่ปล่อยผ่าน นี่คือเหตุผลที่ต้องระวังตัวแปร มากกว่าค่าคงที่

4 · Type inference — compiler เดา type ให้ยังไง

n := 42
f := 3.142
s := "hello"
b := true

fmt.Printf("%T %T %T %T\n", n, f, s, b)

พิมพ์ type อะไรออกมาบ้าง?

int float64 string bool

สังเกตว่า 3.142 ได้ float64 ไม่ใช่ float32 และ 42 ได้ int ไม่ใช่ int64 — นี่คือ default type ของค่าคงที่ที่ยังไม่ระบุชนิด

%T คือ format verb ที่พิมพ์ type ออกมา — เครื่องมือดีบักที่ดีที่สุด ตอนงงว่าตัวแปรเป็น type อะไร

verbพิมพ์อะไรตัวอย่างผลลัพธ์
%vค่าแบบ default{Alice 30}
%+vค่า + ชื่อ field (struct){Name:Alice Age:30}
%Ttypemain.User
%d / %s / %tเลขจำนวนเต็ม / สตริง / bool42 / hi / true
%qสตริงพร้อมเครื่องหมายคำพูด"hi"
%.2fทศนิยม 2 ตำแหน่ง2500.00

5 · เลือก type ตัวเลขยังไง

กฎง่าย ๆ ที่ใช้ได้ 95% ของเวลา

ใช้ int กับ float64 ไปเลย จนกว่าจะมีเหตุผลเฉพาะที่ต้องใช้อย่างอื่น

แล้วเหตุผลเฉพาะคืออะไรบ้าง:

Typeช่วงค่าใช้ตอน
int8−128 ถึง 127protocol, binary data, ประหยัด memory
int32±2.1 พันล้านfield ขนาดคงที่, Unicode rune
int64±9.22e18timestamp, database ID, ขนาดไฟล์
uint8 (byte)0 ถึง 255ข้อมูล byte, ช่องสี, raw binary
rune= int32ตัวอักษร 1 ตัว (สำคัญมากกับภาษาไทย)
byte vs rune — เรื่องที่คนไทยเจอแน่นอน 
s := "สวัสดี"
len(s)              // 18 — นับเป็น byte!
len([]rune(s))      // 6  — นับเป็นตัวอักษร ✓

ภาษาไทย 1 ตัวอักษรกิน 3 bytes ใน UTF-8 → ถ้าจะนับจำนวนตัวอักษร ต้องแปลงเป็น []rune ก่อนเสมอ

6 · ทดสอบความจำ

1. เขียน count := 0 ไว้นอกฟังก์ชัน (ระดับ package) จะเป็นยังไง?

syntax error: non-declaration statement outside function body — := ใช้ได้เฉพาะในฟังก์ชัน นอกฟังก์ชันทุกบรรทัดต้องขึ้นต้นด้วย keyword

2. var s string แล้วยังไม่ใส่ค่า — s มีค่าอะไร?

zero value ของ string คือ "" — ไม่ใช่ nil (string ใน Go เป็น nil ไม่ได้เลย) ใช้ได้ทันทีไม่ต้องเช็คก่อน

3. i เป็น int, f เป็น float64 — เขียนยังไงถึงบวกกันได้?

Go ใช้รูปแบบ T(v) — เอา type ครอบค่า ไม่ใช่แบบ C ((float64) i) และไม่ใช่ type assertion (i.(float64) ซึ่งใช้กับ interface เท่านั้น)

4. len("สวัสดี") คืนค่าอะไร?

len() ของ string นับ bytes เสมอ — ภาษาไทยใน UTF-8 ใช้ 3 bytes ต่อตัว → 6 × 3 = 18

อยากได้ 6 ต้องเขียน len([]rune("สวัสดี")) หรือ utf8.RuneCountInString(s)

7 · ลงมือทำ

ภารกิจ: ทำให้ compiler ด่าแล้วซ่อมให้ได้

  1. ใน Playground ประกาศตัวแปรทั้ง 3 แบบ อย่างละ 1 ตัว แล้วพิมพ์ทั้งค่าและ type ด้วย fmt.Printf("%v %T\n", x, x)
  2. ประกาศ var i int = 42 และ var f float64 = 1.5 แล้วลอง i + f — อ่าน error ให้ครบทั้งบรรทัด แล้วซ่อม
  3. เก็บใส่ตัวแปรก่อน แล้วค่อยแปลง: f := 3.9; fmt.Println(int(f)) และ big := 300; fmt.Println(uint8(big)) — ทำนายผลก่อนรัน แล้วดูว่าตรงไหม
  4. ทีนี้ลองแปลง ค่าคงที่ตรง ๆ: int(3.9) และ uint8(300) — คนละเรื่องกับข้อ 3 นะ อ่าน error แล้วอธิบายให้ได้ว่าทำไม Go ถึงยอมให้ทำข้อ 3 แต่ไม่ยอมข้อนี้
  5. ประกาศตัวแปร 1 ตัวแล้วไม่ใช้เลย — จำ error declared and not used ไว้ให้ขึ้นใจ
  6. พิมพ์ len("สวัสดี") เทียบกับ len([]rune("สวัสดี"))
  7. ท้าทาย: เขียนโปรแกรมที่รับ completedTopics, totalTopics เป็น int แล้วพิมพ์เปอร์เซ็นต์ทศนิยม 2 ตำแหน่ง — คำใบ้: int / int ได้ int (5/2 = 2 ไม่ใช่ 2.5) ต้องแปลงก่อนหาร
ชัยชนะของบทนี้

เจอ error mismatched types หรือ cannot use x (type A) as type B คุณจะไม่งงอีก — รู้เลยว่าต้องหาจุดที่ต้องเขียน T(v) ครอบ
