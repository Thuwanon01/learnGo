บทเรียน 11 · Day 4 · Interface (ต่อ)

any, Type Assertion และการดึงของจริงออกมาจากกล่อง

~14 นาที · ต้องมี: บทเรียน 10

any รับได้ทุกอย่าง — ฟังดูสะดวก แต่พอรับเข้ามาแล้วคุณ ทำอะไรกับมันไม่ได้เลย จนกว่าจะดึง type จริงออกมา บทนี้ว่าด้วยสามวิธีดึง (assertion, comma-ok, type switch) ว่าอันไหน panic อันไหนปลอดภัย และทำไม fmt.Println ถึงรู้จักวิธีพิมพ์ struct ของคุณ

1 · interface{} / any — กล่องที่ใส่อะไรก็ได้

interface{} คือ interface ที่ไม่ขอ method อะไรเลย → ทุก type ในโลกจึงผ่านเงื่อนไขนี้อัตโนมัติ ตั้งแต่ Go 1.18 มี alias ให้ใช้ ชื่อสั้นกว่าคือ any (จำจาก บทเรียน 09: type any = interface{} — เป็น alias ไม่ใช่ type ใหม่) 

func describe(v any) {
    fmt.Printf("Value: %v, Type: %T\n", v, v)
}

describe("hello")        // Value: hello, Type: string
describe(42)             // Value: 42, Type: int
describe(true)           // Value: true, Type: bool
describe(Score(95.5))    // Value: 95.5, Type: main.Score
ตัวแปร any เก็บ สองอย่าง เสมอ:

   ┌───────────────┬───────────────┐
   │  type จริง    │   ค่าจริง     │
   ├───────────────┼───────────────┤
   │   string      │   "hello"     │
   └───────────────┴───────────────┘
        ↑ %T อ่านช่องนี้    ↑ %v อ่านช่องนี้

type assertion = ถามช่องซ้าย แล้วขอช่องขวาถ้าตรง
อย่าใช้พร่ำเพรื่อ

any คือการปิดตา compiler — บั๊กที่เคยถูกจับตอน compile จะไปโผล่ตอน runtime แทน ใช้เมื่อจำเป็นจริง ๆ เท่านั้น เช่นตอนแกะ JSON ที่ไม่รู้โครงสร้างล่วงหน้า หรือเขียน logger ถ้ารู้ type อยู่แล้วก็เขียน type นั้นตรง ๆ

2 · Type Assertion — แบบดิบ (เสี่ยง panic)

var i any = "hello"
s := i.(string)     // syntax: x.(T)
fmt.Println(s)      // hello
var i any = "hello"
n := i.(int)
fmt.Println(n)

เกิดอะไรขึ้น — compile error, พิมพ์ 0 หรือ panic?

Panic ตอน runtime — compile ผ่านสบาย แล้วพังตอนรัน ข้อความจริงที่ผมรันได้:

panic: interface conversion: interface {} is string, not int

อ่านข้อความนี้ให้ออก: "กล่องนี้เก็บ string อยู่ ไม่ใช่ int" compiler ช่วยอะไรไม่ได้เลย เพราะตอน compile มันเห็นแค่ว่า i เป็น any — จะเป็นอะไรก็ได้

3 · Comma-ok — แบบปลอดภัย ใช้อันนี้

var i any = "hello"

s, ok := i.(string)
if ok {
    fmt.Println("String value:", s)
} else {
    fmt.Println("Not a string")
}
เขียนแบบokค่าที่ได้ถ้าไม่ตรง
s := i.(string)—ค่าจริงpanic 💥
s, ok := i.(string)true/falseค่าจริง หรือ zero valueไปต่อได้ ไม่พัง
// ผลรันจริงเมื่อ i เก็บ string อยู่:
s, ok := i.(string)   // s = "hello",  ok = true
n, ok := i.(int)      // n = 0,        ok = false  ← zero value ไม่ใช่ขยะ

รูปแบบ comma-ok คุณเคยเจอแล้ว — ตอนอ่าน map ใน บทเรียน 07 (v, ok := m["key"]) และตอนอ่าน channel Go ใช้สำนวนนี้ทุกที่ที่ "อาจจะไม่มี" — เจอ , ok เมื่อไหร่ แปลว่า Go กำลังบอกว่าอย่าเชื่อว่าจะได้ของ

4 · Type Switch — เช็คหลาย type ทีเดียว

ถ้าต้องเช็ค 5 type ด้วย comma-ok ก็จะได้ if ซ้อนกัน 5 ชั้น — ซึ่งเป็นสิ่งที่ บทเรียน 04 บอกให้เลิกทำ Go มีไวยากรณ์เฉพาะให้: 

func printType(v any) {
    switch value := v.(type) {    // ← .(type) เขียนได้เฉพาะใน switch
    case string:
        fmt.Println("string:", value)   // value เป็น string ตรงนี้
    case int:
        fmt.Println("int:", value)      // value เป็น int ตรงนี้
    case bool:
        fmt.Println("bool:", value)
    default:
        fmt.Println("unknown type")
    }
}

// ผลรันจริง:
printType("hello")   // string: hello
printType(42)        // int: 42
printType(true)      // bool: true
printType(3.14)      // unknown type   ← float64 ไม่มี case
จุดที่เจ๋งของ type switch

ใน case string: ตัวแปร value เป็น string จริง ๆ ไม่ใช่ any — เรียก len(value) หรือ strings.ToUpper(value) ได้ทันที ไม่ต้อง assert ซ้ำ compiler เปลี่ยน type ให้ในแต่ละ branch

5 · Stringer — ทำไม fmt.Println ถึงรู้จัก struct ของคุณ

fmt ทำ type switch อยู่ข้างในนั่นเอง — มันเช็คว่าค่าที่รับมา implement interface นี้ไหม: 

// นิยามจริงใน package fmt:
type Stringer interface {
    String() string
}

มี String()

type Person struct {
    Name    string
    Surname string
}

func (p Person) String() string {
    return fmt.Sprintf("%s %s",
        p.Name, p.Surname)
}

fmt.Println(p)
// Alice Wonder

ไม่มี String()

type Person struct {
    Name    string
    Surname string
}





fmt.Println(p)
// {Alice Wonder}

ไม่ต้องบอก fmt เลยว่าคุณมี String() — duck typing จาก บทเรียน 10 ทำงานให้อัตโนมัติ นี่คือตัวอย่างที่ชัดที่สุดว่า implicit interface มีประโยชน์ยังไง: fmt เขียนขึ้นก่อนโค้ดคุณเกิดเป็นสิบปี แต่ยังทำงานกับ type ใหม่ได้

กับดัก: String() ที่เรียกตัวเอง 
func (p Person) String() string {
    return fmt.Sprintf("%v", p)   // ✗ วนไม่รู้จบ → stack overflow
}

%v บน p จะไปเรียก String() อีกรอบ → วนไม่จบจน stack เต็ม ทางแก้: อ้าง field ตรง ๆ (p.Name) หรือ convert เป็น type อื่นก่อน

6 · Interface Embedding — ประกอบ interface จากชิ้นเล็ก

บทเรียน 10 บอกให้ทำ interface ให้เล็ก แล้วถ้าบางที่อยากได้ครบทุกอันล่ะ — ไม่ต้องพิมพ์ซ้ำ ใช้ embedding: 

type Saver   interface { Save(data []byte) error }
type Loader  interface { Load(id string) ([]byte, error) }
type Deleter interface { Delete(id string) error }

type Storage interface {
    Saver          // ← ไม่ใช่ field แต่คือ "รวม method ของ Saver มาด้วย"
    Loader
    Deleter
}

Storage จึงมี 3 method โดยไม่ต้องเขียนซ้ำ และ type ที่ implement ครบทั้งสามก็เป็น Storage อัตโนมัติ: 

type FileStorage struct{}

func (FileStorage) Save(data []byte) error         { return nil }
func (FileStorage) Load(id string) ([]byte, error) { return []byte("example"), nil }
func (FileStorage) Delete(id string) error       { return nil }

var s Storage = FileStorage{}   // ✓ ผ่าน

ของจริงใน standard library: io.ReadWriter คือ io.Reader + io.Writer ประกอบกันแบบนี้เป๊ะ ๆ — เปิดอ่านได้ที่ pkg.go.dev/io ซอร์สจริงสั้นแค่ 4 บรรทัด

7 · ทดสอบความจำ

1. var i any = "hello" แล้ว n := i.(int) เกิดอะไร?

compiler เห็นแค่ any จึงปล่อยผ่าน แล้วพังตอนรันด้วย panic: interface conversion: interface {} is string, not int ใช้ n, ok := i.(int) แทนเสมอถ้าไม่แน่ใจ 100%

2. n, ok := i.(int) เมื่อ i เก็บ string — n ได้อะไร?

รูปแบบ comma-ok ไม่เคยคืนค่าขยะ — ถ้าไม่ตรงจะได้ zero value ของ type ที่ขอ (0, "", false, nil) พร้อม ok = false เสมอ ปลอดภัยกว่าแบบดิบมาก

3. ใน case string: ของ type switch ตัวแปรมี type อะไร?

compiler เปลี่ยน type ของตัวแปรให้ในแต่ละ branch แยกกัน → len(value), strings.ToUpper(value) เรียกได้เลย นี่คือเหตุผลหลักที่ type switch อ่านง่ายกว่า if ซ้อน

4. fmt.Println(p) รู้ได้ยังไงว่าต้องเรียก String()?

fmt ทำ type assertion ข้างในว่า v.(Stringer) ได้ไหม — ไม่ต้องลงทะเบียนอะไรเลย นี่คือ duck typing ในทางปฏิบัติ และเป็นเหตุผลที่ error interface ทำงานแบบเดียวกันได้ใน บทเรียน 12

8 · ลงมือทำ

ภารกิจ: เขียน formatter ที่รับอะไรก็ได้

  1. เขียน func Format(v any) string ที่ใช้ type switch คืนค่าดังนี้:
    • string → ครอบด้วย " เช่น "hello"
    • int, int64 → เติม comma คั่นหลักพัน (1,234,567)
    • bool → "ใช่" / "ไม่ใช่"
    • nil → "(ว่าง)" — คำใบ้: case nil: ใช้ได้
    • อย่างอื่น → fmt.Sprintf("%v", v)
  2. เพิ่ม case fmt.Stringer: ไว้ก่อน default แล้วคืน v.String()
  3. สร้าง type Temp float64 ที่มี String() คืน "36.5°C" แล้วส่งเข้า Format — เข้า case ไหน?
  4. ลำดับของ case มีผลจริง — สร้าง type ที่ตรงสอง case พร้อมกัน: 
    type FieldError struct{ Field string }

func (e FieldError) Error() string  { return "invalid field: " + e.Field }
func (e FieldError) String() string { return "FieldError(" + e.Field + ")" }
    เพิ่ม case error: เข้าไป แล้วลองสลับว่าใครอยู่ก่อน ระหว่าง case error: กับ case fmt.Stringer:
    สปอยล์ผลรันจริง: error อยู่ก่อน → invalid field: age · Stringer อยู่ก่อน → FieldError(age)
    Go เลือก case แรกที่ตรง ไม่ใช่ที่ตรงที่สุด
  5. ลองสั่ง fmt.Println(FieldError{Field: "age"}) ตรง ๆ ดูว่า fmt เลือกอันไหน — เฉลย: ได้ invalid field: age แปลว่า fmt เช็ค error ก่อน Stringer
  6. ท้าทาย: เพิ่ม case []any: ที่วนเรียก Format กับสมาชิกทุกตัวแล้วต่อด้วย ", " — recursion กับ type switch ทำงานด้วยกันได้สบาย
